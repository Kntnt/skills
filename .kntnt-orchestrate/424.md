## CHANGELOG.md

Under `## [Unreleased]`, in `### Added`:

- `/cloudns` adds a DNS zone at ClouDNS for a domain bought elsewhere, where the instruction asks for the zone itself to be set up or added, as `/cloudns -- set up qwerty.se`. It still acts as the API sub-user and nothing wider: it creates the zone as a master zone with `dns/register.json`, within the quota the sub-user's **DNS zones** field sets in the panel, then reads the NS records ClouDNS put in it and reports those nameservers as what the user enters at their registrar, saying that the zone does not answer for the domain until they have. Record changes asked for in the same instruction follow through the usual read, plan, apply and verify. An instruction that only changes records in a zone the sub-user cannot see still stops with the zone reported as not delegated, and now adds that the Skill can add the zone if it does not exist at ClouDNS yet. Where ClouDNS refuses to add the zone — the quota used up, the plan's zone limit reached, or the zone already existing at ClouDNS — the Skill relays ClouDNS's description verbatim and stops, and for an existing zone names delegating it in the panel as the user's step. `setup`'s panel steps now ask for a **DNS zones** quota with room for the zones the agent will create, and the manpage warns that `/cloudns setup qwerty.se`, written without the separator, is the `setup` subcommand (#424).
