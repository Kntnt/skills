### Changed

- The rules governing a change to what this repository has written down are stated in the module a prose author is routed to. They sat in `docs/rules/general.md`, which every pointer that reaches it announces as the module for writing code — `AGENTS.md` says *read when writing code*, its own trigger says *Read before writing or changing any code*, the subject index says *`general.md` for code form* — so a contributor editing a glossary entry, a manpage, a steps page or a rules module was bound by rules all three pointers routed them away from, and a wave of nine commits of pure prose work did its rework without them. `docs/rules/docs.md`, the module a contributor already reads when the question is *where does this go*, now carries them under `## What a change owes what is already written`: a documented rule is a shared contract whose sweep reaches the prose that shows it, a surface is enumerated by what it asserts rather than by how it words it, what points at a rule is enumerated as well as what states it, and released history is left exactly as it stands. What a change does to a decision record folds into that module's own **A record is never rewritten**, which already carried half of it, and the duty to state a cross-Skill rule in its module was already stated there, so it is dropped rather than moved. `general.md` keeps the sweep over a symbol's callers, which is code work met by a reader changing code, and sends a reader who is also changing prose on. `AGENTS.md`, `CONTRIBUTING.md`, `skills.md`'s scope sentence, `docs.md`'s own trigger line, scope sentence and subject index, and a comment in `tests/test_ms_capture.py` citing the old home each describe what they now point at; `tests/test_rules.py` pins the rules to the one module and pins every pointer a prose change meets to naming it.
