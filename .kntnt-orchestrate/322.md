- `/mirror` fetches in a real browser what plain HTTP cannot. Rung 3 is a headless browser and rung 4 a visible one, both Chrome driven through `agent-browser` in one session of the run's own, named `kntnt-mirror-<pid>` and closed however the run ends, `SIGINT` and `SIGTERM` included. Under `--browser=auto` a host still blocked on rung 2 climbs to rung 3, and to rung 4 only with `--headed`; a URL still blocked in the headless browser without `--headed` ends `blocked`, and the report names it and prints the invocation with `--headed` added, ready to paste. `--browser=always` starts every host on rung 3, or rung 4 with `--headed`, with no HTTP request at all, and `--browser=never` keeps the ceiling at rung 2. For each URL the browser records a HAR with every body, opens it, waits for the network to go quiet, scrolls to the bottom and reads the rendered DOM: a page is saved as that DOM with every `script` element removed and `noscript` kept, its resources are what the browser loaded, taken from the HAR by resource type and saved under `--resources` and `--exclude` as usual, with XHR, fetch and other script-read answers left out, together with what a reading of the DOM finds, and links are followed from the rendered DOM. `robots.txt`, sitemaps, feeds and statically found resources on a browser host go through the browser too. `--user-agent` and every `--header` are passed into the session, `--profile=<name|path>` runs the browser with a Chrome profile, and `--headed` waits up to ten minutes on each page for the person at the window to pass a challenge; either flag with `--browser=never` is refused on exit 2. Before the first browser fetch `agent-browser doctor` is asked whether a browser can launch, and a run that cannot stops on exit 2 with the instruction to run `agent-browser install`. Manifest rows record `fetcher` `browser` and `rung` `3` or `4`, a browser-fetched URL is fetched again on the next run, and `agent-browser` joins `uv` as a dependency of the Skill in every mode (issue #322).
