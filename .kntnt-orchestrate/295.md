### Changed

- Delegation mode asks the selection engine by running it, and no Skill invokes Model Selector as a Skill any more. The standing instruction had told a session to invoke `/model-selector` before every spawn on a foreign model or level, which loads twelve kilobytes of that Skill's body into the session, runs the Manager's invocation engine, and only then reaches the engine that answers — paid once per routed spawn, for the answer `/orchestrate` already gets from one command. The mode now carries that command: `uv run <model-selector>/scripts/selection.py` with the kind, the scope, the harness and seat the session is calling from, the project root a Bridge command needs, `--stakes=high` where the work is irreversible or nothing will check it, and any model or deliberation the user gave. `<model-selector>` is a placeholder `delegation on` resolves and substitutes as it adopts the mode — where the script is being a fact the Skill knows at that moment — so the committed Project and user companions still carry no one machine's path, and the eight Work Kinds are named in the mode itself, so filling `--kind` costs no reading either. Model Selector is therefore never model-invoked: its frontmatter and its Codex sidecar both say so, and its description says that a Skill routing work runs its script.
