### Fixed

- Work that three verdicts refused no longer stays on the run's branch when `/orchestrate` runs at a concurrency of one. Recording the terminal failure now preserves that ticket's commits and whatever it left uncommitted under local refs of the engine's own — untracked files and the staging difference included, ignored files untouched — and puts the branch, the index and the working tree back at the commit that build began on, so the next push publishes nothing the run condemned and the closing branch gate reads a branch without it. The outcome comment and the report name the repository, the refs and the commits, so the work is findable; where it cannot be preserved or the history is not the one the run recorded, the outcome is still written, the recovery is reported incomplete, and a marker ref holds the branch until a repeated `record` finishes the recovery or the developer removes the marker by hand. Runs above a concurrency of one are unchanged (#369).
