### Added
- `/mirror` takes `--include=<regex>` and `--exclude=<regex>`, both repeatable, to widen and narrow its scope. A URL is in scope when it lies under the root or matches any `--include`, and matches no `--exclude`; `--exclude` wins over the root and every include alike. Patterns are compiled by the Python module `regex`, pinned in the engine's metadata, so Perl syntax such as possessive quantifiers, recursion, `\K` and Unicode classes works, and each is matched unanchored against the normalised absolute URL, so `^https://ir\.x\.se/` needs its `^`. The widened scope governs pages, files, sitemaps, feeds and `--resources=in-scope` alike: an included page outside the root, on the start page's host or another, is fetched, read for links and resources, and rewritten like one under the root, while an included URL must still be `http` or `https`. An excluded URL is never requested, a redirect to it included, whether a link, a sitemap, a feed or a page's resources named it; it is recorded in the manifest as `excluded`, ahead of `robots` and `out-of-scope`, a reference to it stays absolute, an excluded sitemap or feed is not read, and the report counts them. A pattern that does not compile, and an `--exclude` that matches the start page, are refused on exit 2 before anything is fetched, naming the pattern and the compiler's error (issue #319).
