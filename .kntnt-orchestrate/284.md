### Fixed

- Two rules the collection states for both kinds of Catalog entry are now held by the suite for both. `apply select` raises a refusal of its own where unchecking a Feature takes what it wrote back out of a Harness's own configuration — a Feature deletes no file, so the gate cannot be raised under the sentence about files — and only the Skill half of that gate had ever been exercised; and `docs/rules/skills.md` says a Feature gets a `### <name>` section under the README's `## Features` heading on the terms a Skill's section is written on, while `tests/test_readme.py` read the `## Usage` part alone and compared it against the Catalog's Skills, so a Feature shipped without a section, or a section left behind by a withdrawn one, was caught by nobody. Both halves are checked now. One test enables the Feature, unchecks it with `--off` — the delta form, because the Skill gate is evaluated first and a whole-set answer would be refused in the Skill's words before this half was read — and asserts the Feature's own sentence together with the absence of the Skill's. A second compares the README's `## Features` sections against the Catalog's `features` on the terms the Skills check already uses, the same heading pattern and the same guard against two empty sets passing each other. `tests/test_kntnt.py` gains a world carrying the one Feature this collection ships for a single Harness, off unless a test asks for it, a Feature being something an Update and an Uninstall both have to account for. The sentence in `docs/rules/skills.md` naming what the suite fails a README on now names a Feature and its sections beside a Skill and its own.
