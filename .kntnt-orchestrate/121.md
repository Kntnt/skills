### Changed

- The suite check that holds the Collection's valued flags to the attached `--flag=value` spelling now derives the flags it applies to from the Collection's own declarations rather than from a list kept beside them by hand: every flag a shipped manpage's `## OPTIONS` section declares with a value, unioned with the flags the Collection's own engines declare as taking one. A valued flag a new Skill or a new engine introduces is enforced with no edit to the suite, and a flag whose declaration is removed leaves the derived set on the same run — which is what the hand list had already failed at, the six flags two new Skills introduced having entered the Collection without entering it. A declaration is read in every spelling a declaration is written in, the space-separated one included, so a flag written wrongly on every surface it appears on is inside the rule rather than outside it, and the engines are read as syntax trees rather than run. The check's self-checking sample is now read against declarations of its own and carries one flag nothing ships, so an empty result still means compliance and what the sample proves is the whole path from a declaration to a caught flag. No flag, spelling, or surface changed, and the derived set is exactly the one the list carried after its last correction by hand. ADR-0105 is the record; it narrows the cost ADR-0096 accepted knowingly, and names the rejected alternative, a staleness check that forces a flag into the list whenever an attached spelling for it is seen (issue #121).
