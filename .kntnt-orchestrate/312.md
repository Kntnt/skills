### Added

- Model Selector keeps its catalogue current by itself. `catalogue.py refresh` could learn a new model and a new price from three structured sources with no agent and no web page, but only when somebody remembered to run it, and nothing did. Enabling the Skill on macOS now installs one owned `launchd` job, `com.kntnt.model-selector.refresh`, that runs `catalogue.py refresh --scheduled` once a day at 05:00 local time, on waking where the Mac slept through it, and at load; Disabling removes it and leaves every other job alone. Unattended, the pass reaches exactly the three sources it already read — Claude Code's and Codex's model lists and OpenRouter's public list — and never runs a model or reads a page ([ADR-0193](docs/adr/0193-the-catalogue-pass-runs-daily-by-itself-and-reaches-only-structured-sources.md), superseding ADR-0185's rule that nothing reaches the network unattended). It is bounded: one pass at a time under `refresh.lock`, one scheduled attempt a UTC day recorded in `refresh-marker.json`, thirty seconds a source and three hundred for the whole pass, a harness exchange killed with its process group at its deadline, and a pass past its deadline before its first write writes nothing but its marker. A pass started by hand always runs, and one that finds the lock busy answers `{"ran": false, "reason": "locked"}`. `/model-selector status` shows the job's health — `healthy`, `degraded`, `absent`, or `unsatisfied` on an operating system with no scheduler adapter — when the next pass is due, whether the last scheduled pass is overdue, and which bound it hit. `launchctl` is reached only where the job's file lies inside the real user's home, so a Manager Sandbox writes the plist and loads nothing.
