### Changed

- `/delegation` now addresses its mode through a command path and its scope through a flag, with one spelling per form: `/delegation on --project`, `/delegation off --user`, and `/delegation status` stand where a scope word, a state word, six long-option aliases, and a free order among them gave a single intent about a dozen spellings — the Skill's own argument prose advertised `/delegation project on`, `/delegation --project --on`, and `/delegation --on --project` as equivalent in one sentence. A collection that refuses an undeclared flag rather than ignoring it, on the grounds that a surface teaching the wrong lesson is worse than a refusal, should not also teach that the same thing has several names; and the free order contradicted the invocation order ADR-0097 settles for every Skill here, in the one Skill whose grammar was made entirely of the words that rule is about. The Skill now accepts four forms and no others: a bare invocation, which toggles the session verdict as it did; `on` and `off`, each taking a scope flag and `--yes`; and `status`, taking a scope flag and reporting all three scopes when given none. The alias set goes rather than being deprecated, two spellings for one form being the defect and a period in which both work being the defect with a schedule attached. The session scope loses its name with them: it is what giving neither `--project` nor `--user` selects, and a bare `/delegation` is now the only way to write a session toggle — which costs a user the ability to write the default scope explicitly for emphasis, and that is the price, stated rather than discovered. Prose stops being a form too: the Skill answered *is it on?* as `status` while interrogating anything wider, so its formal grammar accepted free text at one narrow width and asked about it above that; with the reserved separator carrying instructions collection-wide, an unrecognized bare token is refused like any other invalid form, and the interrogation clause goes with the ambiguity it was answering. Each path is addressable as well: `on`, `off`, and `status` each ship a manpage under the Skill's `help/` with its own `--help` and `-h` route, the root page gains the `COMMANDS` section a command with subcommands carries and loses `STATES`, which those pages replace, while `SCOPES` stays and now describes what the scope flags select. A persistent scope with no state is still refused rather than inferred — the form is now a scope flag with no command path, and flipping a file in a home configuration or a committed file in a shared repository off an inferred state is still the wrong default. Nothing the Skill does changes: the mode's meaning, the three scopes and their placement per Harness, the verdict resolution order, the session scratch file, the staleness report, and the confirmation gate are all as they were. ADR-0109 is the record; it cites rather than restates ADR-0103 where that one already settles command-path addressing in general terms, and it takes over no earlier record's ground, so no outrun pointer is owed — where a record illustrated this Skill with a spelling that is now unwritable, the spelling was corrected in place and that record's decision left as it stands (issue #116).
