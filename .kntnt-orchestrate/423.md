# Entries this ticket owes files the run writes

## CHANGELOG.md

Under `## [Unreleased]`, in `### Added`:

- `/postmark setup server <name>` fetches the server's token from Postmark where the Credential File already holds the account token, instead of asking you to copy it to the clipboard. Every Postmark answer carrying a server lists that server's tokens, so the account token already reaches every server token, and the clipboard step bought nothing while leaving the token readable by any process until the clipboard was cleared. The Skill's engine gains `setup-server`, which lists the account's servers page by page, matches the name exactly, takes the server's first token, has the Collection Library store it under `server:<name>`, and verifies it with `GET server`; the token is never printed, never put on the clipboard and never passed to a process as an argument. A name no server carries, a name several servers carry, and a server with no token are each refused with nothing stored, and the clipboard stays the way through. Where no account token is held, and for `setup account`, `setup` takes the clipboard as before. Rotating a server token with the account token held is regenerating it in Postmark and running `/postmark setup --yes server <name>`. The Library's `credentials.py set` gains `--from-stdin` beside `--from-clipboard`, for a value one of a Skill's own processes already holds: it reads one value from standard input, strips one trailing newline, refuses an empty one, and keeps `set`'s overwrite gate and whole-or-nothing write. `docs/rules/skills.md` names it in the Credential File rule.
