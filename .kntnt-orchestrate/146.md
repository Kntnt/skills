### Fixed

- A Contextual Instruction that a higher-precedence source had already settled was refused as *ineffective* guidance, and the reader got an explanation of the precedence instead of the work they asked for. Two current rules required opposite behaviour on that invocation: the envelope contract every shipped help page carries listed *ineffective* among the grounds for a context refusal, while the editorial Skills' precedence sections put the Contextual Instruction at a level that exists so the levels above it can override it. A level that is there to be overridden cannot make its own overriding an error, so the envelope rule is narrowed collection-wide: *ineffective* now reaches only guidance with no addressable effect at all — guidance touching nothing the addressed Skill's contract addresses — and guidance a documented precedence has already settled against is suppressed rather than refused. The run continues, and the delivery names the suppressed guidance beside the resolved configuration where saying so is useful, through the vent the envelope contract already provided. Two consequences are settled with it: per-parameter suppression is documented semantics rather than partial application, so the *not partially applied* rule reaches guidance that is part invalid and not an instruction with one parameter suppressed and another landing; and the reading that the two rules already reconciled, with the evaluated run at fault, is ruled out on the evidence — the refusal quoted the envelope rule's own reasoning, and it reproduced in sixteen of eighteen fresh runs. The precedence order itself is unchanged, as are the syntax refusals, each Skill's list of invalid forms, and the conflicting, irrelevant, materially ambiguous, and scope-widening categories of the context refusal. ADR-0122 records the decision (issue #146).
