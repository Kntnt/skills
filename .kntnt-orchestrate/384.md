`CHANGELOG.md` — under `## [Unreleased]`, `### Fixed`:

- A text delivered in the response now arrives inside one fenced code block, so it can no longer be run together with the words the reply writes about it. A Redline reply in the Claude-family evaluation of #362 came back with its frontmatter block broken — the artifact's opening `---` sat directly under a paragraph of the run's own prose, where those three characters are also a heading marker, and the blank line that goes in there is exactly what stops a frontmatter block from being one — and the account never mentioned it. The shared delivery contract said where a result goes and nothing about how a response carries it, so sixteen saved replies carried it three ways. It now states the rule for every Skill that delivers by it: the complete Text Artifact in exactly one fence, byte for byte as the run settled it, the fence longer than the longest run of backticks inside the artifact and its info string naming the format; everything the run says about the text outside the fence and everything the run settled as part of the document — the Handoff Metadata, and markings a user asked for in the document itself — inside it. The rule reaches every complete text a reply carries, a stopped Write run's preserved prose included. The short no-change status carries no text and so carries no fence, and a file destination and In-place Editing receive the text itself and never a fence (ADR-0211, #384).
