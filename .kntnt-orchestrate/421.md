CHANGELOG.md
- `/orchestrate` now verifies each piece of work against the gate its own tree's contributing guide states, rather than against a list read once at run start. The guide is a file tickets edit: in the run that built #405–#410, five tickets each added a module to the mypy line in `CONTRIBUTING.md`, so the gate held from run start type-checked none of them, and when the orchestrator read the guide again off the moving run branch, #410's verifier was handed a module a sibling had added and #410's tree did not have, and failed a ticket whose every criterion was met. A ticket's verifier and both attempts of an amend now read the ticket's working tree as it stands when the brief is filled; the repaired-collision verifier reads the repaired tree after the merge; the repair builder reads the run branch, the side its merge brings in, and is told its verdict runs the merged tree's gate; and the wave check, every rerun of it, and the concurrency-of-one branch gate read the branch as it stands. The builder's own brief now carries the gate of its tree too, and tells it that it is held to the commands its guide states when the verdict runs, and that dropping or narrowing one the ticket did not ask for fails the verdict; the ticket and repaired verdicts are shown the gate of the tree's base beside the tree's own, for comparison and never to run, and check for a command dropped or narrowed. A new engine verb, `run.py gate`, picks the tree and its base and keeps the orchestrator's readings in the state directory, one per distinct guide text, so a wave in which no ticket touches the guide still reads it once and no subagent reads it for itself (issue #421, ADR-0219).
