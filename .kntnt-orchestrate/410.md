## CHANGELOG.md

Under `## [Unreleased]`, in `### Added`:

- `/postmark` inspects and changes email at Postmark on the user's behalf: servers and their message streams, domains and their DKIM and Return-Path records, sender signatures, templates, suppressions, bounces, delivery statistics, message search and webhooks, and a send where the user asks for one. `/postmark setup account` and `/postmark setup server <name>` store the account token and each server's token in the Credential File `~/.kntnt/postmark/credentials.json`, read from the clipboard so no token enters the conversation, and refuse to overwrite one already held unless `--yes` is given; `/postmark status` checks every stored token against Postmark, lists the account's servers and marks those the Skill holds a token for, and prints no token. Requests go behind the reserved separator, `/postmark -- <request>`. Its engine, `scripts/postmark.py`, sends each call with the narrowest token the path needs, puts it in its header and nowhere else, and refuses without `--yes` what Postmark cannot undo — any deletion, a send, and a data removal — while a test send under Postmark's test token delivers nothing and is not gated. A domain's DKIM and Return-Path records are reported for `/cloudns` to set rather than set here. A model may start the Skill on its own for a Postmark task (#410).
