CHANGELOG.md
### Added

- Model Selector removes a model its maker has stopped listing, and deletes its measurement with it. `catalogue.load` merged the shipped seed and the refreshed catalogue by id and `adopt` only ever added or replaced, so a model that no longer existed stayed a candidate for as long as the Skill was installed, and deleting its refreshed entry only brought the seed's copy back. `catalogue.py refresh` now treats each chosen maker's own list as the signal: Claude Code's for Anthropic, Codex's for OpenAI, and OpenRouter's public list for Grok. A model is gone when that list, read completely, lacks it on three consecutive UTC days. A day on which any complete read showed it resets the run, and a day with no complete read breaks it. Presence is judged on the version identifier alone — `claude-opus-5[1m]` is `claude-opus-5`, and `x-ai/grok-4.6` is `grok-4.6` by its slug — and never on an alias, so `opus` moving to a successor leaves the old release absent. An entry the Codex list returns marked hidden counts as present. A failed or truncated read is no observation, and failing to run a model never counts: a quota running out would otherwise read as every GPT model gone. When a model is gone, its entry is removed, a record in the new `lifecycle.json` in the data directory masks the seed's copy so no reload or release brings it back, every measurement row and pending Unit carrying its exact id is deleted, the generated agent definitions are resynced, and the removal is journalled as `field: "removed"` with its three dates, the rows deleted and the Units dropped. The deletion runs under the grading lock, which moves from `grade.py` into `evidence.py` as `evidence.lock`. Where the lock is busy the entry still goes at once and the rows go on the next pass that gets it, and every later pass, one choosing no maker included, deletes whatever capture has filed since for a removed model. A removed model that reappears in `catalogue.json`, through the pass or through `adopt`, is an ordinary model again, and `lifecycle.json` forgets it in the same operation. `catalogue.py journal` now also prints every removal `lifecycle.json` records, however old, with its running counts, and `/model-selector status` shows each one with its dates and the rows and Units deleted as two numbers. `reset --evidence` leaves `lifecycle.json` alone. `docs/rules/routing.md`, `references/measurement.md`, `help.md`, `help/reset.md`, `help/status.md` and `SKILL.md` say so, and ADR-0192 records why failing to run is not a signal and why the rows are deleted (issue #311).
