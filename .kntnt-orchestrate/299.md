### Fixed

- An operand or a flag value written in outer quotes reaches a Skill without them. `invoke` kept the quotes deliberately — the engine decides nothing about what an operand means, so it stripped nothing off one — and the result was that `/release` handing `/commit` the message `"Release 0.26.0: …"` gave a Skill following its own body literally a subject line wrapped in quote marks; the agent releasing 0.26.0 took them off, which nothing in the contract licensed. The quotes are the caller's way of holding spaces together rather than part of the value, so the engine takes the outer pair off both an operand and a flag value: `"a b"` and `'a b'` are the value `a b`, `'say "hi"'` keeps its inner pair, and only a value whose own quoted run closes at its last character loses one — two runs beside each other, a run closed early, a backtick-quoted run and an unbalanced quote all keep every mark they carry. It happens on the values a valid form answers with, after the form has been read off the tokens as they were written, so a quoted token is still never a command path, a flag, or a literal the Synopsis names, and `"--"` is formal data exactly as before. `$LIBRARY/references/invocation-envelope.md`, which answered the question nowhere, now states the rule.
