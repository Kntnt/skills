## CHANGELOG.md

Under `## [Unreleased]`, in `### Fixed`:

- `/hetzner` no longer changes the protection of a server whose Cloud resource a tool declares, Terraform for example. Before its first write to a server it did not create in the same invocation, the Skill enabled that server's delete and rebuild protection with hcloud, which on such a server changed the resource outside the tool that owns it: the tool's next run reported the difference, and applying it turned the protection off again. The Skill now first settles, from the deployment documentation and infrastructure files of the project at hand, whether a tool declares that server as a resource of its own; a tool that only configures the host does not count, and neither does a tool's directory whose declarations do not name the server. Where one does, the Skill reads the server's protection with `hcloud server describe` and reports it whatever the instruction is, says which kind is off and that it belongs in the project's declaration of the server, and changes that declaration only where the instruction authorizes it, through the project's own workflow; deleting or rebuilding such a server is left to the tool. Where nothing declares it, or the project at hand does not say, the Skill enables the protection before the first write as before and says so, unless the instruction is to delete or rebuild the server (#426).
