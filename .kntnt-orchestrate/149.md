`CHANGELOG.md` — under `## [Unreleased]`, in `### Fixed`:

- The editorial Skills now agree about what a code sample is. `/unslop`, `/redline`, and `/proofread` each state, in one wording, that a code sample — a fenced block, an indented block, or an inline code span — is quoted material rather than the text's own prose: its contents are read past rather than read against the rules, so nothing inside one is a finding and nothing inside one is changed, the docstrings, comments, and string literals among them, while prose *about* code is ordinary prose and is read like every other sentence. The correction brief each correcting Skill hands a fresh subagent names code in the enumeration it preserves, beside the quotations and formatting it already named, and carries the same clause. Two runs of `/unslop` over one code-carrying article, alike in everything but the Correction Budget, had disagreed about exactly this: the review-only run located three of its fifteen findings inside the fenced Python block — a docstring carrying four catalogue patterns and two comments carrying one each — and the correcting run located none, each stating a defensible opposite reason, with nothing written down that either of them disobeyed. Both preserved every byte of code, so what differed was what counted as a finding, which is what the caller acts on. Proofread is included deliberately: a misspelling inside a code sample is a misspelling in somebody's program. Each manpage tells the reader the same thing, so a document full of samples no longer has to be run through a pass to find out what it will leave alone. ADR-0125 records the decision (issue #149).
