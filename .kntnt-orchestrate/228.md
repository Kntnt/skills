CHANGELOG.md

- Codex and OpenCode integrations are now verified against what those Harnesses actually read rather than assumed from Claude Code's shape. Codex CLI 0.153.0 names its own lifecycle events in camelCase (`sessionStart`, `stop`, `sessionEnd`) and accepts a flat `command`-handler entry — confirmed from the installed binary's own `HookEventName` and generated JSON Schema — never Claude Code's PascalCase names or nested matcher group, which the earlier adapter wrote and Codex silently never read. Codex also reviews a hook that is new or changed before it will run it; a Codex integration this collection writes correctly is now reported `gated` — present, not yet active, naming what the user does to clear the review — rather than `healthy`, and this collection forges no trust decision or trust record on the user's behalf. The OpenCode plugin now redirects its event onto the invoked command's own standard input instead of running it with only `--event=<type>` and no payload, which carries the session identity OpenCode nests inside the event and, verified directly against Bun's shell, keeps the child from inheriting the session's own standard input — the one thing that let a fail-open hook reading standard input to end-of-file block on it (ADR-0157).
