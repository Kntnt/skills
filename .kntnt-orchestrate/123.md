CHANGELOG.md

### Fixed

- `/orchestrate`'s `observe --commit` now takes any commit reference the repository resolves — an abbreviated digest, a branch, a tag, `HEAD` — and records the full digest as the attempt's artifact identity. The check behind it was purely syntactic and took only a full forty-hex digest, so the digest a builder's own commit printed was refused, and refused in the name of a different rule: the message said the value was not a commit the run could name as an artifact, which is a question of reachability the check never asked, and it named no form that would have been accepted. A refusal now says the value is not a commit this repository resolves and names the references that are, so a caller is told what to pass rather than left to guess (issue #123).
- Two `/orchestrate` isolations started together no longer race each other through git's own worktree administration, where one of them could be refused a working tree it could have had. Both listing a repository's worktrees and adding one read every entry under `.git/worktrees`, so an entry a sibling add has created and not yet filled in reads as a corrupt repository — `failed to read .git/worktrees/N/commondir` — and the ticket is dropped from the wave with nowhere to build. A wave whose isolations are started at once, which is how an orchestrator starts independent calls, entered that stretch twice at once; it now takes turns through it under the lock the record-number reservations were already produced under, and overlaps everywhere else exactly as before. The window is a few milliseconds wide and cost about one isolation in a thousand under load, which is why it reached a run once and read there as a flake (issue #123).
