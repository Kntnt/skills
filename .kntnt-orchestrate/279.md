CHANGELOG.md
### Fixed
- Orchestrate now gates the branch it built on before a run at `--at-once=1` reports. Files every ticket appends to are the run's to write rather than a builder's, so a builder leaves its changelog entry as a note and the run applies it to the real file and commits that itself, after that ticket's verifier has already reported. Where worktrees are in use the wave check reads those commits on the integrated branch like any other work, but a run at a concurrency of one has no wave to check, so it ended by reporting every ticket done on a branch whose final commits nothing had read — commits the run makes mechanically, which is the reason to doubt them rather than to trust them. Observed in the unattended run of 2026-09-05 that closed the Harness Integration series, where applying the notes went wrong twice in the run's own writing and neither time in a builder's work: once a `### Fixed` heading landed above `## [Unreleased]` instead of under it, and once an entry landed with a blank line between it and its neighbour, both caught only by the orchestrating session reading what it had just written. Step 11 now settles in its own serial clause whether the wave that just ended was the run's last, and where it was, runs the commands resolved at run start on the branch as it stands before step 12 renders anything: one gate run per invocation that reached a wave, taking no verdict and needing no session of its own, because a gate is a command rather than a judgement. The report names the commit the gate ran at and whether it passed, and a failing gate is reported as a branch that is not green rather than as an unqualified set of done tickets — it changes no ticket's outcome, every ticket having passed its own independent verdict against its own acceptance criteria. Runs using worktrees are untouched: the wave check remains the one reading of the integrated branch, and no second gate run is added to that path. `help.md` says that a run at a concurrency of one gates its own branch before reporting (issue #279).
