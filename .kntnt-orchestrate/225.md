CHANGELOG.md

- Model Selector's `capture` now reads the Seat and the usage a finished Claude Code session actually ran, instead of fingerprinting every session against the guess supplied once at opt-in. At `SessionEnd` or an error signal, the Collection Library's new session-record reader (`session_records.py`) reads that session's own finished record — its transcript and, where the session delegated work, the companion `subagents/` directory beside it — bounded to exactly those files and read field by field onto an allow-list: the exact model, the deliberation control in force, and the token categories the Harness counted (input, output, cache read, cache creation, thinking), never a prompt, a response, reasoning, tool output, a file, or a working directory. A session that ran on more than one Seat now yields one Usage Record per Seat, a delegated Seat's own channel, surface, adapter and serving mode staying an explicit null rather than borrowing the main Seat's. The read runs inline in the one hook invocation that already ends a session — no process, thread, or wait is added, and the per-turn hook path reads nothing new — and a record that is missing, truncated, or will not parse leaves every measurement null and still writes the row from whatever the session's lifecycle signals established, exactly as before. Codex and OpenCode are not yet supported by this reader, so `capture`'s per-Harness status block now names, alongside each Harness's install health, whether that Harness's own finished record can supply measurements at all (ADR-0158, narrowing ADR-0090).
