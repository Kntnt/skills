## CHANGELOG.md

Under `## [Unreleased]`, in `### Added`:

- `/hetzner setup <project>` puts a Hetzner Cloud project's API token on this machine without it entering the conversation. Copied from the project's Security page in the Console, it goes from the clipboard through the Collection Library's `credentials.py exec` into hcloud's own configuration, as a context named exactly as the Console names the project, and stands in the environment of that one `hcloud context create` call and nowhere else. `setup` refuses to replace a context that already exists unless `--yes` is given, which is how a token is rotated; it verifies the token and reports how many servers it sees, and leaves hcloud's active context as it found it. Once per machine it makes the agents' own key, `~/.ssh/kntnt-agent`, an ed25519 key without a passphrase, and registers its public half in the project as `kntnt-agent`, so a server created there gets it at creation. `/hetzner status` lists every context, whether its token is accepted, how many servers it sees and whether its project holds the agents' key, and prints no token. The agents reach a server as a user `kntnt-agent` of their own with passwordless `sudo`, a procedure the Skill carries out on a server it can reach with the user's own key and prints for the user otherwise; an instruction naming a project reaches that project's context; and before its first write to a server it did not create in the same invocation, the Skill enables that server's delete and rebuild protection. An instruction to `/hetzner` is now written behind the reserved separator, as `/hetzner -- <instruction>`, since a bare one would be read as a command (#409).
