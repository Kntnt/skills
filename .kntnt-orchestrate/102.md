- `/proofread` corrects one supplied text's mechanical language errors and nothing else. It corrects spelling, grammar, punctuation, agreement, inflection, duplicated and missing words, and the locale's own conventions for dates, numbers, currency, and quotation, and it preserves wording, meaning, tone, register, structure, factual content, formatting, code, links, and metadata — frontmatter byte for byte, and the text's own choice wherever more than one form is correct, because a preference is not an error. It needs no other Skill and no provenance, so a text written by hand or produced elsewhere is proofread exactly as one this collection wrote. The language is resolved by a fixed precedence — the `--language` value, a `kntnt` map in the text's own leading frontmatter, the Contextual Instruction, applicable Conversation Context, then the language of the text itself — and only that Language Resource's mechanics scope is loaded, so no composition, review, or anti-slop guidance is read; a materially mixed or ambiguous language produces a question rather than a guess, and a recognized `kntnt` map naming a language nothing installs is reported as unusable artifact metadata instead of being read as the code it resembles. Ordinary document frontmatter is never read as configuration. One invocation processes one text, more than one being refused rather than resolved into a configuration per file, and delivery follows the Collection's shared contract: the response by default, `--output` naming a file or an existing directory, `--in-place` replacing the single writable local file the text came from, and a short no-change status in the text's own language where nothing needed correcting. It is the second Skill a model may start on its own, behind a description narrow enough to be honest about it — a specific text plus an explicit proofreading request, with generic editing, rewriting, polishing, improving, and reviewing named as exclusions — and `/proofread` reaches the same contract directly at any time. ADR-0094 records what a model-invocable Skill's description has to bound (issue #102).
