### Changed

- `/tldr` is now `/brief`, and nothing the Skill does changes: the perspective, the range rules, the accepted forms, the two scopes, the persistence mechanism, the staleness report, and the confirmation gate are all exactly as they were. The old name described one of the two things it offers. A bare invocation is feedback that the preceding answer missed the useful level, focus, or density, and *TL;DR* is a fair shorthand for the reply that follows; the standing mode is a different act, adopting a perspective for later replies and deliberately revisiting nothing, so there the name promised a summary that never arrives — and the command path that mode now has made the mismatch a thing a user types, `on` reading as *turn the too-long-didn't-read on*. `brief` holds both: as a verb it is what the bare form does — brief me on that, brief me on only the security part — and as a noun it is a document written for whoever has to act on it, which is the reader the perspective already selects for. The standing mode's name follows the command's, so *TL;DR mode* is *Brief mode* wherever a surface states it, the Codex sidecar's display name included, and the managed block the user scope writes is marked `kntnt:brief`, the Skill writing and reading that spelling alone rather than accepting the old marker as a compatibility case. What it costs is that `tldr` was instantly legible to anybody who has read a forum post and needed no explanation at all, while `brief` needs its first line of help to say that it reframes rather than summarises; it also shares a word with the assignment brief the editorial Skills take as input, which is a reader's double-take rather than an ambiguity in anything typed. **An already-installed copy leaves two things behind, and each is removed by hand.** The Skill Enabled under its old name is a directory to delete — `rm -rf ~/.claude/skills/tldr` for a Global Claude Code install, and the same under the Project layer or another Harness's skills directory where it was Enabled there. A managed block the old Skill wrote into a Harness context file is removed by deleting the lines from `<!-- kntnt:tldr -->` through `<!-- /kntnt:tldr -->` inclusive, in `~/.claude/CLAUDE.md` under Claude Code and its counterpart elsewhere; `/brief on --user` then writes the block under the new marker. ADR-0113 is the record; it takes over no earlier record's ground, and where a record spelled an invocation of this Skill the spelling is corrected in place (issue #124).
