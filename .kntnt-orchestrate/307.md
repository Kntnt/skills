CHANGELOG.md
### Added

- Model Selector keeps one standing objective the user sets and every caller inherits. Whether work should be ordered on time or on cost turns on something only the user knows — how much of their subscription quota is left this week — and until now only Orchestrate's `--fast` ever asked for time, so the only way to reach it from any other caller would have been one more flag per calling Skill for one fact about the user. `/model-selector objective time` and `/model-selector objective cost` set it, and bare `/model-selector objective` says which is in force and whether it is the standing choice or the default. `selection.py` ranks on it whenever the caller passes no `--objective`: the order is the caller's `--objective`, else the standing choice, else cost, so `/orchestrate --fast` still orders its run on time, and with nothing set answers still rank on cost, running out of quota mid-week stopping everything while a slower job is only slower. Every answer, an inheriting one included, now carries `objective` (`time` or `cost`) and `objective_source` (`caller`, `standing` or `default`). The choice is kept in `objective.json` in the data directory, not in `profile.json`, which `setup` replaces whole: `setup_apply.py --objective=<time|cost>` writes it and touches neither the profile nor the agent definitions, `setup`, `update` and `catalogue.py adopt` leave it alone, and `reset` previews and removes it with the profile. A file that cannot be read, or names another word, is treated as absent, and the answer's `note` names it; the call is never refused. The judge `grade.py` asks for is pinned to `--objective=cost`, nobody waiting on a grade. Orchestrate records the objective its first route was answered with and passes it by name on every later request of that run — amend, repair, rebuild and resume included — so a standing choice flipped mid-run reaches the next run rather than this one; an answer naming none, from an older Model Selector, records nothing. `docs/rules/routing.md`, Model Selector's `SKILL.md`, `help.md`, the new `help/objective.md` and `help/reset.md`, its Codex sidecar, Orchestrate's `help.md` and `SKILL.md`, and the README say so, and ADR-0189 records the rule, amending the rules paragraph on what finishing is counted in (issue #307).
