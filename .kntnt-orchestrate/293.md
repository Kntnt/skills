### Changed

- `/model-selector update` is a reading job the agent does, and the machine's half of it is a validator. The unattended pass that ran at every session's end had never learned anything at all: it interprets a body only where a source's own `reads_as` names a reader it implements, the one reader it implements is a document already in this Skill's own catalogue shape, no provider publishes one, and none of the seven sources on the maintainer's machine named any reader — so `catalogue.json` had never been written, nothing created a source row any more, and prices, model lists and plans could move only with a new release of the shipped seed. The agent running `update` now reads every `source_url` the catalogue carries, one per model and one per plan, and the provider's own pricing page where that address does not carry the rate card, and writes what it found as one document in the catalogue's own shape. `catalogue.py adopt <path>` is what decides whether any of it may enter the store: it merges each model field by field over what is in force, replaces a provider's plans whole, writes in one move, and reports per model whether it was added, changed or unchanged and which fields moved, per provider which plan list replaced which, and every entry it discarded by name and with the rule it failed. Every rule is per entry — an entry with nothing to attribute it to, a rate card in a currency other than USD or a unit other than per million tokens, a deliberation level off the ladder — so one bad row costs its own row; only a document that is not the catalogue's shape at all is refused whole, and then nothing is written. `capability` is never fetched, being a seeded prior that measurement refines, and a merged entry carries the seed's own forward. `setup` opens with that same reading where the catalogue has gone stale, so the interview offers current facts, and `status` reports freshness from the `retrieved` dates the entries themselves carry rather than from a source store, naming `update` where the newest is more than thirty days old (ADR-0185).

### Removed

- `scripts/refresh.py`, `data/refresh-cadences.json`, the source-state store behind them, the network call at the end of every session, and `--force` on `update`. 954 lines of code, a shipped cadence file, a store and one connection per session were spent establishing that a page's hash had moved, with nothing able to interpret what had moved in it — real cost, real surface, and no fact. Nothing this collection installs reaches the network any more: the network is reached by `update` and by `setup`, both of which a person asked for, and by nothing else. `source-states.jsonl` joins the files `reset --evidence` removes, so the pass takes its leftovers with it.
