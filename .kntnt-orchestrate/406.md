# Entries this ticket owes files the run writes

## CHANGELOG.md

Under `## [Unreleased]`, in `### Added`:

- The Collection Library carries `scripts/credentials.py`, which holds a credential an outside service issued for a Skill in that Skill's Credential File, `~/.kntnt/<skill>/credentials.json`, so that no credential is ever typed into a conversation and copied into the transcripts every Harness keeps. The value passes through the clipboard: `set --from-clipboard` reads what the user copied from the service's console, `generate --to-clipboard` draws a fresh value and puts it on the clipboard for the user to paste where the service asks for it, `show` names the keys the file holds and its mode, and `exec --env=<VAR>` runs a command with one value in one environment variable, which is how a value reaches a tool such as `hcloud` that keeps its own store. The file is `0600` in a `0700` directory, written whole or not at all, and refused by every reader when its mode admits group or world; nothing the script prints is ever a value, and where a machine has no clipboard tool it says which file a person may write by hand instead. `docs/rules/skills.md` now states what a Skill holding such a credential owes — a `setup` that fills the file and refuses to overwrite one without `--yes`, a `status` that prints no value, an engine that reads the file itself and uses each value in the request alone, and `--yes` before any call the service cannot undo — and ADR-0218 records why a file and the clipboard, rather than the operating system's keyring or environment variables alone.
