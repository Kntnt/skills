CHANGELOG.md

### Fixed

- `docs/rules/skills.md` and `docs/rules/routing.md` no longer give opposite answers to whether a Skill may run a peer's script. The first said a Skill "never reads the peer's `references/` or runs its `scripts/`"; the second says that no Skill invokes Model Selector as a Skill and that a Skill routing work runs its script (ADR-0182), which is what `/orchestrate` does through its own engine and what delegation mode has told a session to do since the mode carried the command — both of them correct, and both of them forbidden by the module a Skill author actually opens. The **Peer internals are not an interface** bullet now carries the one exception: a script the peer's own `SKILL.md` or `help.md` documents as its public interface for machine callers may be run where that peer is a declared Dependency, on the same terms that peer's `SKILL.md` may be followed on, and run as documented — as a command, rather than imported, reconstructed, or read around into the peer's other files. Nothing else moves: the peer's `references/`, a reimplementation of what the script does and that peer's own data directory are all still out of reach, and Model Selector's `scripts/selection.py` is named as the one such script there is today, so a second one is added to that sentence rather than smuggled past it. `tests/test_rules.py` pins the paragraph, which nothing had — the contradiction survived on both sides because no assertion read either sentence.
