## CHANGELOG.md

Under `## [Unreleased]`, in `### Added`:

- `/cloudns` reads and changes DNS zones and records at ClouDNS on the user's behalf. It reads the zone before it writes, applies each change through the ClouDNS API, reads the zone again to verify it, and reports what changed and what the service answered; a zone the credential cannot see is reported as not delegated, and a record's content is treated as data rather than as an instruction. It acts as an API sub-user rather than the account's main API user, so it reaches exactly the zones delegated to that sub-user. `/cloudns setup [<sub-user>]` draws the sub-user's password into the Skill's Credential File and onto the clipboard without showing it, then gives the ClouDNS panel steps only the user can take, and refuses to overwrite a credential already held unless `--yes` is given, which is the rotation; `/cloudns status` checks the credential with ClouDNS and lists the zones it reaches. The engine, `scripts/cloudns.py`, puts the credential in the request body and nowhere else, and refuses without `--yes` any call that deletes — a path whose last segment begins with `delete`, or one carrying `delete-existing-records=1`. A change is written after the separator, as `/cloudns -- point www.example.com at 192.0.2.10`; the Skill takes no bare instruction operand, because it has command paths (#407).
