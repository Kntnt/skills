# Entries this ticket owes files the run writes

## CHANGELOG.md

Under `## [Unreleased]`, in `### Fixed`:

- `/hetzner` now admits the agents to a server a configuration tool manages through that tool, rather than by its hand procedure, which the tool's next converge undid: the tool rewrote `AllowUsers`, and the `kntnt-agent` login stopped working. Before it admits the agents to a server or turns them off on one, the Skill settles who manages that server from the deployment documentation and infrastructure files of the project at hand, the repository it runs in, and where they do not say, it asks the user before any write. On a server a tool manages, the agents become an administrator of their own, `kntnt-agent` with `~/.ssh/kntnt-agent.pub` as its key, declared through the workflow of the project at hand and put on the server by a converge. That account has to meet everything the hand procedure lays down, hold a place in `AllowUsers` or `AllowGroups` where sshd limits logins, and leave no line of root's `authorized_keys` holding the agents' key, which a server the Skill creates still gets at creation until the converge takes it out. Where the project at hand has no way to declare another administrator, or its mechanism cannot express part of that, the Skill says which, names the missing part, and stops; the hand procedure is never a fallback there. After the converge it checks the `sudo -n true` login and reads root's `authorized_keys` for the agents' key. Turning the agents off on such a server removes their declaration the same way. `/hetzner setup` shows the public key and both paths, each opened by the condition it applies under, the tool's path first where the project at hand shows a tool; the hand procedure is for a server nothing converges (#425).
