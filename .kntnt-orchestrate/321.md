- `/mirror` notices when a site blocks it and climbs, host by host, to a browser-like identity. Every host starts each run on rung 1, plain HTTP as the Skill; rung 2 is plain HTTP with Chrome 140's user-agent and the `Accept`, `Accept-Language` and `sec-ch-ua` headers a browser sends with it. An answer is a block when, its retries spent, its status is `403`, `429` or `503`, or when it carries a marker from the engine's table of Cloudflare, Akamai, PerimeterX, DataDome and Imperva signs — header markers on every answer, title markers such as `Just a moment...` on every HTML answer, and body markers only on an HTML answer with a block status; a `robots.txt` disallow is not a block. The first block on a host, on `robots.txt`, a sitemap or a feed as much as a page, moves the host to rung 2, where the blocked URL is asked again and every later request to the host goes; a URL still blocked on rung 2 is recorded as `blocked` and fails the run. `--user-agent` and any `--header` naming a header a rung sets replace it on every rung. `--browser=auto|never`, default `auto`, is accepted and documented ahead of the browser rungs, and any other value is refused on exit 2. Every manifest row gains `rung` beside `fetcher`, both those of the last request made for the URL and `null` where none was, and the report counts blocked URLs and hosts that stayed on rung 1 and names, per host that climbed or ended blocked, the rung it ended on and the status or marker that moved it (issue #321).
