Under `## [Unreleased]`, in `### Changed`:

- `docs/evaluation/protocol.md` now states how an editorial evaluation is staged, under `## How an evaluation is staged`, so that the next evaluation ticket and its builder read the rules in the tree rather than in a closed ticket's readiness addenda, where the unattended run of 2026-09-23 to 2026-09-28 had written them ten times over. The rules binding every provider family are one seat for every run, checker and judge and for the pre-change arm; a fresh pre-change arm from the commit the ticket started from wherever the model or a file the Skill loads has changed; a maintainer's ruling that ships whatever the measurement shows, kept apart from a change the ticket makes conditional on it, which alone ends in a decision record when the defect does not reproduce; at most one revise round, with its ship rule; a miss recorded under the ticket that owns the behaviour; a plan committed before the first run and never edited after; interrupted runs void and rerun; and judges sent paths that name neither arm nor ticket. The Claude family's mechanics follow: installs exported with `git archive` into a layout the section's own commands produce and the suite runs, top-level `claude --print` sessions for any run that starts a correction subagent, `CLAUDE_CODE_ARTIFACT=1` where a run needs a scratchpad, and the #388 runner wherever a criterion is answered from the trace. Every new record's name now carries the issue number, in the protocol, the records index and the record template alike, and records already written keep their names. `AGENTS.md` sends whoever writes an evaluation ticket to the protocol, and the index of focused regressions names the staging rules those regressions keep (#439).
