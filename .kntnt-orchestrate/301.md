### Fixed

- `--scope=callable` asked as a process admits only the points something on this machine can start. The pool is narrowed by the provider the caller is already paying for, and `--harness=process` names no provider, so that floor came out null, every enabled point satisfied it, and the reachability test — which is only ever applied to the points the floor left out — was handed an empty list to filter. No candidate was tested at all: a machine with neither `claude` nor `codex` installed was answered with a Bridge command it could not run, which degrades to `inherit` at launch and reaches the grader as no judge, so the machine reported a judge that could not be reached instead of choosing one that could. A process caller is now offered a point only where all three hold — a Bridge plans a command for it, the profile carries a channel saying who pays for it, and that command's binary is on the `PATH` here — and the caller's own provider is held to the same three, a `--seat` being no evidence that the CLI behind it is installed. The third test is a `PATH` lookup on the head of the argv the plan already carries, so no process is started, no network is touched, and nothing keeps a second list of CLI names to fall out of date. Where it leaves nothing, the answer is the seat with a note saying that nothing on this machine can start a process for any candidate, rather than an empty pool being blamed on the locks. `--scope=limited` and `--scope=all` are unchanged under every harness, and what a real Harness admits is unchanged.
