CHANGELOG.md
### Fixed

- Model Selector's OpenCode launch starts the OpenCode actually installed, so a Grok point it chooses can now be reached. The planned argv passed `--cwd`, which `opencode run` does not have: its flag is `--dir`, and the command died on argument parsing before any model was reached. It also named the model as `spacexai/grok-4.6` when this machine's OpenCode channel pays through OpenRouter, which routes it as `openrouter/x-ai/grok-4.6`, and it carried no deliberation, so a row recorded at a level may have run at another. The command now uses `--dir`, names the model `<gateway>/<slug>` wherever the profile's OpenCode channel for the model's provider names a gateway, and passes `--variant <level>` whenever the point has a level. The slug is a catalogue fact: a model entry gains `gateways`, mapping a gateway as the profile spells it to that gateway's own slug, and the seed carries `{"openrouter": "x-ai/grok-4.6"}` on `grok-4.6`. A model with no slug for the channel's gateway is planned as `inherit` with a note naming the model and the gateway, rather than launched under a guessed name. A channel with no gateway, or a profile with no OpenCode channel at all, keeps `provider/id`. Like `capability`, `gateways` is never fetched by `update`, and where a refreshed entry carries neither field — absent, null or empty — `catalogue.load` takes it from the seed's entry for the same id, so the slug reaches a machine that ran `update` before this release. An `adopt` keeps both fields. The Claude Code and Codex commands were checked against `claude --help` (2.1.268) and `codex exec --help` (0.154.0) and needed no change; a test now holds every flag each of the three bridges plans to the flags its installed help lists. `docs/rules/routing.md`, `help.md` and `help/update.md` name `gateways` beside `capability` (issue #308).
