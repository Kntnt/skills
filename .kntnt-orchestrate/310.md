### Added

- Model Selector's catalogue can be kept current by a script, without an agent reading web pages: `catalogue.py refresh --data=<path>` reads three structured sources and nothing else. It asks Claude Code which models the account is offered, through its control protocol's `initialize`; asks Codex the same through `codex app-server`'s `model/list`; and fetches OpenRouter's public `GET /api/v1/models`, which needs no key. No prompt is sent, so no model is started and no token is generated. The harness lists govern which Claude and GPT models of a chosen maker are offered, with their aliases and their levels wherever the list reports them. OpenRouter governs prices, release dates, the slug it routes each model by, and which Grok models are offered: every `x-ai/` id without a `:` variant suffix, not ending `-multi-agent`, and listing a level on the ladder, which on 2026-09-11 is `grok-4.3`, `grok-4.5` and `grok-4.6`. A harness id is matched to OpenRouter by its slug, or by normalising it (`claude-haiku-4-5-20251001` is `anthropic/claude-haiku-4.5`), and the match is written back. Prices are OpenRouter's per token category, converted to per million with `Decimal` at six places, with the first threshold override becoming the long-context card; OpenRouter's blended average price is never used. OpenRouter's price now stands even where a provider's own page differs, so the first pass reprices `gpt-5.6-sol` from 4 / 0.4 / 5 / 20 to 2 / 0.2 / 2.5 / 10. A new model gets a complete, derived entry with no capability seed. One OpenRouter does not list, such as `gpt-5.3-codex-spark`, is added unpriced and attributed to its harness's documentation. A source that cannot be read changes nothing it governs, and an OpenRouter list short of its `total_count` changes nothing at all. A Codex list served from its bundled fallback, detected when the models cache is older than the pass minus 300 seconds, may still add models and set levels. Every change is appended with its old and new value to `catalogue-journal.jsonl` in the data directory, and each source's outcome (`complete`, `incomplete` or `unreadable`, with a reason) goes to `refresh.json`. `/model-selector status` shows the last pass, the outcome per source and the last seven days of changes through the read-only `catalogue.py journal --days=7`, and never folds "no changes" into "could not read". The generated agent definitions are resynced after any change, into `--agents=<dir>` where given. The catalogue's validator now refuses a price member that is not null or a finite, non-negative number, and `adopt` merges a rate card category by category, so an update omitting a category never loses it. Nothing schedules the pass yet, and `/model-selector update` is unchanged. ADR-0191 records the decision; `docs/rules/routing.md`, `help.md`, `help/status.md`, `help/update.md`, `SKILL.md` and `references/setup.md` describe where catalogue facts now come from (issue #310).
