### Changed

- Model Selector no longer answers with a release its own maker has replaced. Among the models a call would otherwise be answered with, only the newest release of each family is a candidate — as the answer, among the alternatives, as an exploration and as the step up after a failure — so a maker that goes on listing a superseded release indefinitely, which through OpenRouter is every Grok, no longer has each of them ranked for ever. A family is whatever the catalogue's own `family` field says and nothing infers a succession it does not state, so `gpt-6-astra` is no newer `gpt-5.6-sol`; newest is by release date, an undated entry losing to a dated one and a tie going to the smaller id, on one comparison that a family alias, the pool and the generated subagent file names now all go by. The rule is the last gate, applied after both locks and after the deliberation ceiling, so a family whose newest release this call has no route to or no admitted level of is represented by its best remaining release rather than lost, and no pool is ever emptied. It never overrides a `--model` lock naming an older release by its exact id, and it removes nothing stored: a superseded release keeps its catalogue entry, its measurement rows, its pending units and its generated agent definition (ADR-0208) (#375).
