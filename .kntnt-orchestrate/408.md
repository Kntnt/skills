## CHANGELOG.md

Under `## [Unreleased]`, in `### Added`:

- `/nodeping` reads and changes uptime monitoring at NodePing on the user's behalf — checks, their results and uptime, contacts, contact groups, schedules and notifications — through NodePing's API. `/nodeping setup` stores the account's API token, copied from Account Settings under API, from the clipboard into the Skill's Credential File, `~/.kntnt/nodeping/credentials.json`, and checks it against the service in the same step; it refuses to replace a stored token without `--yes`, which is how a regenerated token is rotated in. `/nodeping status` names the account the token reaches. The instruction arrives behind the reserved separator, as `/nodeping -- add a check for kntnt.se`. The Skill reads before it writes, matches a check or a contact by its label and target rather than by a guessed id, and verifies each change by reading it again. Its engine, `scripts/nodeping.py`, sends the token as the user name of HTTP Basic authentication and nowhere else, sends a call's parameters as the `json` form field NodePing reads them from, and refuses a deletion without `--yes` in both of NodePing's spellings — the `DELETE` method and an `action=delete` parameter — since the token reaches the whole account and nothing at the service narrows it. A model may start the Skill on its own for a NodePing task (#408).
