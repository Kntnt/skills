# An unranked main seat suspends the ceiling it cannot state

Model Selector's capability ranking read the shipped `data/seed-evidence.jsonl` and nothing else. A main seat with no `evaluation_prior_seed` row in that file left `main_rank` at `None`, the derivation answered with no selections at all, and every mapping and every adapter spec disappeared; routing then inherited on every request, silently. Four runs of `context` against one profile, identical but for the runtime seat, measured it: `claude-haiku-4-5-20251001`, `claude-sonnet-5` and `gpt-5.6-sol` each yielded eight mappings, and `claude-fable-5-1` — released after the seed's `as_of` — yielded none. Seed membership was the only variable.

The ceiling that puts on the Skill is the whole of its purpose. A model released after the shipped seed could never be the main seat without emptying routing, and nothing the user does reaches it: not `update`, which writes the ledger and may not touch the seed; not the ledger's own accumulated observations; not a profile edit. The seed is a file inside the Skill, so only shipping a new version of the Skill moved it. The Skill exists to keep itself current and answer well unattended, and the one place none of what it collects arrived was the ranking that decides.

This record narrows ADR-0083, which states that unknown ceilings are refusals rather than optimistic fallbacks, and narrows ADR-0136, which states that a main seat with no comparable rank preserves the exact main seat with empty mappings and that unvalidated selections never become mappings.

**Model Selector never refuses a routing request for a state the caller cannot act on.** When another Skill invokes routing — Orchestrate above all — a refusal is read as *start nothing*, so a refusal is the machine-readable form of an interrupting question, and this Skill was commissioned to be set-and-forget. A routing verb therefore refuses only what the caller itself got wrong: a malformed request or snapshot, an ambiguous override, an explicit lock no configured point can carry, a request above the ceiling. Every refusal that reports the state of the world becomes inheritance with a stated reason, because inheritance costs the run its optimisation while a refusal costs the run. Applied to the nine stable request-decision codes, seven are correct as they stand and two convert here: the model half of `unknown_main_seat_ceiling`, and `empty_safe_candidate_set` on a Harness that can inherit, which becomes `unavailable_safe_candidate`. ADR-0165 retired a third, `invalid_profile`, for the same reason. What is left of the first is the caller's own error and not the world's: a null `deliberation_capability`, which is fixed portable ordinals no derivation omits and so only a hand-built snapshot presents, and an exact model lock under a seat nothing scored — the one request whose whole point is a model chosen against the seat's own authority. A deliberation lock is not one of those: the dimension it names still binds, so it is answered exactly.

**A rank comes from the ledger and the seed together, and the ledger supersedes the seed.** An evaluation row names its model by a validated `ModelVersion`'s `model_version_key` or by an `AliasBinding`'s `model_reference_key`, and both are read: reading only the first silently drops every alias-backed model, which on the machine this was measured on is one of the seven rows in the store. A benchmark row bridges to the seed's own benchmark through the `seed_id` the import preserved, so a re-imported prior and its original are one benchmark rather than two. One rule settles the merge — the ledger supersedes the seed for the same model and benchmark, and within one source the maximum score per model per benchmark stands. No timestamp arbitrates, because an imported seed row keeps the seed's original retrieval timestamp and is the same age as its own original by construction.

**The comparison benchmark is selected on candidate coverage alone.** Whether it also scores the main seat is no longer a condition of selecting it. This is the half of the defect that a fix stopping at the ledger does not reach: the ranking returned no ranks in two places, and removing only the derivation's `main_rank is None` guard restores mappings that all carry `model_capability: null`, every point is then excluded as `capability_rank_unavailable`, the pool empties, and the request inherits — a change that satisfies every criterion and leaves the machine exactly as inert as it was. The function now returns a rank for every candidate the selected benchmark scores and the main seat's own rank as `null` where that benchmark does not score it.

**An unranked main seat suspends the ceiling. It does not acquire one.** Every admitted selection is a candidate, objective and evidence order them as they always do, the deliberation dimension binds unchanged, a candidate the comparison never ranked stays excluded as `capability_rank_unavailable`, and the decision carries `audit.main_seat_ceiling` stating `model_dimension_enforced: false` with the stable reason `no_scored_evaluation_for_main_seat` — carried wherever the snapshot holds a configured point the dimension would have been enforced over, and withheld where it holds none, an absent profile leaving the seat unranked because nothing looked rather than because nothing scored it. The seat this was filed from has no score anywhere — not in the seed, not in the ledger, and its local run observations carry no scores at all — because discovery runs weekly while the only index that can score what it discovers runs monthly, so a newly adopted seat is unrankable for up to a month by construction. Suspension is exactly as durable as that gap: it lasts from a release until a benchmark scores it, and closes on its own. The other half of the same design is that such a selection makes its own benchmark release indexes due on the next `update` whatever the cadence says, so the gap is not merely tolerated.

Two substitutes were considered and rejected, and neither may return. *Inheriting a predecessor's score*, which the seat's own capability prior would support, systematically under-rates exactly the population that is unranked — a successor is normally released because it is better — and it persists after the benchmark catches up. *Treating an unranked seat as the top of the ladder* is wrong asymmetrically: where the guess holds it changes nothing, and where it does not it silently admits expensive models beneath a weak seat with nothing in the audit saying a guess was made. The ceiling is a quality rank and cost lives in its own member on the same row, so no rank is synthesised from cost evidence either.

**Candidate admission asks the ledger first and the profile only where the ledger is silent.** A selection is admitted when it is enabled and the ledger records its model — as a validated `ModelVersion`, or as an `AliasBinding` whatever its resolution status — and otherwise when the profile's own `validation_status` is `validated`. That is the second symptom of the same defect: `update` validates a release against its first-party detail page and writes the ledger, but the gate read a profile member `update` is forbidden to rewrite, so a newly adopted model stayed excluded until the user ran `config edit` and no verb said so. Reading it as ledger-only was rejected: every context test writes a profile into a fresh directory and no ledger exists in any of them, and the same holds for any user who has run `setup` and not yet `update`, so a ledger-only gate would take every ranked seat from seven mappings to zero. Letting `update` write `validation_status` back into the profile was rejected too — `update` does not write the user's configuration, and the defect is fully fixed without it.

**What this costs.** Two published inheritance branches where there was one, so a caller distinguishing them reads a token this Collection had not shipped; Orchestrate gained its own constant and its own run-level sentence for it, the two causes being different repairs. The `audit` object of the response contract gains a member, admitted by name rather than by opening the object. Routing now reads four ledger stores it did not read before, each of them append-only JSONL a user may hand-write, so each is read defensively: an absent store, an unreadable one, and a row that is not an object are no evidence rather than a refusal. And a run on an unranked seat is genuinely less bounded than one on a ranked seat — the model ceiling is not enforced, only stated — which is the price of a run that proceeds at all, and it is stated in the decision rather than hidden behind a number nobody measured.
