# A refresh publishes only a verified complete generation

The transport's `add` gives Update the postcondition it needs — every shipped file is copied and stale files are absent — by deleting the destination before it copies. That is correct after the call and unreadable during it. A Manager refreshing itself can therefore erase the entrypoint of the verb still running, and a Harness reading any Skill in the same interval can receive only part of one generation. Treating the transport's exit code or the later presence of `SKILL.md` as verification cannot repair an interval that already happened in the active installation (issue #187).

**The transport remains the acquisition boundary, and it never writes an active installation during a Collection refresh.** The Manager redirects the transport to an isolated home and Project, asks it for the complete intended set, and verifies every resulting candidate before publication begins. A Catalog Skill must carry and match its selected Collection Digest; a local Collection origin supplies the same byte comparison directly. The Manager has no Catalog entry, so the Catalog instead carries a top-level `manager_digest` over every file in its directory except the recursively generated `catalog.json`; the candidate must match that Digest before its Catalog is replaced with the exact Catalog that selected the run, then pass structural checks for its public entrypoints, structured data, and Python helpers. This order lets an otherwise identical Manager acquired through a transport cache converge from an older generated Catalog without letting mismatched Manager files publish. Candidates acquired for several Harnesses must agree with one another. Acquisition or verification failure discards the isolated tree and leaves every active path untouched.

**Publication replaces one complete directory entry with another in a single filesystem operation.** Each verified candidate is copied beside its physical target, checked again, and exchanged with the active non-empty directory by the platform's atomic directory-swap primitive; a previously absent Skill is renamed into place. A reader opening the Skill directory therefore receives the complete old generation or the complete new generation, never the transport's empty interval or a partly copied tree. The old directory remains at the private staging name until the whole publication set succeeds, which makes it the rollback copy rather than a separately constructed backup.

**Logical paths are resolved to physical targets before publication.** Two Harness paths, or a symlinked installation and its real path, that reach one physical Skill tree produce one candidate publication. The symlink remains the Harness-facing entry and the tree it resolves to is exchanged. Stable parent directories are advisory-locked in sorted order while adjacent candidates are prepared and exchanged, so concurrent Manager runs serialize without a lock file that can outlive either run.

**An identical verified candidate is no publication.** The active directory is compared with the staged directory using the Collection's directory Digest algorithm, including the same two ignored runtime artefacts. Equality preserves the directory entry, every inode, and every timestamp. A changed candidate is published; files absent from it disappear with the old generation, so successful refresh still means byte-identical to the selected Collection generation modulo the declared Digest ignores.

**Publication is a transaction over the intended physical targets.** A failure after an earlier exchange swaps every retained old tree back in reverse order; a failure before or during acquisition has no active target to roll back. A withdrawn Skill is an omission from the candidate generation, so Update atomically moves its active directory to an adjacent retained path inside the same transaction instead of asking the transport to delete it afterward. Its integration-owning files are first copied into the isolated acquisition root, and external teardown begins from that copy only after every filesystem target has committed; a publication failure therefore changes neither active trees nor their integrations. If any replacement or omission fails, every retained tree returns to its prior active path and the complete prior Collection remains installed. Every acquisition root, adjacent candidate, rollback copy, and temporary snapshot is removed on success or failure. An atomic swap unavailable on the host is a publication refusal before an active tree moves.

Dry runs need no second implementation: their active paths already resolve inside ADR-0042's Sandbox, and this acquisition and publication transaction runs inside that boundary. The outer Sandbox is still the only tree discarded at the end, so both Global and Project previews retain their no-write guarantee against the real layer.

This decision amends ADR-0001: the transport acquires files but the Manager now owns verified active publication. It replaces ADR-0028's premise that the transport's wipe is itself the active replacement while retaining `add` as the full-tree acquisition. It narrows ADR-0036: presence remains the report boundary for ordinary placement and removal, while a staged refresh is also failed by acquisition, coherence, Digest, or publication verification before the old files are allowed to count as success. It amends ADR-0041's Manager exception: Update still stages the Manager every time because its publication Digest excludes the generated Catalog and cannot preselect a fully identical tree, but an identical staged Manager is proven directly and not republished. It narrows ADR-0090's teardown timing only for refresh publication: the owner is staged while active, then invoked after the filesystem transaction commits.
