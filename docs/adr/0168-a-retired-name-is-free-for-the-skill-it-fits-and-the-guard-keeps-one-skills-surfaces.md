# A retired name is free for the Skill it fits, and the guard keeps one Skill's surfaces

ADR-0113 renamed the reframing Skill from `tldr` to `brief`, and the suite made the rename hold the only way a collection of prose can: `test_the_reframing_skill_answers_to_brief_on_every_shipped_surface` read every shipped text file under `skills/` plus the root `README.md` and `CONTEXT.md`, and failed on any match of the former name in either spelling. A Skill has no parser, so a surface left spelling the old name is a second name the Skill still answers to, and a scan over every surface was how that was caught.

What the scan cannot see is which Skill a match belongs to. It matches a string, and the rename's hygiene is about a Skill: the reframing Skill going on answering to `tldr` is the failure, and the same four letters standing for something else is not. That distinction never had to be drawn while nothing else in the Collection could bear the name. It has to be drawn now — a too-long-didn't-read re-explainer is a Skill this Collection wants, the name is the one every reader already knows for it, and under the guard as written the whole of that Skill and every reference to it fails a gate about a different Skill's name (issue #253).

**The former name is free for a Skill the name fits, because ADR-0113's objection was to a fit and not to a string.** That record's argument runs through what the reframing Skill is: it offers a bare invocation, which reframes the preceding answer, and a standing mode, which adopts a perspective for later replies and deliberately revisits nothing. The bare form the old name suited; the mode it did not, and once ADR-0103 gave the mode a command path the mismatch became a thing a user types, `on` reading as *turn the too-long-didn't-read on* and promising a summary that never arrives. Every step of that is a statement about one Skill's shape. A Skill that re-explains something at too-long-didn't-read length, and carries no standing mode at all, offers nothing for the objection to attach to: there is no mode whose `on` could mislead, and the bare invocation is the whole of what it offers, which is the case the old name always fitted. So the objection stays with the Skill it was made about, and the name is available to a Skill it describes.

**What the guard protects from here is that the reframing Skill answers to `brief` on its own surfaces, not that the Collection is free of the string.** The collection-wide reach was never the rule; it was the cheapest enforcement of the rule while no other Skill could bear the name, and it is now the thing that would make the rule wrong. The surfaces the guard reads are the ones a reader resolves *this* Skill's name from: its own shipped text files, its section of the root `README.md`, and its entry in the Catalog. `CONTEXT.md` leaves the set, naming this Skill nowhere. Records and released changelog entries stay outside it on the ground ADR-0075 already gives — a record's decision stands and an entry is an account of what shipped, so neither is rewritten.

**On those surfaces an invocation of the sibling Skill is a reference, not a second name this Skill answers to.** The line the check keys on is whose command path the token stands in. `/tldr` is the sibling's own path, and a Skill naming a sibling is pointing at it. The former name anywhere else on these surfaces is this Skill wearing it again: in a `name:` frontmatter, which is what every reader outside this Collection resolves the Skill by; in a managed block's marker, which is the spelling the Skill writes and reads on a user's machine; as `TL;DR` in prose, which is the standing mode's old spelling; and in a command path of this Skill's own such as `/brief tldr`, which is a path too, and is exactly why the rule is about whose path it is and never about the shape of the token. That is what this Skill's own check permits, and it is not a rule about how a Skill in this Collection may name a sibling.

**No collection-wide rule follows, for the reason ADR-0113 gave for declining the same question.** Whether a Skill may name a sibling whose name it once carried, and what a name a Skill has retired may be reused for, are larger questions, and this record does not ask them: what is settled here is what one Skill's own check reads and what it permits on the surfaces it reads. So the coding standard gains nothing, a rule governing one Skill's own behaviour needing no statement where a contributor meets the rules binding all of them.

This record **narrows ADR-0113**, whose closing sentence states that where an earlier record spells an invocation of this Skill the spelling is corrected in place. Read as written that is a blanket correction of every occurrence of the former name. What it is narrowed to is an occurrence that invokes *this* Skill; an occurrence that invokes the sibling Skill is left alone, being a citation of a different command. The naming decision itself is untouched, and so is everything ADR-0113 says about what the old name got right and what the new one costs.

**Three substitutes were considered and rejected.** *Keeping the collection-wide scan and excepting the sibling's paths from it* is a hand-maintained list of what does not count, and it grows a line every time the sibling gains a surface — the shape of list this repository has already watched decay into a check that confidently reports nothing wrong. *Naming the new Skill something else* spends the one asset the name has: ADR-0113 named instant legibility as the whole of what the rename cost, and paying that price twice, once to leave the name and once to refuse it, buys nothing. *Retiring the guard* leaves the rename resting on nobody's attention, which is the state that produced it.

**What this costs.** The guard no longer sees the former name outside the reframing Skill's own surfaces, so a stale spelling somewhere else in the Collection is now nobody's test — an acceptable loss, because such a spelling is either the sibling's name used correctly or a defect in prose about a third thing, and neither is what this check exists for. The sanctioned token is written once in the suite, so a sibling that ever spells its invocation differently makes this check permissive about a path nothing answers to, with no red test to say so. And a reader of the reframing Skill's own surfaces now meets a word that used to be its name, pointing elsewhere: a double-take of exactly the kind ADR-0113 accepted when it took a word the editorial Skills already use, and, as there, a reader's pause rather than an ambiguity in anything typed.
