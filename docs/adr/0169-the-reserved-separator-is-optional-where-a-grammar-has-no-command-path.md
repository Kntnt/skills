# The reserved separator is optional where a Skill's grammar has no command path

ADR-0078 gave every Skill of this collection a reserved separator and an optional Contextual Instruction behind it, and ADR-0103 took `/brief`'s free-text operand away in favour of that channel. The price it named for the trade is three characters on the Skill's most-used form, paid once in muscle memory "against a channel that reads the same in every Skill of the collection". A Skill is now being added whose whole grammar is its own name and an instruction — no subcommand, no flag, nothing else (issue #250) — and on that grammar the sentence about the channel is the only thing asking a user to type the separator at all.

**Where a Skill's grammar carries no command path, free text after the Skill name is an operand and the separator is optional.** `/tldr bara säkerhetsdelen` and `/tldr -- bara säkerhetsdelen` are one invocation with one meaning, and both are valid. The Skill declares the operand in its `argument-hint` and in every `## SYNOPSIS` form, beside the separator suffix every form already ends with, and says in one sentence that the two slots carry the same instruction.

**The reason is the premise ADR-0103 rested on, read from the other end.** What forced that record's closed grammar was an ambiguity between an operand and a verb: `on` as a bare word shadowed a legitimate instruction, and `/brief on the security part` had no reading that was both strict and useful. The ambiguity is a property of the grammar and not of free text — it needs something for a leading word to be mistaken for. A grammar with no command path and no flag offers nothing, so prose after the Skill name has exactly one reading, and a refusal there would be strictness bought against an ambiguity that is not present.

**The separator stays on every grammar surface, because what moves is what a user must type.** The `argument-hint` still ends with the instruction suffix and every `## SYNOPSIS` form still ends with its marked-up equivalent, as they do on every Skill here. A user arriving from another Skill of this collection types the separator and is understood; a user who omits it is understood too. The channel is therefore still uniform in the direction that matters — a habit carried from any Skill to any other keeps working — and what stops being universal is only the obligation.

**The operand is formal input, so ADR-0078 is untouched and gets no pointer.** That record already provides that without the separator every part of the payload remains formal input, accepted or refused by the addressed Skill's own grammar. An operand is exactly that, and a Skill declaring one is an instance of the rule rather than an exception to it. Its considered options name trailing prose as ambiguous for a Skill whose formal grammar already accepts free text alongside something else, which is the case this record does not touch.

**A dash-prefixed token inside that operand is part of the instruction.** With no flag in the grammar there is nothing for such a token to shadow, so `/tldr --foo bar` is guidance, obeyed as written or refused as guidance that widens the Skill, and never a syntax refusal for an undeclared flag. The flag-refusal rule and its rationale still appear in the Skill's `DIAGNOSTICS`, every `help.md` here carrying them; what that section says on such a Skill is that this grammar declares no flag and reads the token as prose.

**Two substitutes were considered and rejected.** *Keeping the separator mandatory everywhere* buys uniformity of obligation and pays for it with a refusal that has no ambiguity behind it — the collection's strictness is justified by ADR-0059 as a refusal the user can act on, and a refusal whose only ground is that another Skill needed one is not that. *Letting each Skill decide for itself whether to accept bare prose* is the state this record ends: two Skills with identical grammars could then answer the same payload differently, and a user would have to learn the answer per Skill, which is the cost the reserved channel exists to remove. The condition here is a property a reader can test against the grammar — is there a command path, is there a flag — rather than a preference an author states.

This record **narrows ADR-0103**, whose cost paragraph prices the removed operand against a channel that reads the same in every Skill of the collection. What that channel is now uniform about is availability rather than obligation. Everything ADR-0103 decided stands: `/brief` keeps its closed grammar and carries no operand, its mode is addressed through a command path, the flag spellings are gone rather than aliased, and each path keeps its own page and its own refusal.

**What this costs.** A qualifying Skill documents one instruction in two slots, and a reader of its page meets an operand and a separator suffix whose descriptions say the same thing — a duplication that has to be stated as intended, in a sentence, or it reads as a defect. The condition is a property of a grammar rather than a fact about a Skill, so a Skill that later grows a subcommand or a flag acquires the ambiguity along with it and has to drop the operand in the same change; nothing checks that, and the suite cannot, a grammar's emptiness being exactly what it would have to judge. And a user who learns the shorter form on the Skill that offers it will type it on a Skill that does not, and meet the refusal there rather than here — the same lesson ADR-0103 charged for, arriving in the opposite direction.
