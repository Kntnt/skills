# A wave verdict proves a load flake before passing

A wave verdict once had only one useful fact about a failed gate: the command failed under the complete branch load. The checker could describe a determined correction and buy the existing fix round, or stop when no correction was determined, but it had no way to distinguish a deterministic failure from a timing-sensitive test that the full parallel gate had overloaded. One such failure reproduced green repeatedly on the unchanged head after the run stopped, leaving the developer to perform the inexpensive experiment and repeat the whole gate by hand (issue #199).

**A wave verdict that sees a strict subset of tests fail reruns exactly that subset three times in isolation, using the named gate command's own selection syntax and changing neither tests nor head.** Any isolated failure leaves the existing three-shape verdict and fix-round behaviour unchanged, with the isolation results added as evidence. Three isolated passes classify the failure only as a possible load-induced flake; they earn one complete-gate rerun on the same head, and only a green complete rerun turns the verdict into a clean pass. A second complete-gate failure is a stop. Narrowing a named gate command to the tests it reported failing is that command run again, not discovery of a check outside the carried gate.

**A proved load flake is durable Skill-owned state.** The engine appends one JSON record to `~/.kntnt/orchestrate/flakes.jsonl`, under the same user root as Orchestrate configuration: repository identity, run branch, head commit, failing test identities, three isolation results, full-rerun result, exact narrowed command, load context, and timestamp. Replaying the same record is idempotent and conflicting evidence for the same repository, branch, head, and tests is refused. The complete file is atomically replaced, so interruption exposes either generation and never a partial JSON line.

**The run account selects its own records; the ledger supplies recurrence.** A session-local list identifies which durable records this run established, so a later report does not mistake old flakes on the same branch for current evidence. For every selected record, the report counts earlier ledger records containing each same test identity in the same repository. The ledger remains diagnostic evidence only: it never quarantines, disables, edits, or skips a test, and it never licenses a pass without the final green complete gate.

The protocol costs three narrow reruns and at most one full rerun only after the gate has already failed on a strict subset. A deterministic failure therefore costs narrow evidence but loses none of the correction discipline that existed before. Identity is exact test-runner output rather than a normalized test taxonomy, so renamed or differently parameterized identities count separately; that avoids inventing runner-independent equivalence the engine cannot establish.
