# `/delegation` addresses its mode through a command path and its scope through a flag

`/delegation` took one scope and one state, each written as a bare word or as a long option, in either order among themselves. Six aliases and a free permutation gave a single intent about a dozen spellings, and the Skill's own argument prose advertised three of them as equivalent in one sentence: `/delegation project on`, `/delegation --project --on`, and `/delegation --on --project` all meant the same thing. Two things were wrong with that, and neither is about taste.

**A collection that refuses an undeclared flag should not teach that one thing has several names.** ADR-0059 refuses a flag rather than ignoring it on the grounds that a surface teaching the wrong lesson is worse than a refusal. A grammar with six aliases teaches exactly that lesson from the other side: it says the vocabulary is negotiable, in the one Skill whose whole vocabulary is the words a user has to get right. **And the free order contradicts the order the collection now writes every invocation in.** ADR-0097 settles command path, then flags, then operands, for every Skill here; `/delegation` was the Skill whose grammar was made entirely of the words that rule is about, and it was the one place the rule had to be stated as an exception.

**So the mode is addressed through a command path and the scope is taken as a flag.** The Skill accepts four forms and no others: a bare invocation, which toggles the session verdict exactly as it did; `on` and `off`, each taking a scope flag and the confirmation flag; and `status`, taking a scope flag and reporting every scope when given none. Every form still admits the reserved separator and its Contextual Instruction. ADR-0103 already settles command-path addressing for the collection's other mode Skill, and the argument there — that a closed vocabulary is reached by bare words, that each path becomes addressable under ADR-0077, and that a refusal can then quote the page belonging to the form it refused — is cited here rather than told again.

**The alias set goes rather than being deprecated.** Two spellings for one form is the defect, and a period in which both work is the defect with a schedule attached. This collection has one user, so the migration lands in one change. `--yes` keeps its spelling and its meaning, and `--project` and `--user` are the two scope flags, all three sitting after the command path where ADR-0097 puts them.

**The default scope loses its name.** Session is what giving neither scope flag selects, and it has no flag and no operand of its own: `/delegation on` is the session, and the bare invocation is the only way to write a session toggle. That is the last pair of spellings for one thing, and it is the shape `/tldr` already has, where the session is the unnamed default and only the persistent scope takes a flag. **What it costs is that a user cannot write the default scope explicitly for emphasis.** `/delegation session off` was a legal and readable line, and somebody who wants the scope visible in what they typed no longer has a way to put it there. That habit is worth less than a grammar with one form per intent, but it is a real loss and it is paid by the person who had the habit.

**Prose stops being a form.** The Skill answered *is it on?* as `status` while asking about anything wider, so its formal grammar accepted free text at one narrow width and interrogated it above that. With ADR-0078's reserved separator carrying instructions collection-wide, an unrecognized bare token is refused like any other invalid form, with the addressed `## SYNOPSIS` and the pointer to that path's help route. The interrogation clause and its reasoning go with it — *turn it on everywhere* versus *for this project* was a real ambiguity, and what settles it now is that neither is a form at all rather than that one of them is asked about. Nothing else about what the Skill asks before writing a file changes: the confirmation gate, what it shows, and what `--yes` answers are untouched.

**One refusal survives unchanged in reasoning and changes in shape.** A persistent scope with no state was refused rather than inferred, because flipping a file in a home configuration or a committed file in a shared repository off an inferred state is the wrong default, and an error infers nothing either. Under the new grammar that form is a scope flag with no command path — `/delegation --user` — and it is refused for the same reason, answered from the root page because no command path was recognized.

**Nothing the Skill does moves.** The mode's meaning, the three scopes and their placement per Harness, the verdict resolution order, the session scratch file, the staleness report, the confirmation gate, and what is shown before a write are all exactly as they were. This record is about how the Skill is addressed and about nothing else, which is why it takes over no earlier record's ground: ADR-0026's user scope is still per Harness, and ADR-0059's `/delegation status --yes` is still that string, still an error, still for the reason it gave. Where an earlier record illustrated this Skill with a spelling that is now unwritable, the spelling is corrected in place and that record's decision is left as it stands, as the record deriving the valued-flag registry already did for its own.
