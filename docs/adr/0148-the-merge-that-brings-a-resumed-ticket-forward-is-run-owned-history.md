# The merge that brings a resumed ticket forward is run-owned history

This record amends ADR-0138 in one clause: everything it settled about declared commit roles — the append-only passes, where the walk starts, the `.kntnt-orchestrate/` exemption, and an unmarked merge occupying the next role — stands, and only its enumeration of which run-owned commits the walk skips is outrun (issue #219).

A resumed ticket gets its preserved working tree back standing where the run branch now does, and `isolate()` makes the merge that puts it there. That merge is the engine's own scaffolding: it carries the predecessors this wave integrated, nobody authored it, and no builder ever sees it as work. It carried nothing that said so. `commit_contract_refusal()` skips the marked integration merge and the marked collision repair and reads every other commit as one of the ticket's declared authored roles, so a resumed ticket whose builder had completed one or more valid passes was rejected at integration because the engine's own merge was counted as the next role commit and answered for that role's surfaces. The refusal named files the ticket never touched. Nothing in the gate caught it: the interaction needs a resume, a bring-forward, and a declared contract at once, and no test combined all three.

**A merge created solely to bring a resumed ticket branch forward carries the collection's marker, and is skipped alongside the other run-owned commits.** `<!-- kntnt-orchestrate brought-forward=<number> -->`, written beside the same human subject line the merge always had and read back by the same walk that already reads `merged=` and `repair=`. The regeneration that settles a bring-forward collision confined to declared generated files commits under that message too, so the fact survives the one case where this merge is not clean.

**The marker is the whole of the exemption, and the subject line is no part of it.** An unmarked merge on a ticket branch is a merge somebody authored — a builder bringing a side branch of their own onto the ticket — and it occupies the next declared role and answers for that role's surfaces exactly as a plain commit does, which is ADR-0138's rule unchanged. Exempting by the shape of the commit instead, so that every merge the walk meets falls out of the sequence, would let arbitrary authored history through a gate whose whole purpose is that certified history is checked.

The rejected alternative was reading the merge's subject line. It is already written, it needs no new convention, and it is the thing this collection refuses everywhere else: prose is what a person reads, and a subject line a maintainer reworded would silently reopen this defect with nothing going red.

**What this costs.** A third marker joins the two the walk already reads, so the run-owned markers become one named set — `RUN_OWNED` — that a fourth kind of engine-made commit has to be added to, and forgetting produces a wrong answer rather than a missing one. History made before this record carries no marker, so a ticket resumed by an older engine and integrated by a newer one is refused exactly as it was — nothing rewrites it, and the run that made it is over.
