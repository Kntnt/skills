# Delivery is the response by default, and a source file is replaced only on request

Several Skills produce a Text Artifact, and each of them has to answer the same questions: where the result goes, whether the file that supplied the text may be replaced by it, and what happens when the run finds nothing to change. Answered per Skill, those questions get answers that differ in ways nobody chose, and a user who has learnt one Skill's habits guesses wrong about the next. Answered by a shared output engine, they would introduce a runtime none of the Skills needs — the effect is a single write, and what varies is the decision before it.

**The contract is one reference in the Collection Library.** It has several consumers, so it belongs to no single Skill (ADR-0076), and it is a document rather than a component: each Skill exercises the rules through its own seam, and the Formal Invocation options that expose them stay each Skill's own. The reference therefore states behaviour and never a flag spelling, so a Skill added later is bound by the contract without inheriting a grammar it did not choose.

**Delivery is non-mutating until the caller says otherwise.** The default Output Target is the agent response, and a run that keeps it changes nothing on disk. Supplying a local file as source material selects no destination. An explicit path that does not exist creates exactly that one file; an explicit path naming an existing file overwrites that exact file with no second confirmation, because naming the path is the authorization and demanding a force flag on top of it would teach that naming a destination means less than it says. An explicit directory derives a filename from the source basename, a referenced URL's title, or the Skill's working title, keeps a suitable text extension, and never overwrites what it derives onto: it keeps one stable stem and takes the first free numbered candidate in ascending order beginning at `-2`, so that repeated delivery grows one sequence rather than forking a new stem at every collision.

**Replacing a source has exactly one name.** In-place Editing belongs to the Skills that review an existing Text Artifact; a Skill that creates one never edits the material its brief and sources came from. It requires exactly one writable local source file, excludes a simultaneous separate output option, and is refused for inline text, URLs, uploaded or read-only sources, and more than one Text Artifact. An explicit output path equal to the input path is refused in favour of it rather than honoured, so a reader of an invocation can see that a source is about to be replaced without comparing two paths to find out.

**An unchanged result is reported, not re-delivered.** A response-targeted or in-place run that changed nothing writes nothing and returns a short status in the Text Artifact's own language, since repeating the text spends output on what the caller holds and rewriting the file makes its timestamp claim work that did not happen. An explicitly selected different file or directory still receives the complete Text Artifact, because creating that artifact was the request. Every contradictory, meaningless, or unusable output request is refused before the first side effect and leaves no partial effect behind, under the Collection's ordinary diagnostic and help conventions.

What this costs is a document with no executable check behind most of it: the suite can hold its placement, its silence about flag spellings, and the presence of the rules a consumer depends on, but whether a Skill actually obeys it is visible only through that Skill's own behaviour. The alternative — an output runtime the Skills call — would buy that check by adding a component to a decision whose whole difficulty is deciding, and would still leave each Skill to state which options reach it.
