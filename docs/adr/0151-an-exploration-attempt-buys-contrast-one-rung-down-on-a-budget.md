# An Exploration Attempt buys contrast one Rung down, on a budget

The ledger only ever learns about configurations somebody dared to run, and ADR-0149 gave every Cohort a policy that moves in one direction. A working point gets started at, ratcheted up when it fails (ADR-0150), and never tried from below, so a Cohort converges on a single dot: n successes on one configuration rank nothing, the frontier never separates, and the objective ADR-0147 froze has nothing to order. An Exploration Attempt is the deliberate purchase ADR-0149 named as the one downward path there would ever be — a routed attempt placed one Rung below the Cohort's production Rung, drawn from a shipped probability, capped by a per-run budget, and tagged so its outcome is never mistaken for a verdict on the production point (issue #197).

**Eligibility is exactly the safety facts the request already states.** Reversible work, an external or declared checker, a retry the caller owns, and the Cohort the request names — the facts ADR-0110 already has every Orchestrate execution request carrying, so nothing new has to be true about the work for it to be explorable. An earlier draft required a declared failure-cost bound and was withdrawn: a cost field nobody sets is a dial that ships broken, and the thing the bound was reaching for is already stated, because work whose failure costs hours is work whose failure a checker catches and a retry pays for. A user-configurable bound needs its own ticket and its own public contract.

**Only a task's first routed attempt is ever moved down.** A request carrying a prior point or a verified failure is a retry, and a retry exists to spend the escalation that failure earned. Moving one down would displace the `next_escalation` it was made for, so `amend-<n>-<attempt>` and `wave-fix-<n>-escalated` are routed exactly as they were, whatever the draw says. This also settles what follows a failed Exploration Attempt: the amend is ordinary production selection, arriving with the exploration point as its prior and being answered at the Cohort's own Rung by the ordinary rules, with no escalation bound to it because the prior does not match the selection. The attempt's failure costs the ticket its first amend, which is the price of the information.

**The draw is an input to the artifact and never a coin flipped inside `route`.** Routing is deterministic and a reused snapshot reproduces its decisions (ADR-0083, ADR-0085), so a random number drawn inside the module would make the same artifact answer differently on a resume. The context derivation computes it: SHA-256 over the Cohort's policy seed, the frozen snapshot identity, the run identity, and the request id, joined by single newlines, with the digest's first 53 bits over `2^53` as the value. The derivation freezes the context itself to reach that identity, which is the same function of the same facts `route` applies later, so the two can never disagree. A request without a draw, or without a Cohort, is never explored — which is exactly what a dry run composes, so a preflight renders no Exploration Attempt and the night that follows it is not held to one.

**The budget is a real cap because it is counted on the accepted decision.** `route` carries a per-Cohort counter through the ordered batch, initialized from the count the request states and incremented whenever it emits an exploration selection, so the opening batch cannot spend a budget of one twice. Two requests of one Cohort stating different counts is the caller holding two accounts of the same run and is refused as `inconsistent_exploration_state` rather than settled by picking one. Counting the decision rather than the launch means an attempt prepared for dispatch and then prevented by the environment still spends the budget: the cap can be underused and can never be exceeded, which is the right way round for a term whose whole justification is that it is bounded.

**Orchestrate owns one opaque run identity, minted by the plan that starts the run.** It is not derived from the snapshot identity, which names a context and not a run, and not from a filesystem path. The first plan that may start mints it into the ordinary run state; the routing account copies it when that account is created; every later plan and route reports it from there, together with what each Cohort has already spent — the count of distinct request names in the frozen account whose decision carries the exploration tag. A dry plan composes none of it. The engine reads the tag and counts it and states no selection rule of its own, which is the same boundary every other part of this seam keeps (ADR-0083).

**The tag rides in the decision and reaches the ledger through the allow-list.** An exploration decision's `audit.decision_policy` is `exploration` and a new `audit.exploration` names the production Rung, the selected Rung, and the name the production order would have reported, so the counterfactual is auditable rather than inferred. The observation's provenance gains one field, `exploration`, copied by the emission allow-list out of that audit block, and ADR-0150's window steps over a row that carries it. Isolation of the production configuration's quality needs nothing further: frontiers are per configuration fingerprint (ADR-0145), so a measured point at a lower Rung is a different point and not a worse reading of the same one.

**Exact locks and the floor both outrank the draw.** `--model` and `--deliberation` are the values the caller asked to run at, so a step that would move a locked dimension makes the request unexplorable rather than overriding the lock. The destination may sit exactly on the Cohort's inclusive floor and never below it, which needs no rule of its own: selection already reaches only points inside the resolved bounds, and the descending direction of ADR-0146's adjacency is read over that same pool. `--fast` ends the term entirely — a run frozen for `time_first` (ADR-0147) is a run that bought speed, and buying information at the price of a slower night is not what it asked for.

**This record narrows ADR-0133 and narrows ADR-0134** in the one sentence each carries saying that no exploration policy exists. One does now, and it is this. What those records decided is untouched: the delegation directive still names no exploration, its counterweight still asks the cheap-seat question of every spawn, and execution still takes one of the three paths ADR-0134 chose between. The word *exploration start* in `recommend` also stays what it was — a cold-start classification of a point chosen without measurements — and the manpages say in one sentence that an Exploration Attempt is a different thing, so two established names do not quietly become one.

**What this costs.** One in ten first attempts of eligible work runs a Rung below where the Cohort would have put it, and some of them fail that would otherwise have passed: the price is the ticket's first amend, paid in wall-clock time on a night that has a budget of hours. The cap is per run rather than per period, so a long night and a short one buy the same amount of contrast, and a run that never reaches its second Cohort buys none for it. What travels through the agent is the account's explored request names rather than a count, and the derivation subtracts the batch it is routing before counting them, so a batch re-routed after a resume starts from the count its first routing saw and reproduces its own decision. The names are the shape the agent copies because the count is not a fact the account alone determines: only the derivation sees the batch that has to come out of it, and leaving that subtraction to the agent would put a determinism rule where nothing enforces it. And a Cohort whose work is not homogeneous buys its contrast on whichever ticket the draw happened to land on. In return the ledger stops being a record of one point per Cohort, which is the state every later decision in this collection was designed to read out of.
