# The invocation grammar is executed by one engine

This record settles who carries out the collection's invocation grammar. Until now the strictness every Skill promises — an undeclared flag refused, an operand before a flag refused, an incomplete form refused, never repaired — was carried out by the model, on every invocation of every Skill, from a contract it read in `library/references/invocation-envelope.md` and a grammar it read in the Skill's own `## Arguments`. It is now executed by one engine the Manager ships, `kntnt.py invoke`, which every Skill calls. What the rule is — the call, the payload on stdin, the three answers and their exit statuses, the JSON shape — is stated in [`docs/rules/skills.md`](../rules/skills.md), which is the authority on it. This record argues rather than legislates.

It narrows two standing records. [ADR-0176](0176-how-an-invocation-is-read.md) reasons throughout from the Skills having no parser of their own, the agent reading their files being the whole of the enforcement; the form half of that enforcement now has a parser, and what the agent keeps is the semantic half. [ADR-0177](0177-what-a-skill-ships.md) keeps a Skill with nothing to declare free of the checker so that it does not acquire `uv` for the sake of a check that could only report an empty list; every Skill now calls the engine, `uv` being what the Manager already requires of every user of the collection, so that argument no longer keeps any Skill free of anything. Neither record is annotated: each is read as of its own date, for the reason [`docs/rules/docs.md`](../rules/docs.md) gives.

## The mechanism was uniform, deterministic, and executed by a reader

**Every Skill met the same contract and every Skill asked the agent to perform it by reading** (`docs/research/invocation-mechanics.md`). The Envelope split at the first standalone `--`, the exact help forms routed to a shipped page, the one invocation order, the one refusal shape: identical in sixteen Skills, and carried out sixteen times by a probabilistic reader applying a grammar it had just read. The fixed mechanics weighed about 15 KB of the 212 KB the bodies held — 7% overall, 14% of the median body, a third of `commit` and `push` — and sat before the part of each body that is the Skill. Moving the contract to one Library file, which the collection had already done, made it one editable copy; it did not change who executed it.

**Nothing tested the behaviour, so the strictness was as reliable as the reader on that run.** The suite was structural: it held the `argument-hint`, `## SYNOPSIS` and `## OPTIONS` to one flag set, checked the order every written form is in, and checked that the refusal clause was present. The worked-cases table that pins the split existed as prose the agent was expected to internalise. *Well-tested* meant *held to a form and exercised by daily use*, and a rewrite of any body had no behavioural safety net to lean on.

**The collection already ran part of the mechanism through scripts, unevenly.** The Manager handed every verb's flags to `kntnt.py`, which refused an undeclared one with that verb's synopsis and help route; `orchestrate` passed its flags through to its engine; the editorial Skills resolved `--language` through a script. The precedent for a script reading a Formal Invocation stood in the most-used Skill of the collection. What did not exist was one such reader every Skill could call.

## One engine, on the Manager, fed on stdin

**The engine is a verb on `kntnt.py` rather than a script in the Library, because a body finds the Manager before it finds the Library.** Every body that declares a Dependency already locates the Manager to run `check --here`, and defines `$LIBRARY` from it; a Library engine would be reached one step later through the checker's answer, for nothing. Putting the verb beside `check` also lets one call do both: the dependency check first, then the grammar, so a body opens with one `uv run` where it opened with one before.

**The payload travels on stdin because it reaches the model as text and a Contextual Instruction does not survive a shell argument.** The harness preprocessor that would split arguments for a command file is forbidden for portability (ADR-0177), so what the model holds is the raw text the user typed after the Skill name — several lines, quotes, apostrophes, blank lines between paragraphs. Handing that on verbatim is the act the Manager's own body already asks of it (*pass the user's flags on as they stand*), and it is simpler than applying a grammar; but a multi-line instruction with quotes in it is not a thing a shell argument carries intact, and a heredoc is a shell's own quoting one level down. Stdin carries any text at all.

**The grammar is read from the surfaces the Skill already ships and declared nowhere new.** The suite already machine-reads the `argument-hint` and every `## SYNOPSIS` form and holds the three grammar surfaces to one flag set, so the engine reads the same surfaces: a token is command path exactly where a page under `help/` answers to it, which is the boundary ADR-0176 already draws; a flag is declared exactly where the addressed page's `## OPTIONS` names it, and the `## SYNOPSIS` form says how it carries its value and which flags stand together; the operand slots are the form's, in the order it writes them. A declaration of the grammar in some fourth shape would be a fourth copy to keep true, and the argument for reading the shipped pages is the argument that put the manpage beside the Skill in the first place (ADR-0176): a file a reviewer can read and a Skill can print without deciding anything. What it costs is a reader that parses manpage markup — bold literals, italic metavariables, brackets, alternation bars, the repeat marker inside or outside a bracket — and a page written in a spelling the reader does not know fails the suite, which runs the engine against every shipped page, rather than a session.

**It is not one of the engines the Library's argument grammar binds.** `library/scripts/argument_grammar.py` was written for two engines whose contract is a JSON refusal with a stable code, and its `split` is deliberately permissive: it separates operands from options whichever order the caller wrote them in, because the Skills write the flags first while those parsers read their own operand first (ADR-0176). The strict order is exactly what that module was written not to enforce, and the engine's refusal is the collection's text for a person — what was wrong, the addressed `## SYNOPSIS` verbatim, that page's own `--help` route — rather than a code a caller parses. So the engine reads a Skill's grammar itself and leaves that module to the two engines that have it, while the verb's own command line stays with `argparse` like every other verb of the script.

## What the engine judges, and what it leaves

**It checks the form of an operand and never its meaning.** Present, absent, one, many, and a literal the `## SYNOPSIS` names — `(model|channel)` — are form; what a path, a URL, or an inline text is stays the Skill's, and so does the vocabulary of a value, because a page that says `[=on|off]` in its synopsis accepts `yes` and `true` in its options prose. Everything after the first operand is operand, which is what lets `/commit fix the --yes bug` need no guess (ADR-0176); the price, paid knowingly, is that a declared flag written after the first operand is never read as a flag: `/release minor --yes` reaches the Skill as the single operand `minor --yes`, and it is the Skill's own reading of a version that refuses it. The engine could tell a trailing flag from one in the middle of a sentence only by guessing which the user meant, and a guess is the repair the grammar forbids.

**A Skill whose grammar declares no flag and no command path takes a dash-prefixed token as operand** (ADR-0176). The condition is read off the surfaces — no flag in the `argument-hint`, no page under `help/` — so two Skills with the same grammar answer one payload the same way. For such a Skill the token could be nothing else; for any other it is a flag, declared or refused.

**An empty payload is the bare form.** It is how a model-invoked Skill and a bare `/kntnt` start, and it is valid exactly where the `## SYNOPSIS` admits a form with nothing after the Skill name — `/commit` and `/delegation` do, `/brief` and `/rename-invoices` do not — so nothing special-cases it: it is one more Formal Invocation held to the forms.

**The dependency check runs first, and an Unsatisfied Dependency takes the refusal path with the payload `check` prints today.** A body that answered the checker's exit 2 by printing its stdout and stopping answers the engine's the same way, so the two later changes that move the bodies onto the engine replace one call with one call and change nothing about what the user sees when a binary is missing.

**Three answers, told apart by exit status.** A valid form exits 0 with JSON; an exact help form prints the addressed page and exits 3; an invalid form prints the refusal and exits 2, the status the checker already uses. A body treats both non-zero answers alike — print stdout verbatim and stop — while a test can tell a page from a refusal, and a help form beside a Contextual Instruction takes the context refusal without rendering the page, as the Library file states it.

## What it costs

**One `uv run` per invocation, for every Skill.** The thirteen Skills with a Dependency already paid it for the checker, and the engine folds into the same call; the two that declared nothing now pay it too, and the rule that kept them free of the checker so that they would not acquire `uv` ends with this record. `uv` was never optional for a user of the collection: the Manager's own `SKILL.md` requires it, every script here runs through it, and a Skill that reached the Library for the Envelope contract already stopped with `/kntnt update` where no Manager was installed.

**A grammar reader in the Manager, and the pages it reads becoming an interface.** A `## SYNOPSIS` was documentation a reviewer read; it is now what the engine parses, so a form written out of the collection's order or in a markup the reader does not know is a Skill whose invocations the engine cannot judge. The suite runs the reader against every shipped page for that reason, and a page the engine cannot read fails there.

**At this record's date, no body calls the engine.** The verb, its tests, this record and the rule are additive; the bodies still carry their preamble, their `## Invocation`, and their refusal prose, and the model still executes the grammar in every one of them. Moving the bodies is a change under one invariant across every shipped Skill, and it follows in changes of its own rather than inside the one that builds the engine.
