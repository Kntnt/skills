# A scoped language result exposes content and not its backing path

The GPT-family evaluation of model-invoked Proofread produced the right mechanical corrections through both branches of its trigger and still failed its loading contract. The Harness trace showed the complete `en_US` Language Resource opened after the resolver had returned its mechanics scope, putting composition, review, and anti-slop guidance in context before the pass. Invocation by name had followed the resolver boundary; model invocation had treated the resource itself as further reference. The delivered artifact could not reveal the difference, which is why the trace rather than the text exposed the defect (issue #170).

The body already said exactly which command to run and exactly what was admitted, so the failure was not an absent rule. The scoped response itself carried a `path` to the file it had just filtered. That path was unnecessary to use the response and made the resolver's private input look like the next resource to read. A caller that followed it could obey the selection and defeat the selection in consecutive actions.

**A successful resolver response exposes language identity and the requested scope content, never the backing Language Resource path.** `resolve` returns the canonical identity and only the requested scopes; `list` returns the installed identities and selectors needed to choose among them. The filesystem path is an implementation detail used inside the resolver to read frontmatter and extract scopes. It remains available inside diagnostics where a malformed installed file has to be repaired, because that response stops the editorial run rather than supplying rules for it.

**The scoped content is a terminal result rather than a pointer.** An editorial Skill acts on the returned content directly. It does not need to know whether that content came from the selected locale or an inherited base, because the response already names the scope's source code and contains the resolved rules. The resolver remains the one public seam at which the resource is selected and narrowed, so a caller cannot step around that seam using an address the seam supplied.

**Model invocation and invocation by name converge before resource loading.** The trigger decides whether Proofread starts and supplies the current turn's specific Text Artifact as the omitted operand; after that, both trigger branches and a named invocation enter the same numbered steps. This rule matters even after the path is removed: the response boundary prevents one observed bypass, while convergence prevents the trigger wording from becoming a second execution contract that may invent another.

**Regression evidence observes the Harness trace.** A mechanically correct artifact proves only that the wider guidance did not visibly change that output. Both model-trigger branches are therefore re-run, and each verdict names the scoped resolver call, the returned scope set, the shared mechanics contract, and the absence of any Language Resource file or other editorial guidance from the trace. Static tests hold the convergence and opaque-output contracts; the provider-native record holds what the model actually loaded.

The rejected alternative was another prohibition in Proofread's loading step. That step already excluded every inadmissible scope and document in direct language, and one trigger branch followed it while the other opened the path anyway. Repeating the prohibition would spend more context on the same instruction while leaving the affordance that defeated it intact. A Proofread-specific filtering flag was also rejected: the path has no consumer anywhere in the Collection's successful resolver interface, and making opacity optional would preserve an implementation detail solely so callers could bypass the resolver's defining boundary.

What this costs is the loss of a convenient file address from successful `list` and `resolve` output. A maintainer diagnosing a malformed resource still receives its path in the refusal, and a person administering the installed directory already knows where the Language Resources live. In return, the public result contains everything an editorial caller may use and nothing that invites it to load what the caller explicitly did not request.
