# Inferring a genre reads the installed openings and nothing further

Genre sits in a precedence every editorial Skill of this collection shares: the invocation, then a recognized Kntnt map, then the current instruction, then conversation context, then inference, then the `general` default. The five levels above inference each hand a Skill a name, and a name is verified against the directory that installs it — the directory is the list, and a value with no file is refused rather than resolved to something near it (ADR-0095). Inference hands a Skill nothing. It is the one level where the run has to decide which installed genre the thing in front of it is, and the only reading the resolution step authorised was that same listing, which carries filenames.

A run therefore had a question the installed names could not answer, and answered it the way that was left: by opening a candidate resource to find out what that genre asks for. The evaluations of Write and of Redline against the fixture corpus caught it in eleven runs between them, every one on an invocation that named no genre and never otherwise (issues #139, #140). It reproduced exactly on the condition that produced it, which is what a gap in an instruction looks like rather than a Skill disobeying one.

**Inference reads the installed filenames and the opening of each installed genre resource, and nothing further of any of them.** The opening is the `# <Name>` heading and the paragraph under it, which the resource format has always required so that a Skill showing what is installed has something to show without loading the rest. That paragraph says what the genre is; what the genre asks for is not evidence about whether it applies, so a resource read past its opening has been loaded rather than considered. Where no installed genre fits better than the default does, the default still stands: nothing here makes an unnamed genre resolve to `general` without inference, and nothing here infers a technique, which applies because it was selected and never because a text resembles one.

**The licence sits in the resolution step, and the loading step is unchanged.** Each Skill loads the contract and nothing besides it — the base contract, the resolved genre, the language scopes its resolver returned, an optional technique, and the review halves Redline already loads beside them. What resolution is allowed to read is stated where resolution happens, by name and with its bound; the loading step admits the genre inference settled on and no other, whatever inference read to settle it. The two Skills state the licence in identical words, because one precedence with one question cannot have two answers.

**The opening becomes a requirement rather than a courtesy**, and the resource format page says so beside the format it governs. A genre whose opening does not say what it is leaves a run choosing between installed genres nothing but a filename, and the reading it would fall back on is exactly the one this record removes.

The road not taken is an index: a file, or a frontmatter field, enumerating the installed genres with a line about each. It would answer the same question and cost the property that makes adding a genre a single file — the directory is the list, nothing enumerates it anywhere else, and an index is a second statement of what is installed, kept true by hand and silently wrong the first time somebody adds a resource without it. The openings are already written, already required, and already where a run is looking.

What this costs is a read the loading rule cannot see the end of. Nothing measures how far into a file a run went, so the bound — read the heading and the paragraph, and stop — is held by the instruction and by the same provider-native evaluations that found the gap (ADR-0093), never by an assertion. The suite can hold that both Skills carry the licence, that they carry the same one, that it sits in the resolution step, and that every installed resource opens the way inference needs; whether a run stopped where it was told is visible only in the run's own trace.
