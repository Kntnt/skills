# An engine that reads its own command line parses one grammar the Library owns

Five modules ship under the Collection Library's `scripts/`. Three declare their command lines to `argparse`; two read their own, and those two were the two carrying copies of each other's parsing helpers. The value reader was byte-identical between them, docstring included. The normaliser that separates operands from options was the same loop twice, diverging in one token: the Standing Policy store knew that `--yes` takes no value, and the routed-observation engine had no notion of a valueless flag at all. Nothing exercised the difference, because the engine that had lost it has no such flag — so the copy that did not know they exist would swallow the operand behind the first one anybody added, and answer `Record needs one path.` to a caller who had supplied one (issue #220).

**The two engines that answer in their own words parse one implementation, and it lives beside them in the Library.** `argument_grammar.py` is the whole of how this collection's command lines are read where `argparse` does not read them: a value written apart from its flag is joined to it, because the engines stay permissive about the attached spelling the collection writes everywhere else (ADR-0096), and the operands are separated from the options whichever order the caller wrote them in, because the Skills write the flags first (ADR-0097) while these parsers read their own operand first. This applies ADR-0076 one level in: shared implementation has no honest owner among its consumers, and that holds between two Library modules exactly as it holds between two Skills.

**Which of an engine's flags carry no value is the engine's own fact, declared to the grammar.** A parser that compares a token against a literal is correct for exactly one caller and silently wrong for the next, which is the defect above written as a rule. Each engine names its valueless flags — the policy store its `--yes`, the observation engine an empty set, because it has none — and the grammar takes nothing from behind a flag that was named. No engine gains, loses, or renames a flag here; what changes is that the first valueless flag either of them grows is parsed correctly by construction rather than by somebody remembering.

**Migrating these two to `argparse` was the alternative, and their refusal contract is what it could not carry.** Every line these engines will not run is answered with a JSON body carrying a stable code, on exit 2, on stdout — which is what their callers parse and what the Skills render. `argparse` answers with a usage dump on stderr and an exit status of its own, so an `argparse` migration would have had to reproduce every code in both invocation orders before it was even equal to what stood, and the three engines that already use it are untouched precisely because they have no such contract to reproduce. The parsing seam a Library engine uses therefore turns on whether its refusals are machine-readable, not on taste.

**The grammar is reached by path from beside the module that reads it.** Every consumer of these two modules loads them with `importlib.util.spec_from_file_location`, which puts no directory on `sys.path`, and the Library's own cross-module load already documents why it stays that way: a peer Skill's `scripts/` is not an interface to reach into, and neither is a `sys.path` a module does not own (ADR-0149). So the load mirrors the Standing Policy store's — resolved from the loading module's own directory, never by importing a sibling name and never by amending the path — and the Library travels whole, so the three shipped layouts a Skill adapter already resolves keep working untouched.

**What this costs.** A third module in a Library that had five, and two engines that now fail at import where the Library is incomplete rather than at the first command line they are given — the same revision coupling ADR-0076 already priced, one file wider. A declaration is also a thing that can be left unwritten: a valueless flag its engine forgets to name is parsed as though it took a value, which is exactly today's behaviour rather than a new failure, and it is the one part of this the suite cannot see for an engine whose flag does not exist yet. In return the loop is written once, the fork is gone, and the question a hand-rolled parser cannot answer by looking at a token is answered by the only code that knows it.
