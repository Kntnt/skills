# `--dry-run` is a real run against a Sandbox that is thrown away

Every changing verb commits on the spot, and the user cannot watch a run happen before letting it happen. What the Manager offers instead is the `plan` half of `plan`/`apply`, and what a plan describes is intent: it is composed before the transport has been asked for anything, so it cannot report what the transport did with the files, and the run that follows is the first time anybody finds out. A description of intent is a second account of the verb, kept true by remembering to keep it true. When the two disagree the user is shown the wrong one and nothing in the run can notice.

So `--dry-run` executes the verb. The same code, the same transport calls, the same reading of the disk afterwards (ADR-0036), against a temporary home that is deleted when the run ends. What comes back is an outcome — `intended`, `confirmed`, `failed`, read off the Sandbox's own disk — and it is the verb's own report because there is no second one to disagree with it.

**This is possible because the transport respects an overridden `HOME`**, which was measured rather than assumed: an install with `HOME` redirected to a temporary directory landed entirely inside it and the real home was untouched. Had that not held, `--dry-run` would have had to be a description after all, and this record would say the opposite of what it says. The guarantee it underwrites is stated in terms of the disk rather than of the mechanism: after a dry run, no directory the layer would really have been written to has changed — which for a Project layer is in the working directory rather than under a home, so the redirection has to cover it too.

**The Sandbox is seeded with this collection's own files as they are now** — the Manager, plus every marker-carrying skill found in each Detected directory of the layer being run, and of Global with it where that layer is a Project, and nothing else. The Sandbox has to hold every layer the previewed run *reads*, not only the one it writes to: what Satisfies a Project's Dependency is Global's copy as much as its own (ADR-0013), so a Sandbox holding the working directory alone would read a machine with nothing on it and offer a second copy of every Dependency the user already has. The union runs one way only, and the seeding with it — a Sandbox standing in for Global holds Global alone, since a Global run reads no Project, and one seeded for it would be a directory the real run never looked in. Without the seed every dry run would report installing what the user already has, which is the failure mode of a preview that starts from an empty world. Files belonging to other collections are left out deliberately: no verb of this collection touches them (ADR-0037), so copying them in buys nothing, and if the transport ever did touch one, that is a defect to be observed in reality rather than absorbed by a Sandbox that had made room for it.

**A Sandbox gets its own npm cache**, the cache living under the home that was redirected. The first dry run in a session therefore downloads the transport afresh and takes noticeably longer than the run it is previewing, and the report says so before the wait rather than leaving the user to guess. An unexplained pause in a command whose entire promise is *nothing will happen* is exactly the moment somebody reaches for the interrupt.

`--dry-run` is the expensive, full-fidelity preview, not a routine pre-flight: a verb still confirms before it writes, and that confirmation is not a dry run. The flag is accepted by every subparser of the script, including those with nothing to do with it, for the reason ADR-0029 gives — a forwarded flag must never be the thing that breaks a run.
