# Delegation's user scope is per-harness; its project scope is not

ADR-0005 keeps one desired set across every Harness, but `delegation` persists a standing instruction through a context file, and there is no cross-agent convention for a global one: Claude Code loads `~/.claude/CLAUDE.md`, other harnesses load their own. So `/delegation on --user` covers the harness it runs in, and the user runs it again elsewhere. Project scope has a convention — `AGENTS.md`, bridged where a harness needs it — so one managed pointer and its Project companion cover every harness in that directory. The Manager is not involved: detection says where Skills are Enabled, not which context files a standing instruction belongs in.
