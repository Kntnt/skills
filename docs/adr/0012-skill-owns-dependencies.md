# Each skill declares its dependencies; the catalog is generated; checks are shared

The Skill's `SKILL.md` is the source of its Dependency list, because the Skill must be able to refuse when the Catalog is not there. The Catalog is generated from those files so Select and Update can see the graph. The Catalog is read from the collection origin at each invocation, with the copy stored beside the Manager as the fallback when the origin cannot be reached (ADR-0039). Every Skill calls the same checker in the Manager, so the Unsatisfied message stays one instruction, not a different paragraph in each Skill.

**A skill with nothing to declare calls no checker.** `/tldr` has no binary, no Capability, and no dependency on another Skill, so the check could only ever report an empty list — and running it would mean declaring `uv` for the sole purpose of letting the check that proves there are no dependencies execute. The sentence above is therefore about Skills that have Dependencies, which was every Skill until this one. The rule for the next author is the obvious mirror of it: the day a Skill declares its first Dependency it gains the check alongside it, in the same shape as every other, so the Unsatisfied message stays one instruction wherever there is something to be unsatisfied about.
