# Each skill declares its dependencies; the catalog is generated; checks are shared

The Skill's `SKILL.md` is the source of its Dependency list, because the Skill must be able to refuse when the Catalog is not there. The Catalog is generated from those files so Select and Update can see the graph. The Catalog is read from the collection origin at each invocation, with the copy stored beside the Manager as the fallback when the origin cannot be reached (ADR-0039). Every Skill calls the same checker in the Manager, so the Unsatisfied message stays one instruction, not a different paragraph in each Skill.
