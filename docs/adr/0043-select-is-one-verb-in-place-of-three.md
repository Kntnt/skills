# `select` is one verb in place of three

Status printed a list. Enable and Disable took names. So the everyday act of changing what is Enabled was *read a list under one verb, then retype names from it under another*, and the list the user had just read was not the thing they acted on. Three verbs and a transcription step stood between someone and a decision they had already made by the time they finished reading.

`/kntnt select` prints the Catalog and takes the answer. Rows are grouped by Category so related skills are read together (ADR-0015); each row carries a checkbox that is checked when the skill is Enabled in the targeted layer, the skill's one-line description, and any Capability it requires of the harness (ADR-0030), so nothing about a row has to be looked up somewhere else. The user answers in one sentence of plain text, is asked to confirm once, and nothing reaches the disk before that.

**Reading is never a side-effecting act.** An answer that changes nothing writes nothing — no refresh, no repair, no touching of files to make the disk agree with a list somebody only wanted to look at. Someone who opens `select` to remind themselves what they have must be able to leave knowing they changed nothing, or the verb cannot carry the reading half of its job and the collection is back to three verbs with one of them renamed.

**One verb is not one form.** `--on` and `--off` name skills directly and open no list, because a machine being provisioned has nobody to read one. They apply a delta: naming one skill never silently Disables another, which is what treating a list as a whole-set assignment would do to a script that mentioned one name. `--yes` opens no list either, and Enables nothing that was not already Enabled — it answers the questions that are questions about the disk, refreshing what Deviates and repairing what is incomplete (ADR-0041), and never *do you want this skill*, which there was nobody present to be asked. That is deliberately not what `--yes` does on Update, where the user pointed the verb at the collection's own new entries (ADR-0007).

**There is no `partial` state.** A skill is Enabled or Disabled. One whose files are in some of the layer's Detected Harnesses and not others is a fact about the disk and not a third thing anybody chose: the list shows it checked and marked incomplete, and confirming the list repairs it. Modelling it as a state would have put a value in the payload that no answer of the user's could ever set, and made the list ask a question with no honest answer available.

The script emits a payload and the agent renders it; there is no picker and there will not be one (ADR-0045). What is lost with Status is the union view, and it is given up deliberately (ADR-0038, ADR-0013). What is lost with Enable and Disable is the transcription and nothing else.
