# How work is routed and what becomes evidence

This record settles routing and evidence in one place: how a Skill reaches the one owner of an exact routing decision, what facts that decision is derived from and what a frozen snapshot carries, which ladder an escalation climbs, what a Cohort is for, what a machine may file without asking anybody, when a policy moves by itself, what an ordinary session is allowed to produce, and which of those a Harness integration a Skill owns makes possible at all. It is a consolidation — it supersedes the twenty-one records named below, and carries forward what those records were for, which is the reasoning. What the rules are is stated in [`docs/rules/routing.md`](../rules/routing.md), which is the authority on them; the Library rule about what may enter the evidence ledger without a person, and the shape of the shipped files any of this rides in, are in [`docs/rules/skills.md`](../rules/skills.md), and the Manager seams an owned integration is installed and removed at are in [`docs/rules/collection.md`](../rules/collection.md). This record argues rather than legislates, and where it needs a rule it cites the module that carries it rather than repeating it. A reader who wants today's law should be reading one of those and not this. None of the twenty-one is annotated to say so: the duty that once had a later record reach back into an earlier one is retired, for the reason [`docs/rules/docs.md`](../rules/docs.md) gives, and each of them is read as of its own date until the sweep that removes it.

Pointing at a file that is about to go would be a pointer into nothing.

## Reaching the owner of a routing decision

**A dependency on disk was unreachable by the Skills that depended on it** (ADR-0132). Delegation and Orchestrate must route execution before they spawn it and may observe an externally judged attempt afterwards; both declared Model Selector as a Skill Dependency, and Model Selector was user-invoked only. So a dependent instruction could name its public `route` Interface while Codex omitted the Skill from model context and reported that no slash command or tool endpoint existed.

**Model invocation is bounded to the Interfaces another Skill requires, and to nothing else** (ADR-0132). The description is the complete trigger and excludes recommendation, setup, configuration, comparison, capture, evidence updates, recording and status, each of which stays an explicit user invocation — and `record` stays user-only, so routed work cannot import its own observation by walking in through the front door. What this spends is the standing context of one narrow description; what it buys is that the Interfaces are reachable without copying routing or observation mechanics into every project's always-loaded delegation instruction.

**Neither Harness's spelling denotes a tool endpoint** (ADR-0132). Codex writes `$model-selector` and Claude writes `/model-selector`, and endpoint discovery is no availability check for a Skill Dependency. Making the dependency model-invoked is what puts its description in model context so that a caller can follow its `SKILL.md` at all.

## The context a decision is derived from

**Exact frozen routing had been owned for a while, and the context each decision needed was still each session's to assemble** (ADR-0136, ADR-0083, ADR-0104). That preserved honest routing and left no reproducible path from a persisted profile and an active Harness to the artifact a route request requires. So a public Context Interface stands before `route`: it accepts ordered route requests beside either exact runtime facts — the active Harness and the complete Main Seat — or a frozen snapshot it validates and carries unchanged, and it returns the complete route artifact. It performs no setup, no network access and no persistent write, which is what lets a caller reach it before every route without acquiring policy of its own.

**An adapter ships as a template and becomes concrete only against profile and runtime facts** (ADR-0136). A template declares the Harness and configured surfaces it covers, the model identity it can address, its control source, and a complete launch destination for every relevant field; specialization binds the selected channel, exact model, serving mode, supported controls and the session attestation an inherited destination requires. A selection that is seedless, uncovered, or whose control is unavailable stays visible as a mapping with no reachable adapter rather than being given an invented mapping or rank, and invalid, disabled or unvalidated selections never become mappings at all — so a snapshot can be larger than its candidate pool, which is the honest shape rather than a defect.

**One destination vocabulary covers every launch fact** (ADR-0136, ADR-0104). A parameter destination renders the point value through a template and emits one Harness-native argument; a fixed destination must equal the point and emits none; a carried destination must equal the corresponding frozen Main-Seat fact, requires the verified session attestation, and emits none. Model, surface, serving mode, native controls, tools and policy are all spoken in that one vocabulary, and only emitted parameter names have to be unique. Extending it from the native control it was first written for to every launch-relevant field is what makes a launch reproducible from the snapshot alone.

**Capability rank comes from one independent numeric comparison and from nothing that resembles one** (ADR-0136). A newest non-superseded benchmark definition covering the largest candidate set is selected, and each model's maximum score in it is its rank; a model that comparison never scored has no rank and cannot launch, and qualitative seed prose never becomes a number. A rank is a published quality measurement — not a first-party capability claim, not a price, not a throughput figure — because a ladder built out of anything else is a ladder nobody measured.

**Missing facts inherit rather than trigger setup** (ADR-0136). Empty mappings, and an automatic pool excluded only by unreachable adapters or unknown ranks, preserve the exact Main Seat; an explicit override never inherits, being selected exactly or refused; and commercial dimensions stay unknown rather than being invented from a token schedule with no usage basis. That clause covered too much ground in two places, and both are named below: what a profile's absence is, and what a Main Seat nothing scored does to the mappings.

**The clause about a seat nothing scored is the one that emptied routing** (ADR-0136, ADR-0166). The ranking read the shipped seed file and nothing else, so a Main Seat with no row in it left the rank unset, the derivation answered with no selections at all, every mapping and adapter spec disappeared, and routing inherited on every request silently. Four runs of `context` against one profile, identical but for the runtime seat, measured eight mappings for each of three seats in the seed and none for the one released after it — seed membership the only variable. The ceiling that put on the Skill is the whole of its purpose: a model released after the shipped seed could never be the Main Seat without emptying routing, and nothing the user does reached it. What replaced the clause — a rank read from the ledger and the seed together, a benchmark selected on candidate coverage alone, and a seat nothing scored keeping its mappings while suspending the ceiling it cannot state — is ADR-0166's and is argued there.

**What the derived context costs is data that has to move together** (ADR-0136). The collection owns versioned schemas, adapter data, policy data and observed CLI fixtures, and a Harness dialect change moves all of them at once. In return a caller supplies only facts the live session can know, every derivation rule has one shipped implementation, and a frozen route can be reproduced without hand-authored numbers or declarations.

## A control nobody could name

**Twelve execution decisions were routed in one night and every one of them inherited, each for the same reason** (ADR-0104). No selection control was available, and the module was behaving exactly as designed: a candidate is admitted only through a concrete adapter carrying a complete flag translation, and the Harness in play selects a model family while exposing no deliberation control on a subagent at all. No honest adapter could exist, so every candidate was excluded as unreachable and the audit trail came back complete, honest, and inert. Model selection had been unavailable in exactly the Harness the maintainer works in since routing shipped.

**The framing hid a fact: on a Harness that applies the spawning session's own deliberation to the subagent it starts, the control is not unknown** (ADR-0104). It is the frozen Main Seat's exact value, which the routing snapshot already carries and every verdict already inherits. The point was complete all along, and what was missing was a way to say so. So a native control mapped as carried is a complete translation that emits no launch argument, and it is a different fact from a mapping that is simply absent — which the module refuses and goes on refusing. That distinction is the whole point: an absent mapping means nobody knows what the subagent will deliberate at, and a carried one means somebody checked and the answer is the seat's own value.

**The attestation is required because the claim cannot be computed** (ADR-0104). A carried destination is valid only beside the declaring session's statement that this Harness applies that value to subagents by default, checked against what the Harness actually does before the adapter is declared. No script knows which Harness invoked it, which is why this collection's Harness Capabilities are answered by the running agent rather than tested, and why the adapter stays declared data rather than something the module derives. What the schema can do is refuse to accept the claim implicitly, and that is what it does. The hole this leaves is real and named: a session that declares the attestation without looking gets exact-looking decisions resting on a Harness fact nobody verified, and the fingerprint then binds evidence to a configuration that never ran. The only thing holding it is that the declaring session is the one place with standing to answer.

**A carried control is not a dimension a decision selects over** (ADR-0104). It resolves to the seat's exact portable and native value, so the point yields that one variant rather than one per mapped level; the configuration fingerprint carries the effective seat value, so evidence accrues to what inheritance actually launched rather than to a level nothing ran at; and an explicit deliberation lock over such a variant is refused rather than quietly satisfied.

**Four roads were not taken, and two of them may not come back** (ADR-0104). A genuine partial-selection concept — a point selected in one dimension and unknown in the other — was rejected because an unknown control cannot be fingerprinted, and evidence that cannot bind to a configuration is not evidence about anything. Mapping an existing portable value onto the seam's observed behaviour was rejected as a calibration claim nobody has verified: saying that this Harness's inherited thinking is *high* asserts a correspondence no measurement supports, and the module interpolates or guesses a mapping nowhere else either. Moving selection out into the orchestrating Skill was rejected against the records that put it where it is, a second implementation of adapter reachability living in a caller being the drift those records exist to prevent. And the Harness's other seam — pre-declared agent-type definitions exposing a per-agent effort control behind a user-gated tool — was named rather than built, being a larger piece of work with a consent step in the middle of it.

**The cold-start promise was settled in the same change, because that is where it first bites** (ADR-0104). The contract promises that reversible, objectively checked work begins at the weakest plausibly sufficient configuration and escalates only after verified failure; the code took that branch under a different guard, so a caller that declined unmeasured starts got inheritance for work whose failure its own checker catches, and the two surfaces disagreed about when a heuristic start happens. Reversible work with an external checker or a declared failure signal now takes the heuristic whatever the policy says. That reversible checked work can no longer be held back from an unmeasured start is deliberate: the checker is what makes the start safe, and a caller that wants no start has the choice of not calling.

## A ladder with one rung

**The ladder had one rung, and on the maintainer's own Harness it had none** (ADR-0146). Escalation moved one adjacent portable level on the same model; the model itself was chosen once at cold start and never moved again, nothing was emitted at the top of a model's mapped scale, and on a Harness that carries deliberation by inheritance nothing was ever emitted at all. Claude Code is that Harness, so Haiku, Sonnet and Opus never formed a ladder. A collection whose stated goal is learning the cheapest configuration that holds quality cannot reach it on a ladder with one rung.

**A Rung is therefore two-dimensional** (ADR-0146). Inside one exact mapping it is the next mapped portable value in order, an unmapped level skipped rather than refused — a model that maps two levels and nothing between them has a two-rung scale, not a broken one. Where that scale is exhausted, or the Harness carries the control and no adapter addresses it, the Rung is the next model up by capability regardless of provider, entered at the lowest portable value of its own that survives the request's filters. That step crosses a price boundary a level change does not, which is exactly why the ordering has to be total rather than approximate.

**What changed is not the module's appetite for facts but the facts it is given** (ADR-0146, ADR-0104). The model dimension was declined earlier because the ordering was one nobody had verified; the capability numbers and their provenance now ship in the frozen snapshot as derived priors, and the module reads its ladder from the snapshot alone rather than looking anything up.

**A Rung is always a point the same request already reaches** (ADR-0146). Escalation resolves over the candidate pool selection resolved over, so every hard filter, explicit lock, adapter reachability check and both Main-Seat ceilings have applied before adjacency is read; a point excluded as unreachable, over the ceiling, or outside the workload's capabilities cannot come back as a rung, and a model none of whose levels survive is passed over rather than entered at a level nothing can launch. Each mapping at the target capability collapses to the single value the direction enters it at, and the survivors are ordered by known price first, so equal capability, several mappings of one model, and a snapshot that prices one model and not another all resolve to one launchable point rather than to a set a cold builder would have to choose from.

**A lock is not a Rung, and neither bound is a new guard** (ADR-0146). A request pinning the deliberation gets no escalation in either dimension, the pinned value being the caller's own exact instruction and the pool already excluding every carried variant under such a lock; a request pinning the model needs no rule at all, an alias covering two models being refused as ambiguous before the ladder is reached.

**Down is the same geometry and no downward policy shipped with it** (ADR-0146). One helper answers both directions, so that exploration, when it is priced, inherits one geometry rather than writing a second; only the upward direction is wired to a decision.

**Three roads were not taken** (ADR-0146). Escalating past the next capability to the strongest model the seat allows was rejected because the whole argument for cheap-first routing is that each step is paid for by a verified failure, and a policy that jumps buys capability nobody has evidence it needed. Widening the pool so a carried variant could be escalated into under a deliberation lock would make a lock mean one thing at selection and another at escalation. And ordering within-model adjacency by capability numbers rather than by the portable scale was rejected because two levels may share a number: adjacency has to be a total relation on the scale the request speaks, while capability stays an authority comparison against the Main Seat.

**What the second dimension costs is a purchase the caller may not have priced** (ADR-0146). A step from a model's top level into a stronger model is bigger than the retries this contract was written around, and it is bounded only by the Main Seat and by there being one verified failure behind it. A snapshot whose capability numbers are wrong now routes a wrong ladder rather than merely a wrong start. And where several models tie, the run always climbs into the same representative, so the cheapest of the tied models accumulates evidence and its siblings stay unmeasured until measured selection reaches them.

## A profile somebody wrote, discarded as one nobody wrote

**One reader answered *nothing* for three different situations, and every caller downstream saw the same thing** (ADR-0165). No file, a file it could not read, and a file that failed the profile contract were one answer, so routing inherited on every request with a missing-profile reason, the audit carried a null revision, and a machine that had run `setup` and held three configured channels and eight configured selections on disk was routed as though nothing had ever been configured. It was reachable rather than theoretical: the schema was written after the profile on the maintainer's own machine and the stored file fails it at eighteen paths. The user's only symptom was that runs worked, on the strongest seat available, forever. What that costs is not a degraded selection but the whole of routing — with no mappings and no adapters an exact model override has nothing to be honoured against, and an evidence ledger of any size reaches no decision.

**Absence is the file not existing, and nothing else** (ADR-0165). A file present that cannot be read, cannot be decoded, decodes to something other than an object, fails the contract, or holds a selection resolving to no configured access channel was written by somebody and is rejected. Reporting it as a profile nobody wrote is the defect, so the reading answers with which of three states it met, and the frozen snapshot carries the answer.

**A rejected profile inherits under its own reason token rather than refusing** (ADR-0165). A refusal is read by an unattended caller as *start nothing*, so a profile gone stale would cost such a run every ticket in it, where inheritance costs it only its optimisation. The stable refusal code that had been reserved for the invalid case was retired outright rather than left dead beside its replacement — from the decision path, from the published list, and from the suite — because a code nothing can answer to is a name a caller pins to nothing.

**The rejection rides in the frozen snapshot and carries no value read out of the profile** (ADR-0165). Freezing is the context plus an identity, so putting the detail only in the context response would mean adding a member to a request artifact whose top level admits none, or stripping it inside the shared freeze — both work done to lose information. Where the contract is what rejected the profile, the detail is the schema interpreter's own error text, the failing path beside the constraint it broke; the other shapes name the read or decode failure, the value that is not an object, and the selection resolving to no configured channel. None of them reads a value out of the profile, so none carries the user's plans, tiers or fees into an artifact a caller may print.

**No migration is written, and that is the decision rather than an omission** (ADR-0165). The stored profile that produced the record diverges structurally — a nested fee where the contract expects flat members, objects where it expects strings, and two members the contract has no place for at all — and no transformation bridges those shapes without inventing facts nobody wrote down. The profile is a short interview `setup` recreates in minutes, so a migration framework for a shape this collection has documented exactly one version of would be code kept alive for a case that ends the first time the user re-runs `setup`. The rejection names `setup` as the way back, in the detail itself rather than in a document the user would have to already be reading, and the empty in-memory migration hook went with the decision rather than standing beside it as a seam for a transformation the record refuses.

**A populated ledger survives a rejected profile intact** (ADR-0165). Evidence is read before and independently of the profile branch, so the selections going does not take the measurements with them. What the split costs is a snapshot member with two shapes where it had one, and a user whose profile predates the contract still has to re-run `setup` — the change does not restore their routing, it tells them that it stopped and why, which is the difference between a defect that hides and one that reports itself.

## What a Cohort is for

**Evidence was accounted for and none of it was evidence** (ADR-0145). External judgement was a precondition for routed-work evidence, a run could import that evidence at a verdict, and the context derivation was the collection's rather than each session's — and still the evidence records shipped empty, the route module classified over records nothing produced, and thirteen imported observations left every following decision heuristic. What none of that settled is how a ledger row becomes a fact a later decision can use.

**A routed attempt carries the Cohort of the request it answered, and carries it whole** (ADR-0145). The stage, the workload cohort and the workload tags are copied verbatim from the route request and travel as one: an attempt naming only some of them names none. They are optional because rows written before them are still rows. The benchmark key stays the identity of the check and is not the Cohort.

**A frontier is the exact tuple and not the benchmark key** (ADR-0145). A derived frontier is identified by the benchmark key, the stage, the workload cohort and the sorted tags together, and rows differing on any member are never compared as one — a projected record carries exactly one value for each of those identities, so grouping by less than all four would let it assert a stage the runs behind it never shared. A row naming no Cohort is comparable within nothing: it stays in the ledger and enters no frontier.

**The projection emits records and classifies nothing** (ADR-0145, ADR-0083). One record per fingerprint point, carrying the exact routed point, the Cohort, the judged success rate and the two-sided interval the point's judged runs establish; a point with no decisive run emits nothing, because the quality and interval a record requires do not exist for it. The route module stays the only classifier, and *too few runs* keeps coming from the frozen quality floor rather than from an observation count written down anywhere.

**The context derivation is the only consumer, which is what makes the loop a loop** (ADR-0145). It writes the evidence records for every route request, digests them into the evidence identity, and takes the vintage from the newest instant behind them, so no user step stands between a verdict and the next decision.

**One name yields the Cohort twice, and neither derivation checks the other** (ADR-0145). The engine reads the stage as the role token of the request name and the workload cohort as the run's own prefix plus that role's workload stratum, with empty tags, and freezes all three beside the decision; the Skill body states the same rule for the request the agent writes. Two derivations of one fact from one name is what lets the routed request and the kept observation name the same Cohort — the request name is already trusted the same way.

**What the Cohort costs is history** (ADR-0145). Every ledger row written before it names no Cohort and is evidence about nothing, so the loop starts from an empty frontier rather than from what had been measured, and a frontier file written under the old identity is discarded on the next rebuild rather than migrated. An attempt observed twice across the change is a conflicting identity rather than a duplicate. In return a run's own verdicts are what the next run's decision is made from, and the class a decision reports is a reading of the ledger rather than of a hand-written record nobody wrote.

## The policy that moves by itself

**The one decision an unattended run is supposed not to need was made in prose, mid-run, by asking the user** (ADR-0150). Every workload Cohort had a Standing Policy and one field anybody could store in it, and the only two writers were a person and a reset; nothing moved a Cohort up. A production night made exactly that decision — builders from one deliberation level to the next — by asking. Evidence was already flowing in at every verdict and the policy was already frozen into every route; the missing piece was the sentence that reads the first and writes the second.

**The evaluation lives inside the append, and there is only one append** (ADR-0150). It runs once per Cohort an import touched, after the ledger append, in the Library module that owns it, so the automatic import at a verdict and the user's own `record` reach it through the same call — a threshold that tripped for one and not the other would be two thresholds.

**A row is judged on the ladder its own run froze** (ADR-0150). Every observation carries the Cohort, its policy revision and the resolved rungs, copied by the emission allow-list out of the audit block already on every execution decision, and the evaluation reads that block rather than the current store. A policy that has moved since cannot reinterpret an attempt made under the one before it, and a movement is always to a Rung some frozen decision actually named as the next one. A verdict inherits by authority rather than by policy and carries no block, so it teaches the policy nothing.

**Eligibility is what makes *N of M* mean anything, and a pass is as eligible as a failure** (ADR-0150). A row enters the window when it names the Cohort, is decisive, was machine-judged, carries no exploration tag, carries the Cohort's current revision, ran on exactly its own carried starting Rung, and completed inside the current epoch; the window is the last M such rows and need not be full. An earlier draft that counted only failures made M inert, which is the reason the rule is written out rather than left to the code: under a two-of-four threshold a window holding one failure does not trip, however many failures preceded it.

**The Rung clause is the one that stops a retry from voting twice** (ADR-0150). A row counts only where the Rung it ran on equals the start its own decision resolved, so the escalated retry that follows a verified failure is not counted against the start it escalated from. Without it a cheap-first chain of one failure and one escalated failure reads as two failures at the start, and every Cohort ratchets on its first bad night.

**Every movement begins an epoch** (ADR-0150). A trip and a reset alike stamp the Cohort, and only rows completing after it are eligible — which keeps the same historical failures from escalating a Cohort twice and from immediately undoing a reset somebody just asked for. Staleness is compared on the revision alone, so an in-flight run frozen before another run's movement keeps its evidence and loses only its authority over the policy, reported rather than silently dropped.

**The run reports what it moved from its own import rather than by re-reading the store** (ADR-0150). Selecting the history rows by timestamp, or by the run identity that caused them, was the earlier design and was dropped: the import is idempotent, so what a run moved is a fact the run already holds, and a report that re-reads a shared store to find out what it did can be made to disagree with itself by a second session writing between two renderings.

**The wider reset takes the ratchet down with the evidence that bought it** (ADR-0159). A ledger of forty-seven judged observations naming no Cohort was permanently inert and there was no way to remove it, so an evidence reset was given to the maintainer as the way to throw inert measurement away and start clean. A Standing Policy override is measurement rather than configuration — the override is a claim about what verified failures showed, and the history beside it is the record of which runs showed it — so discarding the failures and keeping the ratchet would leave a Cohort started above its own cold start on a claim with nothing behind it. The policy store and its history therefore go outright, exactly as the ledger, the derived frontiers and the quota store go.

**The narrower reset is unchanged and is the narrower act** (ADR-0159). It restores one Cohort, or every overridden Cohort, to the shipped default while keeping the history that explains how each got there. The price is a second downward path where exactly one was wanted, and it writes no history row because the history it would explain is leaving with it: a user who runs the wider reset for the ledger's sake also loses every Cohort's learned starting point, whether or not they meant to touch routing policy at all. There is no way to keep the override while discarding the evidence that justified it, because keeping it would be exactly the claim with nothing behind it.

**What the ratchet costs is an escalation nobody approved** (ADR-0150). The safeguard is that every step is paid for by externally verified failures at the Cohort's own start and that one command undoes it. A Cohort whose work is not homogeneous averages its lesson across everything in it; the window is per Cohort rather than per benchmark or stage, so two unrelated checks inside one Cohort share a threshold; and a trip that changes the store while a concurrent run is frozen against the old one leaves that run's evidence bought for nothing.

## What a machine may file without asking

**One routed path taught the next night and the other did not** (ADR-0154, ADR-0089, ADR-0137). A run's own verdicts were excepted into automatic import while delegation kept the old rule, so a delegation session could route a subagent, have its work judged by something outside it, write the artifact the contract asks for, name a scratch path in a report — and the evidence reached the ledger only where somebody remembered to import it afterwards. A second gap made the first worse than a missing convenience: the directive named no Cohort at all, and a row naming none is comparable within nothing, so the rows imported by hand were evidence about nothing when they got there.

**A delegated execution request names one Cohort, and the attempt carries it** (ADR-0154). One Cohort is the whole taxonomy on that path rather than a stratum per role, because the frontier identity already holds the benchmark key beside the Cohort: a brief names its own key per workload, so distillation and code execution stay apart without splitting one Cohort into a frontier per brief. A Cohort that discriminates nothing puts unlike work in one comparison, and a Cohort per brief is a frontier of one row — both measure nothing.

**One eligibility rule is held once and read by both routed callers** (ADR-0154). What a machine may file without asking anybody — an outcome an independent verifier, an objective checker or a declared failure signal established, plus the abstain and infrastructure-error conditions no model produced — lives in the Library beside the append it gates, and the run reads it there instead of keeping a constant of its own. A machine that escalates a Cohort unasked and a machine that files a row unasked are answering one question, and two copies of the answer are how two seams writing one ledger come to disagree about what may enter it.

**The import is asked for by name, and a refusal stops nothing** (ADR-0154). Without the flag the verb is what it was, so the hand-run observation acquires no ledger side effect from a decision made for a directive. A conflicting identity, an invalid row or a ledger that cannot be written is reported per identity and stops nothing: the work the row describes is already done, and evidence is not a reason to fail it.

**What this costs is a user's ledger written without being asked** (ADR-0154). An import that brings a Cohort to its threshold can ratchet its starting Rung, so a night of delegation can change what the next route selects. In return the two routed paths behave alike, and the only thing a person still owns is the artifact nobody but a person could have judged.

## The brief and the decision read one ladder

**One request got two answers about its own ladder** (ADR-0153). A low-confidence recommendation answers with a frozen experiment brief — the exact configurations a person is told to go and measure — and the brief froze those points by its own private adjacency, one position up the portable scale inside the launch point's own mapping. The routing decision beside it, in the same module, resolved its escalation through the pool the request actually reaches. So under a deliberation lock the decision emitted no escalation while the brief named a point at the level the lock forbids, and on a Harness carrying the deliberation control the decision climbed into the next model while the brief, whose private adjacency has no second dimension, named nothing and still told the reader to run its permitted adjacent escalation.

**A brief is a promise that the points it lists can be launched** (ADR-0153, ADR-0146). The only construction that knows what a request can launch is the candidate pool as the Cohort's Standing Policy left it, so the brief reads that pool and steps above a selected point with the same Rung resolver the escalation and the Exploration Attempt climb. Its inherited path keeps its measured frontier first and its cap, and only which pool it appends from changes.

**The lock is kept in agreement by a guard rather than by the shared call, and both sides say so** (ADR-0153). With the deliberation pinned to the weakest level the bounded pool still holds every other model at that level, and the shared resolver would return one of them — a point inside the pool that no reachability check can object to. What forbids it is the decision that a lock is not a Rung, so the brief refuses under the lock exactly where the routing escalation refuses, before adjacency is asked for at all.

**Reaching no comparable point removes the comparison and not the section** (ADR-0153). Where the lock holds, or the ladder is exhausted, or the pool offers no further Rung, the section stays, lists the one point the request can launch, and says plainly that there is nothing to compare it against. Measuring that single point is exactly what a heuristic starting point needs — it converts a guess into evidence — so a section that vanished would leave a reader with a low-confidence banner and no route to measurement at all.

**What the shared reading costs is one construction built twice** (ADR-0153). Widening the fingerprint function to take the pool the decision already resolved buys one construction at the price of a seam whose correctness depends on every caller passing the right pool; a shared derivation cannot be passed the wrong one.

## The spawn that is not routed

**A strict reading asked for a route artifact for every spawn, including one where nothing is being chosen** (ADR-0133). The delegation directive said to route the full execution brief before spawning, and a production run found that unworkable and formed a precedent instead: spawns onto a foreign execution surface were routed with full artifacts, while verifier and distiller subagents on the Main Seat's own model were treated as pre-routed and spawned without one. It held all night and it lived in one session's memory, so the next session would either rediscover it or pay the ceremony.

**The boundary is the caller's choice and not a routing outcome** (ADR-0133, ADR-0083, ADR-0104). The shortcut was framed as the answer being inheritance by definition, and in the routing module's own vocabulary it is not: a request carrying any override is selected exactly or refused, never inherited, and where an adapter can express selection controls an automatic request may select a point cheaper than the Main Seat. What is never routed by definition is verdict authority. So the directive states the two paths and the seat between them in one sentence, no judgement call is left for spawn time, and a verifier spawned on the frozen Main Seat costs zero invocations.

**An unrouted spawn produces no observation attempt** (ADR-0133, ADR-0089). An observation begins from the immutable route decision the attempt launched from, and a spawn that legitimately skipped routing has none. Sending the caller back to `route` for a decision object would reintroduce the ceremony the shortcut removes. A minimal local inherit-decision stub — a fingerprint of the frozen seat, written without invoking the owner — was the road not taken, and it was rejected as a second emitter of routing artifacts.

**The shortcut is paired with one sentence of counterweight** (ADR-0133). Making Main-Seat spawns ceremony-free while every cheaper seat still routes tilts each decision toward the expensive seat because it is the frictionless one, and the same run showed the drift in embryo: distiller subagents ran on a cheaper model by precedent from an earlier session, with the reasoning recorded nowhere. So cheap judgment-in-noise roles — distillation, summarization, evidence collection — still weigh a routed cheaper seat rather than defaulting to the frictionless one. The counterweight is a sentence rather than a mechanism, and nothing checks that a session asked the question; the shortcut removes the ceremony for the default and must not remove the question.

**What it costs is work that measures nothing where capture is off** (ADR-0133). An unrouted spawn leaves no trace in the evidence unless ordinary work is being measured, so a machine without it measures nothing about what runs on the Main Seat. In the run this was written from that cost nothing, there being no external judge for a verifier; measurement changes the calculus, which is why the gap was decided rather than left to be rediscovered.

## Three paths, chosen by the shape of the work

**A doctrine naming one mechanism was measured against a night that used three** (ADR-0134). The directive named delegating to a subagent for a bounded report, and a full production night showed the savings coming from three mechanisms with the named one ranking second. The largest was a process detached from the conversation writing to disk — builders, repairs and whole cycles ran that way, the main context received fifty-line reports and searched the progress markers, and hours of build logs and full suites never entered the window. Subagent delegation earned its cost exactly where judgement had to be exercised inside noisy data. And for a small bounded command the Main Seat with output narrowed at the source beat both, because a fenced brief and its reply cost five hundred to a thousand tokens before the subagent has done anything.

**The rule is the shape of the work rather than an order of preference** (ADR-0134). The detached path exercises no judgement and the Main Seat pays no handoff, so neither answers where the other's condition holds. *When unsure, delegate* survives and is scoped to the choice between subagent and Main Seat: uncertainty there is about whether handoff costs less than direct work, which delegating settles cheaply, while uncertainty about whether something needs judgement is never settled by a detached process, which exercises none.

**The detached path is stated as a property and never as a tool** (ADR-0134). The directive is committed into a context file every Harness reads, so it says what the process is — detached from the conversation, its output on disk, its report the one thing read back — and names no command, flag or waiting facility. What one night ran as one CLI's exec mode is one Harness's spelling of the property; the next Harness spells it differently and reads the same sentence.

**The Main Seat ends what it detached, or names it as left standing** (ADR-0134). A subagent already had the rule that whatever it starts it stops before it reports, and a seat that detaches processes acquires the same exposure: a process nobody owns holds the machine other work is done on and goes on speaking for a turn that has finished.

**The roles are listed once, and the word for what comes back is *report*** (ADR-0134). The counterweight sentence already lists the cheap judgment-in-noise roles, so the subagent path names the property rather than a second list that would drift from the first. Verification stays where the directive keeps it: a verifier subagent that runs gates and returns a verdict is judgement inside noisy data and takes the subagent path on that description, while the seat's own verification of what comes back is untouched — a list naming verification as a subagent's role beside a sentence keeping it on the Main Seat would contradict itself in the space of a hundred words.

**A report has a contract, and it is a path plus a cap** (ADR-0135). The directive asked for a bounded, task-shaped report without defining the boundary, leaving each brief to rediscover it. So every brief names a report file inside the spawn's own scratch and the subagent writes complete findings there, while the inline reply is capped to a stated, task-specific budget of conclusions only, with no raw command output and no file dumps; the Main Seat reads the file only where its decision needs the detail, and still verifies results independently. The directive states the shape and each brief chooses the number, because no default cap belongs in the doctrine. The file belongs in the spawn's private scratch so that concurrent delegations cannot collide or expose one another's reports, and keeping the full findings on disk preserves detail without making the inline handoff an unbounded context cost.

**What the three paths cost is a boundary nothing polices** (ADR-0134, ADR-0135). Which path a session took is the reader's judgement, so a session that detaches a distillation reads raw output back and one that briefs a subagent for a test run pays the fence for nothing. A detached process without a report is a process whose output the seat has to go and read, which is the raw output the doctrine exists to avoid. And a Main Seat must choose to open a report when detail matters, while a poor brief can still set an unhelpful cap — brief-level decisions, deliberately outside the fixed contract.

## The integrations a Skill owns

**Measuring was a thing the user had to remember to do** (ADR-0090). Routed work produced importable evidence and the ordinary case stayed where it was: somebody works all day in a Harness and nothing is measured. Closing that means the Harness calling us rather than the user invoking us, which means writing into the Harness's own configuration — the first thing this collection installs that is neither a Skill file nor removed by deleting one.

**The owner travels in what is written** (ADR-0090). Every entry carries a stable ownership identity inside the command it runs rather than beside it in a key the Harness's own schema does not define, so removal is surgical without anything having to be remembered: the disk is read, our entries are found by their owner, and everybody else's survive untouched. Nothing keeps a private ledger of what was installed, so a hand-edited, externally repaired or half-removed Harness is a state the next run converges from, and install, repair, update and remove are one operation applied to whatever is actually there.

**The Manager asks the Skill to remove them while the Skill can still answer** (ADR-0090). Deleting a Skill's files is the moment its integrations become unreachable — after it, nothing on the machine knows what was installed or where — so removal runs first, on the one seam every removal path already passes through, and it is the Skill's own script that runs. The Manager learns no Harness's hook format in the process, and a teardown that fails is reported per Skill and never raised, because external state this collection does not own must not hold up the removal of files it does own.

**Harness-specific mechanics belong to the Library, and which Harness is running stays the agent's to say** (ADR-0090). Three Harnesses, three shapes — two owned hook tables and one plugin file named for its owner — and that knowledge is not one Skill's private business. A Harness whose lifecycle cannot carry the contract reports an Unsatisfied Capability rather than being quietly skipped, because a feature that believes it is installed where it is not is worse than one that knows it is not.

**The per-turn hook path is fail-open, bounded and local** (ADR-0090). It runs inside somebody's session, so it does local metadata I/O and nothing else, and every failure in it is swallowed: capture that breaks a session is worse than no capture, and a user who has to weigh measurement against their Harness working will turn measurement off. Notifications are debounced and user-facing for the reverse reason — a measurement reminder placed where the model reads it would change the configuration being measured, which is also why every later widening below reports on `status` and nowhere else.

**A second opt-in behind an already-Enabled Skill was a feature that never started** (ADR-0160). Writing into a Harness's configuration and handling local session metadata are decisions a user should make knowingly, and the first version of this asked twice for that reason. What it did not price is that a decision nobody makes is a feature that does not exist: automatic capture shipped weeks before and never ran once, anywhere, including on the maintainer's own machine — the Skill Enabled, eight validated selections in the profile across three Harnesses, no capture store, and no owned entry in any Harness's configuration, because opting in was a second gesture behind a command with its own on, off and status forms, a consent statement to read, and a Harness and a Seat to name by hand. Recommendations went on answering from the shipped seed rather than from the maintainer's own work, for exactly that reason.

**Enabling is the whole gesture and Disabling is the whole undo** (ADR-0160). At every seam that already places or refreshes an Enabled Skill's files, the Manager asks a Skill declaring owned integrations to install them, the mirror of the word it already sends a Disabled or withdrawn one; there is no third command, no consent prompt and no question at any point, install and repair and refresh being one convergence over whatever is already on disk.

**The disclosure moved to the one surface a user reads before answering** (ADR-0160). Neither the Catalog nor a Select row carries what a Skill's own integrations install or retain, and teaching either to would be a Manager schema change; what Select already offers is the Skill's own `help.md` in full, readable before the list is answered. So that page states what Enabling installs, what is retained — the Seat, usage counts, timestamps and opaque identifiers, never prompts, responses, reasoning, file contents or paths — and that Disabling removes every entry and keeps what was measured. Only the Global layer is written, an owned entry being keyed by owner inside a Harness's own configuration, so a Global and a Project Enable of one Skill would write and remove one another's single entry; measurement is a property of the machine rather than of a working directory.

**What that costs is a Skill whose routing cannot be had without its measurement** (ADR-0160). A user who wants recommendations and not measurement can no longer have one without the other short of Disabling the Skill. What it buys back is the thing the second opt-in never delivered: a feature that actually runs, and one surface where what Enabling does is stated in full rather than split across a consent prompt nobody reached.

**Two of the three shipped adapters were doing the thing the Unsatisfied rule forbids** (ADR-0157). One wrote a hook table its Harness reads and reported success while that Harness held the newly written hook back from ever running until a human cleared it, so a written-but-inert integration was indistinguishable from one the Harness was acting on. The other ran its owned command with an event type and no payload at all, discarding the only place the session identity ever appears, while leaving the shell to hand the child process this session's own standard input by default — reproduced directly as a hang, which a hook reading standard input to end-of-file can block on for as long as that session's own input stays open. Verification read the file back and confirmed only that the Library had written what it meant, never that the Harness would act on it.

**An adapter is verified against what its own Harness actually reads, established from the Harness as installed** (ADR-0157). Event names, entry shape and file location are read off the Harness on the machine building the adapter rather than assumed from a sibling's — and confirming rather than assuming is what corrected a first pass's own suspicion here: the shape once believed to be the Harness's own belonged to a different surface, its app-server protocol, and is silently dropped rather than read when written into the config file. A schema generator alone conflates the two easily, and re-deriving live against the Harness's own running view is what catches it. Where a fact cannot be established that way, the honest answer is Unsatisfied: a guessed shape that happens to parse is not a verified one.

**A Harness that gates a new integration behind a user's trust is reported gated, never healthy** (ADR-0157). That Harness names the state directly in its own vocabulary and says as much in its startup copy. This collection forges no trust decision and writes no trust record on the user's behalf, so an integration that is fully and correctly written is reported present on disk, not yet active, and naming what the user does next. `healthy` stays reserved for a Harness this collection can observe is actually acting on what it installed, and the new state was added to the health field that exists today rather than to a presence section a later ticket had not yet landed.

**What the verification cannot reach is named rather than assumed** (ADR-0157). One Harness's own hook-invocation payload was not directly observable — every attempt to drive a hook to fire ran into that Harness's session and auth lifecycle before the hook itself — so the field its command receives the moment's name under is carried as the convention that Harness uses everywhere else its JSON API names a moment, not as a confirmed reading. Its OS-level activation, the moment a gated integration becomes healthy once a human clears the review, is likewise something this collection cannot drive and does not attempt to detect.

## Reading the session that has ended

**Capture was fingerprinting every session against a Seat somebody named once at opt-in** (ADR-0158). No lifecycle payload ever carried the model or the deliberation — a Harness's hook payload names a session identity, a transcript path and a working directory, and nothing that could answer what actually ran — so the answer went stale the moment a user changed either.

**A session's own last invocation is not the per-turn path** (ADR-0158, ADR-0090). The hook that ends a session happens once, after the work it describes is over, so reading a bounded amount of that work's own record there costs the ongoing session nothing, there being no ongoing session left to cost. The per-turn path is unchanged, no transcript read of any kind included; what the earlier paragraph did not yet distinguish is the one invocation with nothing left to protect.

**The read is bounded to that one session's own files** (ADR-0158). The transcript the caller's own payload named, and that transcript's own companion subagent directory, and nothing else: no location is computed that was not handed over, no other session's files are opened, and no identity found inside a line is trusted over the file the caller supplied. Nothing is scheduled, queued or deferred to a later pass, so the read is exactly as inline as the rest of the hook it sits in.

**It is field by field onto an allow-list, applied to a source that carries far more** (ADR-0158). A transcript line carries a whole assistant message, a whole set of tool arguments and a whole working directory; the reader takes the model, the deliberation control named beside it, the token categories and the instant, and nothing else — the boundary a lifecycle payload was already under, applied to a richer source. A subagent's turns are counted against a Seat of their own with an explicit null on every field the record cannot describe, because those describe the session's own surface and the main Seat's answer is not the delegated Seat's to lend.

**A record that cannot be read is an absence** (ADR-0158). A missing transcript, a truncated or garbled line, a subagent directory that does not exist, a file that will not parse — every one leaves the reader answering with nothing, and the hook writes what it would have written anyway. Nothing here raises and nothing loses a row over a record that was never there to read.

## Ordinary work is measured and never judged

**A queue existed to ask a question nothing could answer** (ADR-0156). A finished ordinary session had one way to become evidence: wait in bounded pending review until a human answered save, failed, or ignore. The premise was that a Harness's own lifecycle payload could eventually carry a checker or a declared failure signal the way a routed attempt's completion does, and it never has — the events carry a session identity, a transcript path, a working directory and the event's own name. So every captured session took the one branch nobody built a way out of: addressed by an opaque identity nobody could connect to a session they remembered, returned as JSON from a hook the Harness never displays, and evicted by age, count or size exactly as often as it was ever answered, which was never.

**The question the queue existed to ask is settled by not asking it** (ADR-0156). Quality comes from routed work, which something outside it already judged at a verdict; what ordinary work is worth is what it cost and how long it took on a given Seat, and that needs no verdict, no queue and no question. So a finished ordinary session produces a Usage Record carrying the opaque session identity, the Harness and its inventory revision, the exact Seat, the usage categories the environment exposed, and both instants with the elapsed seconds between them — and no outcome, no checker, no Cohort and no configuration fingerprint, a routed attempt's fingerprint existing because something judged the point it names.

**It goes to a second store rather than to a second kind of ledger row** (ADR-0156). The ledger correctly refuses a row with no verdict, so a Usage Record was never expressible in it, and giving quality's own file a row nothing judged would be the thing every future reader of that file has to learn to skip. Idempotency is by session identity and Seat, the same discipline the ledger already keeps for a run key.

**A session that ran on more than one Seat produces one Usage Record per Seat** (ADR-0156). The dimension the whole feature exists to measure is model and deliberation, and a user who switches either mid-session ran two configurations rather than one; each row is timed on that Seat's own first and last turn rather than on the whole session.

**A Usage Record is never quality** (ADR-0156, ADR-0145). It enters no derived frontier, contributes to no success rate, clears no quality floor and produces no evidence record — the same rule a Cohort-less ledger row is already under, because both are one rule: work never grades itself, and a row nothing judged is not a verdict wearing quieter clothes. Nothing waits for a human, so a session that ends abruptly contributes whatever its own record establishes and nothing more.

**What the second store costs is a file that answers no question about quality** (ADR-0156). A reader who wants that goes to the evidence ledger and finds nothing about ordinary work there, which is the point rather than a gap. The review verb and the pending fields a user may have grown to check are gone, and a session a Harness ended abruptly with no further signal leaves an orphaned draft with no daemon left to sweep it.

## Reading the measurement back

**The store nothing consulted** (ADR-0161). Recommendations, charts and comparisons answered entirely from derived frontiers, which are quality: judged runs grouped into points with intervals and cost means attached. A Usage Record has no verdict and belongs to no Cohort, so it reaches none of that by design, and would sit in a store nobody read. What closes the gap is a section that says, beside what is known about quality, what each point named has actually cost and taken on this machine — without becoming a second, quieter selector.

**The reader is a Skill-owned module called only after a decision exists** (ADR-0161). It ships beside the routing engine rather than in the Library, nothing outside that Skill's own rendering consuming it, and it is called only after the selection core has returned a decision, never from inside making one. *A Usage Record never chooses* is therefore a property of where the module is called from rather than a rule every caller has to remember to uphold.

**The banner is untouched and usage carries its own provenance** (ADR-0161). The evidence classes, confidence words and missing-evidence reasons are pinned verbatim across four places and classify the recommendation's own quality evidence; folding a clause about usage into that pinned text would be a four-place synchronized edit for a sentence answering a question the banner does not ask. So usage is a separate section stating the record count and the earliest and latest instant behind each figure.

**The join was written on a pair, and the pair was already false when both halves shipped** (ADR-0162, ADR-0161, ADR-0160). It was meant to be the model and the portable deliberation, judged the coarsest identity every named point and every Usage Record's own Seat could supply. What removed the second half is the same change that made Enabling the whole gesture: the argument a user answered once at opt-in went with it, and what replaced it reads a finished session's exact model and the Harness's own native effort control out of the transcript, where there is no portable form to read. Every Seat capture writes therefore resolves the portable deliberation to nothing, on every machine. The two decisions were built in the same wave, each verified alone, and the contradiction existed only on the branch carrying both: the reader shipped matching nothing at all, and the section, the columns and the Interface were inert.

**The join is the model alone** (ADR-0162). It is the one field a frontier neighbour, a selected launch and a real Usage Record's own Seat all carry. Deriving a portable level from the native control the record does carry is the calibration claim already refused once, and nothing about this reader makes it verifiable; restoring an answer at installation is refused by the gesture that removed it.

**What the coarser join costs is named in the answer rather than left to be inferred** (ADR-0162). Two named points differing only in deliberation share one model, so they draw the same records and report the same figures, and a table can carry one figure twice against two rows that are not the same Seat. Each summary answers that by naming every portable deliberation the matched records actually carry and how many carry each, so a reader can see when one figure stands for a mixture. A figure is now per model rather than per Seat, which is less precision than was intended, and a routing decision that turns on deliberation cannot read one of these numbers as settling it. Against that: the figures exist, where before the section could not have returned a single row.

**A mean is reported only where every contributing record carries it, and a category is read from the data** (ADR-0161). A category one record never measured stays unmeasured for the point rather than silently averaging over fewer records than the count states. The token category set is the union of what the matched records actually name rather than a list copied from the Library reader that derives it, because that tuple is Harness-specific and a second copy here is a duplicated field list about a sibling that can still change; a category the Harness starts naming tomorrow surfaces the moment a record carries it.

**A green suite over an inert feature is the lesson underneath it** (ADR-0162). Every earlier test handed the reader a Usage Record it had shaped itself, in a form capture no longer produced, which is why a full suite stayed green over a feature that could not work. A test that drives capture's own hook and reads the result back through the reader is what closes that.

## What an unattended pass may learn

**Discovery was complete, correctly designed, and had never run** (ADR-0167). The verbs revalidate provider indexes on a cadence, fetch detail pages for newly discovered version keys, and report a newer family version while leaving it excluded until the user adopts it — and every turn of that loop was manual, so a cadence described when a source *became* due and nothing acted on it. Measured on the maintainer's own machine: capture had been writing evidence continuously for the twelve days since the profile was last written, while the model release index had found a new Main-Seat model nobody was told about and the benchmark index that could have scored it sat unfetched. The failure is not an empty answer; it is a confident answer computed over a list nobody had revisited.

**The seam already exists, and the pass rides it** (ADR-0167, ADR-0090, ADR-0160, ADR-0158). The Skill installs an owned lifecycle integration the moment it is Enabled and that integration is already invoked once at a session's end, so there is no daemon, no cron, no second opt-in and no second registered entry. The moment is the one already distinguished as safe: the session's own last invocation, reached once, after the work it describes is over.

**What runs interprets nothing** (ADR-0167). A typed update is prose executed by an agent — semantic judgement over pages rather than parsing — so nothing shipped could ever perform it unattended, and pretending otherwise would have been a feature that goes green and is inert. The pass does one thing instead: validator-conditional retrieval of the non-commercial sources that are due, with no page parsed for meaning, no model started, and no capability fact, benchmark fact, evidence record, derived frontier or adopted model written. The unattended pass establishes *that* something moved; a person's next typed update establishes *what*, and that split is what makes an unattended fetch safe to ship at all.

**Maintenance stops at the money, and the stop is by kind** (ADR-0167). An unattended fetch that mis-parsed a commercial page would write a wrong fact that silently reshapes which model wins, and the user holds knowledge those pages do not state — what a plan actually costs and how a quota actually behaves. So the capability-shaped kinds may be retrieved and every commercial kind, *and any other value including one absent or unreadable*, is treated as commercial: not retrieved, its row not written, reported as due until the user runs the typed verb. Failing closed is what makes a kind added later safe on the day it appears, before anybody has taught this pass about it.

**Delaying no session teardown is a number, because an absolute is unbuildable** (ADR-0167, ADR-0090). Doing this without delay would need the detached or threaded work the hook path forbids, so instead: one connection at a time, no retries, and a total budget of two seconds across the whole pass, enforced in-process against a monotonic clock. Exceeding the budget, failing, or finding no network surfaces nothing, changes no fact the store holds, and leaves every unfinished source due for the next attempt — measured at 2.02 seconds against five hanging endpoints, four of the five left untouched and due.

**Dueness needed a second timestamp, and that is where the fix could have reinstalled the defect** (ADR-0167). Cadence is measured from the last retrieval and from nothing else; a second field records only that a pass considered the source and moves no due date. Stamping the *look* at every session end would push every source's next due date forward at every session end, and nothing would ever become due again — the original defect, rebuilt by its own fix. A source never retrieved is due, which is the state every row written before the change is in, and the field starting empty is the decision rather than an omission.

**A machine that has never run the typed verb does nothing, visibly** (ADR-0167). Dueness iterates rows and rows exist only after a typed update, so on a fresh machine the pass has nothing to iterate and correctly writes nothing; deriving which sources a configuration needs is semantic work this pass is forbidden. Status says so, because a permanently empty pass must otherwise be indistinguishable from a working one — and this whole decision exists because a silent nothing read as a working something.

**What it costs is the network reached from a hook** (ADR-0167). That is a genuine widening of what enabling a Skill does, disclosed where the rest of that disclosure lives. A provider sees a request from a machine at each session end, carrying a plain user agent and no credential or identity of any kind. A first pass over a source with no recorded validator records it as changed, because the store's knowledge of that content moved from nothing to something and under-reporting a change is the failure the decision exists to end; the cost is one page a person reads and finds unremarkable. And the division of labour becomes real rather than aspirational: what the machine can establish without judgement it establishes, and what needs judgement waits for the person, who is told it is waiting.
