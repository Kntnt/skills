# Building may be delegated down; the verdict never is

Three overnight `/orchestrate` runs ran every subagent on the orchestrator's own model, because `--model` was never passed and inheritance is what the absence of a choice does. The sessions were interviewed afterwards and agreed on the finding, independently and in nearly the same words: capability was never the limit. Verifiers on that arrangement were the strongest part of every run — one rebuilt a rename with its own parser rather than trust the ticket's test, one mutation-tested a builder's new suite and found assertions that exercised nothing, one reproduced a survey from scratch to check a number — and builders over-delivered rather than under. What limited the runs was authority and structure: rules that said stop, namespaces nobody owned, turns that died under long commands. Meanwhile the collection already has a considered position on who should execute: delegation mode's rule is that subagents execute on the cheapest model the orchestrator judges able, never above its own, because the saving is real and the judgment of *able* is exactly what the orchestrator is for.

**So the orchestrator is the run's most capable seat, and it delegates building down but never the verdict.** The developer runs `/orchestrate` from the strongest model they have — the model the session runs on is the developer's move, not the Skill's, so this is stated where the Skill documents itself rather than enforced — and the orchestrator's own intelligence is what the run's judgment calls draw on: reading tickets for open decisions, triaging a stopped subagent, naming the run-owned files, deciding what a hinder is. That is where ADR-0070's mechanisms live, and they are only as good as the model asked to apply them.

**Building goes to the cheapest model the orchestrator judges able for that ticket, never above its own.** The judgment is per ticket, made from the ticket's own text — a mechanical rename is not a redesign — and it is delegation mode's rule applied inside a run rather than a new one. `--model` keeps exactly its meaning: where the developer names a model, every builder runs on it and no judgment is made; the flag was always the override, and what changes is only the default underneath it, from silent inheritance to a judged choice. Repairing a collision and amending a failed build are building too, and delegate the same way — with the note that a ticket back for its amend has just demonstrated it was harder than it looked, which is the orchestrator's judgment call to weigh. This model-only selection rule is superseded by ADR-0085, which routes the complete model-and-deliberation execution configuration through model-selector.

**Every verdict runs on the orchestrator's own model: ticket verification, repair verification, and the wave check.** The verdict is the only thing standing between an unattended night and a report the developer cannot trust — the Skill's own documentation already says a run that can report success it cannot support is worse than no run at all — and the field evidence is that strong verifiers earned their cost several times over in defects caught. The saving is taken where a mistake is caught downstream; it is never taken at the last thing that would catch one. This model-only inheritance language is superseded by ADR-0085, which requires exact inheritance of the complete main-seat configuration.

**What this costs.** A builder judged too cheap costs a failed verification and an amend cycle — bounded, visible in the report, and self-correcting, since the amend is the orchestrator's cue to re-judge. The orchestrator makes one more judgment per ticket, from text it was already reading. And the arrangement prices verification above building on the same ticket, which reads upside down until it is read as the run's actual product: the work is the branch, but what the developer buys from an unattended night is the report being true.
