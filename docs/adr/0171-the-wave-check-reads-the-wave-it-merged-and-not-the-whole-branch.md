# The wave check reads the wave it merged, and not the whole branch

Every wave's check read the integrated branch whole, from the run's base to its head, so the reading grew with the run: a three-wave run read its first wave three times and its second twice, on the main seat every verdict inherits (ADR-0085), which makes it the run's dearest reading. The evidence ledger says the check earns its place — six of the eight waves it records ended in mechanical findings, none of which a green gate saw — so what is out of proportion is not the reading but its range. What the check exists to find arrives by construction between a wave's tickets and the branch they forked from: a ticket forked before a sibling's record landed cannot see that record, and the contradiction exists only where the two are merged. The branch before the wave held no such pair the check that ended the previous wave had not already read whole and passed, or declined on stated grounds that bind the next round (ADR-0098).

**A wave's check reads what that wave merged, whole, and goes to the rest of the branch only where those commits point.** The brief carries `<since>`, the commit the run branch stood at when this invocation's last wave check passed clean; every commit from there to the head is the wave's — its merges, its applied notes, and any fix an earlier round of the same check demanded — and each file those commits touch is read with its surrounding text rather than as a hunk. What stands before `<since>` is not read again for its own sake. The check goes there where the wave's commits lead: the registry a new record joined, the release section a new entry was added to, whatever cites a file whose lines the wave moved, and the prose anywhere in the tree asserting what the wave has made false, found by searching for what the wave changed and then reading what the search turned up. The four kinds of defect the check looks for are unchanged, and so is the gate, which still runs whole on the branch as it stands.

**Every round of one wave's check carries the same `<since>`.** A rerun after a fix reads the whole wave again rather than the fix alone, because this class of defect never comes alone and the round that fixed one instance is the round that found the next (ADR-0072). The narrowing is between waves, never between rounds.

**Where an invocation holds no clean pass of its own, `<since>` is the plan's `base`, and the check reads the run's whole work exactly as before.** That is the first wave, and it is the first wave of a resumed invocation: the head at the last clean pass is held by the invocation that saw it, not by the engine, and a run continued from another invocation reads whole rather than trusting a boundary nobody recorded. The head is noted at every clean pass for the next wave's check, which is one more thing the orchestrating session holds for the run and nothing a script computes.

This record **narrows ADR-0072**, whose reading of the integrated branch it keeps and whose range it bounds to the wave. What that record decided stands whole: the check reads coherence beside its gate, what it finds mechanical is fixed by a separate session and read again, and the loop runs to a fixed point.

**What this costs.** A contradiction between a wave's change and prose an earlier wave left standing is found only by following the change outward — a checker that reads the wave and does not search for what it changed misses what a whole-branch reading would have stumbled on, so the brief says to search and then to read. A resumed invocation pays the whole-branch reading once more, on its first wave, for want of a recorded boundary. And the orchestrating session holds one commit per wave that a lost context loses, the loss costing a wider reading and nothing else.
