# The valued-flag registry derives from the collection's own declarations

The check that holds every valued flag to the attached spelling carried a hand-written list of the flags it applies to, and the record settling that spelling accepted the maintenance knowingly, as the price of a scan that does not have to parse Python. The price came due within one run. The first two Skills added after that record introduced six valued flags between them; none of them entered the list; nothing failed, because every use in those Skills happened to be attached already. The registry had silently stopped answering for the newest part of the collection, and it would have gone on not answering until somebody wrote one of those six with a space and nobody noticed. The gap was closed by hand in the commit this record is written against (issue #121), which fixes the instance and leaves the class.

**The valued set is derived, at test time, from declarations the collection already holds to completeness: every flag a shipped manpage's `## OPTIONS` section declares with a value, unioned with the flags the collection's own engines declare as taking one.** The hand list goes. A valued flag a new Skill or a new engine introduces is enforced with no edit to the suite, and a flag whose declaration is removed leaves the derived set on the same run. This record **narrows ADR-0096** in the one half where it accepts a table maintained by hand; everything that record settles — the attached spelling itself, the third-party boundary, the permissive engines, and the surfaces the scan reads — stands untouched.

**The two sources are complete between them, which is why the union is the whole set rather than a better guess.** The suite already holds a Skill's `argument-hint`, its manpage's `## SYNOPSIS`, and that page's `## OPTIONS` to one identical set of flags, so the option terms name every flag any Skill surface offers a user; a flag documented nowhere is a flag no user can write. What the pages cannot name is the flag only a Skill body writes, in an invocation of one of the collection's engines, and those the engines declare themselves. Neither source is trusted to be complete on its own, and neither has to be.

**A declaration is read in every spelling a declaration can be written in, the non-compliant one included.** An option term reaches the derivation whether it closes the bold run after the `=`, puts the `=` outside it, brackets an optional value, enumerates the values it accepts, or separates the metavariable with a space — that last being the spelling the rule forbids. Reading only the compliant spelling would put the flag written space-separated on every surface it appears on outside the derived set, and that flag is exactly the violation the rule exists to catch: the derivation would be blindest in the one case it is for.

**The engines are read as syntax trees rather than run.** A parser here is built inside the function that immediately parses with it, so there is nothing to introspect without driving the engine's command line, and executing eight engines to ask them what flags they take would buy an answer already written plainly in their source. What the reading asks of each declaration is the one question the rule turns on — does this flag consume a value — which is the default for `argparse` and stated explicitly by the actions that do not. The one seam that reads its options by hand is read on its own terms, because a seam nothing looks at is how this record's own defect began.

**The matcher stays self-checking, and its sample now proves the derivation too.** The sample is read against declarations of its own — a manpage and an engine written into the test — rather than against the shipped tree's, so what it proves is the whole path from a declaration to a caught flag rather than the patterns alone. One flag in it is declared nowhere the collection ships, which no hand-written registry could have carried and only a derived one reaches. An empty result still means compliance rather than a matcher that quietly died.

**The road not taken was keeping the hand list behind a staleness check** — a test that forces a flag into the list the moment an attached spelling for it is observed anywhere. It is cheap, it needs no Python parsed, and it would have caught five of the six flags this record was written for. It was rejected for the sixth case it cannot see: a flag written space-separated on every surface and attached on none never triggers the check, stays out of the list, and passes. That is precisely the violation the rule exists to catch, so the alternative's blind spot and the rule's purpose are the same spot.

**What this costs.** The suite now parses the engines' Python, which is the cost ADR-0096 declined to pay and this record accepts: an engine whose source cannot be parsed fails the derivation rather than the file it is in, and a future engine that declares its options through some seam neither `argparse` nor the hand-rolled one is a set quietly short of a flag. That failure mode is real, and it is the one traded for — a derivation goes stale only when the collection grows a new way of declaring an option, where a list went stale every time anybody added one. The derived set is also only as good as the declarations it reads, so a manpage that documents a valued flag as though it took none puts that flag outside the rule; the suite's existing agreement checks hold the three Skill surfaces to each other, not to the engine behind them. And one hand-written table remains beside the derivation, naming the flags whose value is optional and the vocabulary each accepts: it decides nothing about what is valued — a flag absent from it is valued whenever it is declared so — and exists only to tell an operand behind a bare flag from a value, which no declaration states.
