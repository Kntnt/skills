# The wave check reads coherence, and its fixes loop to a fixed point

One overnight run's branch was read six times at branch level, and five of those readings found it defective while the project's own gate ran green through every one. The defects were of a kind no test suite sees: a decision record asserting a default the branch had just changed — found, fixed in the paragraph the finder named, and then found again in the same record's opening framing, arguably more misleading half-fixed than untouched; a changelog whose one release section held two `### Changed` headings; a register of open findings still listing two the branch had closed; dozens of file-and-line citations invalidated by the branch's own edits, three of them inside the release procedure's pre-tag checklist — the branch had broken the pointer to the very check its release would turn on. Two of the five were structural rather than careless: a ticket forked before a sibling's record landed cannot see that record at all — `git ls-tree` on its branch tip lists the registry with the sibling's number simply absent — so no diligence inside the ticket could have caught the contradiction, and only the integrated branch can. The wave check is the run's one look at that branch, and today it is forbidden to act: it runs the gate and changes nothing, on the reasoning that a repair made by the checker is a repair nobody verified.

**So the wave check reads the integrated branch for coherence as well as running its gate — and what it finds mechanical is fixed on the branch and checked again, around a loop that ends only at a clean pass.** Coherence means the branch agreeing with itself: registries where one number answers twice, release-notes structure, citations the branch's own edits invalidated, prose asserting what the branch's own changes have made false. Mechanical means the fix restates what the branch has already decided — renumber the later record, fold the duplicate heading, repoint the citation, bring the sentence up to what the code now does. A finding that requires choosing between two tickets' intents is not mechanical, and it stops the run exactly as a failed gate does: that is a disagreement merged onto the branch, and spending the rest of the night building on it is the outcome the wave check exists to prevent. That comparison is superseded by ADR-0098: a failed gate is no longer a stop in itself, a gate failure whose exact correction the checker can write down being mechanical like any other finding, and only one it cannot being the stop. The range of the reading is narrowed by ADR-0171: a wave's check reads what that wave merged and goes to the rest of the branch only where those commits point, the branch before the wave having been read and passed by the check that ended the wave before it.

**The fix is made by a separate subagent, and the reader that finds is never the writer that fixes.** The checker reports; a fixer with the findings makes the mechanical corrections and commits them; the wave check then runs again — gate and coherence both — on the branch as it now stands. What licenses a commit ahead of a verdict here, when nothing else in the run gets one, is the loop's own shape: the check that found the defect is the check that reads the result, so no fix escapes unread, and the branch the run continues from is always one a full wave check has just passed whole. The old rule's reasoning — a repair made here is a repair nobody verified — is answered rather than dropped: the fixer's work is verified, by the next turn of the very check that demanded it.

**The loop runs to a fixed point, because this class of defect never comes alone.** Every round in the field that fixed one instance found another the first reading had not reached — the framing paragraph behind the annotated one, the second stale citation behind the first. A single fix-and-recheck round would ship whatever the first reading missed with a green stamp on it. The loop ends when a round finds nothing, and it stops the run instead when a round changes nothing — findings repeating with no fix the fixer can make is the non-mechanical case wearing the mechanical one's clothes.

**A reading is a reading, not a grep.** The one correction convention in the field preserves the false sentence verbatim and appends the correction after it, so a pattern search cannot tell a corrected assertion from an uncorrected one; the checker reads the surrounding text or it reports noise. The brief carries this warning because the cheap implementation fails silently in exactly the direction — confident wrongness on the branch — the check exists to catch.

**What this costs.** A wave now ends with at least one more subagent reading the whole branch, and with as many fix-and-recheck rounds as the branch needs, all paid in overnight machine time. The fixer's mandate is a boundary that must hold in prose — *restate what the branch decided, choose nothing* — and a fixer that drifts past it is caught only by the next check round. And a run can now end its wave a commit or two later than the last ticket's merge, which the report absorbs: the branch it names is simply the branch as the wave check passed it.
