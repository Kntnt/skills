# Routed work reports the evidence it never imports

ADR-0083 gave model-selector one public routing Interface and ADR-0085 made Orchestrate route every execution role from a frozen snapshot. Both leave the same thing unsaid: what happened next. A run selected an exact point, a verifier judged the work it produced, and the only record of the pair was prose in a report nobody could import. Selection that cannot learn from its own results stays at the evidence class it started in, however many nights it is run.

**A routed attempt becomes evidence only where something outside it judged the attempt.** The decision the attempt launched from is immutable and already carries the exact point, the native control, the fingerprint, the evidence class, and the provenance, so an observation adds one thing: the outcome, and whatever the environment actually exposed about what the attempt cost. A decisive pass or fail needs an independent verifier, an objective checker, a frozen rubric, a declared failure signal, or the user saying so. A builder's report and a subagent's confidence establish nothing, and an unchecked subjective success is left out rather than recorded as a weaker kind of measurement — the whole value of the ledger is that a number in it was checked by something that could have said no.

**A route decision by itself is audit data.** Nothing is serialized for an attempt that was interrupted, that launched nothing because its decision refused, or that no verdict reached. An account of what a run decided is worth keeping and is kept, in the run's own routing account; it is not an observation, and the difference is what stops an unfinished night from reading later as a successful one.

**The workflow's own failures are not the model's.** A mechanical hinder, an open product decision, a newly discovered dependency, a tracker failure, and a merge collision each end an attempt without saying anything about the configuration that met them. They are retained as infrastructure errors and abstentions, they carry the condition that caused them, and they are excluded from the conservative success rate a frontier is built from. Counting them as failures would make the cheapest point look worst exactly where the environment was worst, which is the one inference the evidence must not support.

**The artifact is statistical metadata, and it is built by allow-list.** Every field is copied by name — identities, fingerprints, outcome, authority, checker, usage, cost, quota, latency, provenance, sanitized artifact hashes — so material sitting beside the facts in the caller's own object has no path into the file. Prompts, responses, reasoning, ticket and source bodies, diffs, terminal output, secrets, transcripts, and absolute paths are absent because they are never copied, not because they are stripped afterwards, and a value that reads as material rather than as an identity refuses its attempt instead of being trimmed into one. A measurement the environment did not expose stays `null`: an absence read as zero would make an unmeasured configuration the cheapest one on the frontier.

**Emission is the caller's, import is the user's.** The artifact is written into caller-owned scratch, its path is named in the report the caller was already giving, and nothing else happens. No ledger, no derived frontier, no profile, no repository file, no tracker state, and no lifecycle hook is touched by a night's work; `/model-selector record` is the only thing that imports one, and a person runs it. Identical observations are idempotent at both seams, and an identity offered twice with different content is surfaced as a conflict that overwrites neither side, because two disagreeing accounts of one attempt are a question for a human rather than a race for the last write.

The user-only import rule is superseded by ADR-0137 for machine-judged Orchestrate attempts; delegation and the public `record` command retain it.

**One contract rather than two.** Model-selector owns emission as well as import: the same module builds the observation, validates it with exactly the validation an explicit import applies, and appends it. Orchestrate and delegation reach it only through the public Interface — Orchestrate records each attempt's established outcome in its own account and hands the collected attempts over, delegation does the same from its standing instruction — and neither reimplements sanitization, validation, or key derivation. Issue #91's opt-in automatic capture reuses this contract instead of creating a second normalized representation of routed work.

**What this costs.** A caller must reach an explicit completion boundary for every attempt it wants recorded, and an attempt whose outcome nobody establishes is simply lost to the evidence. Runs on a Harness that exposes no usage, cost, or quota facts produce observations that are mostly `null` and support little more than a success rate. In return, the evidence a routing decision could later be made from is produced by the work itself, in the shape the ledger already accepts, without any part of ordinary delegated work acquiring an undisclosed persistent side effect.
