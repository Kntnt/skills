# A named destination takes the artifact out of the response

Seven runs of `/unslop` named a file or a directory as the Output Target on one day. Six of them reported where the artifact went and left the response otherwise to the findings; the seventh named its destination and then printed all four paragraphs of the artifact into the response as well. That seventh run is one of the two whose pass found nothing, so the text it echoed was byte-identical to the source the caller was already holding, and the other such run wrote its file and printed nothing. Neither run disobeyed anything. The shared delivery contract settles where the artifact goes and what a response-targeted run does, and says nothing about what a file-targeted run may put in the response beyond the findings, so both behaviours were permitted and the answer was decided per run (issues #148, #111).

**A run that delivers to an explicit destination does not repeat the Text Artifact in the response.** The reasoning is already written down one section above, for the run that found nothing to change: repeating a text into the response spends output on what the caller is already holding, and that is doubly true when the file just written holds it too. A caller who names a destination has said where the text goes, so the response is left for what the file cannot carry — the findings, which of them are unresolved, and where the run put the file, the derived filename included, that last being the one part of the outcome the caller cannot read off their own invocation. The evaluation corpus had taken this view before anything was written: its `new-file` entry rejects a run that *creates the file and also prints the whole artifact as though no destination had been given*.

**It holds whether or not the pass changed anything.** A run that writes a file byte-identical to its source reports the destination and says the text needed no work, and does not become the one run that echoes. The alternative inverts the rule exactly where it costs most to invert: the run with the least to report would be the only one to spend a full artifact on saying it, and the caller who has just been told nothing changed would be handed the text they supplied. This is also what was actually observed — the echo happened on one of the two runs that found nothing, and not on the other.

**It is stated once, in the shared contract.** Several Skills deliver a Text Artifact through that document, and the question belongs to the delivery it owns rather than to whichever Skill's evaluation caught the split (ADR-0076, ADR-0091). A Skill added later inherits the answer by delivering through the contract, without an edit and without knowing the rule exists — which is the same argument the findings-language rule was settled by, on the same document, a day earlier (ADR-0123). Nothing in ADR-0091 is falsified: the response-targeted default still delivers the complete artifact in the response, an explicitly selected file or directory still receives the complete artifact when nothing changed, and the derivation and collision rules stand entire. What is added is what the response holds once the text has gone somewhere else.

**What this does not reach.** Not the destination rules themselves — path handling, overwrite semantics, filename derivation, and collision numbering are untouched. Not which findings a run reports or how, which is each Skill's own contract. And not the response of an In-place run that changed something: what is settled here is the response of a run the caller sent to a destination beside the source, which is the gesture the split was observed on.

## Considered options

**Printing the artifact beside the file** is what the seventh run did, and it has a real argument: the caller reads the result in front of them without opening anything, and a run whose output is a few paragraphs costs little to repeat. It loses on what naming a path means. The caller chose where to read the text, and a response that repeats it says the choice bought a file and changed nothing else. The cost also grows with the artifact rather than with the finding list, so the longer the text the worse the trade, and the response that matters least — a wall of text the caller has — crowds out the response that matters most.

**Printing it only when nothing changed** is the shape the observed runs almost formed, and it can be argued as a courtesy: a caller told the file was written unchanged sees what was written. It is the inversion above. The unchanged run is the one whose text the caller most certainly already has, having supplied it, and the run with a single line to report would be the only one to spend a whole artifact reporting it.

**Leaving it to the run** is the option that was in force. It produced two answers to one question in one day's evaluation of one Skill, which is what a contract's silence produces: not an open question, but a question answered per run by whatever the surrounding context made salient.

## Consequences

Every Skill that delivers through the contract inherits the answer, Unslop and Redline today and any successor without an edit, and a caller learns one behaviour rather than one per Skill: name a destination and the response is the report, keep the default and the response is the text.

The cost falls on the operator who wanted both, and the contract offers them no override. They open the file, or they run without a destination and get the text. That is the same trade the no-change rule made when it declined to reprint an unchanged text, and it is made here for the same reason.

The second cost is the one ADR-0091 already named for this document. There is no executable check that a run obeys the rule, only that the contract states it and that no consumer carries a private copy of it. Whether a run actually keeps the artifact out of the response is visible through the evaluation corpus, whose `new-file` entry rejects the echo — which is where the split was found, and where the fix is confirmed or is not.
