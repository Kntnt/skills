# A brief travels as its subagent's instruction and never as a file

ADR-0107 settled what reaches a correction subagent: the complete current Text Artifact, the complete findings of the most recent review, the parameters the run resolved, and the requirement to leave everything else alone — each of them whole, because a summary is the dispatching session's reading and that reading is what a fresh subagent exists to be without. It did not settle how any of that gets there, and the briefs said only that writing the filled-in brief to a file and pointing the subagent at it was fine wherever it cost less than repeating it.

Every run took the invitation differently. Across a handful of runs of one Skill in one Harness, some passed a path under a freshly made temporary directory, one put the process id in the name, and four independently chose the same fixed path. Two of the four overlapped in time: one run wrote its brief, dispatched its subagent, and had the file deleted underneath it, and the subagent read a longer brief left behind by the other run, holding differently worded findings against an unrelated text. That run recovered because its subagent noticed the text was not the one it had been sent to repair, which is a property of that subagent and not of the Skill.

**The brief is handed to the subagent directly, as the whole of its instruction, and travels no other way.** The brief is text and a subagent's instruction is text, so the file was never buying anything the direct handover does not already give. Handing it over removes the exposure rather than managing it: there is no path to make unique, no directory to create per round, and no window in which a second process can read, replace, or delete what the round is answerable to. Length is not a reason to depart from it — a long text makes a long brief, and passing it whole is the thing ADR-0107 already requires of every element the brief carries.

**It is stated once, in the brief itself, and the delegating step reaches it for both halves.** The step says the correction is delegated from the brief filled in *and delivered* as that brief says, so there is one document to read and one rule in it. A second statement beside the first is how the improvisation started: two instructions where one was needed, and a run picking whichever it happened to weigh more.

**The rule belongs to the Collection rather than to the Skill it was observed in.** Both editorial Skills that spend a Correction Budget dispatch from a brief carrying the user's text under the same words, and ADR-0112 already keeps their loop contracts in step by reuse rather than restatement. A handover that held in one and not the other would be the per-run choice again with a Skill's name on it.

The cost is that the brief is repeated in full into every round's instruction, where a path would have been a line, and a Harness that bounds how much instruction a subagent may be given bounds how long a text this loop can correct. That bound is worth meeting honestly: a run that cannot pass the whole text is a run that cannot make the correction ADR-0107 describes, and discovering it at dispatch is better than discovering it in a repair made against half a text. What is bought is that two runs of the same Skill on the same input do the same thing, and that the user's text is never at a name anything else on the machine can guess.
