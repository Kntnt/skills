# TL;DR selects for the owner of the outcome before it compresses words

The first `/brief` contract treated a bare invocation as a request to compress the preceding answer into three fixed sections, while the standing mode used a smaller set of prohibitions and added structure only above a gate. That makes length the diagnosed problem and rendering the remedy. A reply can instead be short but aimed at implementation mechanics, dense with detail irrelevant to the reader, or full of local choices the agent could have settled. Shortening the same structure then preserves the failure that prompted the invocation.

**A bare `/brief` is feedback about usefulness, not a request for a smaller copy.** It says the preceding answer missed the useful level, focus, or density, so the Skill answers its substance again from the user's perspective. The preceding answer need not be long. An unavailable range is still named honestly, but an available short range is reframed rather than refused.

**The user is a technically capable owner of the outcome.** They may be the software's user, the commissioner of the work, its product owner, or its high-level solution architect; what those roles share is responsibility for the result without an obligation to hold current implementation state. The instruction therefore reduces required context rather than assumed competence. It leads with the conclusion, keeps practical implications and material trade-offs, and admits technical detail when that detail affects behaviour, scope, risk, cost, future options, or an explicit request.

**Selection precedes wording.** Decision-relevant meaning is kept; internal mechanics, work logs, discarded approaches, exhaustive alternatives, and implementation questions the agent can reasonably settle within scope stay out by default. The selected content is then expressed densely: preambles, restatements, filler, ritual pleasantries, weak transitions, redundant examples, process narration, and closing recaps add nothing. Facts, negations, quantities, exceptions, conditions, limitations, and real uncertainty that could change understanding or action survive, and correctness wins over brevity.

**One policy governs both forms, while time still distinguishes them.** `mode.md` is the single source of truth for the perspective. A bare invocation applies it retroactively to the settled range; `--on` adopts it only for subsequent replies and never revisits the preceding answer. An explicit request for more detail overrides the default level for that reply. The mode remains confined to conversation replies: it does not rewrite code, documentation, comments, commit messages, other artifacts, or become a general-purpose text and file compressor.

**Form follows the selected content.** Headings, paragraphs, and lists are available when they clarify, but no structure, item count, or empty verdict is mandatory. A real action or decision required from the user is unmistakable; where none exists, the answer may end naturally. Concrete selection and stopping criteria give a verbose model something to check without making a well-calibrated model wrap a short answer in ceremony.

This supersedes ADR-0049's fixed template, structural gate, and deliberate asymmetry. It amends ADR-0048's description of `mode.md` as seven prohibitions while leaving that record's portable standing-instruction mechanism, scopes, grammar, and persistence decisions intact. **That claim about the grammar is amended by ADR-0103**, which addresses the mode through a command path and drops the free-text operand; the mechanism, scopes, and persistence are still left intact, and nothing this record decides about perspective or content selection moves with the grammar.

**What this costs.** The old template made its three categories mechanically scannable and rendered their emptiness explicitly. The new contract relies on judgement about which meaning affects the owner of the outcome and may produce different natural shapes across Harnesses. In return, `/brief` can repair the focus of a short answer, the standing mode and bare invocation no longer express different ideas, and the user receives fewer implementation details and fewer decisions that were never theirs to make.
