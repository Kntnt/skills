# On-demand files live under `references/`

The Agent Skills specification recommends three directories inside a skill — `scripts/`, `references/`, `assets/` — and calls them recommendations rather than requirements. So nothing here is a conformance fix — but the evidence this record first gave for that, that `agentskills validate` passed every skill of this collection while only `scripts/` was followed and everything else sat flat in the skill's root, was false when it was written: the reference validator rejects every skill here, and did then, on frontmatter fields no directory layout touches (ADR-0066). What the recommendations being recommendations establishes, it establishes without the validator, and the layout below was never held up by that sentence. What the flatness cost was legibility: a root that mixes the two says nothing about which of its files a user reads and which the agent opens when a situation arises, and you had to already know that `help.md` is the manpage and `gates.md` is not. `references/` is the convention that says it, and it says the same thing here as in any other collection, to a reader who has never seen this one (issue #54).

**Two of the three are adopted.** `scripts/` holds a skill's executables, as it already did in all three skills that ship one. `references/` holds what the body opens only when the situation arises — the class ADR-0046 named — so fourteen files moved there: `gates.md`, `placement.md`, and `writes.md` in `agents-md`; `mode.md` and `persist.md` in `delegation`; `mode.md`, `persist.md`, and `shape.md` in `tldr`; `changelog.md` in `commit`; and `brief.md`, `verify.md`, `repair.md`, `repaired.md`, and `wave.md` in `orchestrate`. `assets/` has nothing to hold, and an empty directory is not a statement. This binds the skills shipped today and every one added later, in the manner of ADR-0044: a new skill's on-demand agent files go in `references/`, and its manpage is `help.md` in the root.

**`help.md` stays in each skill's root.** It is not documentation the agent consults; it is the user's manpage, and ADR-0044 made its address derivable rather than registered — `select` fetches `skills/<category>/<name>/help.md` from the origin for a skill the user does not have yet, `category` being a field the Catalog already carries. Moving it would change a published path to buy nothing, since the one thing a manpage never needs is a directory explaining that it is one.

**The Manager keeps `steps/` and `help/`.** The specification describes `references/` as *documentation that agents can read when needed*, and `steps/<verb>.md` is not documentation: it is the procedure the agent carries out, which is exactly the line ADR-0046 draws between what a skill executes and what it consults. Folding `steps/` into `references/` would erase a distinction the collection is built on, and `help/<verb>.md` is the same rule from the other side — one manpage per verb, where ADR-0044 put it so that *where is the help* has a single answer. The Manager is a principled exception rather than an untidied corner.

**A brief a subagent is given is consulted, not executed.** The same line answers `orchestrate`, whose five briefs could have been read as a second `steps/`. They are not: it reads `brief.md` at one step of its own procedure, fills it in from the plan, and hands it to somebody else, exactly as `agents-md` reads `gates.md` at one step and applies it. `steps/<verb>.md` is not read at a step — it *is* the steps, the whole of what the agent does once a verb is named.

**`catalog.json` and `harness-paths.json` stay in the Manager's root.** An installed Manager fetches `skills/kntnt/catalog.json` from the origin, so the path is a published contract rather than internal layout. Moving it would break that fetch for every installation already out there — and `update`, the verb that would deliver the repair, is the one verb that cannot run without the Catalog it could no longer find.

**Two things spelled the same are kept apart.** ADR-0025 calls a *References* line the pointer `agents-md` writes into an `AGENTS.md`, one line per file with the class of work that should open it. A `references/` directory is a place inside a skill. Neither rule reaches the other, and the words are near enough that a record which let them blur would be read as saying that a skill's `references/` is written by `agents-md`, or that a References line points into one.

**What holds it is a test, not the convention.** A layout is only moved once every body that names a file agrees, so the suite follows both pointer shapes the collection uses — `$HERE/<path>` from the directory holding `SKILL.md`, and a Markdown link from the file it sits in — and fails on the first one that resolves to nothing. That is what makes the directory safe to adopt: the cost of the move is a rewrite of every pointer into the moved files, paid once, and a half-done rewrite is caught here rather than in somebody's session.
