# The reference validator is a baseline, not a gate

`skills-ref validate`, the reference implementation of the Agent Skills specification, rejects every skill this collection ships, and has for as long as anyone has looked: `argument-hint` on all of them, and `disable-model-invocation` on all but `agents-md`, against a closed allowlist of the six fields the specification tabulates — `allowed-tools`, `compatibility`, `description`, `license`, `metadata`, `name`. **Both fields stay, the rejection is accepted as a knowing deviation, and the validator is read as a baseline that must not regress rather than a gate that must pass** (issue #63). **The `agents-md` exception stated here, and in the baseline restated below, is outrun by a later change that carries no record of its own: every skill now writes `disable-model-invocation` explicitly, `false` included, so that the `agents/openai.yaml` sidecar Codex reads has something to agree with, which makes the baseline `argument-hint` and `disable-model-invocation` on all nine — everything else this record settles stands.**

**The specification states no rule these fields break.** It tabulates the six fields and then says nothing whatever about an unknown top-level one — no *MUST NOT*, no instruction that a client reject it, not even that it is ignored. The closed allowlist is the reference implementation's own strictness, stricter than the prose it implements, so what the two fields deviate from is a tool's inference and not the specification's text. That distinction is the whole of why the deviation is defensible rather than merely convenient: silence is not permission, but it is not prohibition either, and refusing the fields would mean choosing a validator's inference over a harness's documented behaviour.

**`metadata` is the specification's own escape hatch, and it cannot carry these two.** The field exists so that clients can store additional properties the specification does not define, and this collection already uses it correctly, in the flat `kntnt.`-prefixed namespace ADR-0061 settled. Claude Code, though, reads `argument-hint` and `disable-model-invocation` at the top level only. Relocating them under `metadata` does not preserve the behaviour behind a conformant spelling — it discards the behaviour silently, and leaves a validator-green skill that no longer does what it did. A hatch the reader cannot see through is not a hatch.

**What the fields buy is worth more than a green run.** `argument-hint` is what puts a skill's grammar in front of the user at the moment they type the slash command, and every skill here has a grammar it refuses on (ADR-0059) — a hint withdrawn does not simplify the skill, it hides what the skill will reject. `disable-model-invocation` is what keeps a skill from being invoked by the model on its own, which for eight of the nine skills here is the difference between a verb the user asks for and a verb a session may decide to run: `/release` or `/orchestrate` starting itself is not a trade any conformance argument pays for. Neither field has a spec-blessed equivalent, so the choice is the field or the behaviour, and it is the behaviour that these skills are for.

**A ticket cites the validator as a baseline, in these words.** The command is `uvx --from git+https://github.com/agentskills/agentskills#subdirectory=skills-ref skills-ref validate <skill-directory>`, it is not on PATH and not on PyPI under the name `agentskills`, and what it reports today is the rule above: every skill fails on `argument-hint`, and every skill but `agents-md` on `disable-model-invocation`. An acceptance criterion may require that this state is unchanged — no new field, no new complaint, no skill failing on anything else. An acceptance criterion must not require that the validator passes, and one phrased that way is unsatisfiable while this record stands. The two are easy to confuse, and were: the criteria of issues #52, #53, and #54 asked for *no new complaint* and were verified honestly, but a reader of those closed tickets would conclude the collection validates, because nothing said which baseline the complaint count was counted against. This record is what says it.

**The deviation is bounded by a test rather than by intent.** A skill added later may carry the same two fields on the same reasoning — that is what makes this a stance and not an exception for nine files. It may not quietly carry a third: the suite holds every shipped `SKILL.md`'s top-level fields to the specification's six plus these two, and a field outside that set fails the run until this record is amended to accept it. So the collection's distance from the reference implementation is a number this repository knows, rather than one somebody rediscovers by running the tool.

**ADR-0063's evidence is corrected, its decision untouched.** That record opened by citing `agentskills validate` as having passed every skill of this collection, which was never true; the move of on-demand files into `references/` was about legibility and not conformance, so nothing about its decision rests on the sentence. The false claim is rewritten rather than deleted, in the shape ADR-0017 uses, and points here. Issue #54's body carries the same claim and is left as filed: a closed ticket is the record of what was believed when it was worked, and this record is where the correction lives.
