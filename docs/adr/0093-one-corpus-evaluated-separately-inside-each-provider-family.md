# One corpus, evaluated separately inside each provider family

The editorial Skills promise things no unit test can see: that a draft invents nothing the source did not carry, that a mechanical pass does not quietly improve a sentence, that a directory-targeted result steps past an occupant rather than over it. The seam where those promises are either kept or broken is the Skill's real output in an actual supported Harness, and that seam has a model on the other side of it. Two provider families will run the same Skills, and the point of running both is to find out where they differ.

**The corpus is built from the specification, not from an implementation.** It could therefore exist before the Skills did, which is the only way it tests the contract rather than describing whatever was built. The same property is what makes it usable as a check on a later change: material chosen from the specification does not quietly acquire the shape of the code that grew beside it. Where a run exposes a real defect, the defect becomes its own ticket against the Skill; the corpus and the criteria are not the place that absorbs it, because a criterion softened to accommodate an implementation has stopped testing anything.

**It is fixture material, and it is not a test suite.** Nothing in it asserts an exact sentence, and nothing in it claims a model writes perfectly or finds every error. Each fixture says what the material is, how it reaches a Skill, and what a correct run must never do with it, so an evaluator uses a fixture without first reading the Skill that consumes it. The suite under `tests/` therefore checks the corpus rather than the models: that every kind the specification names is covered, that every file is documented and every documented file exists, that the protocol states its rejections and defines its record fields. It runs no model, which is exactly why it can run on every commit.

**A criterion is semantic, blinded, and floored.** It is answerable from the delivered artifact and the recorded side effects alone, against criteria fixed before the run, without knowing which model produced the output and without a reference text to compare against. Several valid texts pass, and a criterion that would separate two correct drafts on wording is written wrongly. Five things fail regardless of how well the output reads — an unsupported fact, wrong locale behaviour, a substantive edit from a contract limited to mechanics, an unresolved mandatory finding, an incorrect side effect — and no criterion may be phrased so that one of them passes. Without that floor, a semantic criterion decays into approval of anything fluent.

**The artifact-and-side-effects-only claim is narrowed by ADR-0129 for otherwise-unobservable loading obligations, which may be judged from the provider-native Harness trace.**

**The families are isolated, in both directions, as a rule about sessions rather than about tooling.** A Codex session runs only GPT-family evaluations and never starts, controls, or invokes a Claude Harness or model. A Claude session runs only Claude-family evaluations and never starts, controls, or invokes a Codex Harness or GPT model. Neither is a statement about which provider is trusted; both follow from wanting a comparison that no cross-provider agent control could have contaminated, and from the plain operational fact that a session driving another vendor's harness is a session nobody can account for afterwards. No cross-provider orchestration exists in the corpus, in the protocol, or in any tooling around them.

**The comparison is a read, not a run.** Because the families cannot meet, the record is the only place they do. The recording format is therefore fixed in the protocol and materialised as a template: identity fields that say which model in which Harness against which corpus commit, and per-fixture fields that say what was typed, what came back, what the filesystem shows, and how each criterion was judged. Side effects are read from disk rather than from the Skill's account of itself, because a Skill reporting its own writes is the one witness the output contract exists to doubt. A re-run is a new record; what a configuration did on a given day is history, in the same sense ADR-0079 gives a Run Outcome.

**What this costs.** Two runs are needed for every comparison, and the second may happen weeks after the first, on material that must not have moved in between — hence the corpus commit in every record, and hence the immutable URL rather than a live page. Evaluations are hand-run and unautomatable by design, so the corpus grows only when somebody adds to it deliberately. And a corpus written from the specification will contain fixtures no Skill turns out to need, which is a gap worth keeping: a fixture nothing consumes is a question about the contract, not dead weight.
