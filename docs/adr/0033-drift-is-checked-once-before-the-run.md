# Drift is checked once, before the run

Landing each Plan moves `HEAD`, so a per-Plan Drift check would fire on every Plan after the first and stall the run on changes the run itself made. `execute` therefore records the commit it started from and checks every selected Plan against that base, once, before any work begins — the only moment Drift can belong to someone else. From then on the guard is the invariant that `HEAD` stands where the run left it: any other value means a third party committed mid-run, which is real Drift and stops the run. Re-stamping `Planned at` after each Landing would silence the check by destroying its evidence, so it is never done. What this cannot catch is a Plan whose excerpts were invalidated by an earlier Landing; that surfaces as the Plan's own STOP condition and is reported, which is the acceptable failure — visible rather than silent.
