# The reframing Skill is named `brief`

`tldr` named one of the two things this Skill offers. A bare invocation is feedback that the preceding answer missed the useful level, focus, or density, and *TL;DR* is a fair shorthand for the reply that follows. The standing mode is a different act: it adopts a perspective for later replies and deliberately revisits nothing, so the old name promised there a summary that never arrives. Once ADR-0103 gave that mode a command path, the mismatch became a thing a user types — `on` read as *turn the too-long-didn't-read on*, which is not what the mode is.

**What the old name got right.** `tldr` was instantly legible to anybody who has ever read a forum post, and the bare form needed no explanation whatever: the word is the request, and a user who had seen it once could not misremember it. That is the whole of what this change spends, and it is worth naming rather than waving past.

**`brief` holds both forms.** As a verb it is what the bare form does — brief me on that, brief me on only the security part — and as a noun it is a document written for whoever has to act on it, which is the reader the perspective already selects for. It carries the standing form without strain, because briefing is something one can go on doing. The mode takes the command's name rather than keeping one beside it: Brief mode is what the Skill's own surfaces state, so the word a user types and the perspective they switch on are the same word.

**What this costs.** The new name needs its first sentence of help to say that it reframes rather than summarises, where the old one explained itself. It also shares a word with the assignment brief the editorial Skills take as input — a different command and a different part of speech, so the collision is a reader's double-take rather than an ambiguity in anything typed. And the managed block's markers move with the name: the collection has one user, so the Skill writes and reads `kntnt:brief` alone rather than carrying a second accepted spelling in the file forever, and an already-installed copy is left with an enabled directory and a written block under the old name, which the changelog entry names together with the one line that removes each.

**No collection-wide rule follows.** Whether every Skill's name has to hold for every form it offers is a larger question, and this record does not ask it: what is settled here is what this one Skill is called. So the coding standard gains nothing, a rule governing one Skill's own behaviour needing no statement where a contributor meets the rules binding all of them.

**Nothing the Skill does moves.** The perspective, the range rules, the accepted forms, the two scopes, the persistence mechanism, the staleness report, and the confirmation gate are exactly as ADR-0048, ADR-0080, and ADR-0103 left them, and ADR-0012's answer for a Skill with nothing to declare is untouched. No decision this collection has taken is made false by a rename, so this record takes over no earlier record's ground and owes no pointer in either direction. Where an earlier record spells an invocation of this Skill, the spelling is corrected in place and that record's decision is left as it stands, as ADR-0109 did for its own sibling.
