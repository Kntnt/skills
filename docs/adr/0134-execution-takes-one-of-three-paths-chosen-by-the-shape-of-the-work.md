# Execution takes one of three paths, chosen by the shape of the work

The delegation directive named one mechanism for keeping noisy output out of main context: delegate to a subagent and ask for a bounded report. A full production night on that doctrine showed the savings coming from three mechanisms, with the named one ranking second. The largest was a process detached from the conversation writing to disk — builders, repairs, and whole Orchestrate cycles ran that way, main context received the fifty-line reports and searched the progress markers, and hours of build logs and full test suites never entered the window. Subagent delegation earned its cost exactly where judgment had to be exercised inside noisy data: a distiller reading state directories and tickets into a two-hundred-line failure report, a verifier running multi-hour serial gates in a disposable clone and returning a verdict and six bullets. And for a small bounded command the main seat with output narrowed at the source beat both, because a fenced brief and its reply cost five hundred to a thousand tokens before the subagent has done anything. A directive that names only the second path invites a subagent round-trip for pure command execution, where either other path is strictly cheaper (issue #207).

**The directive names three execution paths and the shape of work that selects each: pure execution with large output runs detached from the conversation, writing to disk, and the main seat reads only the report and searches the rest; judgment inside noisy data goes to a subagent for a bounded, task-shaped report; a small bounded command stays on the main seat, narrowed at the source.** The rule is the shape of the work and not an order of preference — the first path exercises no judgment and the third pays no handoff, so neither answers where the other's condition holds. *When unsure, delegate* survives and is scoped to the choice between subagent and main seat: uncertainty there is about whether handoff costs less than direct work, which delegating settles cheaply, while uncertainty about whether something needs judgment is never settled by a detached process, which exercises none. The rule for predictably noisy reads stands as written — narrow first, and delegate before raw output enters main context — because every path is one way of honouring it. Judgment stays on the main seat, results are verified independently, and a foreign spawn is routed exactly as before (ADR-0133).

**The detached path is stated as a property and never as a tool.** The directive is committed into a context file every Harness reads (ADR-0005, ADR-0026, ADR-0030), so it says what the process is — detached from the conversation, its output on disk, its report the one thing read back — and names no command, flag, or waiting facility, exactly as ADR-0127 declined to name the mechanism a subagent waits with. What the production night ran as one CLI's exec mode is one Harness's spelling of the property; the next Harness spells it differently and reads the same sentence.

**The main seat ends what it detached, or names it as left standing.** ADR-0127 gave every subagent the rule that whatever it starts it stops before it reports, and a main seat that detaches processes acquires the same exposure: a process nobody owns holds the machine other work is done on and goes on speaking for a turn that has finished. So the same clause reaches the main seat, in the sentence that names the path, and the report is where a deliberate exception is named, as it is for a subagent.

**The roles are listed once, and the word for what comes back is *report*.** The counterweight sentence ADR-0133 wrote already lists the cheap judgment-in-noise roles — distillation, summarization, evidence collection — so the subagent path names the property, judgment inside noisy data, and not a second list that would drift from the first. The issue's illustrative parenthetical is not adopted into that list. *Exploration* stays unnamed, because no exploration policy exists and a directive asserts only what stays true (ADR-0067, ADR-0133). *Verification* stays where the directive keeps it, on the main seat: a verifier subagent that runs gates and returns a verdict is judgment inside noisy data and takes the subagent path on that description, while the main seat's own verification of what comes back is untouched, and a list that named verification as a subagent's role beside a sentence keeping it on the main seat would contradict itself in the space of a hundred words. *Report* is the word for what the main seat reads from a detached process, so that the report's contract, when it is written, attaches to a word already in the directive without renaming (issue #209).

**What this costs.** The directive grows from 207 to 261 words against the 300-word ceiling ADR-0133 set for the whole doctrine, and the additions issues #208, #209, and #210 still owe it share the 39 words that remain; the ceiling is not a target, and each of those may be a clause. The boundary between pure execution and judgment is the reader's, and nothing checks which path a session took — a session that detaches a distillation reads raw output back, and one that briefs a subagent for a test run pays the fence for nothing; the directive names the shapes and does not police them. A detached process without a report is a process whose output the main seat has to go and read, which is the raw output the doctrine exists to avoid; until issue #209 gives the report a contract, *report* names an obligation and not a format. The manpage now carries the three paths in one clause, one more sentence to keep true beside the directive. And nothing here reaches the Harness's own context costs — loop reinjection, notifications — which no doctrine text can fix. In return, a session that would have spawned a subagent to run a suite starts a process and reads a report, and the doctrine keeps the brevity that is part of its value: a handful of lines, read on every turn.
