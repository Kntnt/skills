# Land each approved Plan before the next one starts

The External `improve` builds each Plan in an isolated worktree that sees only committed files, and it refuses to merge, push, or commit to the user's branch. A Plan that depends on an earlier one would therefore start from a base without its prerequisite, so `execute` Lands every approved Plan before dispatching the next: squash the worktree branch into the working tree, commit through the collection's own `commit` skill so `CHANGELOG.md` stays true, then delete the branch and the worktree. Landing through `commit` rather than a plain merge is what keeps the changelog honest and gives one entry per Plan. It also makes every worktree start from the current `HEAD`, so sibling branches never diverge and merges cannot conflict. `execute` stops there: push, tag, and release stay with `push` and `release`, because an unattended run must not publish.
