# Model Selector derives routing context from shipped adapters

ADR-0083 made Model Selector the owner of exact frozen routing while leaving the current context for each session to assemble. ADR-0104 made inheritance an explicit launch destination while limiting that vocabulary to a native control. Those decisions preserved honest routing but left no reproducible path from a persisted profile and an active Harness to the artifact Route requires. This decision supersedes ADR-0083 only where it leaves context assembly to the session. It also supersedes ADR-0104 only where it limits non-parameter destinations to inherited native controls, and narrows ADR-0132 by adding `context` to the dependent Interfaces for which Model Selector is model-invoked.

**Model Selector owns a public Context Interface before Route.** Context accepts ordered route requests beside either exact runtime facts or a frozen snapshot. Runtime names the active Harness and complete main seat; Context validates the persisted profile, reads the shipped seed, adapter templates, and routing defaults, and returns the complete route artifact. A later call validates and carries the frozen snapshot unchanged. Context performs no setup, network access, or persistent write, so Orchestrate can call it before every route without acquiring Model Selector policy of its own.

**Adapters ship as templates and become concrete only against profile and runtime facts.** A template declares the Harness and configured surfaces it covers, the model identity it can address, its control source, and a complete launch destination for every relevant field. Specialization binds the selected channel, exact model, serving mode, supported controls, fixed empty tool and policy facts, and the session attestation required by an inherited destination. The attestation's `verified` value is the same stable identity as the Harness inventory revision in both current and frozen context. Seedless or uncovered enabled selections and unavailable selected controls remain visible as mappings with no reachable adapter; `all_supported` without seed support freezes empty controls rather than inventing a portable mapping or rank. Invalid, disabled, and unvalidated selections never become mappings. What counts as unvalidated is narrowed by ADR-0166: the evidence ledger's own record of a model admits an enabled selection, and the profile's `validation_status` answers only where the ledger has never seen it.

**Every launch fact has one of three destinations.** A parameter destination may render the point value through a template and emits one Harness-native argument. A fixed destination must equal the point and emits none. A carried destination must equal the corresponding frozen main-seat fact, requires the verified session attestation, and emits none. This single vocabulary applies to model, surface, serving mode, native controls, tools, and policy; emitted parameter names alone must be unique. Claude Code's Agent seam carries deliberation and takes the short family alias as its model parameter. Its Codex-exec seam maps the canonical model to `-m` and portable effort to `-c model_reasoning_effort=<level>`.

**Capability ranks come from one independent numeric comparison.** Context selects a newest non-superseded benchmark definition that scores the main seat and covers the largest candidate set, then uses the maximum score for each model in that definition. A model absent from it keeps an unknown rank and cannot launch; qualitative seed prose never becomes a number. Portable controls use the declared five-level ordinal only where model and adapter both support the value. The build-time Codex fixture records the installed CLI's version, `exec --help` output, and projected supported reasoning levels; `max` is admitted where observed and the non-portable `ultra` value is retained as evidence but never mapped.

**Missing facts inherit rather than trigger setup.** A missing or invalid profile, no comparable main seat, empty mappings, and an automatic pool excluded only by unreachable adapters or unknown ranks preserve the exact main seat with `unavailable_selection_controls` where applicable. The premise that those are one profile state is narrowed by ADR-0165, which keeps the inheritance and splits it in two: a `config.json` that is not there is absent, and one present that cannot be read or validated is rejected, with a reason token of its own. The clause about no comparable main seat is narrowed by ADR-0166: a configured seat no benchmark scores keeps its mappings and suspends the ceiling, only a seat absent from the profile still emptying them. An explicit override never inherits: it is selected exactly or refused. Shipped override defaults provide cold-start selection, a `0.7` quality floor, and no shadow prices. Commercial dimensions remain unknown rather than being invented from token schedules without a usage basis.

**What this costs.** The Collection now owns versioned schemas, adapter data, policy data, and observed CLI fixtures that must move together when a Harness dialect changes. Profile selections remain visible even where they cannot launch, so a snapshot can be larger than its candidate pool. In return, a caller supplies only facts the live session can know, every derivation rule has one shipped implementation, and a frozen route can be reproduced without hand-authored numbers or declarations.
