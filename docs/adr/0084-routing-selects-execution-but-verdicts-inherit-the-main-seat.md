# Routing selects execution configurations; verdicts inherit the main seat

Delegation and Orchestrate already distinguish builder work from the judgment that accepts it: ADR-0074 delegates building down but keeps verdicts on the orchestrator's seat. That rule depended on a main agent informally judging a cheaper builder model. It could not reproduce the complete launch configuration, use configured access and evidence consistently, or prove that a builder remained below its verifier. A human-facing model recommendation is not a safe unattended execution contract.

**Model-selector owns one public Model Routing Module.** Delegation and Orchestrate depend on that Module and use only its public Interface for execution roles; they do not read its private references or scripts. The Interface is offline, read-only, non-interactive, and accepts one request or an ordered batch, returning one ordered `selected`, `inherit`, or `refused` RouteDecision per request. A request states authority, workload, execution stage, reversibility, independent failure signal, field-level overrides, and relevant prior routing or verified failure. A selected decision names the exact configured point, exact native Harness launch control, evidence class, provenance, exclusions, and permitted next escalation. Inheritance and refusal are explicit audit results; refusal contains no launch instruction.

**The portable public deliberation control is exactly `low`, `medium`, `high`, `xhigh`, and `max`.** Omission requests automatic selection; there are no public auto, off, provider, or numeric aliases. Every selectable level maps inside the frozen route snapshot to the exact provider-native effort, reasoning, thinking mode, or thinking budget for that model, channel, surface, and active Harness. `max` is the highest verified native setting available for the exact configured point in that snapshot. A missing mapping is unavailable, never rounded or interpolated. The ordered portable scale permits one-level escalation but does not assert a universal quality ranking.

**Routing selects the weakest plausibly capable complete execution point without surpassing the immutable main seat.** It intersects enabled configured points with the active Harness's concrete launch adapters, workload constraints, evidence, and a verifiable complete capability ceiling from the main-seat identity. An explicit model locks only model selection; an explicit deliberation locks only deliberation selection. An unavailable or ambiguous explicit override is refused, as is any explicit configuration demonstrably above the ceiling. Missing profile or insufficient evidence returns audited inheritance when safe; invalid profile state, an unrepresentable verdict seat, an unverifiable ceiling, or no safe candidate refuses before externally visible work begins. Evidence classes distinguish measured, mixed, and heuristic selection, keeping cash, rolling quota, weekly quota, allocated plan cost, and latency as separate facts.

**Verdict authority always resolves to inheritance of the main seat.** Model-selector does not economically optimize ticket verification, amend verification, repair verification, or wave checking, and neither dependent Skill changes the main session's model or deliberation. Initial builds, amends, collision repairs, rebuilds, and mechanical wave fixes are execution stages. An independently established failure may use only an amend or rebuild attempt the workflow already grants. In cold start it normally advances one adjacent deliberation level on the same model; another move requires matched policy evidence. Routing creates neither retries nor model self-grading.

**Orchestrate freezes all routing facts before its first tracker claim and reuses that snapshot for resume and every later stage.** The frozen state includes profile revision, evidence vintage, Harness inventory, main-seat identity, mappings, overrides, and resolved open-ticket decisions. Route decisions extend existing per-ticket run data and reports; they do not add a Ticket Resolution or change Run Outcomes.

**Routed execution may write a minimal sanitized observation artifact only in caller-owned scratch.** It records the exact configuration, routing provenance, externally established outcome, available cost, quota and latency metrics, and sanitized artifact identities, with unavailable values as `null`. It omits prompts, responses, reasoning, source content, diffs, terminal output, secrets, and unnecessary absolute paths. There is no automatic evidence import or ledger write: explicit model-selector record remains the only mutation. The artifact is the reusable input for the separate opt-in capture work in issue #91.

## Considered options

Letting each caller choose a cheaper model preserves local convenience but duplicates policy and loses reproducibility. Routing every role through the cheapest point undermines the independent verifier that makes unattended work trustworthy. Treating portable levels as provider-neutral quality scores or silently rounding unavailable controls invents equivalences the evidence cannot support. Automatic recording would turn ordinary delegated work into a persistent side effect and would preempt issue #91's consent and lifecycle design.

## Consequences

The Collection gains one compact, testable routing seam while interactive recommendations retain their frontier, uncertainty, and experiment reporting. Callers gain fresh-context and execution-capacity savings only where a verifier stays at the unchanged main configuration. A missing usable profile remains safe through explicit inheritance; corrupted or unsafe state stops before claims. The child implementation issues carry the Module, the two callers, and the artifact contract in dependency order, while this record fixes their shared authority boundaries.
