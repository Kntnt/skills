# The collection writes one flat, prefixed `metadata` namespace

The Agent Skills specification defines `metadata` as a map from string keys to string values: one level, strings on both sides. What every skill of this collection carried was neither — a boolean under `internal`, and a nested map under `kntnt` holding four lists. A reader outside this collection does not refuse that shape, it coerces it, so `read-properties` answered with the Dependency lists flattened into a Python repr and the marker's value as the word `true`. Nothing warned, because a string is a legal value and coercion produced one. **Every key the collection writes under `metadata` is now a string key named `kntnt.<something>` holding a string value, and a list is one space-separated string** (issue #52).

**Space separation follows the specification's own `allowed-tools`,** which is a space-separated string for exactly this reason: a list has to survive in a map whose values are strings. The alternative was encoding JSON into the value, which is a second format to parse and the same repr problem wearing better punctuation. A Dependency name has no spaces in it, so splitting on whitespace is lossless, and an empty list is an empty string — unambiguous under any parser, which is what the nested block never was.

**The marker is now any `kntnt.` key rather than a block.** Provenance still travels in the skill's own `SKILL.md` and nowhere else, on ADR-0037's terms, but what carries it is the prefix rather than the presence of a mapping. A skill with nothing to declare writes its four lists empty and is marked by that, which is a shape a foreign parser can neither lose nor mistake. It also ends the trap the empty block was: there is no value left that means *marked and empty* only to a parser that reads the block whole, so ADR-0060's correction of `/brief` to `kntnt: {}` is withdrawn along with the mapping it corrected.

**`internal` is prefixed with everything else, and that is a real cost paid on purpose.** The specification recommends making key names reasonably unique, and `internal` bare is the opposite: one flat namespace shared with every other collection, and the flag says nothing about whose it is. Prefixing it means a reader that looks for a bare `internal` to keep a skill out of ordinary discovery no longer finds one on these skills. Nothing in this collection reads the key — it is written for readers elsewhere — and a key that any collection may claim is not one this collection can rely on either way. Correctness under the specification is worth more than a convention only some readers honour, so the flag is named `kntnt.internal` and its meaning is this collection's to state.
