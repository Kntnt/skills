# One invocation order: command path, then flags, then operands

Every Skill in this collection wrote its operands before its flags — a message before `--yes`, a ticket list before the run options, a workload before the decision flag — and nowhere was that order stated as a rule. It was inherited by imitation, which means the next Skill added inherits it too, and means a Skill quietly doing the opposite would read as a variation rather than a defect. It was also the one part of the grammar nothing could judge: the suite compares the flags named in `argument-hint`, `## SYNOPSIS`, and `## OPTIONS` as a set, and a set has no order.

**A Formal Invocation is written in one order: the command path, then the flags, then the operands, then the reserved separator and its optional Contextual Instruction.** That is the POSIX guideline that options precede operands, bounded by the one thing POSIX never had to answer for — these Skills have command paths. So the rule has three parts rather than two.

**The command path comes first**, being the Skill name followed by the literal subcommand tokens that address a manpage. The boundary is not a judgement about which words feel like commands: a token is part of the path when a page under the Skill's `help/` answers to it, and an operand otherwise (ADR-0077). `/model-selector config edit` is three path tokens because `help/config/edit.md` exists; the `model` and the identifier that follow it are operands, because nothing answers to them. A builder can test the boundary against the shipped tree.

**Flags follow the command path**, valued or not, in any order among themselves. **Operands come last**, followed by the reserved `--` and the optional Contextual Instruction, which already close every invocation and are untouched by this (ADR-0078).

**The reason is the free-text operand, not symmetry.** Several Skills take free text or a repeatable operand list, and under the old order a flag could follow it. `/commit fix the --yes bug` has no reading that is both strict and useful: either the Skill guesses which `--yes` was meant, or it refuses a message a user had every reason to type. With the flags in front, everything after the first operand is operand, and the grammar stops depending on whether a word in the middle of a sentence happens to look like a flag. It is the same defence the reserved separator already gives at the other end of an invocation, applied to the end that had none. A repeatable operand followed by an optional flag is also the shape `argparse` handles worst, so the collection's own engines get the order they parse most reliably.

**The order is strict, and an invocation that breaks it is refused.** Under the record making an unknown subcommand and a disallowed flag the same error (ADR-0059), a form the grammar does not allow is refused rather than repaired, so an operand written before a flag takes the ordinary refusal: what was wrong, the addressed `## SYNOPSIS` verbatim, and the pointer to that command path's help route. What that costs is real and is not hidden here. The form every Skill documented until now stops working — `/commit "fix the parser" --yes` and `/release minor --yes` were the spelling in the manpages, and both are now errors. A user whose habits come from `git`, `gh`, or any GNU tool meets a refusal where every one of those would have permuted the arguments and carried on. The collection accepts that, because it already trades permissiveness for a grammar that reads the same way in every Skill, and an order enforced in one Skill and repaired in another is exactly the invisible Skill boundary strictness was adopted to remove.

**Permuting was the alternative, and it fails on the operand that matters.** Accepting flags anywhere is what most tools do, it would have cost no diff at all, and it is what a user expects. It cannot be done here without giving up the free-text operand, because permutation and free text are the same ambiguity seen from two sides: a parser willing to find `--yes` after the message is a parser unable to accept a message containing `--yes`. GNU resolves this with `--` in the middle of a command line; this collection has already spent `--` on the Contextual Instruction (ADR-0078), so that escape is not available. The choice was therefore between free text and permutation, and free text is the thing users type.

**An operand with a long-option alias keeps both spellings.** Where a Skill offers one choice as an operand and as a flag — `delegation`'s scopes and states are the case today — the flag spelling sits with the flags and the operand spelling with the operands. Both remain valid, and neither documented form is ambiguous about which of the two it is using. The cost is that a single synopsis form can no longer make such a slot mandatory, since the slot appears in two regions of the line; the pages that have it say so under `DIAGNOSTICS`, where the rest of that grammar's exclusivity already lived.

**The engines stay permissive, as they are for flag spelling.** `argparse` accepts an option before a positional of its own accord, so every engine but one needed nothing. The exception is the seam that reads its options by hand — `observations.py`, for `observe --artifact` and `record --data` — which required its path first and would have refused the very line its Skill body now writes. It normalises the two orders instead of refusing either, which is the same choice ADR-0096 made there: the only writer of those command lines is a Skill body in this repository, and a second parser built to refuse an order would be a second grammar to keep true.

**A third-party command line is out of scope**, on the same boundary ADR-0096 draws for flag spelling. A `git`, `gh`, `uv`, or `npx` invocation a Skill body constructs keeps the order that tool documents. The rule reaches the grammar this collection defines and stops at every grammar it does not.

**Nothing else changed.** No flag was added or removed, no operand changed meaning, and no Skill gained or lost an accepted form. Where a compressed synopsis line collapsed branches that now sit in different regions, the line was split into the branches it already meant; the set of invocations each page accepts is the one it accepted before, minus the orders this record refuses.

**The suite is the enforcement, as it is for every other part of this grammar.** A check reads every `argument-hint` and every `## SYNOPSIS` line, resolves each unit into command path, flag, or operand, and fails where a flag follows an operand or where a subcommand token that answers to a page under `help/` follows a flag. It names the rule and points at the Skills module of the coding standard. An alternation naming both spellings of one slot is a single slot rather than a sequence, so it is read as one unit and allowed only where every unit before it is path or flag and every unit after it is operand.
