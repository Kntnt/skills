# Subcommands have addressable manpages

A root page can teach the outline of a Skill with subcommands, but it cannot remain a usable reference for every subcommand as their arguments, options, diagnostics, and examples grow. `model-selector` demonstrated the failure: one page contained the grammar of fourteen command paths, while `/model-selector recommend --help` was rejected and the user had to search the root page for the relevant paragraphs. The Manager already shipped one page per verb, but direct `/kntnt select --help` still fell through to normal argument parsing instead of selecting that page.

**Every public subcommand has an addressable manpage.** A Skill with subcommands keeps its root page at `help.md` and mirrors command paths under `help/`: `help/recommend.md` for `recommend`, `help/config.md` for `config`, and `help/config/add.md` for `config add`. `/<skill> <command-path> --help` prints the most specific recognized path's file verbatim and stops before normal work; `-h` is the identical short route. The root `/<skill> --help` route remains unchanged. A separate `help <command>` grammar may coexist where the Skill already has one, as the Manager does, but it is not required of every Skill.

**Every command with subcommands lists all of its immediate children.** Its page carries `COMMANDS`, with each accepted child as a tagged term followed by a short description. The root page lists only root children, so `model-selector` lists `config` once rather than flattening six configuration operations beside it; the `config` page lists `show`, `add`, `edit`, `remove`, `history`, and `reset`. A child with children repeats the rule. The page tree and each `COMMANDS` section are checked against one another, so adding a page without listing it and listing a command without a page both fail.

The help route is selected before ordinary grammar validation. `--help` and `-h` remain routes rather than operational options and therefore stay out of `argument-hint`, `SYNOPSIS`, and `OPTIONS`. An exact recognized command path followed by a help route may be incomplete as a normal operation — `config edit --help` needs no record ID — because the request addresses documentation, not the operation. An invalid normal invocation uses the most specific recognized page's `SYNOPSIS` and points to that path's `--help` form, keeping the error beside the grammar it violated.

The pages remain authored files rather than sections extracted or prose regenerated at invocation time. A complete page gives each command its own `NAME`, focused `SYNOPSIS`, applicable `OPTIONS`, and direct review surface; extraction would either reproduce the overgrown root page or introduce a second renderer whose output can drift. Nested directories preserve the command hierarchy without inventing filename separators.

This decision amends ADR-0044 by extending its root `help.md` rule with per-command pages for Skills that have subcommands. It also amends ADR-0063 by making `help/` a user-facing manpage tree for any such Skill rather than an exception belonging only to the Manager.

The cost is more authored pages and repeated background facts. The boundary is command-specific usefulness: shared orientation stays concise on the root page, each command page carries only what is needed to use that path, and the structural tests hold addressing and command discovery while review remains responsible for prose quality.
