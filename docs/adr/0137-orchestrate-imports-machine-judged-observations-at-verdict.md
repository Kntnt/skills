# Orchestrate imports machine-judged observations at verdict

ADR-0089 made external judgement a precondition for routed-work evidence and left every import to the user. ADR-0132 made Model Selector's public routing and observation Interfaces reachable to dependent Skills while keeping `record` user-only. That separation prevented work from grading itself, but it also left a completed Orchestrate run unable to teach the next one without a manual artifact round trip. This decision supersedes ADR-0089 only for Orchestrate's import step and narrows ADR-0132 only where it concludes that routed work cannot import; delegation and the public `record` command remain user-driven.

**Orchestrate owns an explicit lifecycle for every routed execution request.** `attempt-start` persists the first launch instant immediately before an initial build, amend, repair, rebuild, or wave fix is dispatched. `attempt-finish` accepts only a launched request and ends it at an independent pass or fail verdict or at a terminal non-model condition. A repeated start preserves the first instant, a completed request cannot start again, an identical finish is a replay, and a different finish is a conflict that overwrites nothing. A merge collision after a passed build is not a second outcome for that build; its repair is a distinct routed attempt.

**The Collection Library is the single observation implementation.** `skills/kntnt/library/scripts/routed_observations.py` owns emission, validation, artifact merging, and ledger recording. Model Selector's script is a CLI adapter that re-exports those functions, while Orchestrate resolves the same Library in repository, installed-Manager-sibling, or Skill-local layouts. Neither Skill reaches into the other's private files, and a missing Library tells the operator to install or update the Manager.

**Eligible evidence enters the ledger when its verdict lands.** Orchestrate imports outcomes established by `independent_verifier`, `objective_checker`, or `declared_failure_signal`, plus `abstain` and `infra_error` conditions that affect no quality rate. `frozen_rubric` and `user_confirmation` remain manual through `/model-selector record`, as does every delegation artifact. Import refusal never stops the run: imported, identically skipped, conflicting, and refused results are retained on their attempt and rendered by the final report.

**Each real routing account receives one opaque run identity.** The identity is random, persisted independently of the frozen snapshot, copied into every Orchestrate attempt and observation, and included in the run key. A null identity contributes no key term, so existing ledger rows, delegation observations, and capture observations keep their historical keys unchanged.

**What this costs.** An unattended run may now change the user's evidence ledger and derived frontiers during the night. Tests that exercise the completion seam must therefore isolate every home and cache surface. In return, the engine imports only outcomes established outside the work, the builder never writes the ledger, every import result remains auditable in the run account, and the next route can learn without a user step.
