# An Invocation Envelope separates strict grammar from contextual instruction

Every caller starts exactly one Skill through an Invocation Envelope: a Formal Invocation governed strictly by that Skill's declared grammar, and an optional Contextual Instruction containing natural-language guidance. The first standalone, unquoted `--` token separates the two, preserving ADR-0059's refusal of malformed commands and unsupported flags while giving user-, model-, and Skill-initiated calls one explicit context channel (issue #87). This record narrows ADR-0059 only where that record treated every part of an invocation as formal grammar; its strictness is unchanged inside the Formal Invocation.

The separator is reserved across the Collection and belongs to no Skill's formal grammar. It is the first unquoted token exactly equal to `--`, bounded by whitespace or the payload boundary; tokens such as `--force` and `foo--bar`, and a quoted literal `--`, remain formal data. The Contextual Instruction is everything after the separator, may begin after any amount of whitespace within the same payload, and must contain non-whitespace text; later `--` tokens are context. Without the separator, every part of the current payload remains formal input, including later lines and paragraphs, and is accepted or refused by the addressed Skill's grammar.

A Contextual Instruction is read and used rather than parsed as arguments, ignored, or echoed mechanically. Redundant but applicable guidance is valid. It may clarify or narrow choices the Skill's contract leaves open and overrides older conversational preferences within those choices, but it cannot contradict the Formal Invocation or a Skill invariant, widen the Skill's responsibility, disable a required gate, or affect an exact help route whose output is fixed. Applicable guidance already present in Conversation Context has the same semantic bounds and need not be copied into the Envelope.

The agent separates the Envelope before selecting a help route or validating the Formal Invocation, and interprets context only after the formal part is valid. An empty or whitespace-only instruction is a malformed Envelope. A malformed Envelope or Formal Invocation receives the existing syntax refusal with the addressed synopsis; syntactically valid but conflicting, irrelevant, ineffective, materially ambiguous, or scope-widening guidance receives a contextual refusal that names the problem, changes nothing, and does not misreport the problem as syntax. Context accompanying an exact help route receives that contextual refusal without rendering the page. Mixed guidance is not partially applied. Read-only inspection may establish whether guidance is usable before the first side effect; a conflict discoverable only after a legitimate effect stops later effects and is reported with the exact partial outcome rather than being silently rolled back.

One Envelope belongs to one Skill. A Skill remains responsible for applicable guidance throughout its own work, including work performed through another Skill, but forwards only the relevant guidance as an explicit Contextual Instruction in that inner Skill's own Envelope rather than copying context blindly. A successful run adds no mandatory acknowledgement of context, though an existing report names a material choice the guidance changed when that choice belongs in the report.

## Considered options

Treating every prose suffix as invalid preserves the old grammar but forces an agent to retry an invocation even when the Skill already has the facts in its Conversation Context. Inferring context from trailing prose or a new paragraph is not portable across Harnesses and is ambiguous for Skills whose formal grammar already accepts free text. Letting each Skill decide whether prose is formal would recreate the invisible Skill boundary that Collection-wide strictness removed, while accepting prose and ignoring it would create a channel with no semantics.

## Consequences

Every current and future Collection Skill, including the Manager and every command path, exposes the optional context suffix in its argument hint and synopsis, documents the distinction without listing `--` as an option, and performs the same Envelope split before its own grammar. The coding standard and suite hold those surfaces together, and the migration lands atomically across all shipped Skills with no release from a partially migrated state. A caller that needs a literal standalone `--` inside formal free text must quote or otherwise embed it so that it is no longer the reserved token.
