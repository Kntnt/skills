# Cleanup ownership is a Harness process lifetime

Issue #365 showed that a hook or tool call's POSIX session is not the agent session: Claude Code creates short-lived POSIX sessions while the owning Harness works for hours. A new Harness therefore deleted another working session's scratch and containers, and could kill its own registered launcher. Protecting only live recorded children left path-only work and completed-child work exposed.

Cleanup now records the long-lived Harness PID and its start time. A known live owner protects the whole manifest without an age limit. Death or a different start time permits recovery on the next start, including after a hard kill; an unreadable identity retains the manifest. Recorded ancestors remain an unconditional protection against a nested launch killing itself. This ties recovery to a local process lifetime, so a shared server can delay recovery after one conversation disappears without an end event. That cost is preferable to destroying working resources.

Identity is selected using the nearest Harness ancestor. Claude's session ID and Codex's root-session ID match their lifecycle payloads, but both can be inherited into a nested process: environment-variable precedence alone is unsafe. Hooks use their own payload identity. OpenCode exposes conversation identity to plugins but not consistently to shell tools across its runtimes. Its shell recordings therefore use a process/start-time key and wait for the server to exit; ending one conversation cannot clear those shared-process recordings. Unknown owners and legacy SID-only manifests wait for the day-old fallback. That deliberately bounded fallback cannot promise lifetime protection where no owner can be established.

Terminal pointers were rejected because hook and tool do not share their key. They are retired rather than migrated into invented ownership. Live-child heuristics cannot establish the owner's death, age cannot override a known live owner, and suppressing nested starts would leave sibling starts destructive. End-only cleanup would abandon hard-kill recovery. The selected trade-off keeps immediate recovery where ownership is provable and delays it where it is not.

The pre-implementation evidence and alternatives are in the issue thread: matching Codex 0.155.1 and OpenCode 1.18.31 source inspections, and a live Claude Code 2.1.278 hook probe. Start-sweep logs separately identify the manifest owner and the initiating session, so later incidents can be attributed. Hook reporting is log-only because the old stderr error handler could itself raise after its caller closed the pipe.
