# Orchestrate routes execution and inherits verdicts

ADR-0074 established that Orchestrate may delegate building down while its own seat owns every verdict. A model name is not the complete execution configuration, though: the same model can expose materially different deliberation controls, and a builder-only model override used to leave that fact unstated. Letting execution select its own configuration from prose would also let a resumed run drift as profiles, aliases, prices, evidence, and Harness mappings changed.

**Orchestrate delegates every execution role through model-selector's public route Interface and freezes its returned snapshot before the first claim.** Initial builds, amends, collision repairs, rebuilds, replacement claims, and mechanical wave fixes carry model and deliberation overrides only as field-level locks. The Interface alone validates exact points, mappings, availability, the complete main-seat ceiling, evidence class, bounded escalation, and Harness-native controls. A selected decision launches exactly as it says; a safe execution inheritance is reported; a refusal prevents a claim. A later request always carries the same snapshot, including after compaction or resume.

**Every verdict inherits the complete main seat exactly.** Ticket verification, amend verification, repair verification, and wave checking use the orchestrating session's exact model and deliberation configuration. No execution override, automatic decision, route result, repair, or failure can downgrade that seat. This is authority rather than an optimization: independent verdicts, not builder reports, still decide the existing five Ticket Resolutions.

**Portable overrides are independently exact.** `--model` locks only the building model and `--deliberation` locks only the building portable deliberation value (`low`, `medium`, `high`, `xhigh`, or `max`). Omission leaves that one dimension automatic. An unavailable, ambiguous, unmappable, or above-main explicit point refuses before claims and never falls through to a neighbor. A post-claim launch failure is a mechanical hinder with the workflow's existing one repair, not a quality failure or a new attempt.

**What this costs.** Each run preserves a larger route account — snapshot, exact decisions, evidence and selection facts, native controls, exclusions, and reasons — and cannot optimize where the frozen data cannot make a safe decision. In return, unattended execution is reproducible across resumption while its strongest seat remains the final authority.
