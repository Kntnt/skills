# A frozen account that inherits for the run restates its own decision for later roles

Every execution role of a run was routed through model-selector's public Interface in a request of its own: the first frontier as one batch, and after it every later wave, every amend attempt, every collision repair, every rebuild, and every wave fix (ADR-0085). Each request cost the orchestrating session two Skill invocations, `context` and then `route`, and each invocation loaded that Skill's instructions, its Model Routing Module, and its schemas into the session's context again — measured on the maintainer's own seat as roughly 100 KB of prose per wave. On that seat every one of those answers was the same: the snapshot carried a rejected profile, so every decision came back `inherit` for `rejected_profile`, exactly as the first batch had. A run of four waves paid the ceremony four times over for an answer it held after the first, and the ceremony grew the context every later turn of the run re-read.

**Where every decision the frozen account holds inherits for one reason that is the snapshot's own, later roles are restated from the account, and model-selector is not invoked for them.** The engine's `route` verb takes `--inherit` with one `--request` per role. It copies the decision the account already holds under each new name, changed in nothing else, and extends the account exactly as a routed response would have — so the claim gate, the amend gate, the report, and the observation an external verdict later writes all find the decision where they always did, carrying the provenance and the fingerprint model-selector gave it. The plan and every route report the fact as `routing.frozen_inheritance`, and the Skill reads it there rather than judging reasons itself.

**The reasons that count are the ones decided before anything about a request is read.** A profile the snapshot carries as absent or rejected, a Harness no adapter of which can express a point, and a filtering that leaves no safe candidate are each facts of the snapshot, and the snapshot is frozen for the run: model-selector's own module answers every automatic request under such a snapshot with that same inheritance. Evidence too weak to select from is not among them, because an objectively checked request escapes that inheritance where an unchecked one does not — it is the request's own, and a later role may well be selected. A selection anywhere in the account, a mix of reasons, a verdict name, an escalated fix round, a mismatched lock, and a dry run are each refused, and a refused `--inherit` is routed through the Interface exactly as before.

**The first batch of a run is always model-selector's to decide.** Freezing the snapshot is what establishes what it can select, and nothing in this Skill may say so in its place: the fact the shortcut acts on is read off decisions the Interface made under the frozen snapshot, never derived from the snapshot by this Skill. That is also why the shortcut closes itself: the day the profile is repaired or the seat is ranked, the first batch comes back selected and every later role is routed as before.

This record **narrows ADR-0133** on its Orchestrate side, which kept Orchestrate routing every execution role and rejected a local inherit-decision stub as a second emitter of routing artifacts. What that record objected to is upheld: nothing here emits routing content of its own, reconstructs adapter reachability, or fingerprints a seat — the restated decision is byte for byte the one model-selector made, under a name the engine already chose itself, and an observation of it imports through the one module ADR-0089 gave that job. What is narrowed is the invocation count: the Interface decides once what the snapshot can do, and the account repeats the answer. It also **narrows ADR-0085**, whose route-before-claim invariant, frozen account, and refusal of every verdict stand whole, in the one clause that had every execution role reach the Interface in a request of its own.

**What this costs.** A reason token of model-selector's is now read by name in this Skill, and a reason added to the module later is a request-bound one until this record's list says otherwise, which is the safe default. A run whose account inherits for the run and whose profile is repaired mid-run goes on inheriting until the next run, exactly as the frozen snapshot already required. And the saving is real only where the snapshot can select nothing: a Harness whose profile is valid and whose seat is ranked pays the ceremony as before, by design, because there the answer may differ from role to role.
