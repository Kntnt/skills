# The Digest answers freshness, and a mismatch is Deviating

Nothing in the collection could tell a skill on disk from the skill the collection ships. Update re-copied everything Enabled and reported *twelve of twelve refreshed*, which is equally true of a machine where nothing had changed and of one where every file was wrong. Version numbers were the obvious fix and are the wrong one: a version answers *which release did this come from*, which nobody asked, and it cannot see a truncated install or a hand edit at all, because both leave the number exactly where it was.

So each Catalog entry carries a **Digest**: a content digest of that skill's directory as the collection ships it, over the sorted relative paths and the contents of the files, so that a rename, an edit, an added file and a removed file each change it. `catalog` computes it when it generates the Catalog, so no release depends on remembering to bump anything and there is no number to bump. Any verb can compute the same digest over what is on disk and compare. Equal means the same files; different means different files. That is the whole of the claim, and it is more than a version could make.

**The ignore list is exactly `__pycache__/` and `*.pyc`, applied identically on both sides.** This is a correctness requirement and not a convenience. The generator walks a working tree carrying the maintainer's own bytecode cache; the consumer walks an installed directory where running the skill once has created its own. Neither side has a git to ask which files are the collection's, so the two can agree only through one explicit list, defined once and used by both. Disagree by a single artefact and every skill with a script reports itself as Deviating forever — and a signal that is always on is a signal nobody reads, which would cost the Digest the only thing it is for. The consequence is written down rather than left implicit: *nothing on disk the collection does not carry* holds modulo those two patterns, and only those.

**A mismatch is Deviating, never *out of date*.** The comparison sees two states and no history. It cannot tell a Project copy that has fallen behind from a file the user edited an hour ago, and outside a lagging copy the local edit is the commoner cause. *Out of date* would name a direction the comparison does not establish, and would invite the user to accept a refresh without knowing it discards their own work — so every offer to re-copy says in the same breath that local changes are overwritten. The word the collection uses is Deviating, and the vocabulary carries the honesty so that no rendering has to remember it.

**A fallback Catalog establishes nothing, and no verb pretends otherwise.** ADR-0039 lets every verb fall back to the stored copy when the origin cannot be reached, and a report made from a stale list is still worth having. A freshness verdict made from one is not: those digests describe the collection as of the last Update, so a skill matching them may Deviate from what the collection carries now, and one differing from them may be exactly current. Select therefore reports no skill as deviating or as current when the list came from the stored copy, and offers no refresh on the strength of it.

Update goes further, and for a reason that is not about the digests at all: it cannot refresh anything, because the files themselves move through the transport from the same origin the Catalog could not be fetched from. There is nothing to copy. Comparing digests first would be theatre — a careful decision about which skills to refresh, followed by a fetch that cannot happen — so the honest outcome is the one reported: the collection could not be reached, nothing was refreshed, `catalog_refreshed` is false, run it again when it can. This is ADR-0037's shape applied to a second kind of action: a fallback degrades the report and never touches the disk.

The premise that the Manager has no Catalog-carried Digest is amended by ADR-0130: it remains outside the Catalog's Skill entries, but a top-level publication Digest covers its directory except the recursively generated Catalog. Update still stages it because that Digest cannot establish full-tree identity; after acquisition, a fully identical candidate is proven directly and not republished.
