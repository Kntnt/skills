# Observed usage joins a recommendation by model and portable deliberation

ADR-0156 settled what a Usage Record is — what one finished ordinary session cost and how long it took on one Seat, carrying no verdict and entering no frontier — and #224/#225 gave it a store and a Harness-specific reader that fills it. Nothing read it back. `recommend`, `chart` and `compare` answer entirely from derived frontiers, which are quality: judged runs grouped into points, with Wilson bounds and cost means attached. A Usage Record has no verdict and belongs to no Cohort, so it reaches none of that by design, and would sit in a store nobody consulted. Issue #226 closes that gap: the recommendation now says, beside what it knows about quality, what each Seat it names has actually cost and taken on this machine — without becoming a second, quieter selector.

The title's and this paragraph's claim is narrowed by ADR-0162: no Seat capture writes resolves a portable deliberation, so the join is the model alone and what the recommendation says beside its quality evidence is what each named model has cost and taken, with the deliberations behind each figure named beside it.

**The reader is a Skill-owned module, called only after a decision exists.** `scripts/usage_evidence.py` ships beside `route.py`, `context.py` and `capture.py` under `skills/models/model-selector/scripts/`, not in the Collection Library: nothing outside this Skill's own `recommend`, `chart` and `compare` renders this section, so there is no second consumer the Library exists to serve yet. Its one public function, `usage_by_seat()`, is called from `SKILL.md`'s own prose — the same "Interface" posture `route.py`'s `recommend()` already has, a Python function with no CLI wrapper, glued together at render time rather than piped through a subprocess — and it is called only after `route.py`'s selection core has already returned a decision, never from inside making one. "A Usage Record never chooses" is therefore a property of where this module is called from, not a rule every caller of `route.py` has to remember to uphold; `route.py` itself is untouched, and so is `context.py`'s `_commercial()`, which keeps returning every commercial dimension unconditionally null exactly as it did before this record — that emptiness was never about Cohorts, and this record adds no explanation implying otherwise where none is needed.

**The banner is untouched; a separate, self-provenanced section carries usage instead.** The banner's evidence classes, confidence words, and missing-evidence reasons are pinned verbatim across `route.py`, `references/pareto-selection.md`, `SKILL.md` and two regions of `tests/test_model_selector.py`; they classify the recommendation's own quality evidence, and a Usage Record is not that. Folding one clause about usage into that pinned text would be a four-place synchronized edit for a sentence answering a question the banner does not ask. Instead, `recommend` emits a section titled `Observerad förbrukning` after the banner and any experiment brief, `chart` and `compare` add the same figures as columns to their existing table, and both carry their own provenance: the Usage Record count and the earliest/latest instant behind each figure, stated per Seat rather than once for the whole answer.

The per-Seat provenance here is narrowed by ADR-0162: the count and the instants are stated per named point, and what stands behind them is one model rather than one Seat, so each figure also names the deliberations its own records carry.

**The join key is `(model, portable_deliberation)` — the coarsest identity every named point and every Usage Record's own Seat can supply.** `route.py`'s frontier-neighbor entries (`_frontier_audit`) carry only `model` and `portable_deliberation`, never the finer fields — `channel`, `surface`, `native_deliberation`, `adapter_id` — the selected launch happens to carry too; widening the frontier audit to carry them would touch the selection core's own output shape for a field this ticket's own decision 2 says must never feed selection. A Usage Record's own Seat is finer than that for a session's own main turns, and coarser for a delegated subagent's: `session_records.py` reads a subagent's exact model and native deliberation control from Claude Code's own transcript, but never its channel, surface, adapter or serving mode (#225), so those stay an explicit `null` on every delegated Seat capture writes. `(model, portable_deliberation)` is the only pair both sides can always name, so every named point is matched by exactly this pair — the selected launch included, even though it happens to carry more — because matching a finer key for one row and a coarser one for another would make one table's record count mean two different things. A Usage Record whose Seat carries no resolved portable deliberation at all — every delegated Seat capture writes today — matches no point and is absent from every row's count. That is a known, stated limitation of what #225 resolved, not a silent gap: a future ticket that gives a delegated Seat a resolved portable form widens what this reader can match without changing how it matches.

This paragraph is narrowed by ADR-0162: no Seat capture writes resolves a portable deliberation at all — not only a delegated one — because ADR-0160 removed the argument that once supplied it, so the pair matched nothing and the join is the model alone, with the deliberations behind each figure named beside it.

**A mean is reported only where every contributing record carries it, and a category is read from the data rather than a list held here.** `routed_observations.py`'s own `_mean` already refuses to average a partial set of chain costs; `usage_by_seat()` applies the identical rule to a Seat's own token categories and elapsed seconds, so a category one Usage Record never measured stays unmeasured for the point rather than silently averaging over fewer records than the count states. (The unit is narrowed by ADR-0162: the rule is unchanged, but the categories averaged are one model's, across every deliberation its own records carry.) The token category set itself is the union of what the matched records actually name, not a list copied from `session_records.py`'s own `TOKEN_CATEGORIES`: that tuple is Harness-specific and belongs to the Collection Library reader that derives it, and a second copy here would be exactly the kind of duplicated field list ADR-0067 already forbids a ticket to write about a sibling that can still change it. A category the Harness starts naming tomorrow surfaces here the moment a Usage Record carries it, with no edit to this module at all.

**What this costs.** A recommendation, a chart, or a comparison now depends on one more small module, and a delegated Seat's own usage is invisible to it until a later ticket resolves #225's own limitation on delegated Seats. In return, a week of ordinary work answers the half of every routing decision this Skill could not measure before today — what a Seat has actually cost and taken — without touching the selection core, the pinned banner, or a single frontier, quality, or cost figure it already reports.

What this paragraph prices is narrowed by ADR-0162: no Seat capture writes resolves a portable deliberation, delegated or not, so what a week of ordinary work answers is what a model has cost and taken rather than what a Seat has.
