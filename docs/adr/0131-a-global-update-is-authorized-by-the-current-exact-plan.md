# A Global Update is authorized by the current exact plan

Three agent-initiated Global updates on 28 August exposed one missing boundary in the Manager's two-phase interface. One installation was embedded in a broader repair mission, another was repeated after later findings changed what needed repair, and a third was requested by an agent-authored handoff. None began with the current user invoking `/kntnt update --yes`, and none received a new response after showing the complete mutation it was about to perform. The existing prose said to plan and ask, but `apply update` accepted a bare internal call, so surrounding intent could silently become collection-wide authorization (issue #188).

**A real Global Update is authorized only by the current Invocation Envelope or by a later response to its complete current plan.** Formal `--yes` is authorization in the Invocation Envelope itself and keeps ADR-0029's collection-wide meaning: no later question is asked and every yes-or-no question is answered yes. Without that flag, the agent renders every Skill to refresh, every new entry a yes answer Enables, every Withdrawn Skill to remove, and every target directory, then waits. Only a user response arriving after that exact display authorizes Apply. Contextual Instruction, Conversation Context, a response or instruction remembered from earlier in the task, a broad repair request, and an agent-authored handoff provide no authorization, however strongly they ask for a repaired machine.

**The engine binds authorization to the complete plan before the first write.** `plan update` resolves canonical payloads containing the layer, refreshes, already-current Skills, removals, Catalog reachability, and target directories, with one opaque identity for the answer that accepts the proposed Enablements and another for the answer that leaves them Disabled. The plan command remains read-only. A real Global `apply update` requires the identity matching its `--yes` answer, resolves the complete plan again, and refuses a missing, incomplete, contradictory, or changed identity before transport acquisition, Catalog replacement, publication, teardown, or any other write. The identity does not authorize anything by itself: the agent passes it only after the current Formal Invocation supplied `--yes` or the user supplied the later response. A changed plan starts the interaction again; the old answer is not carried forward.

**Dry runs remain outside the gate.** Their Apply half executes inside ADR-0042's discarded Sandbox, so there is no real Global mutation to authorize and no confirmation is required. Project Update is unchanged by this record: the incident and the Manager self-refresh boundary are Global, and widening the new internal gate would decide a separate interaction without evidence.

The internal refusal is deliberate even though the Skill normally calls Apply correctly. The engine is the Collection's deterministic seam (ADR-0050), and an interface whose safety depends entirely on every calling agent remembering why it was entered is not a safety boundary. Requiring the current identity makes a bare Apply from a repair, verification, or handoff fail closed; recomputing it makes an approval stale as soon as any planned fact changes.

This decision narrows ADR-0029's statement that refresh verbs are not gated by `--yes`: the public Update invocation still does not require that flag, while its internal real Global Apply now requires plan-bound authorization supplied either by the flag or by the later response. It extends ADR-0045's structured renderer boundary: the payload now carries the complete mutation and its identity, and the agent still owns the question. It strengthens ADR-0047's before-write rule from *the question was answered* to *this exact complete plan was answered* for Global Update. It extends ADR-0050's one deterministic seam with the identity check that makes direct Apply safe.

What this costs is another opaque value between Plan and Apply and a mandatory re-plan whenever targets or files change while the question is open. The identity proves plan equality, not human authorship; freshness remains an agent obligation because a non-interactive script cannot observe a conversation. That division is explicit rather than accidental: the engine refuses a missing or different plan, while the shipped agent guide refuses to treat context, memory, or another agent's prose as the user's later response.
