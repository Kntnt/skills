# The finished session's own record is read once, at the hook that ends it

ADR-0090 forbade a transcript scan on the hook path, and it was right about the path it was describing: the synchronous hook that runs inside somebody's session, on every lifecycle signal, must stay local, bounded, and fail-open, because a capture that breaks a session is worse than no capture at all. What that paragraph did not anticipate is a session's own last such invocation being a different thing from every one before it — `SessionEnd` and an error signal happen once, after the work they describe is already over, and reading a bounded amount of that work's own record there costs the ongoing session nothing, because there is no ongoing session left to cost. Issue #225 needed exactly that distinction: capture had been fingerprinting every session against a Seat argument supplied once at opt-in, a guess that goes stale the moment a user changes model or effort, because no lifecycle payload ever carried either — Claude Code's own hook payload, like every other Harness's, names a session identity, a transcript path, and a working directory, and nothing that could answer what actually ran. The fix is not to open that question up during the ongoing session; it is to notice that Claude Code already keeps its own answer, written down as it goes, and that the one hook invocation with nothing left to protect is exactly the one already positioned to read it.

**The per-turn hook path is unchanged.** `SessionStart`, a stop, a subagent stop, and an idle signal read nothing but their own payload, precisely as ADR-0090 requires: local metadata I/O, no network request, no model call, no test run, no repository-wide hashing, and, explicitly, no transcript read of any kind from any of them. `test_the_hook_path_is_local_only_and_bounded` keeps asserting the same absences it always has — no `subprocess`, no `threading`, no `asyncio`, no `time.sleep` — because nothing this record adds needed any of them: the read that follows is ordinary local file I/O, run inline, inside the one hook invocation already reached only once a session has ended.

**The session's own last invocation may read that session's own finished record.** `SessionEnd` and `session.error` are not a second lifecycle signal added by this record; they are the two moments `_hook` already routed to `_finish` before this record existed, now given one more thing to do there before anything is appended: ask the Collection Library's session-record reader for the Seats and usage the Harness's own record supports, and use that answer in place of whatever the session's lifecycle signals had gathered on their own where it can be read at all. Nothing is scheduled, queued, or deferred to a later pass — issue #224 already removed every queue capture had, and this record adds none back — so the read is exactly as inline as the rest of `_finish`, and exactly as bounded to the one invocation that was already there.

**The read is bounded to that one session's own files, and nothing wider.** Claude Code's record of a session is a transcript and, where the session delegated work, a companion `subagents/` directory beside it, one file per subagent; the reader opens exactly those — the transcript the caller's own payload named, and that transcript's own companion directory — and nothing else. No encoding is derived from a working directory, no other session's files are ever opened, and no session identity found inside a line is trusted over the file the caller already handed over: the path comes from the lifecycle payload, which already carries it, so the reader computes no location it was not given. `PAYLOAD_ALLOWED` in `scripts/capture.py` gains `transcript_path` for exactly this, alongside the allow-list decision 2 of #225 already names — it is read to open the record and retained nowhere a persisted draft or a Usage Record can be read back from, discarded within the single hook invocation that uses it.

**The read is field by field onto an allow-list, applied to a richer source.** A transcript line carries a whole assistant message, a whole set of tool arguments, and a whole working directory; the reader takes four things from it and nothing else — the model, the deliberation control named beside it, the token categories the usage block counts, and the instant the line was written — the same boundary `references/run-capture.md` already states for a lifecycle payload, applied here to a source that carries far more than a payload ever did. A subagent's own turns are counted against a Seat of their own, carrying the model and deliberation the record actually names for it and an explicit null on every field the record cannot describe — channel, surface, adapter, serving mode — because those describe the session's own surface, not a subagent's, and the main Seat's answer is not the delegated Seat's to lend.

**A record that cannot be read is an absence, applied here to the read itself.** ADR-0156 already said a Usage Record's own measurements stay an explicit null where the environment exposed nothing; this record applies the same rule one layer earlier, to the read that would have produced them. A missing transcript, a truncated or garbled line, a subagent directory that does not exist, a file that will not parse at all — every one of these leaves the session-record reader answering with nothing, and `_finish` falls back to exactly what it would have written before this record: whatever the session's own lifecycle signals established, one Seat per window they opened, nulls where neither a payload nor the opt-in ever named one. Nothing here raises, and nothing here loses a row over a record that was never there to read.

**A Seat named once at install time was a guess about the one dimension being measured.** The opt-in `--seat` argument answers a Skill that could not yet ask the Harness what actually ran; it remains the right answer for a Harness this reader does not yet open — Codex, OpenCode — and the right fallback for a session on Claude Code whose own record could not be read, but it is no longer the primary source for either field it was ever least trustworthy about. `capture status` names, per Harness, whether that Harness's own finished record can supply measurements at all, so a gap here is something the user is told rather than something the store's own emptiness leaves to be discovered.

**This record narrows ADR-0090's hook-path paragraph.** The paragraph beginning "The hook path is fail-open, bounded, and local" stands for the per-turn path exactly as written, "no transcript scan" included; what it did not yet distinguish is that a session's own last invocation is not that path; it is a one-time read of a bounded, already-finished record, and the boundary that now protects a Usage Record from that record's own content is the allow-list this record and `run-capture.md` describe together, not a blanket refusal to ever look. This record narrows ADR-0090 in exactly that one place, and no other paragraph of it.

**What this costs.** Capture now depends on a second small module in the Collection Library, and a session on a Harness that module does not yet support measures exactly as it did before this record: from its lifecycle signals and the opt-in seat alone, with `capture status` naming that gap per Harness rather than leaving a store of rows that simply never populate. A session whose finished record can be read pays one bounded file read, at its own end, for what used to cost nothing and measure nothing true; a session whose record cannot be read pays nothing extra and loses nothing it already had.
