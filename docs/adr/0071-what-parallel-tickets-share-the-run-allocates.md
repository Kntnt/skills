# What parallel tickets share, the run allocates

Worktrees isolate the files a ticket edits, and nothing else. Three overnight `/orchestrate` runs supplied the field evidence for what that leaves uncovered. Two runs minted duplicate record numbers: two tickets each created a decision record under the same next-free number with different filenames, git merged both sides cleanly, and the repository would have carried two records answering to one number — no conflict, no red gate, nothing for the repair path to even see. Three tickets in one run each appended a changelog entry, three conflict-free merges later one release section held two `### Changed` headings. Builders and verifiers in sibling worktrees independently chose the same scratch log path for the same long-running gate, so one nearly read another's exit status as its own; a verifier's cleanup glob deleted the engine's own state file from the shared scratchpad root. And in a third repository, whose ground rules make every ticket append to the same guide and the same worklog, three of eight tickets collided at integration — every collision in those files, none in code — and the repair-and-reverify machinery spent 626,038 tokens, nineteen percent of the run, settling Markdown appends. The repair path (ADR-0055) is the wrong tool twice over here: where git merges cleanly it never fires, and where git conflicts on an append it fires at full price for a collision that carries no disagreement.

**So what every ticket in a wave may reach for, the run hands out before the wave builds, and what every ticket would append to, the run appends itself.** Three allocations:

**`isolate` reserves each ticket its numbers.** A directory of records named by number — files matching the four-digit-prefix pattern the collection's registries share — is a numbered registry the engine can find deterministically, which keeps the reasoning behind the one seam (ADR-0050). For each registry, the ticket's reservation is the next free number offset by the ticket's place among the wave's claims, so no two tickets in flight hold the same one; the brief carries the reservation, and a builder that creates a record takes its reserved number rather than reading the directory for a next-free that three siblings are reading at the same moment. A reservation unused expires with the wave and becomes a gap, which the numbering already treats as legitimate: next free means one above the highest, not the lowest hole (ADR-0067). A ticket needing more numbers than its reservation has found a decision its brief did not close, and stops as it would on any other (ADR-0070).

**Files every ticket appends to are the run's to write, not a builder's.** The orchestrator names them at run start — the changelog above all, plus whatever the repository's own ground rules make every ticket touch, a reading that is judgment and therefore the orchestrator's rather than the engine's. The briefs carry the list. A builder with an entry for such a file writes it as a note in a well-known place in its own working tree instead, committed with its work; at integration the run applies the wave's notes to the real files in integration order, one commit's worth at a time, and sequential appends cannot collide. The wave check then reads the result (ADR-0072), which is what makes this honest: the run's own appends pass under the same verification as everything else on the branch.

**Scratch is private by construction.** `isolate` answers with a scratch directory of the ticket's own alongside its working tree and branch, every brief confines its subagent to the working tree and that directory, and the engine's state file lives where no subagent is sent. Two subagents that cannot name the same path cannot clobber each other's logs, and a cleanup glob has nothing of the run's to catch.

**The repair path stays, as the backstop it always was.** A repository with an append convention the orchestrator failed to name, or two tickets that genuinely edit the same paragraph, still collides at integration and is still repaired, reverified, or rebuilt under ADR-0055. What this record removes is not the machinery but the traffic: the collisions that carried no disagreement stop being collisions at all.

**What this costs.** Reservations that expire leave gaps in the registries, which the numbering rules already absorb. The orchestrator takes on bookkeeping that was previously nobody's, and a run-owned file is one more thing its briefs must say plainly. And the note-then-apply step means a changelog entry lands one step later than the work it describes — inside the same wave, before the wave check reads it, but no longer inside the builder's own commit.
