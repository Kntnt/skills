# A findings report is written in the language of the text

Two runs of `/redline` over the same Swedish Text Artifact, in the same session family and on the same day, resolved `sv` and reported on it in different languages: the review-only run wrote all fifteen of its findings in Swedish, and the run with one correction to spend delivered the Swedish text and wrote its findings in English. `/unslop` reproduced the split with the polarity reversed — twenty-nine English findings on a review-only run, six Swedish ones on the run that corrected. Neither Skill disobeyed anything. The shared delivery contract settled the language of exactly one response element, the short no-change status, and both Skills obeyed that rule on every Swedish fixture that produced one; the findings that accompany a delivered artifact were left for each run to decide, and each run decided differently (issues #145, #111, #109).

**A report about a text is written in the language of that text, and never in the language of the invocation.** This is the answer the no-change status already had, and it is the same answer for the same reason: a report about a text is read by the reader of that text — here, the person who has to finish the work the correction budget did not. The invocation's language records how the run was asked for; the artifact's language records what the run is about, and a findings report is about the artifact. Taking any other answer would leave the two halves of one response in two languages, or reopen a rule that has been right since it was written.

**It is stated once, in the shared contract, rather than in the steps of whichever Skill was caught at it.** The contract already owns where a result goes, whether a source may be replaced by it, and what an unchanged run returns (ADR-0091, ADR-0076), and this is the same kind of question about the same response. The evidence that it belongs there rather than in `redline/SKILL.md` is that the issue was filed against Redline and Unslop had the identical gap before anything was written — a fix in one Skill's steps would have left the second exactly where the first was found, and the third Skill to report findings would arrive with no answer at all. A Skill delivers by the contract, so a Skill added later inherits the rule without knowing it exists. Nothing in ADR-0091 is falsified: its three questions and every answer it gave them stand entire, and this is a fourth question the same document is the place to answer.

**What this does not reach.** Not which findings are reported or how — that is each Skill's own contract. Not the no-change status, whose rule is untouched in the words that stated it. And not the language a run *resolves*, which each editorial Skill settles through its own precedence ladder before any of this applies: what is settled here is which of the languages already in play the run writes its own words in.

## Considered options

**The language of the invocation** is the reading a harness suggests, and it has one real argument: the operator who typed the command is the one waiting for the answer, and a report they cannot read is a report that helps nobody. It loses on who the findings are for. A findings report is not a status line about the run; it is a list of unfinished editorial work in a specific text, quoting that text, naming passages in it, and addressed to whoever opens the text next. Answering it in the invocation's language would also make one response bilingual whenever a Swedish artifact needed no work in one place and further work in another, or else force the status rule open to keep the two halves together — and that rule is not wrong.

**A sentence in each Skill's steps** was the smaller diff and the shape the issue first proposed. Unslop is the evidence against it: the same gap was already there, in a Skill nobody had looked at yet, and was found only because a second evaluation happened to run. A rule written where the defect was reported is a rule the next Skill has to be caught before it learns.

**Leaving it to the run** is the option that was in force, and it is what produced two languages for one text in two invocations a day apart. A question a contract leaves open is not open in practice; it is answered per run, invisibly, by whatever the surrounding context happened to make salient.

## Consequences

Every Skill that reports findings beside a delivered artifact inherits the answer by delivering through the contract, Redline and Unslop today and any successor without an edit. Both manpages tell the reader the same thing they were already told about the no-change status, so the person deciding whether to run the Skill knows what language the output arrives in.

The cost is borne by the operator who does not read the artifact's language, and the contract offers them no override. They receive a report they may have to translate, and it can be fifteen findings rather than the one line a status is — this is the same trade the status rule made, at greater length. The alternative costs more: it would put the reader who has to act on the findings at the mercy of how the run happened to be typed.

The second cost is the one ADR-0091 already named for this document as a whole. There is no executable check that a run obeys the rule, only that the contract states it, that no consumer carries a private copy of it, and that both manpages say it. Whether a run actually writes Swedish findings for a Swedish text is visible only through the Skill's behaviour, which is to say through the evaluation corpus — which is where the split was found, and where the fix is confirmed or is not.
