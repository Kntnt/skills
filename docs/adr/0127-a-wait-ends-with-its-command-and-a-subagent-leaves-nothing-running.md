# A wait ends with its command, and a subagent leaves nothing running

An overnight run finished every ticket it had, delivered every verdict, and then would not stop reporting. One subagent had waited out the test suite by arranging a wait that could not notice the suite finishing — it could only wait out a fixed span and then read the log — and it had arranged several. Its work was committed and its report delivered; the waits were not. Each one that came to an end woke the run, the run answered the waking as though a subagent were behind it, and the answer arranged another wait before saying that the waking was stale. Nineteen were alive at once before anybody looked, all reading the same log for a suite that had exited long before, and stopping them one at a time made it worse, because a stopped child is itself a waking. Nothing was corrupted: the branch was clean, every verdict stood, and the account of the run was accurate. What it cost was tokens, an exit state nobody could tidy, and the maintainer's confidence that a finished run is finished (issue #151).

The rule behind it was not wrong, only half written. **A long command is waited on, not yielded to** came from the failure that costs more — a subagent ending its turn with the gate still running and nothing committed, which unattended is a dead run (issue #75) — and it is carried in one wording by every brief this Skill hands out, a carriage the suite enforces (issue #85). It says to start a wait. It never says the wait ends. Read literally, and a subagent with no other instruction reads literally, the obligation is discharged the moment a waiting mechanism exists and what becomes of that mechanism afterwards is nobody's. Three things then compound: the facility is deliberately unnamed, so the subagent invents one, and the obvious invention is the one implementation that cannot notice its command has finished; no brief said anything about what a subagent may leave *running*, only about where it may write, and a process is not a path; and in a Harness that wakes a session when a child stops, a leftover wait is not litter but a generator.

**The waiting rule gets its second half: the wait ends with the command it waits on, and no wait survives the turn that created it.** Stated in the same one wording, in every brief that carries the rule, by the mechanism the collection already uses for it — so the two halves travel together and neither can drift brief by brief. The obligation the rule already carried is untouched and stays first: the turn still may not end while the command runs, because that failure is the expensive one and nothing here may make it easier. What the second half adds is the shape of the mechanism rather than its name — wait with something that ends when the command ends, and where the only waiting available cannot tell that it has, bound it and end it yourself before reporting. Named as a property, the rule holds on a Harness whose waiting facility notices, on one whose does not, and on one nobody has written yet, which is what the neutrality records ask of every brief (ADR-0005, ADR-0030).

**Beside it stands a rule of its own reaching processes as the confinement rule reaches paths: whatever a subagent starts, it stops before it reports, and anything it deliberately leaves standing it names in its report.** It is a separate rule rather than a clause inside the waiting rule because what it governs is larger than waiting: a subagent starts processes for reasons the waiting rule never mentions, and a rule folded into waiting would reach exactly the leftovers that came from a wait and no others. It sits immediately after **Where you write.** in every brief, because it is that rule's other half — one bounds what a subagent may leave on disk, the other what it may leave running — and the pairing is what makes the second rule read as an extension of a boundary the subagent already accepts rather than as housekeeping. Every brief the reference directory holds carries it and none is exempt, which is the whole of the carriage decision: each of these briefs tells its subagent to run something and to wait on it, so each of them can leave a process behind, and an exemption would have to name a brief whose subagent runs nothing. The suite quantifies that over the directory rather than over a list, so a brief added later is inside the rule from the moment it exists.

**And the run accounts for what its subagents leave running rather than trusting each of them to have left nothing.** The step that dispatches and triages subagents says it: when one has finished or its stop has been triaged, whatever it started is finished with it, so the run looks for anything of its still running and stops it, reading the report's named exceptions rather than taking the absence of leftovers on trust. A waking that is only such a leftover — a command belonging to a subagent already accounted for — is swept rather than triaged, because there is no stop behind it to sort and dispatching that brief again would start another leftover in place of the one just cleared. That sentence is the cheap half of the answer and the one that matters: the failure recurred nineteen times in a single session without the run ever being able to say what was happening, and a run that can name the thing can end.

**The road not taken was naming the mechanism.** The shortest fix is to tell every subagent which facility to wait with, and it is the one thing the briefs may not do: a brief that names one Harness's tool is a brief that works on one Harness, and the collection's whole arrangement is one set of instructions many Harnesses read. Weakening the waiting obligation was the other tempting cheap fix — let a subagent that cannot wait safely end its turn — and it trades a bounded loop that wastes tokens for an unbounded silence that loses the night, which is the trade this collection already made once in the other direction. A run that inspects the process table was considered and left admissible rather than required: it is more than the defect needs, it is the kind of thing that is written for one Harness and quietly stops meaning anything on the next, and the stated obligation is what makes any such inspection an implementation of a rule rather than a rule of its own.

**What this costs.** Two rules now travel in seven briefs where one did, and every brief is that much longer at exactly the moment a subagent is deciding what its job is; the collection has priced that before and answers it the same way, by carrying the rule in one wording so the length buys identical obligations rather than seven similar ones. The second half of the waiting rule asks for a judgement no test can make — whether the waiting available *can* tell that its command finished — and a subagent that judges wrong and does not bound its wait leaves the same leftover, now against a rule instead of a silence. The run's account of leftovers is prose, so a run that reads it loosely sweeps something a subagent meant to leave standing; the report is where that is stated, and a subagent that leaves something standing without naming it has already broken the rule that would have protected it. And issue #75's record of the rule stays as it was written, stating what its evidence could show — this is the half that evidence could not.
