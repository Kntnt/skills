# A code sample is quoted material and produces no findings

Two runs of `/unslop` over one code-carrying article, alike in everything but the Correction Budget, disagreed about whether the prose inside its fenced Python block was the text. The review-only run located three of its fifteen findings inside the block — a docstring carrying four catalogue patterns, and two comments carrying one each — and drew its own boundary through the sample, repairing the prose and leaving the identifiers and the message string as the program. The correcting run reported ten findings, none of them inside the code, and gave the opposite reason: the block is source that ships in the real world, so it is verbatim material. Both preserved every byte of code, so nothing here was a preservation failure; what differed was what counted as a finding, and a finding is what the caller acts on. The correction brief's preservation clause named every sentence, fact, quotation, heading, piece of formatting and line of frontmatter and stopped short of code, and the anti-slop catalogue said nothing about code either, so the boundary was settled per run by whichever reading the run happened to reach (issues #149, #111).

**A code sample is quoted material rather than the text's own prose, and nothing inside one is a finding.** A fenced block, an indented block, and an inline code span are all read past rather than read against the rules, so a docstring, a comment, or a string literal inside one is neither reported nor repaired, however much it sounds like the prose around it. The document quotes a sample; it does not assert it. This sits beside the clause the correction brief already carried for quotations, and it keeps a pass that cannot run the program from rewriting the comments that explain it — a comment is answerable to the code beneath it, and an editorial pass holds none of what would say whether the rewrite is still true.

**The boundary is the sample, not the prose inside it.** The alternative shape — report a defect inside code but never correct it — was the one the review-only run improvised, and it leaves the same ambiguity one layer down: which strings inside a sample are prose, whether a log format string is text or program, whether an exception message is the writer's sentence. That judgement would be settled per run exactly as the outer one was. Drawing the line at the sample leaves nothing to settle, at the price of the occasional real defect going unreported in a comment.

**It is stated in every editorial pass, in one wording.** Unslop surfaced it, but Redline and Proofread state their preservation obligation in the same words and had the same gap; a rule written only where the defect was reported is a rule the next Skill has to be caught before it learns (ADR-0123). So the clause is carried verbatim by all three pass steps and by both correction briefs, whose preservation clause now names code beside the quotations and formatting it already named. Three Skills stating one rule in three wordings would be three answers a run may pick between, which is the disagreement this record exists to end. Proofread is included deliberately: a misspelling inside a code sample is a misspelling in somebody's program, and correcting it is the one change a mechanical pass must not make.

**Prose about code is untouched by this.** A paragraph discussing a function, naming its arguments, or explaining what it returns is ordinary prose and is read against the rules like every other sentence. What is quoted is the sample.

## Considered options

**Report but never correct** is the reading the `--max=0` run produced, and it has the honest argument that a comment is prose somebody wrote and a reader is entitled to know it sounds like a machine. It loses on the inner boundary. A pass that may report inside a sample has to say what inside a sample counts, and no answer to that is available to a reader who cannot run the program: the docstring is prose, the exception message is arguably prose, the log format string is arguably both, and the identifier is not. Every run would draw that line itself, which is the defect one layer down rather than a fix for it. It also splits the two Skills that correct from the one that only corrects: Proofread has no findings to report separately, so the option gives it no answer at all.

**Leaving it to the run** is what was in force. It produced six items of work in one invocation and a clean region in the next, over one text, with nothing written down that either run disobeyed. A caller who reviews first and repairs second gets a list that shrinks for a reason nothing explains.

**A flag** — a switch selecting whether code is in scope — was not seriously weighed. It offers the caller a choice between two answers where one of them is wrong, and it would have to be carried by three Skills and every one of their grammar surfaces to settle a question a sentence settles.

## Consequences

A run over a document carrying code reports the same findings whatever its Correction Budget, and none of them sits inside a sample. Each manpage says so, so somebody deciding whether to run one of these over a document full of samples reads what it will leave alone rather than discovering it. The suite holds the clause present in all three bodies, in both briefs, and on all three pages, and holds the briefs' preservation enumeration naming code.

The cost is the genuine defect that goes unreported: a docstring that opens with an empty flourish, a comment that inflates the importance of the loop under it. That prose is a person's to fix, and the pass says nothing about it. This is the same trade the preservation clause already made for quotations, where the material's own wording outranks the pass's opinion of it.

What no check can see is whether a run actually reads past a sample. The suite holds the contract stated; whether the behaviour follows is visible only through the evaluation corpus, which is where the split was found and where the fix is confirmed or is not.
