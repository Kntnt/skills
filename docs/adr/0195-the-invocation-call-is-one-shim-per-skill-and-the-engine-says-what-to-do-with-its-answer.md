# The invocation call is one shim per Skill, and the engine says what to do with its answer

This record settles what a Skill's body says before its first step. Until now it said three paragraphs: where the Manager is and what to install where it is not, the engine call with the payload on stdin and what to do with each of its three answers, and the shape of the JSON a valid form answers with. It now says one sentence — run the shim this Skill ships, with the payload on stdin, and do what it prints — because the shim finds the Manager and the engine's answer carries the rest. What the rule is — the sentence, the shim, the sheet — is stated in [`docs/rules/skills.md`](../rules/skills.md), which is the authority on it. This record argues rather than legislates.

It narrows two standing records. [ADR-0181](0181-the-invocation-grammar-is-executed-by-one-engine.md) moved the grammar into the engine and left the body to say where the engine is; the body no longer says that either. [ADR-0177](0177-what-a-skill-ships.md) puts anything several Skills run in the Collection Library; the shim is the one file that cannot live there, for the reason given below. Neither record is annotated: each is read as of its own date, as [`docs/rules/docs.md`](../rules/docs.md) says.

## Three paragraphs, read on every invocation, before the part that is the Skill

**The opening was uniform and it was large.** Thirteen bodies opened with the same 220 to 320 words: the location of the Manager beside the Skill or under a Global harness skills directory with `npx skills add Kntnt/skills` as the fix, `$LIBRARY` with `/kntnt update` as the fix, the engine call, the three exit statuses and what to do with each, the Capabilities to answer first, and the JSON's four fields with the Envelope contract the instruction is applied under. Every word of it was read into the session on every invocation, before the Skill's own steps, and every word was the same in every Skill. `docs/research/invocation-mechanics.md` had measured the previous preamble at a third of the small bodies; ADR-0181 cut what the model did and left what the model read nearly as long. The maintainer's judgement of the result was that it had become a monster, and that a Skill should open with what it is for.

**Nothing in those paragraphs was a judgement.** Whether `$HERE/../kntnt/` exists is a file test. Which Global directory a Harness keeps its Skills in is a table the Manager already ships as `harness-paths.json`. What to print when the engine refuses is *print it*. What the Capabilities are and where the Library is are things the engine knows before it answers. Prose that asks a model to do a file test is a script that has not been written, and a model doing it is a model spending a turn on a directory listing before it reaches the Skill.

## Where the location goes

**A body cannot name the Library, because nothing has found it yet when the body is read.** That is the one fact that shapes the answer. The contract every Skill executes lives in the Library (ADR-0177); the Library lives in the Manager; the Manager is beside the Skill when both were Enabled at one layer and under a Global directory when the Skill was Enabled for a Project and the Manager for the machine. Whatever finds it has to be in the Skill's own tree, and it has to be found by name.

**Three places were weighed.** Prose in the body, as it was: nothing to ship, and the cost is the paragraphs above, paid per invocation in context and in the model's turns. A reference file the body points at: the same words in the same context, one tool call later, and a per-Skill copy either way since the Library cannot hold it — nothing is shorter, only moved. A script per Skill: never read, one command, deterministic across layers, and its cost is a copy in every Skill and a list of Global directories that has to match the Manager's. The script wins on everything the maintainer asked for — the body focuses on its use, the extra file is as short as it can be because there is none, and what can be a script is one — and its cost is held rather than argued: the suite reads every copy against the one under `skills/agents/explain/` and fails on a byte's difference, and reads the shim's list against `harness-paths.json` and fails on a directory's.

**The copy is the exception to the Library rule, and it is the only one.** Ownership follows consumers because one authoritative copy is what a reviewer can diff; the shim has one authoritative copy too, and the suite is what makes the other fifteen the same file. A Skill that shipped a copy of anything else would be argued against on the same ground and would lose, because anything else can be found through the Library the shim reaches.

## The engine prints the sheet

**What a body used to explain about the JSON, the engine now says beside it, and only where it applies.** On a valid form the engine prints `Invocation read.`, then the directive to answer the Capabilities first where the Skill declares any, then the directive to read the Envelope contract — by its absolute path — where a Contextual Instruction was given, then `$LIBRARY` as an absolute path, then the reading as fenced JSON. A Skill with no Capability invoked without an instruction gets the reading and `$LIBRARY` and nothing else. The prose the body carried was written for every case at once; the engine writes it for this case, which is shorter in the common one and exact in the rare one.

**The sheet is the engine's and not the shim's.** The shim could have rendered it from the JSON, which would have left the engine untouched and put presentation in sixteen copies. The data and the words about it belong together in one file, the engine's tests run against the sheet rather than against a copy of a renderer, and the shim stays what its name says: a locator that hands stdin on and hands the answer back, adding a line of its own only where the engine could not answer — no Manager found, or a Manager old enough not to know `invoke`, which argparse reports on stderr and the shim turns into `/kntnt update`.

**The JSON stays, fenced, so that nothing downstream changes.** Every Step that reads `flags`, `operands`, `path` or `instruction` reads them where it did. The Manager's own body, which calls its engine directly because it is where the engine is, continues from the same JSON. A body on the previous form that says *continue from the JSON* still can.

## What it costs

**A copy in every Skill, and a list in every copy.** Sixteen identical files change together or the suite says so; the 66 Global directories in the shim are the Manager's table read into a tuple, and a Harness added to one is added to the other or the suite says so. The list is the price of the shim finding a Manager it has no other way to ask about, and it is paid in a file nobody reads.

**One more process, and one thing the model still resolves.** The shim is one `uv run` that starts another; the second is the one every body already paid for. `$HERE`, the directory holding the `SKILL.md`, is still the model's to know — the Harness tells it — and the one sentence still says what `$HERE` is, because a fresh reader of one Skill has no other place to learn the name.

**At this record's date, one Skill is on the form.** `/explain`, written this day in place of `/tldr` and `/brief`, was the pilot; the maintainer tested it and approved the form. Thirteen bodies still carry the previous opening, the rules module describes both, and the suite holds each body to the form its own files say it is on. Moving the thirteen is one change under one invariant, a Solo Ticket like the move ADR-0181 deferred, and it takes the previous form out of the module and the suite with it.
