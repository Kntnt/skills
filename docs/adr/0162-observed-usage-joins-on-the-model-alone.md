# Observed usage joins on the model alone

ADR-0161 settled that a Usage Record reaches a recommendation through a join on `(model, portable_deliberation)`, the pair it judged to be the coarsest identity every named point and every Usage Record's own Seat could supply. That premise was false by the time both halves of it shipped. ADR-0160 removed the only thing that ever put a portable deliberation on a Seat — the `--seat` argument and the configured-seat fallback a user answered once at opt-in — because Enabling the Skill became the whole gesture and nothing is supplied at installation any more. What replaced it, the Collection Library's `session_records.py`, reads a finished session's exact model and the Harness's own native effort control out of the transcript, and there is no portable form in that record to read. Every Seat capture writes therefore resolves `portable_deliberation` to `null`, on every machine. The two decisions were built in the same wave, each verified alone, and the contradiction existed only on the branch that carried both: the reader shipped matching nothing at all, and the section, the columns and the Interface were inert.

This record narrows ADR-0161.

**The join key is `model`, and nothing finer.** It is the one field a frontier neighbor, a selected launch and a real Usage Record's own Seat all carry. Deriving a portable level from the native control the record does carry is not available: ADR-0104 already refused to map an existing portable value onto an observed seam's behaviour, that being a calibration claim nobody has verified, and nothing about this reader makes it verifiable. Restoring an answer at installation is refused by ADR-0160 for the reason that record gives.

**What the join costs is named in the answer rather than left to be inferred.** Two named points that differ only in deliberation share one model, so they draw the same records and report the same figures; a chart table can therefore carry one figure twice, against two rows that are not the same Seat. Each summary answers that with `deliberations`: every portable deliberation the matched records actually carry and how many carry each, unresolved ones counted under `null`, which is where every record capture writes today lands. A reader can see when one figure stands for a mixture. That is the honest form of what ADR-0161 was protecting when it refused to let one table's record count mean two different things — the count means one thing, per model, and says what it is made of.

**Nothing else about ADR-0161 moves.** The reader stays a Skill-owned module called only after a decision exists, so a Usage Record still chooses nothing; the banner is still untouched; a mean is still reported only where every contributing record carries it; the token category set is still read from the data. `route.py`'s selection core is not touched by this record either.

**What this costs.** A figure is now per model rather than per Seat, which is less precision than ADR-0161 intended, and a routing decision that turns on deliberation cannot read one of these numbers as settling it. Against that: the figures exist. A week of ordinary work now answers what a model has actually cost and taken on this machine, where before this record the section it fills could not have returned a single row. A later ticket that gives a Seat a resolved portable form — by reading one the Harness comes to expose, not by deriving one — narrows the join again without changing where it is made.

A test now drives capture's own hook and reads the result back through the reader. Every earlier test handed the reader a Usage Record it had shaped itself, in a form capture no longer produces, which is why a full suite stayed green over a feature that could not work.
