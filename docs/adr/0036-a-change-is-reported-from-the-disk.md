# A change is reported from the disk, never from the plan

Enable, Disable, and Update hand the work to the transport and used to report the plan they had just handed over, treating a zero exit code as proof. It is not one. A transport that removes nothing and exits 0 is indistinguishable from one that did the work, and that is not hypothetical: a Disable of two skills reported both as changed, exited 0, and left both on disk, where the next Status contradicted it (issue #7).

So every verb that changes what is on disk reads the disk afterwards and reports what it finds. The check is the presence test Status already decides Enabled with — the same layer, the same directories, no cache and no second notion of presence — and it sits in the two wrappers that ask the transport to place and remove files, which return the outcome rather than raise on it. Returning is what lets a run where one skill landed and another did not report both; a wrapper that could only raise would have to throw away the half that worked.

What presence can see, it sees completely: a skill that was to be placed and is not there, or was to be removed and still is. What it cannot see is a refresh that overwrote nothing, because the files were already in place either way. Update is verified on the same test regardless, which catches the case that matters — a Harness detected since the last Enable, which the refresh is supposed to reach — and a stronger check would mean a second notion of presence, which is exactly what this record forbids.

One payload shape carries this for every verb: `intended` is what the verb set out to do, `confirmed` what the disk showed afterwards, and `failed` the rest, each entry naming the skill and the directories that contradict it, because *where to look* is what a user can act on. Any entry in `failed` exits non-zero, including when other skills succeeded — a run that half worked is not a clean run — and the payload is still emitted, since an exit code alone says nothing about which skill or which directory.

ADR-0003 already made the disk the truth for deciding what to do. This is the same rule applied to reporting what was done. It is a safety net rather than a fix for any one transport defect: the specific defect behind issue #7 is unreachable once every call names every present Harness (ADR-0035), and this record is what converts the next silent failure — from any cause — into a legible error. It matters most for a verb that removes the Manager itself, where there is nothing left afterwards to contradict a false report of success.
