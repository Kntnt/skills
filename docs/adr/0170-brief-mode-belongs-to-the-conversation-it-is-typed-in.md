# Brief mode belongs to the conversation it is typed in and persists nothing

`/brief` carried two jobs. A bare invocation reframed the preceding answer for the person who owns the outcome; `on` and `off` adopted the same perspective for later replies, in a session scope or a `--user` scope written as a managed block into the Harness's global context file. The reframing job has left for `tldr` (ADR-0169, issue #250), and what is left is the mode. Almost all of its weight was the persistence around it — the target file, the block and its markers, the confirmation before writing, the staleness comparison, the two-blocks-in-one-file case, `--user` and `--yes`, and a `status` that had to report which of two scopes won: 28.5 KB across eight files against a 2.2 KB payload (issue #251).

**Brief mode is adopted for the conversation it is typed in, and nothing is written anywhere.** `/brief on` holds until `/brief off` or until that conversation ends; `/brief status` reports which of the two it is in. There is no settings key, no style file, no block in a context file, and no scratch state, in any Harness. Two windows open on the same project hold independent states, another project is untouched, and no later session starts with the mode on. With nothing persisted there is no target to show, nothing to confirm before writing, nothing that can go stale against `mode.md`, no marker without its pair, and nothing to remove when the conversation ends.

**The reason the scope is the conversation is that the mode is a property of the work in front of you, not of the person.** A window where a long design discussion is running wants the perspective; a window where a build is being driven wants the file-level detail the perspective removes. Both are open at once, on the same project, and a scope wider than the conversation forces one answer on both. That is the defect the `--user` scope could not avoid: the mode became a standing default nobody chose per conversation, and turning it off in the window that wanted detail was a write to a file every other window read.

**An Output Style cannot carry this, and that is now on the record so it is not proposed a third time.** Issue #43 asked for one, ADR-0048 declined it, and this ticket's own body proposed it again. Beyond that record's three reasons — only one Harness has them, the route into them moved, and they are read once at session start so the flag cannot change the conversation it was typed in — there is a fourth that is decisive here. An Output Style is read from a settings file, which is one file per user or per project: two windows on one project read the same file and therefore get the same state, and giving them different states is the whole requirement. The managed block has the same defect from the other end — it lives in the global context file the Harness loads in every session, so both windows share it and every later session inherits it.

**A bare `/brief` is an invalid form rather than a toggle.** It is refused the way every other invalid form here is: what was wrong, the root `## SYNOPSIS`, a pointer at `/brief --help`, and nothing changed. `delegation` toggles its session on a bare invocation, but that Skill's bare form has one obvious reading and this one's does not — `/brief` was the reframing command for as long as this Skill has existed, and a user typing it out of habit would silently get a state change instead of the answer they meant. Every form of this Skill now names the state it produces, and the muscle memory is caught by the root page's `SEE ALSO`, which names the sibling the reframing job went to.

This record **supersedes ADR-0080**'s claim that one policy governs both forms while time still distinguishes them. The two forms are two Skills now, each with its own perspective text: `mode.md` here is the standing instruction and nothing else reads it, and what that record decided about selecting for the owner of the outcome before compressing words is exactly what this one's `mode.md` still says. It also **narrows ADR-0048** from two scopes to one. What that record decided centrally is upheld and is why this decision is possible at all: the mode is a portable standing instruction rather than an Output Style, `mode.md` is the single source of truth, and it takes effect on the turn that switches it on. What is narrowed is everything that record built on top of it: the persistence into a context file the Harness loads, the two scopes `session` and `user`, and the paired-argument form that only existed because `--user` needed a state beside it. Each of those three claims carries the answering pointer beside itself (ADR-0075). Its reasoning for refusing a `project` scope survives the narrowing intact and now reaches one scope further: perspective and density are how one person likes to read one piece of work.

**What this costs.** A user who wanted the mode on by default now sets it in their own configuration, and the Skill will not do it for them — which is the honest division, a standing default across sessions being a preference the user owns and not a thing a Skill should be writing into a hand-curated file. Two windows that should agree have to be told twice. Compaction can drop the instruction, and nothing detects that: the repair is retyping `/brief on`, which is ADR-0048's own argument for writing no session state file, now applied to the only scope left. And the Skill can no longer answer *is it on somewhere else* — `status` reports this conversation, because this conversation is all there is.
