# An unattended pass may learn what a model can do, never what it costs

Model Selector's discovery was complete and correctly designed, and nothing ever ran it. `update` revalidates provider model and release indexes on a cadence, fetches detail pages for newly discovered version keys, and reports a newer family version while leaving it excluded until the user adopts it; `status` reports due sources against the current date. Every turn of that loop was manual, so a cadence of seven days described when a source *became* due and nothing acted on it. Measured on the maintainer's own machine, capture had been writing evidence continuously for the twelve days since the profile was last written, while the model release index had found a new main-seat model nobody was told about and the benchmark index that could have scored it sat unfetched (issue #247). The failure is not an empty answer; it is a confident answer computed over a list nobody had revisited.

**The seam already exists, and this rides it.** The Skill installs an owned lifecycle integration into every supported Harness the moment it is Enabled (ADR-0090, ADR-0160), and that integration is already invoked once at a session's end. So there is no daemon, no cron, no second opt-in, and no second registered entry: the refresh is dispatched from *inside* the session-end invocation `scripts/capture.py` already answers, through the same by-path loader that module already reaches its other dependencies with. Enabling the Skill remains the whole gesture and Disabling it remains the whole undo.

**What runs is a new module, and it interprets nothing.** A typed `update` is prose executed by an agent — semantic judgement over pages, not parsing — so nothing shipped could ever perform it unattended, and pretending otherwise would have been a feature that goes green and is inert. `scripts/refresh.py` does one thing instead: validator-conditional retrieval, ETag or Last-Modified with a content hash as the fallback, of the non-commercial sources that are due. No page is parsed for meaning, no model is started, and no evidence beyond the source's own state is written — no capability fact, no benchmark fact, no evidence record, no derived frontier, and no adopted model. **The unattended pass establishes *that* something moved; a person's next `update` establishes *what*.** That split is what makes an unattended fetch safe to ship at all.

**Maintenance stops at the money, and the stop is by `kind`.** An unattended fetch that mis-parsed a commercial page would write a wrong fact that silently reshapes which model wins, and the user holds knowledge those pages do not state — what a plan actually costs and how a quota actually behaves. So `model_release_index`, `model_detail`, `capability_source` and `benchmark_release_index` may be retrieved unattended; `commercial_terms`, `gateway_rate_card`, **and any other value, including one absent or unreadable, are treated as commercial** — not retrieved, their rows not written at all, and reported as due until the user runs `update`. The invariant this buys is the whole design: *an unattended pass may change what a model is judged capable of, never what it is judged to cost.* Failing closed is what makes a `kind` added later safe on the day it appears, before anybody has taught this pass about it.

**This record narrows ADR-0090 in exactly one phrase, and keeps everything else that record protects.** The hook path is no longer *no network request*; it is *no model call, and network only as bounded conditional metadata retrieval under a stated budget*. Fail-open, no long-lived work, no test run, no transcript scan, and every failure swallowed all remain true of the new path, and capture itself stays exactly as inert as it was — the shipped test asserting that `capture.py` reaches no network, no process and no concurrency machinery is kept, and `refresh.py` gets its own pinning what it may and may not import and that it starts no model. The moment this runs is the one ADR-0158 already distinguished: the session's own last invocation, reached once, after the work it describes is over.

**"Delays no session teardown" is a number, because an absolute is unbuildable.** Doing this without delay would need the detached or threaded work ADR-0090 forbids, so instead: one connection at a time, no retries, and a total budget of two seconds across the whole pass, enforced in-process against a monotonic clock rather than by a thread or a timer. The pass runs once per session end. Exceeding the budget, failing, or finding no network surfaces nothing, changes no fact the store holds about a source, and leaves every unfinished source due for the next attempt — measured at 2.02 seconds against five hanging endpoints, with four of the five left untouched and due.

**Dueness needs a second timestamp, and this is where the fix could have reinstalled the defect.** Cadence is measured from `last_retrieved_at`, new here, and from nothing else. `last_checked_at` records only that a pass considered the source — one found not due and one nothing could reach are both recorded there — and moves no due date. Stamping the *look* at every session end would push every source's next due date forward at every session end, and nothing would ever become due again: issue #247's own defect, rebuilt by its own fix. A source whose `last_retrieved_at` is absent or null has never been retrieved and is due, which is the state every row written before this record is in; no migration is written and no `finding` prose is parsed, because the field starting empty is the decision rather than an omission. The cadences themselves become shipped data the code reads, in `data/refresh-cadences.json`, and the profile carries no cadence member and cannot override them — the vestigial one it once carried was read by nothing and vanished without anyone noticing, which is the evidence that it does not carry its own weight.

**The rows are updated in place, and `status` is the only surface.** `source-states.jsonl` holds exactly one row per source with no superseding history, so a pass rewrites the row for each source it concluded on and appends nothing; the append-only rule stays the evidence stores' and the reference now says so. What the pass could not keep current is reported by `/model-selector status` and nowhere else. Not `route`, whose response schema is unchanged, and not a routed run's account: ADR-0090's own closing warning is that a measurement reminder placed where the model reads it changes the configuration being measured, and a routed run's account is exactly there. Nothing the report emits can refuse a request, stop a run, or ask a question.

**A machine that has never run `update` does nothing, visibly.** Dueness iterates rows and rows exist only after a typed `update`, so on a fresh machine the pass has nothing to iterate and correctly writes nothing — deriving which sources a configuration needs is semantic work this pass is forbidden. `status` says that unattended refresh has nothing to check and that a typed `update` establishes the sources, because a permanently empty pass must otherwise be indistinguishable from a working one, and this whole record exists because a silent nothing read as a working something.

**What this costs.** The collection now reaches the network from a hook, which is a genuine widening of what enabling a Skill does, and it is disclosed where the rest of that disclosure lives — the Skill's own `help.md`, read before Select answers. A provider sees a request from a machine at each session end, carrying a plain user agent and no credential or identity of any kind. A first pass over a source with no recorded validator records it as changed, because the store's knowledge of that content moved from nothing to something and under-reporting a change is the failure this record exists to end; the cost is one page a person reads and finds unremarkable. And the division of labour is now real rather than aspirational: what the machine can establish without judgement it establishes, and what needs judgement waits for the person, who is told it is waiting.
