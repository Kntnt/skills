# A withdrawn skill is removed without asking

The repository is the truth about what the collection provides. A skill withdrawn from it is withdrawn everywhere: it can no longer be updated, supported, or reasoned about, and the Catalog entry that named it is gone, which is what Disable and Status resolve a name through. Leaving the files behind does not leave the user a skill — it leaves instructions no command of the collection can reach, and the only way out is deleting a directory by hand. So Update removes it, in the layer it is acting on, and does not ask.

The asymmetry with ADR-0007 is the point of this record rather than a wrinkle in it. Adding a skill silently would inject instructions the user has never read into every Harness's context, so a new Catalog entry is reported and left Disabled until Enable is run. Removing one injects nothing. It takes away something the collection has already stopped shipping, and asking would only offer a choice that cannot be honoured — *keep it* means keeping an orphan. Consent governs what enters the context, not what leaves it.

This is why Update fetches the Catalog before it decides anything. Resolving the work first meant resolving it against the list the collection had already moved on from: the withdrawn skill was still Enabled, so it went into the refresh, the transport was asked for a name the source no longer carried, and the run died with the transport's raw error and no report at all (issue #5). Adopting the Catalog first makes the withdrawn set fall out of the comparison, and makes *only what the current Catalog carries* the thing that is refreshed.

Removal goes through the same wrapper Disable uses. The collection has one way to delete skill files, and a second one would be a second thing to get wrong in a place where being wrong means deleting the wrong directory. What Update adds around it is per-skill reporting on ADR-0036's terms: each withdrawn name is reported with what the disk then showed — removed, absent because it had never been Enabled here, or failed with the directories its files survive in. A failure belongs to that skill and not to the run, so the refresh still happens and the report still comes out; and, being a change the disk does not show, it exits non-zero like every other.
