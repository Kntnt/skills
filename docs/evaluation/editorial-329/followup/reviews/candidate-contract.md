## Contract checks

- The checker is a separate, fresh subagent with no conversation history, inherited Main Seat and no model or deliberation override. That conforms to the verdict rule without introducing Model Selector as a dependency. It receives the actual gathered material and complete draft, not the writer's summary or proposed findings. Conversational source material must be supplied in full; inaccessible or incomplete input stops delivery.
- Its task is bounded to source comparison. Claims and applicable quotation guidance accompany it, with the resolved language. No genre review half, additional editorial pass, external browsing, peer Skill or recursive delegation is introduced. Supported certainty, voice and editorial choices are explicitly preserved; neither particular error sentences nor blanket prohibitions on interview framing enter runtime guidance.
- The parent reads the complete report, checks findings against the source and makes only supported repairs. A disputed finding or any prose change triggers a fresh, unprimed comparison of the complete current draft. Two comparisons are the ceiling; only a complete no-findings result permits delivery. A missing report, unresolved second result or incomplete comparison is not converted into approval.
- After approval, checked prose is preserved exactly. Only resolved handoff metadata and the delivery wrapper remain. File delivery therefore cannot precede comparison, and an existing output is not overwritten with an unchecked draft. The account remains answerable to the same factual contract without becoming an extra editorial pass.
- Checker reports are internal scratch, read before removal. Cleanup is required on success and failure, and the response-target cleanup duty still covers all created artifacts. Each checker has its own directory and may write only its report. Actual clean termination and filesystem restoration remain matters for trace and inventory verification.
- The new hard subagent dependency appears consistently in frontmatter compatibility, capability metadata, the initial capability check, help and the README dependency summary. Help explains refusal when checking is unavailable or unresolved and the extra execution time. The description and Codex sidecar still accurately promise one first draft; they do not promise the absence of an internal source comparison. No new flags, peer dependencies or external installation are introduced.
- The CHANGELOG describes the changed process without asserting a verified repair. The source-check resource belongs to Write because it has one consumer. The supplemental matrix records the changed process as S1 and retains the existing semantic criteria; historical failures remain failures.

## Limits to establish in execution

The two-comparison ceiling deliberately trades availability for withholding an unchecked result. Repeated false-positive findings could therefore refuse otherwise supportable drafts; the positive controls and artifact review must examine that risk rather than counting refusals as successful prose. Structural review cannot prove the checker's independence in an actual Harness, complete input transfer, absence of prose changes after approval, correct handling of unavailable capability, or cleanup on interrupted checking. Preserve and inspect that evidence where exercised, and distinguish unexercised refusal paths from verified paths.

The original #329 demand for concise direction and editorial autonomy remains respected: the new resource changes how source fidelity is verified and does not expand the genre instructions into an error catalogue. The authorized reopening makes #349 and #352 quality blockers; this review supplies no basis for closing them before the declared native evaluations and independent source-aware judgements are complete.
