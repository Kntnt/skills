# Prospective native dispatch acquisition

Use this method when an evaluation requires exact correction or checker input
and the native delegated instruction is unavailable. Read
[the evaluation protocol](../protocol.md) first. This is unshipped evaluation
tooling; normal editorial Skill invocations do not load it.

## Prepare before freezing

Commit a finite preparation plan naming proposed fixtures, the actual resolved
contract resources, two independent validators, and explicit attempt and
replacement bounds. Zero replacements stays zero. Keep target classification
separate from whole-text conformance.
Give each validator a neutral packet with the complete fixture, material needed
for source support, exact contract files, a path-and-digest manifest, and the
[complete-contract brief](complete-contract-brief.md). The packet reveals no
arm, ticket, proposed expectation, intended classification or other report.

Each report covers every applicable rule, including semantic anatomy rules
that the counting script does not settle. A lead-only implication assessment
establishes no global anatomy conformance. Preserve both reports, their actual
loaded resources and failed proposals. Both validators must support a clean
expectation before it is frozen. A conflict stops dependent measurement.

After preparation succeeds, commit the final plan, accepted inputs, complete
resource manifest, expectations, turn files and judge briefs before the first
editorial run. Later changes start a separate prospective campaign. Use a
distinct bounded issue when another campaign needs a canonical record already
occupied that day; the same-day namespace gains no invented suffix.

## Declare the observation boundary

Keep two streams: ordinary native parent invocations and controlled invocations
whose named correction/checker dispatch uses `native_dispatch.py`. Commit the
exact evaluator overlay and exported product digest. The overlay changes only
dispatch acquisition, preserves the complete filled child brief, and is identical
in baseline and candidate arms. No shipped resource is edited.

The controlled child is a fresh top-level native CLI session rather than the
Harness's opaque `spawn_agent` call. Call every acquired row **instrumented**.
Its receipt establishes that boundary only, never what an ordinary parent would
have dispatched or a historical sealed state. Product conclusions require
separate native terminal observations and independent semantic evidence, and
cannot rest on the shim alone. Retain gaps and adverse results under their
actual method.

Before an editorial matrix, run a bounded neutral native parent that invokes
the helper and consumes its entire return. Retain the parent's actual tool call,
complete tool output and final message, the child's request/binding/native
records, and their identity mapping. A direct helper-child smoke establishes
only the child boundary. A separate exact-seat capability receipt establishes
availability for a fresh verifier, without borrowing planner history.

The editorial campaign and its blind semantic judges share its declared seat.
An independent whole-task verifier uses the separately declared verification
seat. Neither role's capability receipt authorizes a model substitution for the
other. For the Oct3 repair, editorial work is GPT-6.1-Sol/xhigh and whole-task
verification is GPT-6-Astra/high, both on CLI0.160.0; actual native contexts
settle the launch, and an unavailable seat is an explicit capability obstacle.

## Acquire one child

Pass the complete filled brief to the helper's stdin, without a second prompt
argument or a file path in place of its content. Supply a new absolute packet
directory, staged run root, declared seat/version, authentic parent identity,
role, finite timeout and each additional writable inventory root. Read
`native_dispatch.py --help` for the arguments. Existing lifecycle hooks stay
enabled; the helper uses vetted copied hook configuration and private native
authentication/runtime storage. The helper registers its own process group before
reading stdin or preparing native execution; version checks are bounded and run
inside that registered group.

The helper returns the complete native final message on stdout only after
input, actual context, completed turn and terminal bytes agree. Its stderr
carries transport/cleanup status separately. Ensure the parent tool's output
allowance carries every result byte; truncated transport fails acquisition even
when the child completed. A failed receipt is never an empty list or a negative
editorial result. There is one attempt and no automatic retry.

The original contract keeps real HOME and isolates CODEX_HOME, caches and
environments inside owned runtime. The unchanged retained-source default uses
its private HOME. Inventory every staged writable root, including runtime and
scratch; `.git` paths receive the same coverage. Retain directories, file kinds, modes,
symlink destinations and file content digests. The complete recorder packet,
including lifecycle output and private runtime, is inventoried alongside the
staged roots. Only the explicitly enumerated
private native authentication path has metadata without a content digest; an
ordinary staged file with the same basename receives its full digest. Distinguish enumerated recorder output
from product side effects using raw inventories, rather than discarding whole
directories. The helper names its owned runtime before removal and retains
cleanup receipts. Move actual deliverables out of registered temporary roots
before session cleanup. Failed ownership verification preserves reachable
runtime and reports the outstanding group.

## Prove whole parent consumption

The optional original-contract `--consume-spec` takes frozen JSON containing
`packet`, `launch_command`, `launch_tool_input`, `command` and `tool_input`.
Commands are exact native CommandExecution argv arrays; tool inputs are exact
`exec` JavaScript source. The child packet is separately reauthenticated,
including its original source digests, strict one-session boundary, declared
seat, observed retained flags, helper identity, exit and cleanup. The parent
must execute the declared launcher and then receive the entire child return in
its original plaintext tool response, with agreeing completed command stdout,
formatted output and final bytes. A later full parent final cannot repair a
truncated tool response. This checks source consumption, not understanding or
an editorial verdict.

A frozen proof may relay the complete recorder stdout through an owned file.
Disclose that file relay, retain the actual launcher and read commands and keep
the original child sources. A terminal-only file, matching later echo or
reconstructed source is insufficient. The receipt records both namespaces,
source offsets/digests and actual consumption ordinals. It never widens the
helper's one-native-session selector into an ordinary spawn consumer.

`--auto-compact-token-limit` is explicit original-contract instrumentation.
It passes the supported CLI token threshold with total-context scope and records
both overrides before launch. A lowered threshold proves only the instrumented
scenario; missing genuine compaction is an unmet boundary. Freeze finite input,
tool-output and time bounds before any launch. There is no automatic retry.
