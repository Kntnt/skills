No revert and no decision record follow from a miss or from a non-reproduction, as the clarifications settle.
2. **The candidate ships as it stands** where the post-change arm meets lines 1 to 5 as exercised and the regression clause.
3. **One revise round**, at most, where it does not. The revised wording is committed first, staged to `install-revise` and run on the failed subset — each input on which an exercised line or the regression clause was missed, as many runs as that input has in the post-change arm, a #392 row as its own procedure above says — and on every one of the ten controls, all judged as above. The wording that meets more of the rows run, as *Which rows a wording meets* counts them, ships; on a tie, the first. The #392 rows are compared between wordings, not against a pre-change value.
4. Either way, each criterion the shipped wording misses and each control it regresses is written down as measured and filed as its own `needs-triage` ticket naming #400, and the ticket is done.

No criterion is softened, no frozen plan, brief, turn file or fixture is edited to fit a result, and no arm is re-run to get a better reading.

**Void runs.** A run or judge cut off by a usage limit, an HTTP 5xx or an overload is void, not a finding, and is rerun. A void run's directory and packet are moved whole to `voided/` beside `runs/` before its input is run again. A run that completes and stops is a finding.
