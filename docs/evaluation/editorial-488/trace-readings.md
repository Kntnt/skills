# How the separate trace audit is read

This is the builder's unblinded audit, separate from the two identity-blind delivery judgements. `response.txt` is the Harness's terminal reply; the supplied input is never substituted for a delivered artifact. Every counted run has its own JSON event stream, persisted native parent and child rollouts, source stat, full private-root inventories and observed transient file versions.

Each packet's `trace-audit.json` preserves native session identity, model/effort contexts, assistant final messages, parent tool-call order and completed commands that perform removal. Its terminal comparison excludes only the CLI's final newline. Its artifact digest compares the fenced artifact or captured file with observed mechanical output. The underlying native rollouts remain the authority where the summary is insufficient.

## What establishes the lifecycle

Correction agents are identified by native `thread_spawn` ancestry and the parent's spawn call. Their returns and the final delivered artifact distinguish an accepted correction from a rejected one. An unchanged input digest establishes source preservation, not no-change review. The six baseline targeted responses actually changed text: every unnamed article repaired its headline, and every opinion repaired the mandatory flaws while retaining reported structural findings.

The closing mechanical operation is read from the submitted Proofread invocation and its completed output, not merely from a parent saying it proofread. The baseline's first opinion performs that public Skill inline; the other baseline rows delegate it. Every baseline delivers the bytes of observed mechanical output. Measurements after that operation are retained in native command arguments and output. Exactly one fresh reply checker completes in each baseline row before its terminal delivery; the checker return is preserved in its native final message.

Removal and final filesystem accounting are read from actual commands and their results. An empty net inventory is not proof that nothing was written transiently. File-version captures preserve observed intermediate editorial copies; before/after inventories show what remains. `inventory-account.md` enumerates all net effects, classifying requested output, retained run-owned scratch and Harness storage separately.

Both remain in the after-inventory. The cleanup account is truthful and does not replace delivery.

Evaluator teardown of the retained native root happens only after preserving this evidence. It is distinct from the Skill's refused cleanup and does not change the run's recorded outcome.

Other traces contain pre-execution `CreateProcess` rejections of compound UV wrapper commands containing `mktemp` and an `rm -rf` trap or tail. The entire command was refused before execution: its private temporary directory was never created and there was no concrete retained removal target. The run repaired its command construction and invoked the Skill in a fresh private directory. These are kept distinct from the baseline file control's standalone removal of an existing, fully named directory. A successful alternative removal of that retained directory would fail T2; no such workaround appears in its trace.

## Limits of the reply-check comparison

Some native spawn/message arguments are encrypted. Child rollouts omit the complete inherited checker prompt, and no full drafted reply was captured externally for every baseline run. The audit preserves the checker return and the terminal reply separately. It can compare a draft sentence quoted by the checker with its delivered correction, but cannot reconstruct every unfaulted statement or prove its word-for-word preservation. T1 records that unavailable comparison as skipped; mechanical completion, final measurement and the one-shot checker ordering remain established separately.

These frozen inputs carry no leading frontmatter. The complete delivered artifact preserves that absence. The campaign does not independently test delivery of a frontmatter-bearing input and claims no such measurement.
