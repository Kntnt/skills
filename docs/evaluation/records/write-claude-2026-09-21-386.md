The staged install is a byte copy of `skills/editorial/{write,redline,proofread,unslop}` and `skills/kntnt` taken from `9a29bad3` with `git archive`, in the session scratchpad; one install served the whole wave. Each run's working directory held `source.md` and an empty `scratch/` and nothing else. The dispatching session's own seat is `claude-fable-5-1`, and it ran and judged nothing itself — a declared difference from *inherit the session's identity*, taken to spare that seat's budget. No Codex Harness and no GPT model was started, controlled or invoked from this session.

Three statements beyond the invocation went into each turn, and they are the evaluator's rather than the Skill's: copy the source-check scratch to `evidence/` before it is removed; save the complete user-facing reply verbatim to `response.md`; and, where the Skill tells the run to ask the user something, state the question in the final reply and stop, because nobody is available to answer. No run's `response.md` write was refused, so both files are the runs' own and are declared evaluator additions rather than Skill side effects, as is `evidence/`.

Counted requirements are counted by script. `skills/kntnt/library/scripts/article_anatomy.py` as `9a29bad3` holds it was run by the evaluator, from its own copy and never from the staged install, on each delivered draft; the JSON sits beside the run as `anatomy-delivered.json`, and its figures are the evidence for every counted line below. A judge was handed those figures and counted nothing itself. A Write row's source package is a brief rather than an article, so no `anatomy-input.json` exists for either row.

Every draft was judged by two fresh subagents, blind to each other, to this ticket, to the model identity and to any wording of the expected outcome beyond the criterion text. Where they split, both readings are recorded and neither is the oracle.

## What this evaluation exposed and did not settle

Write delivered on both rows, both drafts measure `conforms: true`, and fifteen of sixteen judged criterion lines pass. The one failure is a part not doing its job rather than a claim outrunning its material: `column-sv`'s third subheading repeats the sentence under it, and neither source checker nor the delivery account saw it, which is [#390](https://github.com/Kntnt/skills/issues/390). The `column-sv` Redline row in the same wave found it on the first pass and repaired it, so the defect is one a review catches and the writing pass does not.

Both rows also hit the same harness wall: a source-check subagent cannot write its report file, and the run starts an unbounded background wait for the file. The evaluator saw it in the process table while the runs were in flight — three `until [ -f …/report-1.md ]; do sleep 5; done` shells for each Write row — and found none left once the last run had ended; the one loop known to have outlived its run, by five hours and fifty-five minutes, came from a staged run made earlier the same day outside this evaluation. It is a process rather than a file, so the before-and-after inventory that establishes `O1` cannot see it. Filed as [#391](https://github.com/Kntnt/skills/issues/391).

Nothing here establishes whether the scoped contract loading happened, because `T1` and `R2` are answerable only from a Harness trace and a session cannot read the transcript of a subagent it started. The trace-bearing Claude-family harness is [#388](https://github.com/Kntnt/skills/issues/388).
