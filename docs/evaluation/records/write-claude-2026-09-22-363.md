## Run conditions

Sixteen `case-study` `Write` runs of one frozen source — `docs/evaluation/corpus/editorial-quality/sources/case-study.md`, copied whole into each run's working directory as `source.md` and nothing else — across **three arms of one product**: `b`, the collection unchanged at `8a37e57e`; `c`, that tree plus the first candidate wording of #363; and `r`, that tree plus the revised wording, which was the one revise-and-remeasure round the ticket's exit criterion allows. The matrix was frozen before the first run in [`../editorial-363/plan.md`](../editorial-363/plan.md), the results are in [`../editorial-363/results.md`](../editorial-363/results.md), and every artefact is under [`../editorial-363/runs/`](../editorial-363/runs/).

**Entries below are one per row per arm**, with each run of that row inside, because the matrix replays one row up to three times in one arm and a section per run would say the same eight fields sixteen times. No run is left out.

**Two harnesses, declared.** The `b` and `c` arms were run by an earlier session as fresh subagents, one per invocation, each told that a staged `SKILL.md` was its instructions and `$HERE` its directory. The `r` arm could not be: this session is itself a subagent, a subagent of this harness has no agent-spawning tool, and Write's step 1 correctly stops on the unsatisfied `subagents` capability before it resolves anything. The `r` arm therefore ran each invocation as a **fresh top-level Claude Code session**, `claude -p` given the turn as its prompt, with Claude Code's own `--model` set to `claude-opus-5`, `--effort` to `high` and `--permission-mode` to `bypassPermissions`, with the child-session environment unset and the working directory set to that run's `work/`. Same model, same deliberation, same turn text, no history; what differs is that the seat is a session rather than a subagent. Wall times are not comparable across that line, and ten to fourteen of those sessions ran at once, so the `r` arm's times measure contention. The editorial outcomes are comparable: the Skill, its resources, its input and its blindness are identical.

**The invocation line in each entry is asserted, not preserved.** The turn text is in [`../editorial-363/runs/write-turn.md`](../editorial-363/runs/write-turn.md) and says the invocation is in the message that dispatched the run; those messages are not in the tree.

**Four evaluator instructions** went into every turn, declared in the plan as not the Skill's: copy the source-check scratch to `evidence/` before the Skill removes it, save the complete reply verbatim to `response.md`, save the delivered draft to `delivered.md` with nothing added, and write UTC timestamps to `started.txt` and `finished.txt`. Each is visible in the run directory as a file the Skill did not write.

**Inventories.** All eighty-four files of each staged install carry the same `sha256` after the wave as before it, and each matches the repository at its arm's product state; no run wrote into the product it measured. Five runs across the two later arms have no `finished.txt`, because the session that made them was stopped by an account limit between the run and the marker; their artefacts are complete and they count for every criterion, with wall time recorded as unavailable.

**Voided attempts, kept.** Seven subagent attempts at `r`-arm rows, made before the capability problem was understood, are preserved under the run scratch's `logs/voided/` and count for nothing. One of them is the Write run that stopped on the unsatisfied capability, which is how the problem was found.

**Judging.** Every delivered draft was read by two judges, each a fresh subagent that saw the run under an opaque id in a directory carrying neither its arm nor any other run's, without this ticket, without the hypothesis and without each other. The brief is [`../editorial-363/runs/write-judge-brief.md`](../editorial-363/runs/write-judge-brief.md). Both judgements sit beside each run as `judgement-a.md` and `judgement-b.md`. One run carries a third, for the reason its `judgement-c.note.md` gives. Where the two split, both readings are recorded and neither is the answer.

**`T1` and `R2` are `skipped`** on every row, with the reason the ticket's addendum gives: a subagent's transcript is not readable from the session that started it, and a headless session's is not an artefact here either. The loading question is carried instead by [`../editorial-363/reviews/load-chain-review.md`](../editorial-363/reviews/load-chain-review.md). [#388](https://github.com/Kntnt/skills/issues/388) is the ticket for making them judgeable.
