# Rules — routing and evidence

Read before changing how a Skill of this collection routes work it delegates, what it may file as evidence about it, or what an owned Harness integration installs and reports.

This module covers the routing chain: when Model Selector is reached at all, what its public Interfaces promise, what a frozen decision carries, how a Cohort's ladder moves, what may enter the evidence ledger and what may only be measured, how delegated execution is shaped, and what an owned Harness integration is allowed to do on the machine. It is not about how the collection reaches a machine, which is `collection.md`, nor about the form of a Skill's shipped files, which is `skills.md`. Model Selector's own references — the adapter schema, the selection reference, the ledger's record shapes — hold the detail; this module states what is true of them and where the boundaries are.

The capitalised terms — Seat, Main Seat, Cohort, Standing Policy, Rung, Outcome Authority, Usage Record, Exploration Attempt, and the rest — are defined in [`CONTEXT.md`](../../CONTEXT.md). That file says what a term means; this module says what is true of it.

The rules whose reasoning is settled in a decision record are named here in a phrase and cited to the record rather than argued again — the record is where the alternatives and their costs live, and a second telling of the argument is a second thing to keep true.

## When routing happens at all

**Model Selector is model-invoked only where another Skill requires its public `route` or `observe` Interface** (ADR-0179). Its description is the complete trigger and excludes recommendation, setup, configuration, comparison, capture, evidence updates, recording, and status, each of which stays an explicit user invocation; `record` stays user-only, so routed work cannot import its own observation. A caller reaches it by its own Harness's spelling — `$model-selector` in Codex, `/model-selector` in Claude — and neither spelling denotes a tool endpoint, so endpoint discovery is no availability check for it.

**A spawn the caller runs on the frozen Main Seat, with no model, deliberation, or surface override, is not routed** (ADR-0179). The boundary is the caller's own choice rather than a routing outcome: a spawn onto any foreign surface, model, or deliberation override routes exactly as before, and there is no judgement call left for spawn time. Such a spawn produces no `observe` attempt either, an observation beginning from an immutable route decision the spawn never had; where capture is enabled, it is recorded as the inheritance that actually happened.

**The shortcut removes the ceremony for the default, and must not remove the question** (ADR-0179). Making Main-Seat spawns free while every cheaper seat still routes tilts each decision toward the expensive seat because it is the frictionless one, so cheap judgment-in-noise roles — distillation, summarization, evidence collection — still weigh a routed cheaper seat rather than defaulting to it. Nothing checks that they did.

**A verdict inherits the complete Main Seat exactly and is never routed** (ADR-0085). Judging work is authority rather than a decision that happened to come back inheriting, so no execution override, route result, repair, or failure can downgrade that seat, and verdict work is never price-optimised. A Skill that keeps a persisted account of what decided what routes every execution role, and may restate a decision the account already holds for a later role only where the account's inheritance is the snapshot's own (ADR-0172).

## The Interfaces, and what a frozen decision carries

**A Skill that delegates execution routes through Model Selector's public Interface and reproduces none of its policy** (ADR-0083). That Interface alone validates exact points, mappings, availability, the complete Main-Seat ceiling, evidence class, bounded escalation, and Harness-native controls, and it returns a frozen snapshot binding the profile revision, evidence identity and vintage, Harness inventory, native mappings, commercial facts, Main Seat and override policy. Only a selection carries an exact Harness-native launch instruction; an inheritance audits why no override was safe, and a refusal has a stable reason and starts nothing. The Main Seat is never among the things a decision selects: the user chose it for their own session, so routing decides only what runs beneath it, and no Interface of this collection picks, raises, or replaces it. A caller reads none of Model Selector's private references.

**A public Context Interface stands before route** (ADR-0179). Context accepts ordered route requests beside either exact runtime facts — the active Harness and the complete Main Seat — or a frozen snapshot it validates and carries unchanged. It validates the persisted profile, reads the shipped seed, the adapter templates and the routing defaults, and returns the complete route artifact. It performs no setup, no network access, and no persistent write, so a caller can reach it before every route without acquiring policy of its own.

**A stored profile that does not validate is rejected, not absent** (ADR-0179). Absence is the file not existing and nothing else; a file present that cannot be read, cannot be decoded, decodes to something other than an object, fails the profile contract, or holds a selection resolving to no configured access channel was written by somebody and is rejected. A rejected profile inherits under its own reason token rather than refusing — a refusal would cost an unattended run every ticket in it, where inheritance costs it only its optimisation — and the rejection rides in the frozen snapshot carrying the failure that caused it and no value read out of the profile. No migration is written: the profile is a short interview `setup` recreates, and the rejection names that as the way back. A populated evidence ledger survives a rejected profile intact.

**Missing facts inherit rather than trigger setup** (ADR-0179). An invalid profile, empty mappings, and an automatic pool excluded only by unreachable adapters or unknown ranks all preserve the exact Main Seat. An explicit override never inherits: it is selected exactly or refused. Commercial dimensions stay unknown rather than being invented from a token schedule with no usage basis.

## Adapters and launch destinations

**An adapter ships as a template and becomes concrete only against profile and runtime facts** (ADR-0179). A template declares the Harness and configured surfaces it covers, the model identity it can address, its control source, and a complete launch destination for every relevant field; specialization binds the selected channel, exact model, serving mode, supported controls, and the session attestation an inherited destination requires. A selection that is seedless, uncovered, or whose control is unavailable stays visible as a mapping with no reachable adapter rather than being given an invented mapping or rank, and invalid, disabled, or unvalidated selections never become mappings at all.

**Every launch fact has one of three destinations** (ADR-0179). A parameter destination renders the point value through a template and emits one Harness-native argument; a fixed destination must equal the point and emits none; a carried destination must equal the corresponding frozen Main-Seat fact, requires the verified session attestation, and emits none. One vocabulary covers model, surface, serving mode, native controls, tools and policy, and emitted parameter names alone must be unique.

**A control carried by inheritance is a complete translation, not an absent one** (ADR-0179). A native control mapped as carried emits no launch argument and is a different fact from a mapping that is simply missing, which the module refuses: an absent mapping means nobody knows what the subagent will deliberate at, a carried one means somebody checked and the answer is the seat's own value. Such a destination is valid only beside the declaring session's attestation that this Harness applies that value to subagents by default — a claim no script can compute, since no script knows which Harness invoked it, and one the schema therefore refuses to accept implicitly.

**A carried control is not a dimension route selects over** (ADR-0179). It resolves to the frozen Main Seat's exact portable and native value, so the point yields that one variant; the configuration fingerprint carries the effective seat value, so evidence accrues to what inheritance actually launched rather than to a level nothing ran at; and an explicit deliberation lock over such a variant is refused rather than quietly satisfied.

**Portable deliberation is a five-level ordinal, and a missing native mapping is unavailable rather than approximated** (ADR-0179). Mapping an existing portable value onto a seam's observed behaviour is a calibration claim nobody has verified, and the module interpolates or guesses a mapping nowhere.

## The ladder a Cohort climbs

**Capability rank comes from one independent numeric comparison** (ADR-0179). Context selects a newest non-superseded benchmark definition that covers the largest candidate set, and uses each model's maximum score in it; a model that comparison never scored has no rank and cannot launch, and qualitative prose never becomes a number. A rank is a published quality measurement and nothing else becomes one — not a first-party capability claim, not a price, not a throughput figure. The local evidence ledger's own row supersedes the shipped seed's for the same model and benchmark, and a configured Main Seat no benchmark scores keeps its mappings and suspends the ceiling it cannot state rather than acquiring one (ADR-0166).

**A Rung is two-dimensional** (ADR-0179). Inside one exact mapping it is the next mapped portable value in order, an unmapped level skipped rather than refused. Where that scale is exhausted, or the Harness carries the deliberation control and no adapter addresses it, the Rung is instead the next model up by capability regardless of provider, entered at the lowest portable value of its own that survives the request's filters. That step crosses a price boundary a level change does not, which is why the ordering has to be total.

**The ordering is shipped snapshot data, never a fact the module looks up** (ADR-0179). The capability numbers and their provenance ship in the frozen snapshot as derived priors, and the module reads its ladder from the snapshot alone.

**A Rung is always a point the same request already reaches** (ADR-0179). Escalation resolves over the candidate pool selection resolved over, so every hard filter, explicit lock, adapter reachability check and both Main-Seat ceilings have applied before adjacency is read; a point excluded as unreachable, over the ceiling, or outside the workload's capabilities cannot return as a rung. Each mapping at the target capability collapses to the single value the direction enters it at, and the survivors are ordered by known price first, so one exact launch is always determined.

**A lock is not a Rung** (ADR-0179). A request pinning the deliberation gets no escalation in either dimension, the pinned value being the caller's own exact instruction; a request pinning the model needs no rule, an ambiguous alias already being refused.

**The objective is frozen with the context, and it orders the frontier lexicographically over two measured axes** (ADR-0147). Cost first is what the shipped defaults freeze: the lowest observed cash, ties broken on the lowest Time to Verified Pass, and a run started for time reverses the two and breaks a further tie on the Rung order. Neither order invents a rate between the axes — converting a minute into a dollar is a statement about what the work is worth, and only a person can make it, which is why a complete set of declared shadow prices still outranks the objective. The ordering reads what a configuration was measured to cost rather than what it is advertised to cost, a seat that exposes no cash at all is ordered by the Rung ladder whose cheaper end is cheaper by construction, and a half-measured frontier orders nothing and inherits instead. Freezing the objective is what keeps a run selecting under one order from its first request to its last.

**Downward adjacency exists as geometry and carries no shipped policy** (ADR-0179). One helper answers both directions so that exploration, when it is priced, inherits one geometry rather than writing a second; only the upward direction is wired to a decision.

**An Exploration Attempt buys contrast one Rung down, on a budget** (ADR-0151). It is drawn from the Cohort's bounded budget and tagged, so its outcome never counts against the production configuration and never enters the window a ratchet is read from.

## Cohorts, and the policy that moves

**A routed attempt carries the Cohort of the request it answered** (ADR-0179). An observation gains the stage, the workload cohort and the workload tags, copied verbatim from the request and travelling as one — an attempt naming only some of them names none. They are optional, because rows written before them are still rows and captured work nobody routed names no Cohort at all. The benchmark key stays the identity of the check and is not the Cohort.

**A frontier is the exact tuple, not the benchmark key** (ADR-0179). A derived frontier is identified by the benchmark key, the stage, the workload cohort and the sorted tags together, and rows differing on any member are never compared as one; a row naming no Cohort is comparable within nothing and enters no frontier. The projection emits one record per fingerprint point and classifies nothing, the route module remaining the only classifier (ADR-0083), and a point with no decisive run emits nothing because the quality and interval a record requires do not exist for it.

**The context derivation is the only consumer of that projection** (ADR-0179). It writes the evidence records for every route request, digests them into the evidence identity, and takes the vintage from the newest instant behind them, so no user step stands between a verdict and the next decision.

**A Cohort starts where its Standing Policy says, and only a reset lowers it** (ADR-0149). The policy is script-owned state beside the user's configuration with shipped defaults; it fixes the Rung a Cohort starts at, moves it up after repeated externally verified failures, never moves it down by itself, and bounds Exploration Attempts.

**Verified failures ratchet a Cohort at the import that recorded them** (ADR-0179). The evaluation runs once per Cohort the import touched, after the ledger append, in the one Library module that owns the append — the automatic import at a verdict and the user's own `record` reach it through the same call, a threshold that tripped for one and not the other being two thresholds. A row is judged on the ladder its own run froze, carried on the observation, so a policy that has since moved cannot reinterpret an attempt made under the one before it. A row enters the window when it names the Cohort, is decisive, was machine-judged, carries no exploration tag, carries the Cohort's current revision, ran on exactly its own carried starting Rung, and completed inside the current epoch; the window is the last M such rows and need not be full, and the policy moves when at least N of them failed. The Rung clause is what stops an escalated retry from voting against the start it escalated from.

**Every movement begins an epoch** (ADR-0179). A trip and a reset alike stamp the Cohort, and only rows completing after it are eligible, which is what keeps the same historical failures from escalating a Cohort twice or from immediately undoing a reset somebody just asked for. Staleness is compared on the revision alone, and an in-flight run frozen before another run's movement keeps its evidence and loses only its authority over the policy. Nothing is appended at the top of a Cohort's resolved ladder; the evidence still lands and the run reports the ceiling instead. The run reports what it moved from its own import rather than by re-reading the store.

**An evidence reset takes a ratcheted Cohort's Standing Policy down with it** (ADR-0179). A ratchet is a claim about failures the ledger holds, so discarding the failures and keeping the ratchet would leave a Cohort started above its own cold start on a claim with nothing behind it: the wider reset removes the policy store and its history outright, exactly as it removes the ledger, the derived frontiers and the quota store. The narrower `config policy reset` is unchanged and keeps the history that explains how each Cohort got where it was.

**A recommendation's experiment brief reads the same ladder the routing decision does** (ADR-0179). It reads the bounded pool as the Standing Policy left it and steps above a selected point with the same Rung resolver, so the points it lists are points the request can actually launch. Under a deliberation lock it refuses a step exactly where the routing escalation refuses. Where no comparable point is reachable the section stays, lists the one point the request can launch, and says plainly that there is nothing to compare it against — measuring a single heuristic point is what turns a guess into evidence.

## What may enter the evidence ledger

**A routed attempt becomes evidence only where something outside it judged the attempt** (ADR-0089). An independent verifier, an objective checker, a frozen rubric, a declared failure signal, or the user saying so makes an outcome decisive; a builder's report and a subagent's confidence establish nothing, and an unchecked subjective success is left out rather than recorded as a weaker measurement. A decision nothing reached a verdict on is audit data and not an observation. The workflow's own failures — a mechanical hinder, an open product decision, a newly discovered dependency, a tracker failure, a merge collision — are retained as infrastructure errors and excluded from the success rate a frontier is built from.

**The observation is built by allow-list, and every field is copied by name** (ADR-0089). Prompts, responses, reasoning, ticket and source bodies, diffs, terminal output, secrets, transcripts and absolute paths are absent because they are never copied; a measurement the environment did not expose stays an explicit null, an absence read as zero making an unmeasured configuration the cheapest on the frontier. Model Selector owns emission as well as import, so a caller reaches it through the public Interface and reimplements no sanitization, validation, or key derivation of its own.

**One eligibility rule is held once and read by both routed callers** (ADR-0179). What a machine may file without asking anybody — an outcome established by an independent verifier, an objective checker, or a declared failure signal, plus the abstain and infrastructure-error conditions no model produced — lives in the Collection Library beside the append it gates, because a machine that escalates a Cohort unasked and a machine that files a row unasked are answering one question. The import is asked for by name, so the `observe` a person runs by hand acquires no ledger side effect, and a refusal is reported per identity and stops nothing: the work the row describes is already done, and evidence is not a reason to fail it.

**Delegated execution files into one Cohort** (ADR-0179). Every request that path routes names the same stage and workload cohort and no tags, and the observation copies all three: a Cohort per brief is a frontier of one row and a Cohort that discriminates nothing puts unlike work in one comparison, while the frontier identity already holds the benchmark key beside the Cohort, so unlike briefs stay apart without splitting it.

## What is measured but never judged

**A finished ordinary session produces a Usage Record, not an observation** (ADR-0179). It carries the opaque session identity, the Harness and its inventory revision, the exact Seat the work ran on, the usage categories the environment exposed, and both instants with the elapsed seconds between them. It carries no outcome, no Outcome Authority, no checker, no condition, no Cohort, and no configuration fingerprint: a routed attempt's fingerprint exists because something judged the point it names, and nothing judges a Usage Record. Every measurement the environment did not expose stays an explicit null.

**A Usage Record goes to its own append-only store beside the evidence ledger** (ADR-0179). A second store rather than a second kind of ledger row, because `record` correctly refuses a row with no verdict; idempotency is by session identity and Seat. A session that ran on more than one Seat produces one Usage Record per Seat, each timed on that Seat's own first and last turn.

**A Usage Record is never quality** (ADR-0179). It enters no derived frontier, contributes to no success rate, clears no quality floor, and produces no evidence record — the same rule a ledger row naming no Cohort is already under, because both are one rule: work never grades itself, and a row nothing judged is not a verdict wearing quieter clothes. Nothing waits for a human: there is no pending queue, no review verb, and a session that ends abruptly contributes whatever its own Usage Record establishes and nothing more.

**Observed usage reaches a recommendation through a Skill-owned reader called only after a decision exists** (ADR-0179). It ships beside the routing engine rather than in the Collection Library, nothing outside that Skill's own `recommend`, `chart` and `compare` rendering it; a Usage Record therefore chooses nothing, as a property of where the reader is called from rather than a rule every caller has to remember. The recommendation's own evidence banner is untouched — it classifies quality evidence, and a Usage Record is not that — so usage is carried in a separate section with its own provenance: the record count and the earliest and latest instant behind each figure. A mean is reported only where every contributing record carries it, and the category set is read from the data rather than copied from the reader that derives it.

**The join is on the model alone** (ADR-0179). It is the one field a frontier neighbour, a selected launch and a real Usage Record's own Seat all carry, and deriving a portable level from the native control a record does carry is the calibration claim that record already refused. Two named points differing only in deliberation therefore draw the same records and report the same figures, so each summary names every portable deliberation the matched records actually carry and how many carry each — a reader can see when one figure stands for a mixture.

## How delegated execution is shaped

**Execution takes one of three paths, chosen by the shape of the work** (ADR-0179). Pure execution with large output runs detached from the conversation, writing to disk, and the Main Seat reads only the report and searches the rest; judgment inside noisy data goes to a subagent for a bounded, task-shaped report; a small bounded command stays on the Main Seat, narrowed at the source. The rule is the shape of the work rather than an order of preference. *When unsure, delegate* survives and is scoped to the choice between subagent and Main Seat: uncertainty about whether something needs judgment is never settled by a detached process, which exercises none.

**The detached path is stated as a property and never as a tool** (ADR-0179). What is said is that the process is detached from the conversation, that its output is on disk, and that its report is the one thing read back; no command, flag, or waiting facility is named, one Harness's spelling of the property being another's.

**The Main Seat ends what it detached, or names it as left standing** (ADR-0179). Whatever a session starts it stops before it reports, and a deliberate exception is named in the report — the same rule a subagent is already under (ADR-0127).

**A delegation brief names a report file inside the spawn's own scratch, and caps the inline reply** (ADR-0179). The subagent writes complete findings to that file and replies with a stated, task-specific budget of conclusions only, no raw command output and no file dumps; the Main Seat reads the file only where its decision needs the detail, and still verifies results independently. The directive states the shape and each brief chooses the number.

## Owned Harness integrations

**A Skill owns the Harness integrations it installs, and the owner travels in what is written** (ADR-0179). Every entry carries a stable ownership identity inside the command it runs rather than beside it in a key the Harness's own schema does not define, so removal is surgical without anything having to be remembered: the disk is read, our entries are found by their owner, and everybody else's survive untouched. Nothing keeps a private ledger of what was installed, so install, repair, update, and remove are one operation applied to whatever is actually there. Harness-specific mechanics belong to the Collection Library, where a second consumer finds them rather than reaching into the first. Which Harness is running stays the agent's to say and never a script's to sniff, and a Harness whose lifecycle cannot carry the contract reports an Unsatisfied Capability rather than being quietly skipped.

**Capture follows the Skill's own Enabled state and asks for nothing beyond it** (ADR-0179, superseding the second opt-in capture once asked for). Enabling the Skill through the Manager is the whole gesture and Disabling it the whole undo, at the seams `collection.md` describes. A second opt-in behind its own command produced not a more considered choice but no choice at all — eight weeks Enabled and zero sessions captured on the maintainer's own machine — so the disclosure moved to the one surface a user reads before answering: the Skill's own `help.md`, readable in Select before the list is answered, which states what Enabling installs, what is retained, and that Disabling removes every entry and keeps what was measured. Only the Global layer is written, an owned entry being keyed by owner inside a Harness's own configuration, and only a Harness the Library has an adapter for is ever attempted.

**An adapter is verified against what its own Harness actually reads** (ADR-0179). Event names, entry shape, and file location are established from the Harness as installed rather than assumed from a sibling's, and where a fact cannot be established that way the honest answer is Unsatisfied — a guessed shape that happens to parse is not a verified one.

**A Harness that gates a new integration behind a user's trust is reported gated, never healthy** (ADR-0179). This collection forges no trust decision and writes no trust record on the user's behalf, so an integration that is fully and correctly written into such a Harness is reported present on disk, not yet active, and naming what the user does next. `healthy` stays reserved for a Harness this collection can observe is actually acting on what it installed.

**The per-turn hook path is fail-open, bounded, and local** (ADR-0179). It runs inside somebody's session, so it does local metadata I/O and nothing else — no model call, no test run, no repository-wide hashing, no transcript read, no long-lived work — and every failure in it is swallowed, capture that breaks a session being worse than no capture. Notifications are debounced and user-facing for the reverse reason: a measurement reminder placed where the model reads it would change the configuration being measured.

**The session's own last invocation may read that session's own finished record** (ADR-0179). That moment is not the per-turn path: it is a one-time, inline, bounded read at the hook that ends the session, of the transcript the caller's own payload named and that transcript's own companion subagent directory, and nothing wider. No location is computed that was not handed over, no other session's files are opened, and no identity found inside a line is trusted over the file the caller supplied. The read is field by field onto an allow-list — the model, the deliberation control named beside it, the token categories, and the instant — applied to a source carrying far more, and a subagent's turns are counted against a Seat of their own with an explicit null on every field the record cannot describe. A record that cannot be read is an absence: the reader answers with nothing and the hook writes what it would have written anyway.

**An unattended pass may learn what a model can do, never what it costs** (ADR-0179). The same session-end invocation dispatches a conditional re-retrieval of the non-commercial sources that are due — validator-conditional, one connection at a time, no retries, and a total budget of two seconds against a monotonic clock. It interprets nothing: no page is parsed for meaning, no model is started, and no capability fact, benchmark fact, evidence record, derived frontier, or adopted model is written. The unattended pass establishes *that* something moved; a person's next typed update establishes *what*. Maintenance stops at the money and the stop is by kind — a commercial source, and any kind the pass does not recognise, is never retrieved unattended and is reported as due instead, so a kind added later is safe on the day it appears. Cadence is measured from the last retrieval and never from the last look, or nothing would ever become due again. Status is the only surface it reports on, and nothing it emits can refuse a request, stop a run, or ask a question.
