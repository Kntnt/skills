# Anti-slop ownership and register prompting

## Questions and scope

This note asks whether Redline should depend on Peter Yang's `no-ai-slop` Skill or own an adapted rule set, and whether a register instruction such as “write in prose suitable for a Swedish daily newspaper or magazine” should appear early in Write. External-repository findings are pinned to upstream commit [`d30eddb9e04562234f2070b5ee63ca4649d9a05e`](https://github.com/petergyang/no-ai-slop/tree/d30eddb9e04562234f2070b5ee63ca4649d9a05e) from 2026-08-06. Prompting claims use model-provider documentation and primary research; conclusions that go beyond those sources are labelled as inference.

## Dependency decision

Kntnt should own an adapted anti-slop reference inside Redline rather than require or opportunistically invoke upstream. A required External cannot be supplied by Select and would make Redline refuse whenever the user had not separately installed it; an optional integration would make the editorial contract depend on an unrecorded global Skill and whatever upstream version happens to be present. Both outcomes conflict with the Collection's explicit, checked Dependency model ([domain model](../../CONTEXT.md) and [ADR-0012](../adr/0012-skill-owns-dependencies.md)). Upstream's questions, standalone output, editing loop, English lexicon, and broad style absolutes also conflict with an internal Redline pass.

The owned version should retain compact language-independent pattern definitions in a Redline-private reference and put words, phrases, punctuation, and constructions under the relevant language's Redline extension. It should emit findings into Redline's existing correction loop, not conduct a second conversation or produce `What changed`. Mechanically searchable phrases can later be surfaced as candidates by a script, but semantic patterns such as false profundity, empty interpretation, or flattened voice still require model judgment.

The reference should remain private while Redline is its sole consumer. If a second Collection Skill later needs the same implementation, move it to the Collection Library rather than making one Skill read another's private files ([ADR-0076](../adr/0076-shared-implementation-belongs-to-the-collection-library.md)). If wording or a substantial portion of Yang's catalogue is copied or adapted, ship the MIT notice with it.

## Evidence for a register instruction

There is good evidence that a concise tone or role instruction can steer generation. OpenAI documents that the high-authority `instructions` field controls behaviour including tone and takes priority over `input`; its recommended developer-message structure begins with an identity section that includes communication style, while warning that optimal content and order vary by model ([OpenAI prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering)). Anthropic likewise says that a role in the system prompt focuses behaviour and tone and that even one sentence makes a difference; it also calls examples one of the most reliable ways to steer tone and structure ([Anthropic prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)). These are provider recommendations, not controlled evidence for the exact Swedish newspaper phrase.

The evidence does not support a universal claim that physical earliness is what makes the instruction persist. Anthropic recommends placing 20K-plus-token source documents above the query and instructions and reports up to 30 percent better response quality with the query at the end; an earlier reproducible Anthropic study similarly attributed better recall to keeping instructions close to the end ([current guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) and [long-context study](https://www.anthropic.com/news/prompting-long-context)). Liu et al. moved task instructions after long inputs during fine-tuning and consistently improved translation and summarisation across 1B, 7B, and 13B models, including up to 9.7 BLEU on a zero-shot translation setting ([ACL 2024 paper](https://aclanthology.org/2024.findings-acl.693/)). Those experiments concern recall and conditional sequence tasks, not journalistic register on current Claude or GPT models, so their applicability is directional rather than conclusive.

Position effects are not a simple recency rule either. Liu et al.'s long-context retrieval experiments found a U-shaped pattern, with relevant information used best near either the beginning or end and worst in the middle; repeating the query at both ends fixed synthetic key-value retrieval but did little for multidocument question answering ([“Lost in the Middle”](https://arxiv.org/abs/2307.03172)). The defensible design principle is therefore salience through instruction authority, clarity, separation from source material, and measured placement, not a theory that the first sentence remains in a special memory.

**Inference:** A short default-register sentence in each language base contract is a sensible low-token experiment. It should describe a culturally recognisable but broad editorial register in that language and explicitly yield to the requested or genre-required voice. Keeping the sentence language-owned avoids a central multilingual phrase table and lets future contributors distinguish variants such as Sweden Swedish and Finland Swedish. “Daily newspaper or magazine” is otherwise too broad to serve as a hard style definition and can be wrong for letters, advertisements, speeches, or strongly personal prose.

**Inference:** For Write, put the stable register sentence in the operative Skill or language instruction, clearly separated from source data and in the highest-authority channel the Harness provides. When a Harness flattens everything into one long user prompt, place the actual drafting instruction after the source material rather than duplicating a large rule set at both ends. The minimal candidate should be tested against no register sentence and against a more precise alternative such as “Use idiomatic contemporary Swedish in the restrained, concrete register of a quality general-interest newspaper or magazine, unless the requested genre calls for another voice.”

## Why mixture-of-experts is not the explanation

No primary source reviewed here establishes that GPT-5.6 Sol or Claude Opus uses a mixture-of-experts architecture, and the current official prompting and model guides do not disclose such a topology ([OpenAI GPT-5.6 guidance](https://developers.openai.com/api/docs/guides/latest-model) and [Anthropic model system cards](https://www.anthropic.com/system-cards)). OpenAI's GPT-4 technical report illustrates the disclosure limit: it identifies a Transformer-style next-token predictor but explicitly withholds further architecture details ([GPT-4 technical report, section 2](https://cdn.openai.com/papers/gpt-4.pdf)). Treating a proprietary model as MoE is therefore speculation unless its provider says so.

Even in a documented sparse MoE, “an early prompt lights up one part of the brain and the model stays there” is technically misleading. Mixtral's router chooses two experts separately for every token at every layer, and the selected experts may differ at each timestep ([Mixtral paper, sections 1–2.1](https://arxiv.org/abs/2401.04088)). Routing can depend on the token's contextual representation, but it is not one prompt-level expert selection that remains fixed through the response.

**Inference:** A better mechanistic story is ordinary conditional generation: the instruction changes the context from which output tokens are predicted, and early generated choices then become part of the prefix conditioning later choices. That can produce stylistic continuity without a permanent route or special memory. This explanation is compatible with the provider guidance but does not by itself prove the Swedish phrase improves prose.

## Recommended validation

Adopt the owned anti-slop reference and trial one compact, language-owned register sentence, but settle its wording and position by evaluation rather than neural folklore. OpenAI explicitly recommends pinning model snapshots and building evaluation suites because prompt behaviour varies across model types and snapshots ([prompt engineering guidance](https://developers.openai.com/api/docs/guides/prompt-engineering)). A useful test crosses Claude Opus and GPT-5.6 Sol, short and interview-length sources, several genres, and register instruction absent versus high-authority versus final-user-instruction placement; blinded native-language reviewers should judge idiomaticity, concrete journalistic register, voice fit, unsupported claims, and named slop patterns.
