# Compilation judgement

Read this reference while turning one durable child and its parent into a current executor bundle. `$LIBRARY/references/compiled-plan.md` is the binding output Interface; this file governs the judgement that fills it without inventing product intent or copying its format into a private contract.

## Reconcile the durable and current views

Start from the child's complete tracker source and the relevant parent outcome, decisions, and constraints. Treat the child's publication vantage and compilation hints as directions for recon, not as the executor base: compare them with the captured `HEAD`, inspect what changed in the named areas, then describe only the current committed tree.

Resolve every binding statement to its source. Later child comments override earlier contradictory child text. Parent decisions constrain the child; sibling detail does not. Repository rules constrain implementation; current exemplar code remains advice unless the rule makes its shape binding. Where two sources genuinely conflict, stop and classify the conflict before drafting around it.

Use owner intent only from the durable sources or applicable owner context already written back to the child. Technical decisions inside established frames belong in the plan with their reason. A product, architecture, priority, risk, or scope choice the sources do not settle is owner-owned and makes the child parkable, never a blank for the executor.

## Fix scope before steps

Translate the ticket boundary into an exact footprint against the captured tree. Name every committed file whose bytes support the binding contract or Advisory appendix under `reads`, and every allowed executor write under exactly one of `modifies`, `creates`, or `deletes`. Keep compiler-owned tests and dispatcher-owned shared writes out of executor ownership. Name an exact serial registry only when execution consumes an identifier from it.

Paths are literal repository-relative POSIX paths. A directory, glob, example list, or phrase such as “files under” cannot become an exact footprint. When current recon exposes one technically determined path, take it and explain the choice. When more than one product scope is honest, stop for the owner instead of granting all of them.

Inspect all call sites and consumers of a changed shared contract before fixing the footprint. Every path the implementation must change is in the right write class; every file whose current content the plan relies on is in `reads`. A fresh finding outside those boundaries becomes a STOP condition, not implied executor authority.

## Allocate serial resources

Determine each plan's exact serial-resource count during scope recon; a possible dynamic serial need means scope is not fixed yet. Only after the whole selected batch has settled may the Skill apply `$LIBRARY/references/compiled-plan.md`'s allocation rule. Record its resulting registries and identifiers without restating or varying that shared algorithm.

## Write the two registers

Fill every section the shared Interface requires. The Binding contract is complete enough for an executor to act without tracker access or rules archaeology: identity and provenance, goal, scope and exact footprint, inlined invariants, current context with source-blob and line-qualified excerpts, seam tests, executable verification, machine-checkable done criteria, and STOP conditions.

Give each acceptance criterion one stable identifier and an independent machine check. Add the footprint and compiler-owned-test integrity criteria. A command is an exact executable string with working directory, environment assumptions, expected exit, and any destructive, interactive, or network behaviour exposed. A checkbox that repeats product prose is not machine-checkable.

The Advisory appendix may recommend ordered steps, exemplars, likely edit points, and focused commands. It may not add scope, intent, invariants, tests, or done criteria. An executor may discard every proposed step while remaining bound by the contract.

Write `manifest.json` as the shared machine-readable subset and materialise finished tests below `tests/` at the Interface's mirrored destinations. Compare prose, manifest, and overlay explicitly; disagreement invalidates the candidate rather than letting one register outrank another.

## Author the seam tests

Translate the ticket's approved seam contract into the smallest finished compiler-owned test that observes the promised behaviour through that public boundary. The test may constrain settled product intent; it may not refine an ambiguity by silently choosing for the owner or couple itself to private implementation.

For every destination, record the base blob from captured `HEAD`, the compiled blob of the finished bytes, the focused command, and the expected red result. Overlay the exact bytes on a clean detached tree and observe the command fail at the intended behavioural assertion. A syntax, import, fixture, collection, or environment failure is no red test, and neither is an unrelated assertion.

An already green test means either the behaviour already exists or the test is insensitive. Establish which from the public seam: report an already-satisfied ticket instead of manufacturing a change, or strengthen the test inside the approved seam and observe the meaningful red result. Seal the destination and blob identities only after that result is recorded.

## Review the candidate

Before cold read, account for every acceptance criterion, every path and serial resource, every excerpt address, every manifest reference, and every test overlay entry. Reproduce the bundle fingerprint from the candidate bytes. If any executor decision would still change product scope or observable behaviour, the candidate is incomplete even when its schema validates.

Apply the shared worked fixtures as concrete boundary checks:

| Fixture | Compiler finding | Required action |
| --- | --- | --- |
| Valid | Every Git, source, bundle, footprint, allocation, and test identity agrees | Send the complete candidate to cold read |
| Stale source | A child or parent fingerprint changed while Git and bundle identities still agree | Recompile that child from the complete current thread |
| Changed HEAD | The integration branch moved while tracker and bundle identities still agree | Restart the whole batch from the new tip |
| Changed test | The overlay or materialised compiler-owned test differs from its compiled blob | Reject the candidate or execution result; never accept altered test bytes |
| Out of footprint | A required or resulting executor write has no exact executor-owned class | Reject the candidate or execution result; widen only through honest recompilation |
