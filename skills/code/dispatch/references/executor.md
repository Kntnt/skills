# Dispatch executor brief

Fill this brief for one recorded Route decision and give it to that execution role. The dispatcher retains every decision, review, Git integration, tracker mutation, and final report on the unchanged main seat.

## Inputs

- Complete compiled plan: `<absolute-escrow-plan-path>`
- Worktree at the plan's captured `HEAD`: `<absolute-worktree-path>`
- Executor's ticket-specific scratch: `<absolute-scratch-path>`
- Executor's exact write paths: `<modifies, creates, deletes>`
- Compiler-owned tests: `<destinations, compiled blobs, focused commands>`
- Serial allocations: `<registries and exact identifiers>`
- Dispatcher-owned write proposal: `<absolute-proposal-path or none>`
- Accepted checkpoint: `<absolute-patch-path or none>`
- Review finding: `<exact constructive finding or none>`

## Execution contract

Work only in the supplied worktree and scratch. Read the complete compiled plan as the sole requirement: every part of its Binding contract is owed, while its Advisory appendix may be replaced by a better route that stays inside the Binding contract and is reported.

Modify, create, or delete only the exact executor-owned paths. The compiler-owned tests are immutable input: run them, but never change, replace, delete, relocate, regenerate, or stage different bytes. Use only the recorded serial allocations; another identifier activates the plan's STOP condition. Write proposed content for a dispatcher-owned path only to the dispatcher-owned write proposal channel, never to its repository destination.

The brief supplies no tracker access, rules archaeology, sibling design, compiler notes, journal, integration credentials, or authority to expand scope. A fact outside the plan that prevents honest execution is reported as a STOP condition with its exact evidence. A newly discovered numbered dependency is reported by reference; an owner choice is stated as one question rather than answered.

## Return

Return the implementation result, focused command outcomes, every departure from the Advisory appendix, every STOP condition encountered, and any dispatcher-owned write proposal. State every changed repository path and scratch artifact. The report is input to independent review and never evidence that the result is correct.

For REVISE, keep the same execution role and apply the exact constructive finding to the clean captured base plus the last accepted checkpoint. A rejected ownership-violating patch is evidence only and is never an input. When live conversation continuity is lost, the dispatcher may rehydrate this same role and recorded Route point with this complete brief, the last accepted patch, and the exact finding; fresh context does not spend a revision round.
