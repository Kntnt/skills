# Model Routing Module

This is the public routing Interface owned by model-selector. A caller invokes `/model-selector route <path>` with the single canonical UTF-8 JSON envelope defined by `route-request.schema.json`. The response conforms to `route-response.schema.json` and contains `schema_version`, `snapshot`, and `decisions`; `decisions` contains exactly one decision per request in the same order. Route is offline, non-interactive, and read-only: it never starts setup, performs no network access, research, evaluation, or evidence refresh, and writes no configuration or evidence.

## Request contract

The accepted `schema_version` is the integer `1`. The envelope always contains an ordered `requests` array, including for one request. Every request supplies a unique `request_id`, `authority` (`execution` or `verdict`), `stage`, `workload` containing the verbatim workload material, optional `workload_cohort`, `workload_tags`, `reversible`, and `checker`. Optional `rubric` preserves the frozen human or machine quality criteria, while optional `required_capabilities` carries normalized workload requirements backed by frozen categorical capability facts, never invented numeric scores. `checker` identifies an external checker, a declared failure signal, or explicitly says neither exists. Optional `overrides` has only `model` and `deliberation`; optional `retry_available` says whether the caller already owns one retry, optional `prior` carries the complete earlier point, and optional `verified_failure` binds an independently verified failure and checker to that exact point. Human recommend may also supply `economics` with `decision` (`route` or `renew`) and at most one numeric budget or quality floor. The envelope contains exactly one of `snapshot`, copied unchanged from an earlier response, or `context`, assembled by the public Skill adapter from the selected local profile and evidence plus current Harness and main-seat facts.

The public deliberation scale is exactly `low`, `medium`, `high`, `xhigh`, and `max`. Omission means automatic selection. Numeric values, provider control names, `auto`, `none`, `off`, and default aliases are invalid public values. A model override is an exact configured model version or an alias resolving unambiguously inside the snapshot; a family name is not exact.

Reject a malformed artifact or structurally malformed shared context as a whole before routing because no valid response snapshot can reproduce decisions from it. Semantic snapshot failures and request-level failures instead produce ordered refused decisions so one bad request does not erase its peers' audit results.

## Frozen routing snapshot

When `context` is supplied, `freeze_context()` freezes its profile revision; evidence vintage and identity; active Harness inventory and actual spawn capabilities; main-seat identity including its complete model, channel, adapter, surface, native control, serving mode, tools, policy, and two-dimensional capability ceiling; verified portable-to-native control mappings and their native order; categorical workload capabilities; separate commercial facts on each point; and override policy. Give the canonical snapshot a deterministic `snapshot_identity` over those facts and return the complete snapshot. A supplied snapshot whose identity no longer matches its canonical facts is invalid rather than silently re-signed.

When a snapshot is supplied, validate it and use only its frozen profile, aliases, evidence, prices, quotas, Harness facts, main-seat identity, mappings, and policies. Never silently adopt a later profile revision, alias target, evidence record, price, quota, or Harness capability. A structurally incomplete shared snapshot receives an artifact refusal; a structurally valid snapshot with a mismatched identity or cross-field invariant refuses affected requests.

## Exact-point selection

Use the same complete-point, hard-filter, evidence-class, multidimensional-cost, uncertainty, and escalation rules as human `recommend`; both adapters call the same executable selection core in `scripts/route.py`. Begin with enabled points in the snapshot. Require every normalized workload capability to appear in a point's frozen categorical capability facts, then intersect the survivors with the active Harness's actual spawn capabilities and exclude every channel without a concrete current-Harness adapter. A frozen adapter lists exact models, channel, Harness, surface, serving modes, native controls, tool sets, policies, and a complete flag mapping; reachability requires every field to match and every destination flag to be unique, and translation emits every launch-relevant field. Exclude incomplete points, unavailable native mappings, unsafe workload points, and execution points above either dimension of the complete main-seat ceiling.

An explicit model locks only that dimension and leaves deliberation selectable. An explicit deliberation locks only that dimension and restricts candidates to points with a verified mapping for that exact portable value. Refuse an unavailable or ambiguous override rather than substituting a neighbor, alias, or model. Refuse an explicit point above the main-seat ceiling. Automatic execution selection never exceeds the complete main-seat capability. Because inheritance launches without explicit controls, a locked dimension is resolved before every graceful inheritance branch: an execution request carrying any override is selected exactly or refused, never inherited.

Portable levels define adjacency only; adjacency does not imply quality ordering, and matched evidence may prefer a lower portable level. For every model, channel, surface, and Harness point, resolve a usable portable value to its verified exact native effort, reasoning, thinking mode, or thinking budget. Route never interpolates, rounds, or guesses a missing mapping. Resolve `max` within the frozen snapshot to the highest verified native value for that exact point; include that resolved value in the configuration fingerprint.

Matched representative measurements are required for a `measurement_based` selection. Applicability binds the configuration fingerprint, model, portable and native control, channel, Harness, surface, serving mode, workflow stage, workload cohort, coverage, uncertainty, and quality floor. Use `mixed` when measurements exist but a decision-relevant match or assumption remains, and `heuristic` for a visibly cold-start choice. Stale evidence retains its recorded vintage and cannot silently support a fresher claim. Missing evidence remains unknown, represented as `null` where a field exists, and never becomes zero, dominance, a cleared quality floor, or measurement-based support; a measured point cannot dominate an unknown candidate. Exact representative evidence below the quality floor excludes that point from heuristic selection rather than letting it re-enter as unmeasured. Cash, rolling quota, weekly quota, allocated subscription cost, and latency remain separate dimensions; Pareto dominance may select a unique frontier point, but multiple non-dominated points produce audited `underdetermined_frontier` inheritance unless the frozen profile supplies explicit shadow prices for every non-cash dimension. Human budget and quality-floor constraints use marginal cash for route decisions and allocated subscription cost for renew decisions only when that chosen dimension is known, while every other dimension remains visible.

Verdict authority always returns exact main-seat inheritance and is never price-optimized. If the Harness cannot represent exact inheritance of the frozen main seat, refuse it.

## Decision contract

Each decision has `request_id`, exactly one `status` value—`selected`, `inherit`, or `refused`—and `audit`. The three shapes are discriminated and must not be partially combined.

A `selected` decision alone carries `launch`. It names the exact configured model version or resolved alias, adapter, channel, surface, native deliberation control, portable deliberation, serving mode, tools, policy, configuration fingerprint, and Harness-native launch arguments. It also carries evidence class, provenance, exclusions with stable codes and details, and any bounded next escalation. `launch.arguments` must be a complete instruction produced by the frozen Harness adapter, never generic provider syntax. `audit.exclusions` repeats the stable hard-filter facts used by compact and human adapters rather than leaving successful filtering invisible.

An `inherit` decision carries `inheritance`, never `launch`, and states the exact main-seat identity for verdict authority or the audited reason no safe execution override is applied. Verdict inheritance is the exact frozen main seat. Every execution inheritance instead launches without explicit model or deliberation arguments, so it is reserved for automatic dimensions: a missing profile may inherit, insufficient discriminating evidence may inherit when selection would require invented facts, and unmeasured, below-floor, or non-dominated evidence may inherit rather than invent a winner. When automatic execution has no overrides, the Harness supports inherited subagents, and no complete current-Harness adapter can express a safe point, route inherits with `unavailable_selection_controls` so fresh-context delegation remains available without invented launch controls. An execution request that locks a dimension refuses with `unavailable_override` and names the inheritance branch that blocked exact selection, because inheritance would silently execute the user's exact instruction on the main seat.

A `refused` decision carries `reason` with one stable code and detail, never `launch` or launch arguments. Stable request-decision codes are `invalid_profile`, `invalid_snapshot`, `invalid_request`, `ambiguous_override`, `unavailable_override`, `unknown_main_seat_ceiling`, `above_main_seat_ceiling`, `unrepresentable_verdict_inheritance`, and `empty_safe_candidate_set`. Before request routing, the process seam instead returns an empty ordered decision list plus one `artifact_refusal` for `invalid_arguments`, `unreadable_artifact`, `malformed_json`, `invalid_snapshot`, or an invalid top-level request artifact; it emits no traceback or partial launch data.

The `audit` object records the snapshot identity, evidence class when applicable, provenance identities, and exclusions considered. Provenance points to frozen profile and evidence identities rather than restating workload material.

## Bounded escalation

Emit a bounded next escalation only for reversible, objectively checked execution with an external checker or declared failure signal and `retry_available: true`. Self-confidence is not verification. The prior point, selected point, failure record, native control, adapter, and checker identity must all describe the same failed attempt. Without matched policy evidence supporting a different route, the next escalation is one adjacent portable level on the same model, only when that complete point has an exact verified native mapping, a concrete launch adapter, and remains at or below both main-seat ceilings. Escalation returns the next native control, fingerprint, and full launch arguments, consumes only a retry the caller already owns, and creates no attempt.

Human `recommend` retains its evidence banner, frontier neighbors, uncertainty, exclusions, and experiment brief. Route is the compact machine-readable form; neither form owns separate selection semantics.
