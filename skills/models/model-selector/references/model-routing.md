# Model Routing Module

This is the public routing Interface owned by model-selector. A caller with runtime facts first invokes `/model-selector context <path>` with the envelope defined by `context-request.schema.json`, then passes the returned complete artifact to `/model-selector route <path>` under `route-request.schema.json`. A later context call accepts the frozen snapshot and returns it unchanged beside new ordered requests. The route response conforms to `route-response.schema.json` and contains `schema_version`, `snapshot`, and `decisions`; `decisions` contains exactly one decision per request in the same order. Context and Route are offline, non-interactive, and read-only: neither starts setup, performs network access, research, evaluation, or evidence refresh, or writes configuration or evidence.

## Request contract

The accepted `schema_version` is the integer `1`. The envelope always contains an ordered `requests` array, including for one request. Every request supplies a unique `request_id`, `authority` (`execution` or `verdict`), `stage`, `workload` containing the verbatim workload material, optional `workload_cohort`, `workload_tags`, `reversible`, and `checker`. Optional `rubric` preserves the frozen human or machine quality criteria, while optional `required_capabilities` carries normalized workload requirements backed by frozen categorical capability facts, never invented numeric scores. `checker` identifies an external checker, a declared failure signal, or explicitly says neither exists. Optional `overrides` has only `model` and `deliberation`; optional `retry_available` says whether the caller already owns one retry, optional `prior` carries the complete earlier point, and optional `verified_failure` binds an independently verified failure and checker to that exact point. Human recommend may also supply `economics` with `decision` (`route` or `renew`) and at most one numeric budget or quality floor. Context accepts exactly one of `runtime` or `snapshot`; its success replaces runtime with complete derived `context` and passes the ordered requests through. Route then accepts exactly one of `snapshot`, copied unchanged from an earlier response, or that complete derived `context`.

Runtime names the active Harness, its stable inventory revision and inheritance support, an attestation whose `verified` value equals that same inventory revision wherever it carries a launch fact by inheritance, and the exact main-seat model, portable and native deliberation, surface, serving mode, tools, policy, and optional channel. Context validates `config.json` against `profile.schema.json`, retains only enabled validated selections as mappings, and retains such a selection even when its model has no seed, its selected control is not verified as launchable, or no shipped adapter covers its configured surface. An `all_supported` policy with no seed support freezes empty controls and capabilities rather than inventing a portable mapping or rank. Missing or invalid configuration yields `profile: null`; a main seat absent from the profile or unscored by a shared benchmark yields empty mappings and an unknown model ceiling. Neither state starts setup.

Model capability ranks come only from numeric independent evaluation priors in the shipped seed. Context keeps the newest version of each benchmark definition, selects the one scoring the main seat and the largest number of candidate models with newest version breaking a tie, and uses each model's maximum score within that benchmark. A candidate absent from that comparison keeps `model_capability: null` and is excluded as `capability_rank_unavailable`; no prose capability tag becomes a number. Portable control capabilities are the fixed ordinals `low: 1`, `medium: 2`, `high: 3`, `xhigh: 4`, and `max: 5`, restricted to exact supported mappings. Commercial dimensions are `null` because token schedules without a usage basis are provenance rather than per-attempt cost.

The public deliberation scale is exactly `low`, `medium`, `high`, `xhigh`, and `max`. Omission means automatic selection. Numeric values, provider control names, `auto`, `none`, `off`, and default aliases are invalid public values. A model override is an exact configured model version or an alias resolving unambiguously inside the snapshot; a family name is not exact.

Reject a malformed artifact or structurally malformed shared context as a whole before routing because no valid response snapshot can reproduce decisions from it. Semantic snapshot failures and request-level failures instead produce ordered refused decisions so one bad request does not erase its peers' audit results.

## Frozen routing snapshot

When `context` is supplied, `freeze_context()` freezes its profile revision; evidence vintage and identity; active Harness inventory and actual spawn capabilities; main-seat identity including its complete model, channel, adapter, surface, native control, serving mode, tools, policy, and two-dimensional capability ceiling; verified portable-to-native control mappings and their native order; categorical workload capabilities; separate commercial facts on each point; and override policy. Give the canonical snapshot a deterministic `snapshot_identity` over those facts and return the complete snapshot. A supplied snapshot whose identity no longer matches its canonical facts, or whose adapter attestation names a different inventory identity, is invalid rather than silently re-signed.

When a snapshot is supplied, validate it and use only its frozen profile, aliases, evidence, prices, quotas, Harness facts, main-seat identity, mappings, and policies. Never silently adopt a later profile revision, alias target, evidence record, price, quota, or Harness capability. A structurally incomplete shared snapshot receives an artifact refusal; a structurally valid snapshot with a mismatched identity or cross-field invariant refuses affected requests.

## Exact-point selection

Use the same complete-point, hard-filter, evidence-class, multidimensional-cost, uncertainty, and escalation rules as human `recommend`; both adapters call the same executable selection core in `scripts/route.py`. Begin with enabled points in the snapshot. Require every normalized workload capability to appear in a point's frozen categorical capability facts, then intersect the survivors with the active Harness's actual spawn capabilities and exclude every channel without a concrete current-Harness adapter. A frozen adapter lists exact models, channel, Harness, surface, serving modes, native controls, tool sets, policies, and a complete launch translation. Each launch-relevant field has exactly one destination: a bare or templated `parameter` emits its exact Harness-native argument, `fixed` must equal the point and emits nothing, and `carried_by: inheritance` must equal the corresponding frozen main-seat fact, requires the session attestation, and emits nothing. Only emitted parameter names must be unique. Exclude incomplete points, unavailable native mappings, unsafe workload points, and execution points above either dimension of the complete main-seat ceiling.

One destination names no flag. A native control mapped to `{"carried_by": "inheritance"}` is carried by inheritance: the active Harness applies the spawning session's own value to the subagent it starts, so the mapping completes the translation, emits no launch argument, and is a different fact from a missing mapping. Such a destination is reachable only where the adapter also carries `inheritance_attestation`, the declaring session's statement that the Harness applies that value to subagents by default — verified against what the Harness actually does before the adapter is declared, never assumed. The same mapping without it launches nothing. A carried control is not a dimension route selects over: it resolves to the frozen main seat's exact portable and native value, the point yields that one variant instead of one per mapped level, only the model dimension of the ceiling can exclude it, and the configuration fingerprint carries that effective seat value, so evidence binds and accrues to the configuration inheritance actually launches. An explicit deliberation lock is never satisfied there: the variant is excluded with `carried_control_not_selectable` and the request refuses with `unavailable_override`. An adapter that addresses the control and one that carries it, both declared for the same exact point, are a contradictory declaration rather than a choice, and the carried one is taken; two seams of one Harness that really do differ are told apart by surface, as every other adapter dimension is.

An explicit model locks only that dimension and leaves deliberation selectable. An explicit deliberation locks only that dimension and restricts candidates to points with a verified mapping for that exact portable value. Refuse an unavailable or ambiguous override rather than substituting a neighbor, alias, or model. Refuse an explicit point above the main-seat ceiling. Automatic execution selection never exceeds the complete main-seat capability. Because inheritance launches without explicit controls, a locked dimension is resolved before every graceful inheritance branch: an execution request carrying any override is selected exactly or refused, never inherited.

Portable levels define adjacency inside one model and nothing about quality; adjacency does not imply quality ordering, and matched evidence may prefer a lower portable level. For every model, channel, surface, and Harness point, resolve a usable portable value to its verified exact native effort, reasoning, thinking mode, or thinking budget. Route never interpolates, rounds, or guesses a missing mapping. Resolve `max` within the frozen snapshot to the highest verified native value for that exact point; include that resolved value in the configuration fingerprint.

Matched representative measurements are required for a `measurement_based` selection. Applicability binds the configuration fingerprint, model, portable and native control, channel, Harness, surface, serving mode, workflow stage, workload cohort, coverage, uncertainty, and quality floor. Use `mixed` when measurements exist but a decision-relevant match or assumption remains, and `heuristic` for a visibly cold-start choice. An automatic request whose candidates are all unmeasured takes the cold-start heuristic: the strongest complete candidate for irreversible work with neither an external checker nor a declared failure signal, and the weakest complete candidate for everything else. Where the frozen ledger holds no record at all, `override_policy.cold_start` decides whether such a request may start anyway — `select` takes the heuristic, `inherit` declines it with `insufficient_evidence`. Reversible, objectively checked work takes the heuristic under either value, its failure being caught by the caller's own checker and its cheap start being what this contract promises it. Stale evidence retains its recorded vintage and cannot silently support a fresher claim. Missing evidence remains unknown, represented as `null` where a field exists, and never becomes zero, dominance, a cleared quality floor, or measurement-based support; a measured point cannot dominate an unknown candidate. Exact representative evidence below the quality floor excludes that point from heuristic selection rather than letting it re-enter as unmeasured. Cash, rolling quota, weekly quota, allocated subscription cost, and latency remain separate dimensions, and every one of them is compared as the exact point's own observed mean rather than as the price its mapping advertises. Pareto dominance may select a unique frontier point. Where several survive, the order is: explicit shadow prices for every non-cash dimension where the frozen profile supplies them, then the frozen `override_policy.objective`. `cost_first`, the shipped default, takes the lowest observed cash and breaks a tie on the lowest Time to Verified Pass; `time_first` reverses the two and breaks a further tie on the Rung order. Where no surviving point exposes cash at all, which is what a subscription seat looks like, `cost_first` orders by the Rung order — the weaker model and the lower deliberation first — and names itself `cost_first_rung_order`. A dimension some surviving points measured and others did not orders nothing: that is audited `objective_metrics_missing` inheritance, and an unmeasured Time to Verified Pass is the same. `underdetermined_frontier` remains for a frontier the applicable order cannot separate at all. Human budget and quality-floor constraints use marginal cash for route decisions and allocated subscription cost for renew decisions only when that chosen dimension is known, while every other dimension remains visible.

Verdict authority always returns exact main-seat inheritance and is never price-optimized. If the Harness cannot represent exact inheritance of the frozen main seat, refuse it.

## Decision contract

Each decision has `request_id`, exactly one `status` value—`selected`, `inherit`, or `refused`—and `audit`. The three shapes are discriminated and must not be partially combined.

A `selected` decision alone carries `launch`. It names the exact configured model version or resolved alias, adapter, channel, surface, native deliberation control, portable deliberation, serving mode, tools, policy, configuration fingerprint, and Harness-native launch arguments. It also carries evidence class, provenance, exclusions with stable codes and details, and any bounded next escalation. `launch.arguments` must be a complete instruction produced by the frozen Harness adapter, never generic provider syntax. `audit.exclusions` repeats the stable hard-filter facts used by compact and human adapters rather than leaving successful filtering invisible.

An `inherit` decision carries `inheritance`, never `launch`, and states the exact main-seat identity for verdict authority or the audited reason no safe execution override is applied. Verdict inheritance is the exact frozen main seat. Every execution inheritance instead launches without explicit model or deliberation arguments, so it is reserved for automatic dimensions: a missing profile may inherit, insufficient discriminating evidence may inherit when selection would require invented facts, and unmeasured, below-floor, or non-dominated evidence may inherit rather than invent a winner. When automatic execution has no overrides, the Harness supports inherited subagents, and mappings are empty or every variant is excluded only as `adapter_unreachable` or `capability_rank_unavailable`, route inherits with `unavailable_selection_controls` so fresh-context delegation remains available without invented launch controls. An execution request that locks a dimension refuses with `unavailable_override` and names the inheritance branch that blocked exact selection, because inheritance would silently execute the user's exact instruction on the main seat; with an unknown main-seat rank, that explicit request retains `unknown_main_seat_ceiling`.

A `refused` decision carries `reason` with one stable code and detail, never `launch` or launch arguments. Stable request-decision codes are `invalid_profile`, `invalid_snapshot`, `invalid_request`, `ambiguous_override`, `unavailable_override`, `unknown_main_seat_ceiling`, `above_main_seat_ceiling`, `unrepresentable_verdict_inheritance`, and `empty_safe_candidate_set`. Before request routing, the process seam instead returns an empty ordered decision list plus one `artifact_refusal` for `invalid_arguments`, `unreadable_artifact`, `malformed_json`, `invalid_snapshot`, or an invalid top-level request artifact; it emits no traceback or partial launch data.

The `audit` object records the snapshot identity, evidence class when applicable, provenance identities, and exclusions considered. Provenance points to frozen profile and evidence identities rather than restating workload material.

Every selected or inherited execution decision also carries `audit.standing_policy`, the Standing Policy that decision ran under: `policy_revision`, the Cohort's own integer revision, `0` while the shipped default is its whole policy; `workload_cohort`, the request's literal Cohort or `null`; the resolved `starting_rung`, `current_rung`, `floor`, `ceiling`, and `next_rung_up`, each a concrete `{model, portable_deliberation}` Rung or `null`; and `start_fallback`, `null` or `standing_policy_start_unavailable`. `current_rung` is the launched point under selection and the main seat under inheritance. An inheritance with no surviving candidate still names the revision and the Cohort and reports every Rung as `null`. A verdict inherits by authority rather than by policy and carries no such block.

## Standing policy

The frozen `override_policy.standing_policy` carries a `default` entry and a `cohorts` object keyed by the request's literal `workload_cohort`, byte for byte. A request naming no Cohort routes under the default and can never receive an override. Each entry names a `starting_rung`, an inclusive `floor` and `ceiling`, the `failure_threshold` that may move it, its own `revision`, and the `exploration` budget. The shipped values are symbolic — `starting_rung: "cold_start"`, `floor: "weakest_enabled"`, `ceiling: "main_seat"` — and each resolves against the individual request's own filtered candidate ladder, so under them the ladder's own ends are the bounds and nothing is excluded. `cold_start` means exactly the cold-start heuristic this contract already states, `cold_start_strongest` or `cold_start_weakest` by the request's safety facts; it is unrelated to `override_policy.cold_start`, which stays what it is.

Bounds are read on the total order of `model_capability` and then position on the portable scale, both ends inclusive; a Rung whose deliberation the Harness carries is compared on the model dimension alone, launching as it does at the seat's own control. An otherwise eligible point outside the resolved range is excluded as `standing_policy_out_of_bounds` and is gone for every later step, so the same resolved ceiling bounds selection and escalation alike. A concrete `starting_rung` replaces both cold-start branches where the exact Rung is still an eligible reachable candidate; where it is not, routing falls back to the cold start and audits `standing_policy_start_unavailable` rather than clamping silently or guessing a replacement. A concrete bound naming a model the snapshot no longer ranks bounds nothing and resolves to the ladder's own end.

A Standing Policy ratchets up only. Nothing moves it down but a user's `config policy reset`, it is stored by scripts rather than edited by hand, and it enters the snapshot identity, so a change is a new snapshot and never reaches a run already frozen.

## Exploration

Each entry's `exploration` names an `epsilon`, a `max_per_run` budget, and a `seed`. Where a draw lands inside epsilon and the budget is unspent, routing returns an Exploration Attempt: the one Rung below the point ordinary selection resolved, chosen by the same adjacency `next_escalation` climbs and read downward. It is a different thing from `recommend`'s *exploration start*, which classifies a cold-start point nothing has measured.

A request is explorable only where it states reversible work, an external or declared `checker`, `retry_available: true`, and a `workload_cohort`; carries an `exploration_draw`; carries neither `prior` nor `verified_failure`, a retry existing to spend the escalation a verified failure earned; and routes under a frozen `objective` of `cost_first`. An explicit `model` or `deliberation` lock outranks the draw: where the step would move a locked dimension, ordinary production selection is returned. The destination may equal the resolved inclusive floor and never falls below it, the pool being bounded before adjacency is read.

`exploration_draw` is a number in `[0, 1)` the caller supplies and `route` never invents; `exploration_attempts_used` is what this Cohort has already spent in this run. Both are optional, and a request carrying neither routes exactly as it did before either existed. Across one ordered batch `route` carries its own per-Cohort counter, initialized from the stated count and raised on each accepted exploration, so an opening batch cannot spend a budget of one twice. Two requests of one Cohort stating different counts refuse the whole artifact as `inconsistent_exploration_state`. The count is a ceiling on accepted decisions rather than on launches: an attempt prepared for dispatch and then prevented still spends it.

An exploration decision's `audit.decision_policy` is `exploration`, and its `audit.exploration` names the `production_rung` it stepped from, the `selected_rung` it launched on, and the `production_decision_policy` the ordinary order would have reported. The attempt that follows a failed one is routed as any other retry: production selection returns the Cohort's own Rung, with no escalation bound to it, the prior point not being the one selection chose.

## Bounded escalation

Emit a bounded next escalation only for reversible, objectively checked execution with an external checker or declared failure signal and `retry_available: true`. Self-confidence is not verification. The prior point, selected point, failure record, native control, adapter, and checker identity must all describe the same failed attempt. Without matched policy evidence supporting a different route, the next escalation is one adjacent Rung. Escalation returns that Rung's model, native control, fingerprint, and full launch arguments, consumes only a retry the caller already owns, and creates no attempt.

A Rung is two-dimensional, and it is always an exact point the same request already reaches: hard filters, explicit locks, adapter reachability, and both main-seat ceilings have all applied before adjacency is read, so escalation never reintroduces a point the request excluded. Inside one exact mapping the Rung is the next mapped portable value in scale order, an unmapped level skipped rather than refused. Where that mapping's scale is exhausted, or the Harness carries the deliberation control and no adapter addresses it, the Rung is instead the next model up by `model_capability` regardless of provider, entered at the lowest portable value of its own that survives the same filters, a model none of whose values survive being passed over. Among the mappings sharing that next capability, the target is the one with the lower known `cash`, a known price ordering ahead of an unknown one, ties settled after it by model, channel, surface, serving mode, adapter, and scale position, so one exact launch is always determined. A carried target keeps the seat's own inherited deliberation and is fingerprinted at it rather than claiming a level of the model it moves into. A request that locks the deliberation emits no escalation in either dimension, that value being the caller's own; a request that locks the model reaches no other model to step into. Where nothing is adjacent, none is emitted, as at the top of a scale. Every number this ordering reads is the frozen snapshot's own, never a fact route looks up for itself.

Human `recommend` retains its evidence banner, frontier neighbors, uncertainty, exclusions, and experiment brief. Route is the compact machine-readable form; neither form owns separate selection semantics.
