# Run observations

Use this reference for `observe`, beside `evidence-ledger.md` for the public `record` command, and as the shared Library contract Orchestrate calls at verdict. A routed caller — Orchestrate, delegation, or any other Skill that launched work from a route decision — emits evidence under one representation. The `observe` command is offline, non-interactive, and writes the artifact the caller named. It starts no setup, performs no network access, evaluation, or research, and writes no configuration or profile. Asked for `--import` it also writes the evidence ledger and the affected derived frontiers; asked for nothing it writes the artifact alone. Library `record` is the sole ledger mutation seam, and what may reach it without a person is one rule the Library holds: the public `record` command reaches it because the user invoked `record`, while Orchestrate at its verdict and `--import` on a routed caller's behalf reach it only for machine-judged attempts and non-model conditions.

## The completed attempt

A caller supplies one canonical UTF-8 JSON envelope holding `schema_version` `1` and an ordered non-empty `attempts` array. Each attempt describes one routed execution that has reached an eligible completion boundary, and carries: `attempt_id`, the caller's own request name; `session_identity` and `task_identity`, both opaque; optional opaque `run_identity`; `workload_stratum`; `attempt_index`, counting from one within the work the task identifies; `harness`, naming the active Harness and its inventory revision; `benchmark`, whose `key` identifies the workload or benchmark the attempt is comparable within; `decision`, the public route decision the attempt launched from, kept whole; `outcome`; `completed_at`; and optionally `started_at`, `resolution`, `measurements`, `prior_attempt_id`, `checker_charge`, `seed`, `artifact_hashes`, and the three Cohort identity fields below.

`stage`, `workload_cohort`, and `workload_tags` are the Cohort of the route request the attempt answered, copied verbatim from it so the request that was routed and the observation the ledger keeps name the same work. They are optional and travel as one: an attempt carrying only some of them names no Cohort and is emitted with all three null, which is what every row written before routed callers carried a Cohort holds. A field that is present and is not the identity it claims to be — an empty or non-string `stage` or `workload_cohort`, a `workload_tags` that is not an array of non-empty strings — refuses the attempt rather than being dropped. Tags are emitted sorted and de-duplicated. `benchmark.key` stays the identity of the check or comparison definition and is not the Cohort.

The workload strata are `initial_build`, `amend`, `collision_repair`, `rebuild`, `mechanical_wave_fix`, and `delegated_execution`. An initial build and a mechanical wave fix are different work rather than the same work priced twice, and an amend is a distinct attempt at the first one's work, so each is its own stratum and its own attempt.

The attempt begins from its immutable route decision and the configuration fingerprint inside it. A `selected` decision names the exact point; an `inherit` decision ran on the frozen main seat and is fingerprinted from that seat; a `refused` decision launched nothing. Nothing is re-resolved here: the model, the native deliberation control, the channel, the adapter, the evidence class, and the provenance are read out of the decision the caller already holds, never chosen again.

## What establishes an outcome

An outcome is `pass`, `fail`, `abstain`, or `infra_error`, and only something external to the attempt may establish it. A decisive `pass` or `fail` requires an authority of `independent_verifier`, `objective_checker`, `frozen_rubric`, `declared_failure_signal`, or `user_confirmation`, together with a checker that names itself and is marked independent. A builder's or a subagent's self-report is never one: an authority of `self_report`, a checker that is not independent, and an unchecked subjective success are each refused rather than downgraded, so unchecked work cannot become measurement-based quality evidence.

`abstain` and `infra_error` carry a non-model condition instead: `mechanical_hinder`, `open_decision`, `discovered_dependency`, or `tracker_failure`. A mechanical hinder and a tracker failure are infrastructure; an open product decision and a newly discovered dependency are abstentions. They may be established by the Harness or the tracker as well as by a checker, they are retained as what happened, and they never enter a configuration's quality: `record` computes a conservative success rate from judged model outcomes alone and counts the rest beside it. A decisive result offered together with a condition is refused, because the two are different claims about the same attempt. A merge collision after a passed build is not another result for that attempt; its routed repair is a separate attempt.

## What an artifact carries

`observe` builds each observation field by field from an allow-list, so nothing reaches the artifact by sitting beside the facts in the input. An observation carries the run key and the identities it derives from — configuration fingerprint, benchmark key, opaque task identity, seed, optional run identity, attempt index — the opaque run identity as its own top-level field, the opaque session identity, the workload stratum, the three Cohort identity fields or their three nulls, the exact routed point and the point that actually served with the fallback it resolved from, the outcome with its authority, checker, condition, and permitted score dimensions, the available token categories and tool counts, retries, cash, provider bill, allocated subscription cost, and quota facts under exactly one accounting basis, wall and first-useful-output latency, both instants, sanitized artifact hashes, and the provenance of the decision: route status, snapshot identity, evidence class and vintage, profile and evidence identity, main-seat model, the Standing Policy block, whether the decision was an Exploration Attempt, Harness, and Harness inventory revision. A null run identity contributes no run-key term, preserving every existing delegation, capture, and ledger key; a non-null identity makes the same task and point in a later Orchestrate run a distinct row.

Every measurement the environment did not expose stays an explicit `null`. A missing value is never inferred as zero, because a zero is a reading and an absence is not. Wall latency is derived only from the attempt's own two instants when the caller exposed no measured value.

An artifact never retains full prompts, responses, reasoning, ticket or source bodies, source files, diffs, terminal output, secrets, credentials, complete transcripts, or absolute paths where an opaque identity is sufficient. Score dimensions are normalized identifiers with numeric values, artifact hashes are an algorithm and a digest rather than a file name, and every emitted string is held to an identity: an absolute path, an embedded newline, or a value longer than an identity refuses the attempt as `unsanitized_value` and names only the field it was in.

## Cheap-first policy accounting

Where an attempt names a `prior_attempt_id` present in the same batch, its observation carries a `cheap-first` policy account: the run keys of every attempt in the sequence, the retries, and what the whole sequence was charged in cash, rolling quota, weekly quota, allocated subscription cost, and wall seconds. A sequence is as long as it took: a policy that escalated twice carries three run keys and the cost of all three. The account adds every failed attempt, the one that finally passed, and the `checker_charge` the caller supplied for the verdicts between them, because a routing policy is a configuration of its own rather than free capability. A dimension no contributor exposed stays `null` rather than reading as a saving.

Every observation also carries its own `attempt_id` and its `prior_attempt_id`, so the chain a batch saw can be read back out of the ledger by a later reader that saw none of it.

## Idempotency, conflict, and import

Emission is deterministic: the same attempt produces the same run key and the same content. Merging into an artifact skips an identical observation rather than repeating it, and an identity already present with different content is a conflicting identity — `conflicting_identity` — that surfaces both digests and overwrites neither. `record` applies the same rule against the ledger: an unseen run key is appended, an identical duplicate is skipped, and a conflicting duplicate is rejected while nothing changes. Only the derived frontiers whose eligible run set actually changed are rebuilt.

`observe` validates every observation with exactly the validation `record` applies before reporting it as importable, so a reported artifact is one an explicit import accepts and a hand-written one meets the same rules. What a caller may file without asking anybody is the Library's `machine_judged`: authorities `independent_verifier`, `objective_checker`, and `declared_failure_signal`, plus non-model `abstain` and `infra_error`, with `frozen_rubric` and `user_confirmation` left to a person. Two callers read that one rule. Orchestrate calls the shared `observe` and `record` functions at each lifecycle finish; a routed caller that reaches this command asks for `--import` and gets the same rule applied to what this call observed, its artifact still written to caller-owned scratch and named in its report. A caller that asks for no import keeps the artifact alone and leaves the ledger to the user through `/model-selector record`. Imported, identically skipped, conflicting, and refused results are reported per call, each touched Cohort's Standing Policy answer beside them, and ledger refusal never stops the work that produced them.

## Derived frontiers and the projection

A derived frontier compares configurations, so everything else about the work it compares them on is held still: a frontier is identified by the exact tuple of `benchmark_key`, `stage`, `workload_cohort`, and sorted `workload_tags`, and rows differing on any member of it are never unioned, intersected, reduced, or reported as one frontier. Within one frontier, rows are grouped into points by `configuration_fingerprint`. A row naming no Cohort is comparable within nothing: it stays in the ledger and its accounting, enters no frontier, and produces no evidence record. `derived-frontiers.json` keys each frontier by a stable digest of those four values and carries all four inside the entry, so the file stays readable without a separator becoming part of the contract. Each point carries its fingerprint, its judged `runs` and `successes`, the two-sided 95% Wilson `quality_lower_bound` and `quality_upper_bound`, the conditional outcomes it excluded, and its cost means. `record` reports `frontiers_rebuilt` as those four identity fields per rebuilt frontier, in deterministic order. An entry written under an older frontier identity is discarded rather than migrated or left beside the current ones: the file is a reproducible summary of append-only rows, so the rows themselves are what survives a change of shape.

The projection is the ledger read as evidence rather than as accounting. It answers with one evidence record per point of one frontier, of exactly the shape `references/route-request.schema.json` already defines: the fingerprint and the exact routed point — model, portable and native deliberation, channel, Harness, surface, serving mode — from the ledger rows themselves; `stage`, `workload_cohort`, and `workload_tags` from the frontier the point belongs to; `representative` true, because the group is that exact match and nothing wider; `coverage.decision_relevant` true where both bounds exist; `stale` false; `quality` the judged success rate rounded to six decimal places; `uncertainty` the point's two Wilson bounds; and `commercial`, the observed means the ledger's own chains establish for that point. A point with no decisive run emits no record, the numeric quality and interval one requires not existing for it, and a point whose own routed identity the ledger does not hold whole emits none either. Nothing is classified here: the route module owns the only classifier there is, and `measurement_based` continues to mean what the frozen `override_policy.quality_floor` says it means. The context derivation is what consumes the projection, writing `context.evidence.records` from it for every route request.

The projected `commercial` is the point's policy cost rather than its advertised price. A chain is one task's routed attempts inside one run, grouped by `run_identity` and `task_id` across the whole ledger rather than inside one frontier — an escalation changes the workload stratum and so the frontier, and a chain assembled inside one would never see it — and ordered by `attempt_index`, with `prior_attempt_id` validating the links where the ledger holds a whole one. A chain that reached a passing verdict contributes twice to that fingerprint inside the frontier the passing row itself belongs to, so a fingerprint measured in two Cohorts keeps them apart: the cash of every attempt up to and including the pass, and the Time to Verified Pass — the seconds from the chain's first `started_at` to that verdict's `completed_at`. A failing row still contributes its `fail` to its own point's quality, but its cost goes to the chain that later passed and never to its own point's means. A chain no verdict passed contributes nothing, a censored attempt being neither fast nor free. Each dimension is reported as a mean only where every contributing chain carried the measurement, and the other three dimensions are `null`: the projection prices only what the ledger actually observed.

## Stable refusals

Per-attempt refusals: `invalid_attempt`, `no_outcome`, `unlaunched_decision`, `incomplete_attempt`, `self_reported_outcome`, `unchecked_outcome`, `non_model_condition_outcome`, `missing_non_model_condition`, `invalid_scores`, `invalid_quota_accounting`, `unfingerprinted_inheritance`, `unfingerprinted_configuration`, `unsanitized_artifact_hash`, `unsanitized_value`, `invalid_observation`, `incomplete_observation`, `invalid_run_key`, and `conflicting_identity`. A route decision that no external judgement completed is `no_outcome` and remains audit data rather than a `RunObservation`; an interrupted attempt is `incomplete_attempt` and can never be reported as a successful one.

Import refusals are reported in the import account rather than raised, and name the run key they are about: `conflicting_identity` for an identity the ledger already holds with different content, the per-attempt codes above for a row the ledger will not take, and `automatic_import_failed`, once per observation this call could not file, for a ledger it could not write at all.

Process-level refusals, emitted before any attempt is read: `invalid_arguments`, `unreadable_artifact`, `malformed_json`, and `invalid_artifact`. Every refusal is machine-readable on stdout, carries no traceback, and names no caller material.

## Boundary

This contract is the narrow routed-work observation representation. `run-capture.md` owns explicit-opt-in automatic capture across ordinary Harness work — lifecycle installation and cross-Harness hook ownership among them — and produces a Usage Record rather than reusing this contract: ordinary work has no independent verifier to found an outcome on, so it is measured and never judged, and nothing it produces reaches `observe`, `record`, or the evidence ledger this contract owns. Orchestrate owns only its explicit routed-attempt lifecycle and automatic import at an independent verdict or terminal non-model condition, and delegation only the `--import` it asks this command for at the same kind of boundary.
