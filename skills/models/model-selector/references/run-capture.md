# Automatic run capture

Use this reference for `## Capture`. It measures ordinary Harness work; it never judges it. A finished session produces a Usage Record — what it cost and how long it took on the exact Seat it ran on — appended to its own store beside the evidence ledger. It is not a `RunObservation`, does not reuse `run-observations.md`'s envelope, and is never imported by `record`.

## Consent and lifecycle

Capture follows the Skill's own Enabled state and asks for nothing beyond it (#223). Enabling the Skill through the Manager is the whole gesture: the Manager installs this feature's owned lifecycle integration into every supported Detected Harness of the Global layer at the same seams that already place and refresh the Skill's own files, and Disabling the Skill is the whole undo, removing every entry those seams installed. There is no second opt-in, no consent prompt, and no third command — what is installed, what is retained, and how to stop it are stated once, in this Skill's own `help.md`, read before Select answers.

Every installed integration carries a stable ownership identity, so install, repair, refresh, remove, withdrawal, and uninstall converge on the same disk state however often they run — asking an already-installed Skill to install again changes nothing. Removal is surgical: entries this feature installed go, and unrelated hooks, unrelated configuration, and Harness session history are left exactly as they were. Installation and removal are verified by reading the Harness's own file back, and a Harness that only partly applied is reported as that rather than as a complete one.

Making the Skill Disabled is sufficient to stop capture and remove what it owns. There is no second shutdown step, because the Manager asks the Skill to remove its integrations while the Skill's own files are still on disk — after they are deleted, nothing left on the machine knows what was installed or where. Accepted Usage Records survive every one of these transitions: turning a measurement off is not a reason to forget what it measured, and a purge is a separate act the user has to ask for by name — `config reset --evidence`, which removes the whole `capture/` subdirectory and the Usage Record store together, leaving the Harness hooks installed and working.

A Project-layer Enable installs no integration. An owned entry is keyed by owner inside a Harness's own configuration, so a Global and a Project Enable of the same Skill would write and remove one another's single entry; measurement is a property of the machine, not of a working directory, so capture installs from the Global layer alone.

## Harnesses

Adapters exist for Claude Code, Codex, and OpenCode, whose supported lifecycle APIs can carry the contract: the first two through their owned hook tables, the third through a plugin file named for its owner. Session start, agent stop or idle, session end, and error are the moments observed. Each is a lifecycle signal and none is a verdict — a stop says a turn ended, never that its work succeeded, and there is no verdict for a Usage Record to carry either way.

Each adapter is verified against what its own Harness actually reads — event names, entry shape, and file location established from that Harness as installed, never assumed from a sibling's. Claude Code and Codex each keep an owned hook table in their own file, and confirmed live, Codex's own config file accepts the same PascalCase event names and the same nested matcher-group entry Claude Code's does; the flat, camelCase shape its unrelated app-server protocol reports back is not what the config file reads. A Harness outside the supported set, or one whose accepted shape cannot be established, reports an Unsatisfied integration capability and is never reported healthy.

Codex additionally reviews a hook that is new or has changed before it will run it, and this collection forges no trust decision and writes no trust record on the user's behalf — a gate is the Harness's own. A Codex integration that is correctly written is reported gated: present, and not yet active, naming what the user does to clear the review. OpenCode's plugin hands its event object on unmodified and redirects it onto the invoked command's own standard input, which is what carries the session identity nested inside it and what keeps the command from ever inheriting the session's own standard input, which a hook that reads it to end-of-file could otherwise block on.

A script cannot know which Harness invoked it and must not guess, so the Manager — which already resolves Detected Harnesses to decide where a Skill's own files go — names them when asking this feature to install, and the guessing an agent once did at opt-in time disappears with it. Only a Harness the Library has an adapter for is attempted; the rest is reported as a single count naming the supported set rather than one row each, because a Detected-Harness list this large would otherwise bury the outcome that matters under Harnesses no adapter exists for. The shared mechanics live in the Collection Library rather than in this Skill, where a second consumer finds them instead of reaching in here.

Claude Code additionally writes its own record of a session as it runs — one JSON-lines transcript, and, where the session delegated work, a companion `subagents/` directory beside it — and that record is read once, after the session's last lifecycle event, through the Collection Library's session-record reader (`session_records.py`, #225). Where it can be read, it supplies the two dimensions capture exists to measure — the exact model and the deliberation control each turn actually ran under — and the token categories the Harness itself counted. Codex and OpenCode keep no record this reader knows how to open yet, so a session on either still measures from its lifecycle signals alone; `status` reports, per Harness, whether its own finished record can supply measurements at all.

## The pipeline

A small per-session draft is created when substantive work begins, and updated only from allowed lifecycle, Seat, and usage signals. Two sessions at once are two drafts under two opaque identities, so neither can read or clear the other's.

Within one session, a Seat's own active window opens at the first lifecycle signal naming it and extends at every later one, so its Usage Record is timed on that Seat's own first and last turn rather than on the whole session's start and end. A session that ran on more than one Seat — the user switched model or deliberation mid-way — produces one Usage Record per Seat at the session's end, because each Seat is a distinct configuration the session actually ran on.

At `SessionEnd` or an error signal, one further read happens before anything is written: where the ending session's own Harness keeps a finished record and it can be opened, that record — not the lifecycle signals gathered so far — decides how many Seats this session produces and what each one's usage was. It is read once, bounded to exactly that session's own transcript and its own companion subagent directory, and nothing broader is ever opened. Every Seat window the draft holds becomes one Usage Record only where no such record could be read at all; the two paths never blend within one session. Records are appended to the store and the draft is deleted either way. Idempotency is by session identity and Seat: a Usage Record whose key the store already holds is skipped rather than repeated, so a lifecycle signal redelivered after the store was already written adds nothing the second time. An error signal ends the session exactly as a normal end does — there is no outcome left for either to carry, so neither is a verdict of any kind.

Where the record distinguishes a subagent's own turns from the session's own — Claude Code's own companion directory, one transcript per subagent — each subagent's usage is counted against its own Seat rather than the main session's: that Seat carries the model and deliberation control the record actually names for it, and an explicit null on every field the record does not supply — channel, surface, adapter, serving mode — because those describe the session's own surface and are not a subagent's to borrow. A session whose own turns alone switched model or deliberation splits the same way, one Seat per distinct configuration actually run, main or delegated.

Nothing is supplied at installation any more (#223 decision 7): no lifecycle payload carries the exact seat a session runs on — a Harness reports what happened rather than what it is — and a script may not guess it either. A payload that does name a seat wins, and a Harness whose finished record can be read wins over that, for the two fields the record actually supplies: the exact model and the deliberation control in force. A session with no Seat known at all — no readable record and no payload — still writes a Usage Record, its Seat fields explicit nulls, because nothing here waits for anybody to supply one.

## Data boundary

Temporary capture and the permanent Usage Record both carry only what one is built from: opaque session identity and usage key; the Harness and its inventory revision; the exact Seat — model, deliberation control, serving mode, access channel, and tool fingerprints; the usage categories the environment exposed — tokens, tool calls, retries, cost, quota, latency, and fallback; and the two instants a Seat ran between. Every measurement the environment did not expose stays an explicit `null`, because a zero is a reading and an absence is not.

Never full prompts, responses, reasoning, source files, diffs, terminal output, secrets, credentials, or complete Harness transcripts, and never an absolute path where an opaque identity is sufficient. A lifecycle payload is copied onto an allow-list rather than stripped afterwards, so nothing forbidden enters by sitting beside something wanted, and a raw session identifier — which is a path or a workspace name often enough — is hashed rather than kept.

`transcript_path` is the one allow-listed field that is never itself retained. It names where a session's own finished record lives, is read only to open that file and its own companion subagent directory, and is used and discarded within the single end-of-session hook invocation that reads them — it never becomes part of a draft written to disk, and it never reaches a Usage Record. The session-record reader itself reads that record field by field onto its own allow-list of what a Seat and its usage may be, the same discipline applied to a richer source: a transcript line carries a whole message, a whole set of tool arguments, and a whole working directory, and none of it is read for anything but the exact model, the exact deliberation control, the token counts, and the instant each turn happened.

A Usage Record carries no outcome, no Outcome Authority, no checker, no condition, no Cohort, and no configuration fingerprint. It is never quality: it enters no derived frontier, contributes to no success rate, clears no quality floor, and produces no evidence record, exactly as a Cohort-less ledger row already stays out of every comparison — applied here to a record that carries no outcome to compare in the first place.

## The hook path

Fail-open, always. A capture that cannot run must never block an agent response, a tool execution, or a session ending, so every failure inside the hook is swallowed and the hook exits clean.

Bounded and local, always. The synchronous path does local metadata I/O and nothing else: no model call, no test run, no repository-wide hashing, and no long-lived background work. Network is reached from one place only and never by capture itself — the unattended source refresh a session's own last invocation dispatches beside this work, as bounded conditional metadata retrieval under a stated budget, documented in `unattended-refresh.md` and owned by its own module (#247). What capture writes is unchanged by it: its own store and its Usage Records, and no evidence ledger row of any kind.

`SessionStart`, a turn, and an idle signal read nothing but their own payload, exactly as before this read existed — no transcript is ever opened from any of them. The one exception is the session's own last lifecycle event: `SessionEnd` and an error signal are already a single, one-time invocation rather than the ongoing per-turn path the rest of this section describes, reached only once, after the session it describes is already over, so nothing left running is put at risk by it — and it is there, and nowhere else, that the finished session's own record may be read, bounded to that one session's own transcript and its own companion subagent directory, nothing broader ever opened. A record that cannot be opened, is truncated, or will not parse leaves the read exactly where it would have been without it: an absence the session's own lifecycle signals answer for instead, never a raised error and never a lost row.

## Boundary

This contract owns automatic capture of ordinary Harness work and the Usage Record it produces. It is not the routed-work observation representation `run-observations.md` owns, reuses none of that contract's envelope, validation, or import, and writes no ledger row of any kind. Deliberately routed work stays entirely `run-observations.md`'s, whose `observe` and `record` this reference never calls.
